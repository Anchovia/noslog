# CLAUDE.md — NosLog 2.0 디자인 작업 규칙

> **이 파일을 모든 작업 시작 전에 반드시 먼저 읽는다.** 세션이 바뀌어도, 대화가 길어져도,
> 작업을 재개할 때마다 다시 읽는다. 여기 적힌 규칙은 사용자가 반복해서 지시한 것이며
> 어긴 적이 있는 항목만 남겨 두었다.

---

## 0. 절대 규칙 (어긴 이력이 있음 — 반복 금지)

1. **시작 게이트** — 사용자가 명시적으로 "시작"이라고 말하기 전에는 아무것도 만들지 않는다.
   스킬 로딩이나 "phase 진입"도 시작으로 간주된다.
2. **문서 우선** — 만들기 전에 해당 Page Brief를 끝까지 읽는다. 상위 문서만 읽고 시작하지 않는다.
3. **추측 금지** — 문서에 없는 값(패딩·정렬·색·구조·컬럼·라벨)을 감으로 정하지 않는다.
   `AGENTS.md`에 이미 명시: _"Do not make ambiguous decisions from assumptions."_
4. **애매하면 멈추고 질문** — 문서에 근거가 없는 시각 결정이 나오면 **만들지 말고 먼저 묻는다.**
   질문할 때는 말로만 하지 말고 **비교 시안을 그려서** 보여준다.
5. **만든 직후 전수 검증** — 아래 §2 체크리스트를 예외 없이 전부 돌린다.
   "스크립트가 에러 없이 돌았다" ≠ "결과가 맞다".
6. **실행한 검사만 보고** — 안 돌린 검사를 "검증했다"고 말하지 않는다.
7. **Light/Dark 둘 다** — 문서 24는 Light·Dark 양쪽을 요구한다. 한쪽만 만들고 끝내지 않는다.
8. **정의값 그대로 쓴다 — 눈대중 금지** ⚠️ **가장 자주 어긴 항목**
   **레이아웃(패딩·간격·크기·정렬)·색·타이포는 §3에 적힌 값 집합 안에서만 고른다.**
   근사값·중간값·"보기 좋아 보이는 값"을 만들지 않는다. 스케일에 없는 숫자가 필요해 보이면
   그건 값을 새로 만들 신호가 아니라 **멈추고 질문할 신호**다(규칙 4).
9. **매 컴포넌트마다 다시 확인한다** — 레이아웃·색·타이포 세 가지는 §2에서 **예외 없이 매번**
   전수 재확인한다. 앞 컴포넌트에서 지켰다는 이유로 다음 컴포넌트에서 생략하지 않는다.
   패딩·정렬 같은 "기본적인 것"일수록 건너뛰지 않는다 — 실제로 여기서 반복해서 틀렸다.

## 2. 검증 체크리스트 (만들 때마다 전부)

> **레이아웃 · 색 · 타이포 세 블록은 만들 때마다 전부 돌린다. 하나도 건너뛰지 않는다.**
> 안 돌린 검사는 "통과"가 아니라 **미실행**이며, 미실행을 통과로 보고하지 않는다(규칙 6).

### A. 레이아웃 감사 — 패딩 · 간격 · 크기 · 정렬

- [ ] **spacing 스케일** — 모든 padding/itemSpacing이 `0·4·8·12·16·24·32·48·64` 중 하나.
      `2px`는 **아이콘·배지·차트 내부 광학보정 전용** — 일반 레이아웃 간격으로 쓰면 위반(문서 24)
- [ ] **패딩 역할 일치** — `4` 분리불가 디테일 / `8` 인라인 피어 / `12` compact inset /
      `16` 기본 component inset / `24` subsection / `32` section / `48` page-region /
      `64` 희귀 대구획. 역할과 다른 값을 쓰면 근거를 남긴다
- [ ] **좌우·상하 패딩 대칭** — 비대칭이면 의도된 것인지 확인하고 근거를 남긴다
- [ ] **가장자리 아이콘 컨트롤 광학 패딩** ⚠️ 2026-08-13 사용자 지적 — 선언값만 보면 못 잡는다
      양쪽 끝이 고정된 컨테이너의 첫/마지막 자식이 아이콘 전용 컨트롤이면,
      그 컨트롤의 내부 여백 `(타겟−아이콘)/2` 을 컨테이너 패딩에서 뺀다.
      AppHeader = 왼쪽 16 / 오른쪽 8(44 타겟 안 24 아이콘 = 내부 10). **선언 비대칭이 정상이다.**
      타겟이 컨테이너 경계에 닿을 만큼 줄이지 않는다(SearchField 는 그래서 8 유지).
      검사는 `audit.js` `A17_edgeIconOptical` — 잉크·아이콘 박스 기준으로 본다
- [ ] **죽은 여백(FILL 자식이 남는 공간을 삼킴)** ⚠️ 2026-08-14 사용자 지적 — `A15`는 반대 경우만 잡는다
      부모가 FIXED이고 자식이 세로 `FILL`이면, 자식은 남는 공간을 흡수하고 정렬이 `MIN`일 때
      그 공간이 **콘텐츠 아래 죽은 여백**으로 깔린다. 선언 패딩만 보면 안 보인다.
      **고정 높이는 반드시 내용에서 유도한 숫자여야 한다** — 유도 안 되는 숫자면 HUG로 바꾼다.
      실제 사고: Music Grid 카드가 297 고정인데 내용은 277 → 난이도 마커 아래 20px 죽은 공간
      (하단 패딩 12까지 32px). 검사: `자켓 + gap + (body 패딩+내용) + 카드 패딩 == 카드 높이`
- [ ] **컴포넌트 크기 일관** — 같은 역할 컴포넌트는 높이가 서로 일치.
      variant 간(Default/Focus/Filled…) 크기가 들쭉날쭉하면 위반
- [ ] **아이콘 크기** — 렌더 `20`(일반 액션) / `16`(라벨 옆 보조) / `24`(강조)만.
      아이콘 전용 컨트롤 타겟 **모바일 44×44 · 데스크톱 40×40** 충족
- [ ] **정렬** — ① `counterAxisAlignItems=CENTER` 선언 지점의 자식 centerY 오차 ≤0.5px
      ② `primaryAxisAlignItems` 선언과 실제 배치 일치
      ③ 같은 행 텍스트끼리 baseline 어긋남 없음
      ④ 세로로 쌓인 라벨/값의 좌측 정렬선 일치
- [ ] **원형 요소** — 원이어야 하는 것(배지·dot·아바타)은 width=height 고정
- [ ] **radius 역할** — control `4` / container `8` / overlay `10` / full `50%`.
      focus 는 컨트롤의 기존 radius 를 그대로 사용하며 파생 radius 를 만들지 않는다
- [ ] **strokeWeight** — 1 또는 2
- [ ] **페이지 겹침** — top-level 노드 간 bounding box 교차 0
- [ ] **텍스트 넘침** — 부모 가용폭 초과 0
- [ ] **아이콘 클리핑** — 인스턴스 크기 = 내부 프레임 크기, clip 해제
- [ ] **그리드/컨테이너** — Compact <672(4col g12 m16) / Intermediate 672–1055(8col g16 m24) /
      Wide 1056+(12col g16 m32). container 최대값은 **천장이지 고정 캔버스가 아니다**

### B. 타이포 감사

- [ ] **Text Style만 사용** — 노드에 size/weight/line-height를 직접 찍지 않는다.
      39개 Text Style(13 composite × ko/ja/latin) 중 하나를 적용
- [ ] **composite 정확 일치** — size/line-height/weight 조합이 §3 표의 **13종 중 하나와 정확히 일치**.
      임의 조합(예: 16/20, 14/24) 금지
- [ ] **weight** — `400·500·600·700`만. `100–300`·`800–900`·중간값 금지
- [ ] **최소 크기** — 사용자 대면 텍스트에 12px 미만 없음
- [ ] **tabular figures** — `metric-display`·`metric-value`에만. 나머지는 proportional
- [ ] **역할 오용 없음** — `entity-title`을 섹션 제목으로, `body`를 컨트롤 라벨로 쓰는 식의 혼용 금지.
      `control`=액션/선택/필드 라벨, 입력된 값=`body`

### C. 색 감사

- [ ] **바인딩 100%** — 모든 fill/stroke/effect가 변수 바인딩. 하드코딩 0
- [ ] **NI-A 준수** — interaction fill이 hover/selected/menu-set/disabled **외의**
      resting 요소에 칠해져 있지 않음. 보편적 hover/selected 배경은 없다
- [ ] **경계 오용 없음** — `divider`는 장식 리듬 전용. quiet 경계(`divider`·`border-subtle`)를
      유일한 필수 단서로 쓰지 않음. Dark 컨테이너를 전부 외곽선 두르지 않음
- [ ] **Light·Dark 양쪽** — A·B·C 전부를 두 모드 각각에서 재확인 (한쪽만 돌리면 미실행)

### 구조 변경 함정 (실제로 화면을 깨뜨린 적 있음)

- **auto-layout 부모에서 `appendChild`/`insertChild`는 z-순서만 바꾸는 게 아니라 flow 위치까지 바꾼다.**
  2026-08-14: P1 셸(VERTICAL auto-layout)에서 z를 맞추려고 `appendChild(header)` 했더니
  헤더가 flow 끝(y=1488)으로 밀려 화면에서 사라졌다. 일반 프레임(절대배치)에서는 z만 바뀐다.
  **오버레이 z는 `layoutPositioning='ABSOLUTE'` 로 해결하고, flow 자식의 순서는 건드리지 않는다.**
- 이 사고는 겹침·이탈·넘침 검사를 **전부 통과했다** — 헤더가 셸 안에 있고 크기도 그대로였기 때문이다.
  셸을 만들면 `헤더가 flow 최상단(index 0 · y=0)이고 폭이 셸 폭과 같은지`를 따로 확인한다.
- **`figma.createAutoLayout()`·`createFrame()` 은 SECTION 이 아니라 현재 페이지에 붙는다.** ⚠️ 2026-08-18 사용자 지적
  좌표만 섹션 위치에 맞춰 두면 화면에서는 섹션 안처럼 보이지만 실제로는 섹션의 자식이 아니다.
  Z1 결정 시안 4개가 이 상태로 만들어졌고 `section.children.length` 가 0 으로 찍혀서야 발견했다.
  **새 판은 `section.appendChild(node)` 로 먼저 붙이고 좌표는 그다음에 준다.**
  검사: `page.children` 에 SECTION 아닌 노드가 남아 있으면 위반이다.
- **섹션 안 배치는 좌표를 손으로 박지 말고 직전 형제에서 계산한다.** 같은 지적.
  판 높이는 만든 뒤에도 계속 바뀌므로(텍스트 폭 수정·블록 추가) 미리 계산해 둔 y 는 곧 어긋난다.
  규약: `x = section.x + 48` · `y = 직전 형제.y + 직전 형제.height + 64` · 섹션 크기는 내용에 맞춘다.
  내용을 고쳐 높이가 바뀌면 **그 섹션을 통째로 다시 흘려보낸다.**
- **생성 API 전부가 `figma.currentPage` 에 붙는다 — 내가 지정한 노드가 아니다.** ⚠️ 2026-08-18/19 반복 발생
  `createAutoLayout()` · `createFrame()` · `createSection()` · `clone()` 이 전부 해당한다.
  2026-08-19 에는 Z1 을 currentPage 로 둔 스크립트 안에서 P2 용 섹션 2개를 만들어
  **Intermediate·1440 섹션이 통째로 Z1 페이지에 생겼다.** 좌표를 P2 기준으로 계산했기 때문에
  위치만 그럴듯해서 감사·스크린샷에도 안 걸렸고, handoff 를 쓰려고 `p2.children` 을 세다가 발견했다.
  **다른 페이지의 노드를 만들려면 그 페이지를 currentPage 로 두거나, 만든 직후 `targetPage.appendChild()` 한다.**
  검사: 작업 후 `page.children` 개수와 섹션 목록을 직접 세어 본다.
- **`clone()` 도 원본이 SECTION 자식이어도 페이지에 붙는다.** ⚠️ 2026-08-18
  상태 화면 3개를 복제했더니 전부 페이지 직속으로 생겼다. 복제 직후 `section.appendChild()` 한다.
- **`layoutPositioning='ABSOLUTE'` 자식의 `x`/`y` 는 부모 프레임 기준이다.** 절대 캔버스 좌표를 넣으면
  프레임 밖으로 나가 clip 되어 아예 안 보인다. `absoluteBoundingBox` 차이로 계산한다.
- **인스턴스를 배치하기 전에 그 컴포넌트의 컨테이너 계약을 먼저 읽는다.** ⚠️ 2026-08-18 사용자 지적
  `ResultCollection · Music List` 행은 `surface/surface` 면 + radius 8 을 가진 **독립 카드**인데
  gap 0 으로 쌓아 모서리가 부딪히고 자켓(`surface/sunken`)이 회색 기둥으로 이어졌다.
  또 팝오버를 만들면서 승인된 오버레이 계약(`DestinationPanel`: `surface/overlay` + `border/default` 1px
    - radius 10 + **`elevation/overlay-light` 그림자 스타일**)을 확인하지 않아 그림자가 통째로 빠졌다.
      **재사용 = 인스턴스만 가져오는 것이 아니라 그 컴포넌트가 놓이도록 설계된 면·간격·고도까지 맞추는 것이다.**
- **`appendChild` 는 대상 서브트리의 폰트가 로드돼 있지 않으면 던진다.** 텍스트를 품은 노드를 옮기기 전에
  쓰이는 폰트 패밀리·스타일을 먼저 `loadFontAsync` 한다.
- **`findAll` / `findAllWithCriteria` 는 INSTANCE 내부로 내려가지 않는다.** ⚠️ 2026-08-18
  로케일 프레임을 만들 때 일반 프레임의 목적지 라벨은 번역됐는데 AppHeader·SearchField·OrdinaryFooter
  **인스턴스 안의 텍스트만 한국어로 남았다.** 인스턴스 내부를 훑어야 하면 그 인스턴스를 기점으로
  다시 `findAll` 하거나 `children` 을 직접 재귀한다.

### 색 바인딩 함정 (실제로 파일을 망가뜨린 적 있음)

- 변수 바인딩 paint를 만들 때 **raw 색을 반드시 실제 값으로 채운다.**
  `{r:0,g:0,b:0}`으로 두고 `setBoundVariableForPaint`만 걸면, 바인딩 해석이 안 되는 순간
  **전부 검정으로 렌더**된다. Dark 플레이트가 통째로 검게 변한 사고의 원인.
- Dark 노드는 `explicitVariableModes`로 모드가 걸려 있다. 검사·수정 시 **노드의 실효 모드**
  (자신 또는 조상의 explicit mode)를 기준으로 값을 해석한다. Light 기준으로 비교하면
  Dark 노드가 전부 "불일치"로 오판되고, 그걸 고친다며 덮어쓰면 파일이 깨진다.
- **대량 변경(수십 개 이상) 전에는 반드시 소수로 시험하고 눈으로 확인한 뒤 확대 적용한다.**

### 3.2 spacing 역할 (이외 값 금지)

`0` 의도적 부재 · `2` **아이콘/배지/시각화 내부 광학보정 전용** · `4` 분리불가 디테일 ·
`8` 인라인 피어 · `12` compact inset · `16` 기본 component inset · `24` subsection ·
`32` section · `48` page-region · `64` 희귀 대구획

> `2px`를 일반 레이아웃 간격으로 쓰지 않는다. `48/64`를 여백이 허전해 보인다는 이유로 쓰지 않는다.

### 3.3 나머지

- 중립 = **Adobe Spectrum S2 정확값** (Tailwind 금지)
- focus = **FI-C** Light `#000000` / Dark `#FFFFFF` · **컨트롤 자신의 1px INSIDE 경계 하나**
  (`FOCUS-1B`, 2026-08-13 사용자 결정)
    - 평상시 경계가 있으면 **그 색만** focus 색으로 교체 (invalid 가 빨강으로 바뀌는 것과 같은 방식)
    - 평상시 경계가 없으면 **포커스에서만** 1px 경계를 부여. 평상시 외형은 그대로
    - INSIDE 라서 크기·위치·주변 레이아웃이 변하지 않는다. **두께를 바꾸지 않는다**
    - 면이 진해 focus 색이 3:1 을 못 맞추면 그 면의 on-fill 색(`primary/on-primary`) 사용
    - 자켓처럼 **bleed 자식이 경계를 덮는 카드**는 최상단 절대배치 `focus-border` 오버레이로 그린다
    - ⚠️ 1px 색상 단서는 WCAG 2.2 SC 2.4.13(2px 최소)을 못 맞춘다 — 사용자가 알고 승인함
    - **포커스에 면 변화를 함께 주는 보조안은 제안했으나 미채택**(2026-08-13). focus 는 경계만 건드린다
    - **hover 는 면(fill), focus 는 경계(stroke)** — 축이 달라 동시에 표시된다. 서로 대체하지 않는다
- **NI-A**: 보편적 hover/selected 배경은 **없다**. interaction fill은
  hover / selected / menu-set / disabled **에만** 사용. 평상시(resting) 요소에 칠하지 않는다.
- 아이콘 = **Lucide** 실제 geometry (`node_modules/lucide-react` 1.24.0에서 추출, 손으로 그리지 않음)
    - 렌더 20px(일반 액션) / 16px(라벨 옆 보조) / 24px(강조)
    - **아이콘 전용 컨트롤 타겟: 모바일 44×44, 데스크톱 40×40**
- 도메인 색: DU-01 난이도 4 / JD-02 판정 5(FAST/SLOW 아님) / LD-03 SAP / FS-BN 피드백
- **눌림(pressed)** = `transform: scale(0.98)` + `100ms`(MO-02 Pressed feedback 슬롯) · 상수 `motion/press-scale`
  (2026-08-13 승인). transform 이라 **박스 크기·레이아웃 불변** — 축소값을 레이아웃 크기로 만들지 않는다.
  작은 컨트롤(버튼·아이콘 버튼·페이지 번호)만. 리스트 행·그리드 카드에는 쓰지 않는다.
  `prefers-reduced-motion` 에서는 제거되고 Neutral·Ghost 는 색 단계가 남는다(Primary·Destructive 는 변화 없음).
  ⚠️ Primary·Destructive 의 pressed **색** 차이는 1.13~1.26:1 로 비가시 — 승인 램프에 여유가 없어서이며
  `primary/pressed`·`feedback/destructive-border-pressed` 는 reduced-motion 잔여 단서로만 존재한다.
- **`border/empty-slot`** ⭑ 신규 별칭 토큰(2026-08-13 승인, CONFLICT-17) — 아트 없는 자켓 슬롯의 1px 경계.

  들어오면 stroke 를 제거한다. 문서 24와 Figma에 반영 완료.
- grid: Compact <672(4col g12 m16) / Intermediate 672–1055(8col g16 m24) / Wide 1056+(12col g16 m32)
