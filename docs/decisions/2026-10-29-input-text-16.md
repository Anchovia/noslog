# 입력 글자 16 · 검색칸 높이는 모든 화면 40

- 상태: 유효
- 날짜: 2026-10-29
- 분야: 디자인 · 기초값
- 고른 사람: 사용자 지시(「인풋 16으로 수정해」, 「홈 검색 크기가 정사이즈」), 입력 토큰 · 보상 입력 · 검색칸 안 셀렉트는 시안 추천대로

## 맥락

아이폰에서 검색칸에 글을 쓰면 화면이 확대됐다. iOS Safari 는 입력 글자가 16 보다 작으면 포커스 때 확대한다.
입력 글자는 [2026-10-25 체계 묶음](./2026-10-25-design-system-cluster.md) 4번에서 14 가 됐는데, 확대 문제는 「알아 둘 점」 한 줄로만 남았고 사용자가 고른 항목이 아니었다.
입력 글자 크기는 입력칸(`--nl-type-size-14`) · 검색칸(`nl-control` 클래스) · 마크다운 입력(`--nl-type-size-14`) 세 곳에 따로 묶여 있어 한 곳만 고쳐지는 일이 되풀이됐다.
검색칸 높이도 홈만 화면 CSS 가 40 으로 덮어써서, 넓은 폭에서 홈 40 · 다른 화면 32 로 갈렸다.

## 결정

1. 입력 글자는 16 이다. 입력칸 · 검색칸 · 단위 입력 · 마크다운 입력이 모두 공용 토큰 한 곳을 따르고, 화면 CSS · 인라인으로 덮어쓰지 않는다. 모든 폭 같다.
2. 검색칸 높이는 홈 검색 크기(40)다. 모든 화면 · 모든 폭 같고, 부품이 정한다. 화면 CSS 가 덮어쓰지 않는다.
3. 입력 글자를 묶는 곳은 역할 토큰 `--nl-type-input-size`(16) 하나다. `.nl-input` · `.nl-search__input` · `.nl-markdown-editor__input` · `.nl-admin-reward__input` 이 이 토큰을 쓴다.
4. 관리자 시험 편집기 보상 이름 입력은 회색 줄 모양을 그대로 두고 글자만 같은 토큰을 따른다.
5. 검색칸 안 범위 셀렉트는 올리거나 눌러도 면 · 글자색이 바뀌지 않는다(알라딘 · 교보문고 · Alamy). 키 포커스는 공용 포커스 선만 보인다.

## 고르지 않은 안

- 새 토큰 없이 세 규칙에 원재료 토큰 `--nl-type-size-16` — 크기를 바꿀 때 세 곳을 함께 고쳐야 한다.
- 보상 이름 입력 14 그대로 — 아이폰에서 누르면 화면이 확대된다.
- 셀렉트 안쪽 알약 칩이 기본부터 있고 올리면 진해짐(Depositphotos) — 실제 서비스 30곳 중 2곳.
- 셀렉트 칸 전체에 면, 바깥 모서리를 따름(IMDb · Amazon) — 실제 서비스 30곳 중 2곳, 디자인 시스템 7곳 중 3곳.
- hover 때만 안쪽에 떨어진 면(앞 세션 구현) — 실제 서비스 30곳 중 1곳(Wikipedia), 디자인 시스템 0곳. 사용자가 거부했다.

## 사용자 확인 전

- 지우기 × 의 올림 면(위아래 4 를 비운 32 정사각)은 앞 세션이 정한 값 그대로다. 실제 서비스 조사 밖이라 사용자가 고르지 않았다.
- 범위 셀렉트를 누를 때 모양은 재지 않았다. 올림과 같이 바뀌지 않게 두었다.

## 근거

- 사용자 지시 두 가지와 시안 추천(위 「고른 사람」).
- 검색칸 안 범위 셀렉트 hover: 실제 서비스 30곳(변화 없음 19, 알약 검색칸 5곳 중 변화 없음 3) · 디자인 시스템 7곳을 1280 폭에서 올려 캡처해 셌다. 봇 차단 · 동의 벽에 막힌 약 60곳은 세지 않았다.
- iOS Safari 는 입력 글자가 16 보다 작으면 포커스 때 화면을 확대한다([2026-10-25 체계 묶음](./2026-10-25-design-system-cluster.md) 「알아 둘 점」).
