# 커밋 제목은 변경 하나 · 50칸 권장 72칸 상한 · 필요한 커밋은 본문

- 상태: 유효
- 날짜: 2026-11-11
- 분야: 구조
- 고른 사람: 사용자(판 1 A · 판 2 A)

## 맥락

NosLog 커밋 제목은 한 줄에 여러 변경을 가운뎃점으로 늘어놓았고(최근 300개 중 53%), 본문이 있는 커밋이 없었다. 공개 저장소 43곳은 나열이 중앙 1%, 본문이 중앙 69% 였다. 사용자가 「일반적인 커밋 제목처럼 쓰자」 고 했다.

## 결정

- 제목 하나에 변경 하나만 적는다. 변경이 둘 이상이면 커밋을 나눈다.
- 제목은 50칸을 권장하고 72칸을 넘기지 않는다. 한글은 두 칸으로 센다.
- 제목만으로 무엇이 왜 바뀌었는지 알 수 없는 커밋은 본문을 쓴다. 에이전트는 제목과 함께 본문도 준다.
- `type: 한국어 설명` 앞머리는 그대로 둔다.

## 고르지 않은 안

- 72칸 상한만(GitLab · Django): 한글 33자까지 들어가 두 가지를 한 제목에 다시 담기 쉽다
- 50칸 상한(Git · Pro Git · Tim Pope · Rails): 한글 22자가 상한이라 무엇을 고쳤는지가 빠지기 쉽다. 실측 43곳 중 28곳은 길이 중앙부터 50자를 넘는다
- 제목만 쓰기(Vite · Mastodon · Home Assistant): 세 곳은 PR 마다 설명을 쓰지만 NosLog 는 `dev` 에 바로 커밋해 PR 이 릴리스 때만 있다

## 근거

- [커밋 제목 조사](../research/2026-11-11-commit-titles.md): 공개 저장소 43곳 실측, 가이드 문서 16곳.
- 50칸 권장 · 72칸 상한은 Chris Beams 와 Kubernetes 기여 가이드의 방식이다. 실측 길이는 중앙 54자, 긴 쪽 10% 경계 75자다.
- 본문에 「왜」 를 쓰라는 가이드 10곳, 한 커밋에 변경 하나를 말하는 가이드 8곳.
- 한국어 제목의 말끝은 표본에 한글 제목이 없어 정하지 않았다(미확인).
