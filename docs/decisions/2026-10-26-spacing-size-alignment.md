## 맥락

공개 화면 27개를 390 · 1280 두 폭에서 잰 결과, 같은 자리가 화면마다 다른 값이었다. 페이지 제목 아래가 8 · 16 · 24 · 48, 컨트롤이 28 · 30 · 36 · 44 로 나왔다. 대부분은 가이드에 값이 있는데 화면 CSS 가 따로 덮어쓴 것이라 가이드대로 맞췄다. 가이드에 자리가 없는 다섯 칸은 실제 서비스를 재서 골랐다.

## 결정

1. 넓은 폭(1056 이상) ≡ 창은 ≡ 버튼 바로 아래(버튼 아래 0)에 연다. 창 위쪽이 헤더 아래 칸에 걸친다.
2. 홈 메인 검색은 모든 폭 크게(40).
3. 글자만 있는 표 줄 = 목록 행 = 컨트롤 높이(넓은 폭 32 · 좁은 폭 40, 아래 선 포함). 여러 줄 칸은 그만큼 늘어난다. 자켓이 있는 프로필 기록 표는 화면 문서 값 그대로.
4. 뒤로 링크 → 페이지 제목 24, 모든 상세 화면.
5. 헤더 → 첫 요소 24. 홈도 같다(프로필은 화면 문서 값).

## 고르지 않은 안

- ≡ 창 버튼 아래 4(Speedrun.com · Primer · Ant 기본 offset) · 지금 그대로 헤더 아래 8 — 열어 잰 14곳 중 8곳이 0.
- 홈 검색 32 그대로(GitHub · Goodreads 헤더 검색 32) — 폰과 높이가 달라진다.
- 표 줄 모든 폭 40(Geist · Quaver) · 36(Speedrun.com · ESPN · Primer · Polaris) — 36 은 새 높이 값이 된다.
- 뒤로 링크 → 제목을 화면대로(8 · 24 · 32) 두기.
- 홈만 32 로 더 띄우기 — 32 로 맞춘 서비스가 없었다.

## 근거

- 실제 서비스 37곳(게임 · 랭킹 18 · 음악 · 미디어 · 개발 · 스포츠 19), 디자인 시스템 8곳(Geist · Primer · Atlassian · Fluent 2 · Ant · Carbon · Polaris · M3)을 같은 역할 칸으로 두 폭에서 쟀다. 막혀서 세지 않은 곳 6곳.
- ≡ 창: 넓은 폭 트리거 아래 거리 0 = GitHub · AtCoder · Lichess · BeatLeader · BeatSaver · HLTV · MusicBrainz · Steam(14곳 중 8), 2–5 = 3곳, 12–16 = 3곳.
- 홈 검색: 본문 안 검색 6곳 중 40 이상 3(Linear 40 · ScoreSaber 40.5 · BeatLeader 48), 36–38 3. 근거 약함.
- 표 줄: 글자만 있는 표 11곳이 30–41 에 흩어짐(osu! 32 · AtCoder 37 · Quaver 40 등). 가이드의 목록 행 규칙을 넓혀 새 값을 만들지 않았다.
- 뒤로 링크 → 제목: 우리 화면 9곳 중 7곳이 24. 외부 서비스는 재지 않았다.
- 헤더 → 제목: Last.fm · BeatLeader 24, Atlassian · Carbon 페이지 머리 위 안쪽 24.
