# 커밋 양식 — 대상 + 동작 명사 · 끝 낱말 열두 개 · 본문은 문장

- 상태: 유효
- 날짜: 2026-11-11
- 분야: 구조
- 고른 사람: 사용자(판 1 A · 판 2 A · 판 3 A, 기호는 사용자 지시)

## 맥락

[길이와 본문 결정](./2026-11-11-commit-message.md) 뒤에도 제목에 가운뎃점이 남았고 말끝이 「막기」 처럼 다른 곳에서 쓰지 않는 꼴이었다. 사용자가 AI 말투를 피하고 커밋 쓰는 양식 자체를 정하자고 했다.

## 결정

- 제목 설명은 「대상 + 동작 명사」 로 쓴다. 조사는 줄이고 뜻이 흐려질 때만 넣는다.
- 끝 낱말은 추가, 수정, 변경, 구현, 제거, 적용, 해결, 삭제, 반영, 설정, 분리, 개선 가운데 고른다.
- 제목과 본문에 가운뎃점, 줄표, 화살표, 「및」, 괄호 설명을 쓰지 않는다.
- 본문은 문장으로 쓰고 세 줄을 넘기지 않으려 한다. 글머리표 목록, 굵은 글씨, 머리말을 쓰지 않는다. 왜 바꿨는지를 적고 바뀐 코드를 다시 설명하지 않는다.

## 고르지 않은 안

- 조사를 넣어 풀어 쓰기(SOPT 메이커스 등 8곳): 4–8칸 길어지고 24곳의 가운데 값보다 조사가 많다
- 「~기」 로 끝내기: 한국어 커밋 24곳의 가운데 값이 1% 다(근거 약함)
- 끝 낱말을 정하지 않기: 쓰는 사람마다 낱말이 갈린다
- 본문을 글머리표 목록으로(Laravel · Cal.com · Element Web · 토스 slash · 카카오 SDK): 무엇만 남고 왜가 빠지기 쉽고, AI 가 쓴 커밋의 표지로 꼽힌다

## 근거

- [커밋 제목 조사](../research/2026-11-11-commit-titles.md)의 「한국어 커밋 제목 24곳」: 명사로 끝나는 제목이 중앙 79% 이고 23곳에서 절반을 넘는다. 끝 낱말 상위 열두 개가 제목 5,905개의 61% 다. 가운뎃점과 줄표는 67곳 모두 0–1% 이고 NosLog 는 53% · 12% 였다.
- 같은 기록의 「AI 가 쓴 커밋 메시지의 표지」: 본문이 diff 를 되풀이한다, 왜가 빠진다, 길다.
- 본문 「세 줄」 은 길다는 의견에서 온 값이고 숫자 자체의 근거는 없다.
- 한국어 표본은 교육 · 동아리 팀 프로젝트다. 한국 회사의 공개 저장소는 영어로 커밋해 표본에 넣지 못했다.
