# 채보 틱 한도와 겹침 검사 비용

- 상태: 유효
- 날짜: 2026-11-02
- 분야: 기능
- 고른 사람: 사용자(보안 점검의 높음 항목 수정 지시, 값은 개발 DB 실측으로 정함)

## 맥락

로그인 사용자가 400바이트 안팎의 초안을 저장하고 검토를 요청하면 서버가 멈췄다. 노트 길이 상한이 10억 틱이고, 겹침 검사가 트릴 구간을 길이에 비례해 만들어 이중 반복으로 비교했다. 검사를 통과한 트릴은 검토 화면에서 육각형 수천만 개로 늘어날 수 있었다.

## 결정

- 모든 채보: 노트 하나의 길이는 100만 틱까지다.
- 유저 초안: 노트 끝 틱 1,000만, 트릴 · 글리산도 길이 합 200만 틱, 경로 제어점 합 2,000개까지다. 저장뿐 아니라 검토 요청 · 초안 읽기 · 검토 목록 · 공개에서도 같은 검사를 해, 이미 저장된 초안도 걸러진다.
- 겹침 검사는 판정을 바꾸지 않는다. 시간이 겹치는 구간 쌍만 앞으로 훑고, 트릴 구간은 상대 노트와 겹치는 시간만 만든다.
- 서버 검사는 첫 겹침에서 멈춘다(`hasChartNoteConflicts`). 겹침이 없는 동안 비교 중인 노트는 28개를 넘지 않는다. 겹침 목록이 필요한 에디터는 그대로 `findChartNoteConflicts` 를 쓴다.

## 고르지 않은 안

- 곡 길이(`durationMs`)로 상한 계산 — 빈 채보는 0 이고, 기존 채보가 그 길이를 넘는 노트를 거절당할 수 있다
- 틱 상한만 두기 — 노트를 많이 이어 붙이면 그리는 구간 합이 다시 커진다
- 시간 초과로 끊기 — 동기 계산은 중간에 끊을 수 없다

## 근거

개발 DB(공개 719 · 관리자 초안 719 · 유저 초안 3 · 리비전 1,547개, 2026-11-02)의 최댓값과 한도:

| 값                      | 실측 최대 | 한도           |
| ----------------------- | --------- | -------------- |
| 노트 길이(틱)           | 20,880    | 1,000,000      |
| 노트 끝 틱              | 370,560   | 10,000,000     |
| 문서당 트릴 길이 합     | 38,000    | 합쳐 2,000,000 |
| 문서당 글리산도 길이 합 | 51,441    | 합쳐 2,000,000 |
| 문서당 경로 제어점 합   | 125       | 2,000          |

리포 밖 복사본 운영 빌드 · 로컬 DB 에서 같은 요청을 잰 값. 검토 요청 응답 시간과 서버 메모리 최고값이다.

| 요청                           | 수정 전                   | 수정 후           |
| ------------------------------ | ------------------------- | ----------------- |
| 트릴 10억 틱 + 일반 노트       | 1.8초 · 3,002MB · pending | 저장 거절 · 283MB |
| 칸이 다른 트릴 둘(각 3천만 틱) | 45초 안에 응답 없음       | 저장 거절 · 271MB |
| 칸이 다른 트릴 둘(각 90만 틱)  | 6.5초 · 408MB             | 52ms · 271MB      |
| 같은 칸 긴 노트 9천 개         | 9.6초 · 2,720MB           | 33ms · 270MB      |
| 정상 일반 노트 3천 개          | 70ms · 273MB              | 64ms · 273MB      |

무작위 노트 쌍 30만 개와 문서 5천 개에서 옛 구현과 판정 · 겹침 목록이 모두 같았다.

## 한계

운영 값은 사용자가 읽기 전용 SQL 로 확인한다. 한도를 넘는 공개 채보가 있으면 파싱이 실패해 화면에서 빠지므로, 배포 전에 확인한다. 검토 화면의 탭 정지는 재현하지 않았고, 한도 끝 문서의 재생 데이터 계산(25ms)만 쟀다.
