# 세션 3층 — master · 조사 취합 · 조사로 모델과 강도를 나눔

- 상태: 일부 대체됨(1 층 이름 · 권한 설명) → [새 파일](./2026-11-23-session-orchestration.md)
- 날짜: 2026-11-23
- 분야: 구조
- 고른 사람: 사용자(사용자 지시)

## 맥락

master 와 하위 세션을 모두 Opus 로 띄우는 규칙(2026-11-17 `AGENTS.md`) 아래에서 토큰 사용량이 너무 많다는 사용자 지적이 나왔다. 실측 · 캡처 · 판 HTML 제작처럼 판단이 적은 일까지 Opus 가 맡고, master 가 캡처를 모두 직접 열면서 긴 대화를 이어 간 몫이 컸다.

## 결정

1. 세션은 세 층으로 나눈다(사용자 말: 「master세션(opus 높음) <- 조사 취합(opus 중간 ~ 낮음) <- 조사(sonnet 중간 ~ 높음)」).
    - 1층 master: Opus 높음. 사용자와 대화하고 결정 · 규칙 판단을 한다. 판마다 캡처 2–3장을 표본으로 직접 연다.
    - 2층 조사 취합: Opus 중간–낮음. 실측 결과를 후보 꼴로 묶고, 캡처와 숫자를 대조하고, 판 설계서(물음 · 안 · 추천 이유)를 쓰고, 게시한 판을 검수한다.
    - 3층 조사: Sonnet 중간–높음. Playwright 실측 · 캡처 · 계산값을 기록하고, 설계서대로 판 HTML · 그림을 만들어 게시한다.
2. 에이전트가 낸 숫자 · 추천을 캡처와 모두 대조하는 일은 2층이 한다. master 는 표본만 연다.
3. master 는 판 하나나 결정 하나가 끝나면 인계문을 남기고 새 master 로 연다.
4. 보고는 공유 폴더 파일로 남기고, 세션 사이 메시지는 몇 줄 요약만 보낸다.
5. 조사 세션에는 앞 조사 기록에서 필요한 절만 짚어 준다. 기록 전체를 읽히지 않는다.

## 고르지 않은 안

- 모든 세션 Opus 유지 — 토큰 사용량이 너무 많다는 지적의 원인.

## 근거

- 사용자 지시(2026-11-23): 토큰 사용량이 너무 많다는 지적 뒤 「이 구조로 바꿔」, 같은 날 층 이름과 강도를 위 1번 인용대로 다시 말함.
