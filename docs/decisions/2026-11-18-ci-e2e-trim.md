# CI · e2e 덜어내기 — e2e 스모크 8스펙 · axe 뺌 · 공용 부품 스토리만 · build 잡 · knip · 의존성 워크플로 뺌

- 상태: 유효
- 날짜: 2026-11-18
- 분야: 구조
- 고른 사람: 사용자(판 1 · 2 · 3 · 4 · 5 · 6 · 7 · 9 추천대로, 판 8 은 추천 대신 「둘 다 지움」)

## 맥락

CI 한 번이 약 420초 걸리고 e2e 잡이 그중 391초를 썼다. CI 300회 실패 67회 가운데 40회가 e2e 였고, e2e 가 실제 버그를 잡은 기록은 2026-07-22 서열표 날짜 hydration(`144dd5c4`) 하나였다. 사용자는 1인 서비스 규모에 비해 CI · e2e 가 너무 많다고 보고, 다른 서비스 구현을 잰 판에서 덜어낼 것을 골랐다. Storybook 은 「내용은 줄여도 되지만 없애면 품질이 떨어진다」 고 해서 줄이는 안에서 골랐다.

## 결정

1. e2e 는 핵심 흐름 스모크 8스펙만 둔다. `public-navigation` · `noslog-v2-auth` · `noslog-v2-sync` · `noslog-v2-music-record` · `noslog-v2-music-ranking` · `noslog-v2-global-rankings` · `noslog-v2-tiers` · `profile-ranking-preservation`. 운영 빌드(`next start`)를 대상으로 돈다.
2. Playwright 프로젝트는 모바일 한 폭(390) 하나다. 다른 폭은 스펙 안에서 `setViewportSize` 로 바꾼다. `@desktop` · `@responsive` 태그는 쓰지 않는다.
3. e2e 에서 axe 접근성 검사를 뺀다. `@axe-core/playwright` 의존성과 `test:a11y` 스크립트도 뺀다.
4. Storybook 스토리는 공용 부품(`components/ui`)에만 둔다. `features` 스토리 8개(온보딩 · 제보 폼 흐름과 그 폭 계약 `Contract*` 포함)를 뺀다. 부품 동작 검사 · WCAG A · AA 검사(`a11y.test: "error"`) · 부품 스토리의 폭 계약(버튼 · 대화상자 · 정렬 메뉴)은 그대로다.
5. CI 의 build 잡을 뺀다. 빌드와 전체 타입 검사는 e2e 잡 안 `npm run build` 가 한다.
6. knip(의존성 · `knip.json` · `check:dependencies` · `audit:unused`)을 뺀다. ESLint · Prettier 검사는 그대로다.
7. 의존성 워크플로(`dependencies.yml` 의 PR 의존성 검토 · 주 1회 운영 의존성 감사)와 `audit:production` 스크립트를 뺀다. 권고는 필요할 때 `npm audit` 로 본다.
8. 그대로 두는 것: 잡을 나란히 돌리고 `ci-ok` 하나를 필수로 모으는 구성, husky · lint-staged, `tests/docs-links`, 운영 데이터를 지키는 검사(`lint:migrations` + Squawk · prisma-lint · `prisma migrate diff` · 기록 · 랭킹 계산 · DB 통합 테스트).

## 고르지 않은 안

- CI 에서 e2e 를 빼고 로컬에만 두기(umami · typehero 꼴) — 운영 빌드에서 흐름을 확인하는 장치가 CI 에서 사라진다
- axe 를 `accessibility.spec.ts` 하나에만 두기(rallly 꼴) — 근거가 1곳뿐이다
- Storybook 지우기 — 사용자가 품질이 떨어진다고 보고 고르지 않았다
- Storybook 을 공용 UI 가 바뀐 커밋에서만 돌리기(twenty · PostHog 등) · `play` 를 빼고 문서 · 접근성만(grafana-ui 등) — 앞은 `ci-ok` 의 「건너뜀이면 실패」 를 풀어야 하고, 뒤는 부품과 기능이 어긋나는지 보는 부분을 잃는다
- build 결과물을 e2e 가 받아 쓰기(documenso · linkwarden) — e2e 가 build 를 기다려 벽시계가 길어진다
- 검사 잡을 하나로 합치기(umami 꼴) — 벽시계가 줄지 않는다
- Prettier 검사도 CI 에서 빼기 · husky 지우기 — 서식 어긋남이 CI 로 옮겨 가거나 검사가 사라진다
- 의존성 PR 검토만 지우고 주 1회 감사는 두기(추천안) — 사용자가 의존성 검사 워크플로가 필요 없다고 보고 둘 다 지웠다
- `tests/docs-links` 지우기 — 25회 실제로 깨진 링크를 막았고 시간이 거의 들지 않는다

## 근거

- 실제 서비스: [CI · e2e 규모 조사](../research/2026-11-18-ci-e2e-scale.md). 1인 · 소규모 29곳 중 15곳이 CI 에 e2e 가 없고 12곳이 PR 마다 돌린다. CI 에서 axe 를 도는 곳 1곳, Storybook 검사 1곳, knip 1곳, 의존성 감사 워크플로 1곳(컨테이너 검사). `dependency-review-action` 을 쓰는 곳은 46곳 중 0. Storybook 을 쓰는 곳 23곳 가운데 11곳이 공용 부품 · 디자인 시스템에만 스토리를 둔다.
- 문서: Next.js Testing 은 e2e 를 가입 같은 특정 일에, 운영 빌드 대상으로 쓰라고 한다. Google Testing Blog 는 e2e 를 적은 수로 둔다. Playwright 접근성 문서는 자동 검사가 일부 문제만 잡는다고 한다.
- 측정: build 잡이 막은 5회는 모두 e2e 잡 build 단계에서도 똑같이 실패했다. 서열표 스펙은 유일하게 실제 버그를 잡은 곳이라 남겼다. 흔들리던 스펙 넷(`music-info` · `wide-rails` · `privacy` · `tiers`) 가운데 셋이 빠지고, 2026-11-18 전체 실행에서 그림 생성 대기로 흔들린 서열 이미지 스토리 2개도 빠진다.
- 바뀌는 옛 결정: 2026-10-15 CI 정비 B안(리포 안 결정 파일 없음)의 두 폭 e2e · build 잡 「빠른 관문」, D4 의 폭 계약 Storybook 이전, D6 의 의존성 보안 워크플로. 2026-10-08 공용 UI 검증 기반의 e2e axe 와 기능 화면 스토리 부분. [규모에 비해 없어도 되는 코드 정리](./2026-11-18-scale-cleanup.md)에서 손 이름 검사를 맡긴 e2e axe.
