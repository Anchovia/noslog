# 관리자 화면 개선 — 사이드바 셸 · 목록 카드 · 상세 서랍 · 이름 입력 삭제 · 홈 배치 · 건수 탭

- 상태: 유효
- 날짜: 2026-11-17
- 분야: 디자인 · 화면(관리자)
- 고른 사람: 사용자(판 1–7 · 판 9 · 판 10 사용자 선택, 구현 질문 1–5 추천대로)

## 맥락

관리자 화면이 와이어프레임 수준이라 정식 출시 뒤에도 쓸 수 있게 다듬기로 했다. 제목 모양 2벌 · 상태 탭 3방식 · 삭제 확인 3방식이 섞여 있었고, 목록 9곳이 100줄에서 끊겼으며, 빙고 · 보관 서열표 · 인증 제출 · 서열표 구간 · 항목 삭제에 확인이 없었다. `AGENTS.md` 는 관리자 화면 재설계를 막고 있었다.

## 결정

1. 셸은 Medusa Admin 꼴이다. 1056 이상은 왼쪽 사이드바(묶음 제목 없이 14개, 현재 항목은 면) + 위 막대, 좁은 폭은 위 막대의 메뉴 버튼이 왼쪽 서랍(가장자리 8 · 최대 폭 304 · 가림막)을 연다. Medusa 는 1024 에서 나누지만 NosLog 의 넓은 폭 기준 1056 을 쓴다(사용자 확인). 사이드바 · 메뉴 서랍 맨 아래에 사이트 헤더의 계정 링크를 두고, 판 1 에 있던 「검색 ⌘K」 항목은 두지 않는다(두 가지 모두 판 없이 글 권고로 정함).
2. 목록은 Medusa 꼴 카드 하나에 머리 줄 · 도구 줄 · 표 · 페이지 줄을 쌓는다. 한 쪽 50줄로 나누고, 상태는 점 + 글자, 줄 끝은 ⋯ 메뉴다.
3. 상세 · 편집은 Medusa 꼴 2열 카드와 읽기 줄이고, 고치기는 오른쪽 서랍에서 한다. 새로 만들기는 지금처럼 새 페이지다(판 7 안 A). 공지 편집기는 범위 밖이라 그대로 둔다.
4. 삭제 확인은 Supabase Text Confirm 꼴이다. 딸린 줄이 함께 지워지는 삭제(공지 · 검정 · 빙고 · 보관 서열표 · 서열표 구간 · 인증 제출)만 이름을 입력하고, 인증 제출은 제출한 유저 닉네임을 입력한다. 나머지(서열표 항목 빼기 · 오락실 사진 · 자켓 되돌리기)는 같은 창에서 입력 칸만 뺀다.
5. 홈은 Laravel Nova 배치(지표 카드 4칸 → 그래프 → 처리할 일 표)이고 카드 · 표 모양은 Medusa 그대로다. 나머지 패널 일곱 개는 그 아래 Umami 꼴 같은 폭 2열 격자(사이 12, 홀수로 남는 마지막은 전폭)이고 순서는 지금 홈 그대로다.
6. 대기열(피드백 · 인증 · 기여 · 업데이트 · 이벤트)은 GitLab 꼴 건수 탭을 목록 카드 위에 둔다.
7. 색 · 글자 · 간격은 지금 리포에 있는 토큰으로 옮긴다. 새 토큰을 만들지 않는다. 토큰이 없는 폭 넷(216 · 440 · 560 · 304)은 관리자 CSS 안 부품 변수로 시안 값을 쓰고, 서랍은 대화상자와 같은 페이드만 쓰며, 삭제 창은 있는 대화상자 작은 크기(440)를 쓴다.
8. 관리자 화면은 파운데이션 판 · 결정의 기준이 아니고, 관리자 화면 때문에 파운데이션을 바꾸지 않는다(`AGENTS.md` 「손대지 않는 곳」).
9. 유저 「점검 필요」 필터는 최근 100명이 아니라 전체에서 거른다.
10. 관리자 행동 기록 표는 만들지 않는다는 [2026-11-01 결정](./2026-11-01-security-defenses.md)을 그대로 둔다.

## 고르지 않은 안

- 판 1–6 의 다른 안 — 시안 판에서 사용자가 고르지 않음(결정 기록 원본 `~/noslog-research/admin-2026-11-17/decided/DECISIONS.md`)
- 시안의 Medusa 다크 값 그대로 — 토큰 검사와 부딪쳐 있는 토큰을 쓰기로 함
- 폭을 공용 크기 토큰으로 — 새 토큰이라 뺌
- 서랍이 오른쪽에서 밀려 들어오는 움직임 — 새 움직임이라 뺌
- 판 치수 그대로의 삭제 창(폭 384 · 둥글기 8) — 토큰 밖 값이라 뺌
- 모든 삭제에 이름 입력 — 항목 하나 빼기 · 사진 한 장 같은 잦은 일이 느려짐
- `AGENTS.md` 에서 관리자 화면을 파운데이션과 양쪽 모두 떼어 놓기 — 있는 토큰을 쓰는 결정과 부딪침
