# 결정 기록

화면 · 동작 · 구조를 왜 그렇게 정했는지 남기는 곳이다. 지금 규칙은 [디자인 가이드](../design/README.md) · [기능 규칙](../design/product-rules.md)에 있고, 여기에는 이유만 둔다.

## 쓰는 법

- 결정 하나에 파일 하나. 이름은 `YYYY-MM-DD-짧은-이름.md`(날짜 + 영어 소문자 · 하이픈). 연번을 쓰지 않는다 — 여러 세션이 같은 번호를 쓰지 않게.
- 아래 양식을 쓴다. 한 파일은 한두 쪽 안으로.
- 받아들인 결정의 본문은 고치지 않는다. 결정이 바뀌면 새 파일을 쓰고, 옛 파일은 「상태」 줄만 `대체됨 → [새 파일](…)` 로 바꾼다. 일부만 바뀌면 바뀐 항목 번호와 이름을 모두 적는다(`일부 대체됨(1 포커스 선 · 4 카드 모서리) → [새 파일](…)`). 옛 파일을 지우지 않는다.
- 결정을 쓰면 같은 작업에서 가이드 · 기능 규칙의 해당 문서 한 곳을 고치고, 그 문서 끝 「바뀐 기록」 에 한 줄 링크를 더한다. 링크 제목에는 무엇을 정했는지만 쓰고 값(크기 · 색 · 모양 결론)은 쓰지 않는다. 값은 가이드 본문에만 둔다.
- 결정에 쓴 조사 원문(`docs/research/`)은 「근거」 줄에 링크한다.
- 아래 「지금 유효한 결정」 표에 한 줄을 더한다(대체되면 그 줄을 「대체됨」 표로 옮긴다).
- 근거 링크는 다른 사람도 열 수 있는 것으로 쓴다. 비공개 시안 링크만 근거로 두지 않는다 — 시안의 핵심 숫자는 파일에 옮겨 적는다.

## 양식

```md
# 제목

- 상태: 유효 | 대체됨 → [새 파일](./YYYY-MM-DD-이름.md) | 일부 대체됨(바뀐 항목) → [새 파일](./YYYY-MM-DD-이름.md)
- 날짜: YYYY-MM-DD
- 분야: 디자인 · 기초값 | 디자인 · 부품 | 디자인 · 화면(이름) | 기능 | 구조 | 데이터
- 고른 사람: 사용자(추천대로 / 사용자 지시)

## 맥락

무엇이 문제였나. 두세 문장.

## 결정

무엇으로 정했나. 지금 규칙 문장 그대로.

## 고르지 않은 안

- 안 이름 — 물린 이유 한 줄

## 근거

- 실제 서비스: N곳 중 M곳 …(어느 서비스)
- 디자인 시스템 · 문서: …
- 측정: …

## 바뀌는 곳

- 문서: `docs/design/…` 의 어느 절
- 코드: 파일
```
