# 쓰기 한도는 사람 · 목적별 잠금으로 세기

- 상태: 일부 대체됨(한도 화면 버튼) → [새 파일](./2026-11-02-draft-delete-timing-order.md)
- 날짜: 2026-11-02
- 분야: 기능

## 맥락

`upload_token_grants` 한도를 Serializable 트랜잭션으로 세어, 같은 계정이 동시에 저장하면 재시도 3회를 넘겨 저장이 실패했다. 같은 시각에 저장한 다른 사용자도 실패했다.

## 결정

세기와 쓰기 사이를 `pg_advisory_xact_lock` 으로 사람 · 목적마다 줄 세운다. 격리 수준은 기본값으로 두고 재시도를 없앤다. 표와 마이그레이션은 바꾸지 않는다.

초안 한도 화면은 기존 부품 `ResultState` 에 보조 버튼 「악곡 상세로 돌아가기」 를 단 모양으로 맞춘다.

## 근거

복사본 운영 빌드 · 로컬 e2e DB 에서 초안 50개에 8번씩 동시에 저장(400건)하고, 그동안 다른 사용자가 150ms 간격으로 저장했다. 각 2회 측정이다.

| 값                 | 수정 전               | 수정 후               |
| ------------------ | --------------------- | --------------------- |
| 성공               | 138 · 124             | 300 · 300             |
| 한도 거절          | 0 · 0                 | 100 · 100             |
| 그 밖의 실패       | 262 · 276             | 0 · 0                 |
| 세어진 행          | 138 · 124             | 300 · 300             |
| 다른 사용자의 실패 | 36건 중 1 · 40건 중 1 | 35건 중 0 · 35건 중 0 |

수정 전 실패 540건의 서버 로그는 모두 쓰기 충돌이었다.

## 고르지 않은 안

- 재시도 횟수 늘리기: 충돌이 그대로 남고 요청이 길어진다
- 한 문장 SQL 로 세고 넣기: 잠금 전에 잡은 스냅샷으로 세어 한도를 넘을 수 있다

## 한계

e2e DB 는 로컬 Postgres 이므로 운영 PlanetScale 의 지연에서 다시 재지 않았다.
