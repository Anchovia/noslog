# 폰 입력 창은 전체 화면 — 보내기는 아래 막대 오른쪽

- 상태: 유효
- 날짜: 2026-10-26
- 분야: 디자인 · 부품
- 고른 사람: 사용자(비교 시안 A, Google 피드백 보내기 방식)

## 맥락

2026-09-26 결정은 672 미만에서 입력 칸이 있는 창을 전체 화면으로 열었다(Primer 좁은 화면 규칙). [2026-10-25 체계 묶음](./2026-10-25-design-system-cluster.md) 8번이 이것을 「폰에서도 가운데 창」 으로 바꾸면서 `ResponsiveDialog` 를 지웠고, 피드백 · 오류 제보처럼 글을 쓰는 창이 폰에서 좁은 가운데 창이 됐다. 그 근거는 데스크톱 대화상자 칸을 잰 것이었고 폰 입력 창을 따로 재지 않았다.

## 결정

1. 672 미만에서 입력 칸(입력 · 글 칸 · 셀렉트 · 콤보 · 슬라이더)이 있는 창은 전체 화면이다. 672 이상은 가운데 창 그대로다.
2. 머리 = 제목 왼쪽 · 닫기 오른쪽 · 아래 구분선, 본문만 스크롤, 발 = 위 구분선 · 주 동작 오른쪽 글자 폭(Google 피드백 보내기 폰 실측). 닫기는 머리 × 가 맡는다.
3. `ResponsiveDialog` 를 쓰던 창 8개(피드백 · 오락실 제보 · 공지 · 이벤트 작성 · 투표 만들기 · 뮤즈캣 고장 제보 · 게임 정보 고치기 · 뮤즈캣 공유 설정)은 9월 코드로 되돌린다. `ModalDialog` 로 연 입력 창은 CSS 가 내용으로 갈라 같은 모양으로 연다.
4. 필터 전체 화면 창의 발(「초기화」 + 남은 폭 주 버튼)은 그대로다. 입력 칸이 없는 창 · 확인 창은 폰에서도 가운데 창이다.

## 고르지 않은 안

- 별도 페이지(카카오 문의하기 · Apple 피드백) — 서비스 실측에서 가장 많지만(16/25) 대부분 고객센터 문의 페이지다. 새 주소가 생기고 보던 화면을 벗어난다.
- 아래 시트(Airbnb 피드백) — 근거 2곳.
- 지금대로 가운데 창(Threads 문제 신고) — 2곳, 규칙으로 정한 디자인 시스템 없음.

## 근거

- 390 폭 실측 25곳(목표 30곳 미달, 캡차 · 로그인 벽 · 차단 18곳 이상 제외): 별도 페이지 16 · 전체 화면 창 3(Google · Bandcamp · Intercom) · 아래 시트 2 · 가운데 창 2 · 본문 안 2. 페이지 안 창끼리의 비교는 근거 약함(7곳). 보내기를 위 막대에 둔 곳 0.
- 디자인 시스템 14곳 문서 중 규칙을 적은 9곳: 전체 화면 5(Primer · Material 3 · Material 2 · Salesforce · Gestalt) · 아래 시트 3(Apple HIG · Spectrum · shadcn) · 둘 다 1(Carbon). Primer 는 입력 칸이 있으면 늘 전체 화면이라고 적는다.
- 2026-09 실측 19곳에서도 폰에 작은 가운데 창을 쓰는 곳은 0곳이었다.
