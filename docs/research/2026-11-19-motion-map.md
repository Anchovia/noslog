# 지도 미끄러짐 — 목록 · 핀을 누를 때 지도가 옮겨 가는 방식 실측

조사일 2026-11-19. 공통 층 3단계 움직임 판 3-j 「지도 미끄러짐」(오락실 지도: 목록 카드를 누르면 지도가 핀으로 옮겨 감)의 재료다. 실제 서비스와 지도 SDK · 디자인 시스템을 따로 센다.

## 재는 법

- headless Chromium(Playwright), colorScheme dark, ko-KR, 위치 권한 없음(permissions 빈 목록). 데스크톱 1440×900, 모바일 390×844(iPhone UA · 터치).
- 쪽이 뜨기 전에 지도 SDK(카카오 · 다음 · 네이버 · Google · Mapbox · MapLibre · Leaflet · MapKit)의 `Map` 원형 메서드(`panTo` · `setCenter` · `setLevel` · `flyTo` · `easeTo` · `fitBounds` 등)를 감싸 누가 언제 무엇을 불렀는지와 인자를 적었다. 누른 뒤에는 프레임마다 지도 중심 · 확대 값을 읽어 위치 곡선과 확대 곡선을 얻었다.
- SDK 를 밖에서 볼 수 없는 곳은 CDP 스크린캐스트 프레임(약 16ms)을 흑백 160px 폭으로 줄여 프레임 사이 평행이동을 찾아 화면 이동 곡선을 얻었다. 확대가 섞이면 시간만 적었다.
- 곡선 맞춤은 진행(0–1)을 알려진 곡선 16개에 대어 RMS 오차가 작은 순서로 적었다. 오차 0.05 아래만 「가까움」 으로 쓴다.
- 고른 핀 강조와 목록 연동은 누르기 전 · 뒤 캡처와 프레임 띠를 눈으로 보고 적었다. 목록 스크롤은 스크롤되는 요소의 `scrollTop` 을 프레임마다 읽었다.
- 동작 줄이기는 `reducedMotion: "reduce"` 로 같은 동작을 다시 눌러 쟀다(잰 곳만).
- 원자료: `~/noslog-research/motion-map-2026-11-19/` 아래 `json/<곳>.json` · `frames/<곳>-<경우>/` · `frames/<곳>-<경우>-strip.jpg` · `shots/`. 커밋하지 않는다.
- 로그인 벽 · 캡차 · 봇 차단에 막힌 곳은 세지 않고 막혔다고 적었다.

## 같은 방식끼리 묶음

센 곳은 실제 서비스 35곳(국내 21 · 해외 14)이다. 막혀서 세지 않은 곳(로그인 벽 · 봇 차단 · 캡차 · 403 · 약관 동의 창 · 쪽이 안 열림)과 지도+목록 화면이 없는 곳은 아래 「곳마다 기록」 에 「세지 않음」 으로 적었다. 디자인 시스템 쪽은 지도 SDK 7곳을 따로 셌다. 값은 곳마다 기록과 원자료 json 에 있다.

## 곳마다 기록

### 카카오맵 — 데스크톱 (https://map.kakao.com, 검색 「강남역 오락실」)

- 확인 2026-11-19 · SDK 카카오(전역 kakao · daum) · 원자료 `json/kakaomap.json` · `json/kakaomap-reduce.json` · 띠 `frames/kakaomap-pin-strip.jpg`
- 목록 카드 누름: 지도 안 움직임(SDK 이동 호출 없음, 중심 · 확대 2→2 그대로). 그 카드 면이 옅은 파랑으로 바뀌고 「길찾기」 단추가 나오며, 지도의 A 핀이 커지고 파랑으로 바뀌며 옆에 이름 꼬리표가 붙는다.
- 먼 카드: 목록을 내려 E 카드를 눌러도 지도 안 움직임, E 핀만 같은 방식으로 강조. 검색 결과 8곳이 모두 첫 화면 안에 있어 화면 밖 핀으로 옮기는 경우는 미확인.
- 핀 누름: 지도 미끄러짐, `panBy(0,-96)` 호출(위에 뜨는 말풍선 카드 자리를 만들려고 아래로 96px), 화면 프레임 기준 약 281ms, 곡선 ease-out (0,0,.58,1) 오차 0.063(가까움 아님), 확대 2→2 그대로. 핀 위에 이름 · 별점 · 주소 · 사진 · 길찾기가 든 말풍선 카드가 열리고, 목록의 B 카드 면이 강조된다(B 가 이미 보이는 자리라 목록 스크롤 바뀜 없음).
- 카드 올림: 핀 강조 있음(누를 때와 같이 핀이 커지고 이름 꼬리표, 카드 면 강조).
- 동작 줄이기: 같음(핀 누름에서 `panBy(0,-96)` 이 그대로 움직임, 약 376ms, sine-in-out 오차 0.013).

### Google 지도 — 데스크톱 (https://www.google.com/maps/search/arcade+seoul)

- 확인 2026-11-19 · SDK 없음(자체 WebGL canvas, 전역 지도 SDK 안 잡힘) · 원자료 `json/gmaps.json` · `json/gmaps-reduce.json` · 띠 `frames/gmaps-card-3-strip.jpg`
- 목록 카드 누름: 목록 오른쪽에 상세 패널(폭 약 408px)이 열리고, 지도는 남은 오른쪽 영역 가운데로 그 곳이 오도록 미끄러진다. 확대는 그대로(경복궁–남산 화면 거리 183px → 183px). 화면 프레임으로 지도 움직임은 +934ms 부터 +1604ms 까지 약 670ms(헤드리스 프레임이 띄엄띄엄이라 곡선은 믿을 수 없음, 맞춤 1위 linear 0.082). 고른 곳의 핀은 작은 빨간 점에서 큰 빨간 물방울 핀으로 바뀐다.
- 먼 카드: 첫 카드(G-Plex, 지도 왼쪽 끝 → 오른쪽 영역 가운데, 약 600px)와 넷째 카드(짱오락실 종로점, 약 320px)를 따로 눌렀다. 둘 다 미끄러짐이고 확대 그대로, 첫 카드 움직임 길이는 화면 프레임 기준 약 1044ms(+877 → +1921).
- 핀 누름: 지도 안 움직임(핀 화면 위치 976,161 → 976,158). 상세 패널이 열리고 핀이 큰 빨간 물방울 핀으로 바뀐다. 목록 스크롤 바뀜 없음(누른 곳은 목록 첫 화면에 없는 곳).
- 카드 올림: 해당 핀 옆에 가게 이름 말풍선이 뜬다(「最强ゲームセ…」), 지도는 안 움직임, 프레임 변화 없음 수준의 작은 변화.
- 동작 줄이기: 같음(reduce 에서도 넷째 카드 누름에 중간 프레임 5장에 걸쳐 약 580ms 미끄러짐).

### 네이버 지도 — 데스크톱 (https://map.naver.com, 검색 「강남역 오락실」)

- 확인 2026-11-19 · SDK 네이버(전역 naver.maps, 지도 인스턴스 1개를 프레임마다 읽음, 감싼 공개 메서드 호출은 잡히지 않음) · 원자료 `json/navermap.json` · `json/navermap-reduce.json` · 띠 `frames/navermap-card-near-strip.jpg` · `frames/navermap-pin-strip.jpg`
- 목록 카드 누름: 목록 오른쪽에 상세 패널이 열리고, 지도가 미끄러져 핀을 상세 패널 오른쪽 보이는 자리로 옮김. 중심 이동 144 세계px, 확대 15→15 그대로. SDK 곡선은 샘플 7개뿐이라(헤드리스 렌더 지연) 길이 1293ms 는 믿지 않는다. 진행은 시작 뒤 약 360ms 에 74%, 약 420ms 에 97% 로 끝 쪽이 긴 감속(expo-out 0.081 · quint-out 0.098, 가까움 아님). 고른 핀은 큰 빨강 말풍선 핀으로 바뀌고 아래에 이름이 붙으며, 고른 카드 면은 회색.
- 먼 카드: 목록 아래 「고고크레인X드르럭 강남역점」 을 눌렀을 때 지도 안 움직임(중심 이동 0, 핀이 이미 패널 오른쪽 보이는 자리에 있었음). 상세 패널과 핀 강조는 같음. 화면 밖 핀으로 옮기는 경우는 미확인.
- 핀 누름: 지도 미끄러짐, 중심 이동 184 세계px, 838ms(샘플 9), 곡선 quart-out 오차 0.051(경계), 확대 15→15. 상세 패널이 열리고 핀 위에 이름 · 주소 · 저장 · 출발 · 도착이 든 말풍선 카드가 뜬다. 목록은 그 항목으로 스크롤되지 않음(목록이 iframe 안이라 scrollTop 은 읽지 못했고, 뒤 캡처에서 목록 그대로).
- 카드 올림: 카드 면이 회색으로 바뀜. 핀 강조는 뒤 캡처에서 보이지 않음.
- 동작 줄이기: 같음(처리 없음으로 보임). 카드 누름에서 중심 이동 144 세계px 이 여러 프레임에 걸쳐 움직임(샘플 6, 진행 31%:83 · 45%:96, quint-out 0.012).
