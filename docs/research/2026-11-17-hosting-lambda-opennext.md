# AWS Lambda + OpenNext 호스팅 검토 (2026-11-17)

Vercel Pro 를 대신할 호스팅으로 AWS 서울(ap-northeast-2)의 Lambda 에 OpenNext 로 Next.js 를 그대로 올리는 안을 검토한 기록이다. 2026-10-28 에 추천한 Lightsail 서울 2GB 안과 비교할 때 쓴다. 출처는 190곳(공식 문서 · 릴리스 · 이슈 71 · 가격표 · AWS 문서 56 · 실사용 후기 63)이다.

## 방법

- 코드 쪽은 리포를 읽어 Lambda 로 옮길 때 걸리는 곳을 파일 · 줄로 셌다.
- 웹 조사는 네 갈래(문서 · 요금 · 후기 · 코드)를 나눠 곳마다 바로 적었다. 숫자 가운데 결론에 쓰인 것은 다시 직접 확인했다(아래 「직접 확인」).
- 사용량은 Vercel 청구 화면의 2026-10-14 ~ 11-14 한 달 값이다. 함수 호출 150,805 · Active CPU 3시간 32분 · 메모리 11.467 GB-시간 · Fast Origin Transfer 3.12 GB · CDN 요청 197,766 · 이미지 변환 223 · ISR 읽기 1,360 · 빌드 CPU 4시간 8분 · Blob 60 MB · 합계 $4.48(크레딧 $20 안).
- 한계: 서울 리전에서 잰 콜드 스타트 수치는 찾지 못했다(도쿄 4곳). Reddit 은 열리지 않았고 AWS re:Post 는 403 이라 검색 요약만 썼다(미확인 표시). 사용자 송출량 · 로그 크기 · 배포 횟수는 가정 값이다.

## 직접 확인

- `npm view @opennextjs/aws@latest`: 4.1.16(2026-11-12), peer `next: ">=15.5.29 <16 || >=16.4.5"`. 리포 `package.json` 의 `next` 는 16.4.5 라 범위 안이다. npm `next` latest 는 16.4.6.
- GitHub 이슈 상태(2026-11-17): #1358 열림(11-16, Lambda Function URL 에서 동적 경로로 넘긴 Server Action 이 400) · #1330 닫힘(10-29, `revalidateTag(tag, "max")` 오래된 항목 갱신) · #1315 열림(10-16, 스트리밍 응답이 가끔 끝나지 않음) · #1232 열림(08-31, Next 16.3 404 가 읽기 전용 경로에 파일 캐시를 씀) · #1180 닫힘(06-04, `"use cache"` 항목이 `revalidateTag` 로 무효화되지 않음).
- 리포에서 동적 경로 안의 Server Action 파일 6개: `app/(site)/profile/[id]/actions.ts` · `app/(site)/profile/[id]/contribution-actions.ts` · `app/(site)/bingo/[id]/actions.ts` · `app/(site)/music/[index]/[difficulty]/proposal-actions.ts` · `app/(site)/music/[index]/[difficulty]/draft-actions.ts` · `app/admin/music/[index]/[difficulty]/pattern/actions.ts`. #1358 에 걸리는지는 미확인.

## 코드에서 걸리는 곳

- 캐시: `unstable_cache` 32곳(22파일) · `revalidateTag(tag, "max")` 21곳 · `updateTag` 48곳 · `revalidatePath` 75곳. Lambda 는 인스턴스마다 디스크가 따로라 OpenNext 의 S3 증분 캐시 · DynamoDB 태그 캐시 · SQS 재검증 큐가 있어야 무효화가 모든 인스턴스에 퍼진다. Next 문서도 "calling revalidateTag() on one instance only invalidates the cache on that instance" 라고 적는다.
- `proxy.ts`: Node 런타임, Prisma 로 요청마다 사용자 언어 · 역할을 읽고 `event.waitUntil` 로 API 호출 기록을 쓴다. OpenNext 에서는 엣지가 아닌 Node(외부) 미들웨어로 배포해야 한다. OpenNext 문서에 `proxy.ts` 지원 여부는 적혀 있지 않다(미확인).
- `next/og`: `lib/metadata/brand-image.tsx` · `features/profile/server/profile-card-service.tsx` 가 `process.cwd()/assets/fonts/...ttf` 와 `public/flags/*.png` 를 읽는다. `next.config.mjs` 의 `outputFileTracingIncludes` 는 `/profile/*/card` 만 덮는다. Lambda 묶음에 파일이 빠지지 않는지 확인해야 한다.
- 요청 크기: `app/api/receivePlayerData/route.ts:28` 상한 8 MB, 머스캣 사진 1장 15 MB(`features/musecat/schemas/musecat-action-schema.ts`). Lambda 요청 본문은 6 MB 까지다. Vercel 함수도 4.5 MB 라 지금 실제 요청은 그 아래로 보이지만 실제 크기 분포는 미확인.
- 크론: `vercel.json` 의 `privacy-retention`(하루 1회) · `partner-outbox`(5분) 은 EventBridge Scheduler 로, `official-x` 는 지금처럼 GitHub Actions 가 부른다(최대 120초라 API Gateway REST 29초 상한을 피해 Function URL 을 써야 한다).
- Vercel 의존: `@vercel/blob` 4파일 · `@vercel/analytics` · `VERCEL_ENV`(`lib/analytics.ts` · `features/privacy/server/privacy-retention.ts` · `lib/env/server.ts`) · `VERCEL_URL`. Lightsail 안과 같은 양이다.
- DB: `lib/db.ts` 는 인스턴스마다 pg 풀(기본 최대 10)을 만든다. Lambda 동시 실행이 늘면 연결이 곱으로 는다. 지금처럼 PgBouncer 6432 로 붙어야 한다.
- 문제없는 것: 업로드 횟수 제한은 DB 잠금 방식이라 인스턴스가 여럿이어도 맞다. 서버 쪽 `setInterval` 은 없다.

## OpenNext · 다른 길

- OpenNext AWS 4.1.16 이 Next 16.4.5 이상을 받는다. Next 16 지원은 v3.9.0(2025-11-18)부터. 호환표 쪽은 15.3.2 에서 멈춰 있다. 인프라는 만들어 주지 않아 SST · CDK · Terraform 이 필요하다.
- SST v4.17.2(2026-10-08)가 마지막 릴리스다. `Nextjs` 문서는 아직 OpenNext 3.9.14 를 적어 `openNextVersion` 을 직접 지정해야 한다. 기본 1024 MB · nodejs24.x · 20초 · warm 0. 5분 크론은 `CronV2`(EventBridge Scheduler).
- Next.js Deployment Adapter API 는 16.2 부터 안정(`adapterPath`). 검증된 어댑터는 Vercel · Bun 뿐이고 OpenNext 의 어댑터 판은 2026 년 말 출시 예정으로 아직 없다.
- Amplify Hosting: 문서상 Next.js 15 까지, 요청 시 ISR · 스트리밍 · `after` 미지원. 콜드 스타트 후기 5–30초(5곳). 이번 앱에는 맞지 않는다.
- Lambda Web Adapter + `output: "standalone"`: 단순하지만 캐시 공유를 직접 만들어야 한다(`cacheHandler` · `cacheHandlers`).
- Lambda Web Functions(2026-10-12 발표): Node HTTP 앱을 그대로 돌리고 I/O 대기를 과금하지 않는다. 서울 출시와 OpenNext 지원은 미확인.

## 실사용 후기에서 되풀이된 것

- 콜드 스타트: 초기화 464–899 ms, 첫 응답 1.1–1.9초(6곳, 도쿄 · 미국). 트래픽이 적으면 6분 넘게 쉬면 식어서 요청의 21% 가 콜드였다는 측정이 있다. 5분마다 깨우는 warmer 가 흔한 대책(7곳).
- 재검증 실패: 권한 누락으로 조용히 실패 · CloudFront 무효화 지연 · 태그 표 어긋남(8곳). Vercel 은 거의 즉시.
- Next 새 버전 뒤처짐 · 깨짐(12곳): Turbopack 빌드 실패, 패치 판 올림에 `/_next/image` 깨짐(SST #6867) 등.
- 스트리밍 · 헤더 문제(7곳): #1315 · accept-encoding 502 · ALB 뒤 Set-Cookie 여러 개 유실.
- 비용: 작은 사이트 연산 $0–5(9곳). 놀란 비용은 NAT 게이트웨이 약 $33(3곳, Lambda 를 VPC 에 넣을 때) · DB.
- 운영: 첫 SST 배포 10–15분 · 이후 2–5분, 디버깅은 CloudWatch 로그뿐. Vercel 15분 대 AWS 6시간 설정 사례.
- 떠난 사례 3곳(SST → Fargate · SST → Cloudflare · Amplify → Vercel), Vercel → AWS 6곳.
