# 공개 디자인 시스템 문서 구조 조사 (2026-10-24)

## 방법

- headless Playwright(Chromium)로 페이지를 실제로 렌더링해 메뉴 · 제목(h1~h3) · 탭 · 링크 · 본문을 뽑았다. JS로만 그려지는 사이트(Material · HIG · SLDS 등)도 포함한다. 일부는 WebFetch · curl로 보충했다.
- 원본 덤프: (세션 임시 폴더 — 리포에 없음)(약 200쪽).
- **보는 범위:** 대부분 시스템에서 "버튼" 부품 페이지 1개와 토큰 · 변경 기록 · 수명주기 페이지 1~2개만 열었다. 부품 양식은 버튼 페이지 하나로 판단했다. 다른 부품 페이지는 양식이 다를 수 있다.
- **「미확인」** = 열지 못했거나, 열었지만 그 칸을 판단할 내용이 없었다는 뜻이다.
- **확인 수준:** A = 메뉴 + 부품 페이지 + 기타 1쪽 이상, B = 홈 · 메뉴 또는 한 쪽만, X = 실패했거나 제품 DS 문서가 아님.
- "Do/Don't"는 그림이나 캡션으로 「Do / Don't」(또는 良い例/悪い例, 推荐/慎用)를 짝지어 보여 주는 경우만 센다.
