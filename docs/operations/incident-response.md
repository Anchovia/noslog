# 사고 대응

유출이나 침입이 의심될 때 위에서부터 차례로 한다. 운영 DB · Vercel · GitHub 작업은 사용자가 한다. 비밀값은 채팅 · 문서 · 로그에 쓰지 않는다.

시작한 시각과 유출을 알게 된 시각을 먼저 적어 둔다. 통지 · 신고 기한은 알게 된 때부터 센다.

## 1. 점검 켜기

Vercel 운영 환경 변수에서 `MAINTENANCE_MODE=true` 로 바꾸고 다시 배포한다. 공개 화면과 API 가 503 이 되고 앱의 DB 연결은 읽기 전용이 된다. `/login` · `/admin` · `/discord/` 와 cron 은 점검 중에도 열려 있다. cron 은 읽기 전용 연결로 돈다.

## 2. 로그 내보내기

교체 · 복원 전에 먼저 받는다. Vercel Pro 런타임 로그는 기본 1일만 남는다.

- Vercel 런타임 로그 · 배포 기록 · 환경 변수 변경 기록
- GitHub 보안 로그
- PlanetScale 대시보드에 남은 기록(어떤 기록이 있는지는 미확인)

앱이 남기는 구조화 로그는 `auth.discord.succeeded` · `auth.discord.failed` · `auth.discord.admin-mfa-denied` · `auth.sessions-revoked` · `admin.user.role-changed` · `admin.user.sync-token-reset` · `account.deleted` 다. 어떤 사용자가 무엇을 했는지만 있고 IP 는 없다.

## 3. 비밀값 교체

새어 나갔을 수 있는 값만 바꾼다. 범위를 모르면 표의 값을 모두 위에서부터 바꾼다. 값을 바꾼 뒤 다시 배포해야 적용된다.

| 값                                                        | 바꾸면 생기는 일                                                                                         |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL` · `DATABASE_MIGRATION_URL`                 | PlanetScale 에서 비밀번호를 새로 만들고 옛 비밀번호를 지운다. 바꾸는 사이 앱이 DB 에 붙지 못한다         |
| `DISCORD_CLIENT_SECRET`                                   | Discord 개발자 화면에서 새로 받는다. 진행 중인 로그인만 실패한다                                         |
| `COOKIE_PASSWORD`                                         | 모든 사람이 로그아웃된다. 진행 중인 Discord 로그인과 재확인도 끊긴다. 아래 4번의 전원 끊기가 이것이다    |
| `BOOKMARKLET_SECRET`                                      | 서명이 맞지 않아 모든 동기화 토큰이 무효가 된다. 모든 사람이 북마클릿을 다시 받아야 하므로 공지에 적는다 |
| `BLOB_READ_WRITE_TOKEN` · `PRIVATE_BLOB_READ_WRITE_TOKEN` | Vercel Blob 에서 새로 만든다. 파일은 그대로다                                                            |
| `CRON_SECRET` · `OFFICIAL_X_SYNC_SECRET`                  | `OFFICIAL_X_SYNC_SECRET` 은 GitHub Actions 비밀값도 같이 바꾼다                                          |
| `X_BEARER_TOKEN` · `GEMINI_API_KEY`                       | 각 서비스 콘솔에서 새로 받는다                                                                           |
| `MUSECAT_PARTNER_KEY` · `MUSECAT_CLIENT_SECRET`           | 뮤즈캣 개발자 센터에서 새로 받는다                                                                       |
| `MUSECAT_TOKEN_KEY`                                       | 맨 마지막에 한다. 다음 문단을 먼저 읽는다                                                                |

`MUSECAT_TOKEN_KEY` 는 DB 에 저장한 뮤즈캣 토큰을 암호화한 키다. 코드의 키 id 가 `k1` 하나뿐이라 옛 키로 푸는 길이 없다. 키만 바꾸면 저장된 토큰을 풀 때 오류가 난다. 키가 샜다면 저장된 토큰도 샜다고 보고, 뮤즈캣 쪽에서 토큰을 폐기해 달라고 요청한 뒤 뮤즈캣 연결 행을 끊고 키를 바꾼다. 사용자는 다시 연결해야 한다.

## 4. 세션 끊기

전원은 `COOKIE_PASSWORD` 교체로 끊는다. 쿠키를 푸는 키가 바뀌므로 모두 끊긴다.

한 사람만 끊을 때는 코드의 `revokeUserSessions`(`features/users/server/user-session-service.ts`)와 같은 일을 운영 DB 에서 한다.

```sql
SELECT id, session_version FROM users WHERE id = 대상_id;
UPDATE users SET session_version = session_version + 1 WHERE id = 대상_id;
SELECT id, session_version FROM users WHERE id = 대상_id;
```

쿠키를 푸는 `getSession` 이 버전을 비교하므로 관리자 · 일반 기능 모두 다음 요청부터 로그아웃으로 처리된다. `proxy.ts` 는 언어와 온보딩 이동만 보고 권한을 판단하지 않아 비교하지 않는다.

동기화 토큰은 세션과 따로 산다. 관리자 화면의 연동 토큰 초기화나 `BOOKMARKLET_SECRET` 교체로 끊는다.

## 5. 복원

데이터가 바뀌거나 지워졌을 때만 한다. PlanetScale 백업에서 복원한다(복원 화면과 순서는 미확인, 대시보드에서 확인한다). 복원본의 내용을 확인한 뒤 옮긴다. 침입 경로를 막기 전에 복원하지 않는다. 복원 뒤 `MAINTENANCE_MODE` 를 끄고 다시 배포한다.

## 6. 공지 · 통지 · 신고

아래는 2026-09-11 시행 「개인정보 보호법」 제34조와 같은 법 시행령 제39조 · 제39조의2 · 제39조의3 · 제40조를 국가법령정보센터 원문으로 2026-11-01 에 확인한 내용이다. 조문 번호와 내용이 개정으로 옮겨졌으므로 사고 때 [법](https://www.law.go.kr/법령/개인정보보호법)과 [시행령](https://www.law.go.kr/법령/개인정보보호법시행령)을 다시 본다. 법률 자문이 아니다.

### 정보주체 통지

- 유출 등을 알게 되면 72시간 안에 서면 등으로 알린다(시행령 제39조 제1항). 신고 대상이 아니어도 통지는 한다.
- 알릴 것(법 제34조 제1항): 유출된 항목, 시점과 경위, 피해를 줄이는 방법, 대응 조치와 구제 절차, 신고 접수 부서와 연락처, 손해배상 · 법정손해배상 · 분쟁조정 등 법적 권리와 행사 방법. 시행령이 더 정한 사항이 있는지 함께 본다.
- 항목이나 경위를 아직 모르면 유출 사실과 그때까지 확인한 내용, 나머지 사항을 먼저 알리고 확인되는 즉시 더 알린다(제39조 제2항).
- 긴급 조치가 필요하거나 부득이한 사유가 있으면 사유가 해소된 후 즉시 알릴 수 있다(제39조 제1항 단서).
- 연락처를 알 수 없는 등 정당한 사유가 있으면 홈페이지에 30일 이상 게시해 통지를 갈음할 수 있다(제39조 제3항). NosLog 는 Discord 로그인만 받고 메일을 모으지 않으므로 이 경우에 해당하는지 먼저 본다.

### 유출 가능성 통지

2026-09-10 에 새로 생겼다. 시스템에 불법 접근이 있어 유출이 의심되지만 대상자를 특정하기 어려운 경우처럼 유출 가능성을 알게 되면, 그때부터 72시간 안에 가능성이 있는 모든 정보주체에게 알린다(법 제34조 제2항, 시행령 제39조의2 · 제39조의3). 실제 유출을 확인하면 유출 통지로 바꾸고, 유출이 아니었음을 확인하면 즉시 그 사실을 알린다.

### 신고

다음 중 하나로 유출 등을 알게 되면 72시간 안에 개인정보보호위원회 또는 한국인터넷진흥원에 신고한다(시행령 제40조 제1항 · 제3항).

- 1천 명 이상의 개인정보가 유출 등이 된 경우
- 민감정보 또는 고유식별정보가 유출 등이 된 경우
- 개인정보처리시스템이나 취급자 기기에 대한 외부의 불법 접근으로 유출 등이 된 경우. 사람 수와 상관없다

부득이한 사유가 있으면 해소된 후 즉시 신고한다. 경로를 확인하고 회수 · 삭제 등으로 권익 침해 가능성이 현저히 낮아졌으면 신고하지 않을 수 있다. 통지하지 않거나 신고하지 않으면 3천만 원 이하 과태료 대상이다(법 제75조 제2항 제17호 · 제18호).

### 사이트 공지

점검을 끄기 전에 공지를 준비한다. 무엇이 있었는지, 바뀐 것(다시 로그인 · 북마클릿 다시 받기 · 뮤즈캣 다시 연결), 할 일을 적는다. 사고 내용과 조치를 [결정 기록](../decisions/README.md)에 남긴다.
