## 결정 라벨

- **Observed:** 저장소, 현재 브라우저 근거, 승인된 상위 산출물 또는 인용 출처에서
  확인된 내용입니다.
- **Approved:** 사용자가 명시적으로 승인했으며 후속 디자인의 권위가 있는 내용입니다.
- **Proposed:** 사용자 승인을 기다리는 근거 기반 방향입니다.
- **Open:** 추가 조사, 테스트 또는 사용자 결정이 필요합니다.
- **Rejected:** 검토 후 명시적으로 선택하지 않은 내용입니다.
- **Superseded:** 이후 승인 방향으로 대체된 내용입니다.

이 기획서는 오락실 페이지군의 제품 의미, 콘텐츠, 내비게이션, 데이터 의미,
상호작용, 개인정보, 반응형 동작, 상태 및 인수 기준의 권위입니다. 정확한 타이포,
색상, 간격, radius, elevation, 지도 스타일, marker 그래픽, sheet geometry, card
표현, control 치수, grid track 및 콘텐츠 기반 전환값은 Foundation과 후속 Claude
Design 작업으로 남깁니다. 후속 시각 작업은 표현을 다듬을 수 있지만 이 제품
계약을 삭제하거나 재해석할 수 없습니다.

## 목적

오락실 페이지군은 순서대로 다음 네 질문에 답합니다.

> NOSTALGIA를 어디에서 플레이할 수 있는가, 내 주변이나 검색한 오락실 중 어디가
> 적합한가, 각 기체의 검증된 상태는 어떠한가, 그리고 어떻게 길을 찾거나 오래된
> 정보의 정정을 도울 수 있는가?

이는 위치 탐색기인 동시에 커뮤니티 정보를 활용한 NOSTALGIA 플레이 지원
화면입니다. 실시간 혼잡도 감지기, 일반 사업체 Directory, 리뷰 사이트, 오락실
소셜 Feed 또는 KONAMI 공식 기체 상태 서비스가 아닙니다.

## 주 사용 맥락과 성공 조건

- **Approved upstream:** 오락실은 Play support 페이지군의 독립된 NosLog 목적지와
  홈 직접 바로가기로 유지합니다. 악곡, 서열, 빙고 또는 검정과 가상의 상위
  라벨로 묶지 않습니다.
- **Approved:** 플레이할 장소를 정하거나 오락실로 이동하는 동안의 모바일 사용이
  주 맥락입니다. 사용자는 복잡한 대시보드를 지나지 않고 적절한 장소를 찾고,
  검증된 기체 이용 가능 여부를 판단하고, 길찾기를 열 수 있어야 합니다.
- **Approved:** 비로그인 방문자는 모든 공개 오락실을 검색·탐색하고, 권한 기반 내
  주변 검색을 사용하고, 상세와 최신성을 확인하고, 가상의 개인 상태 없이
  길찾기를 열 수 있으면 성공합니다.
- **Approved:** 로그인 방문자는 여기에 하나의 선호 오락실 지정과 문맥형 정정·기체
  문제 제보를 추가로 할 수 있으면 성공합니다.
- **Approved:** locator는 “NOSTALGIA가 어디에 있는가”와 “커뮤니티가 어디에
  모이는가”를 모두 지원합니다. 커뮤니티 선호는 사실 기반 집계 맥락이지 실시간
  혼잡도나 자동 부여된 `성지` 품질 상이 아닙니다.
- **Approved:** 데스크톱도 필수입니다. 추가 폭은 고정 약 `390px` 제품 shell을
  유지하는 대신 결과 목록과 지도를 함께 비교하는 데 사용합니다.
- **Approved:** 초기 공개 목록은 한국 오락실만 포함할 수 있지만, 일본과 글로벌
  오락실을 추가할 때 가이드와 데이터 계약을 다시 설계할 필요가 없어야 합니다.
- **Approved:** 현재 스타일과 geometry는 감사 근거이지 NosLog 2.0의 시각 권위가
  아닙니다.

## 현재 제품 및 도메인 근거

### 저장소와 데이터 근거

- **Observed:** 현지화된 공개 경로는 현재 `/[locale]/gamecenter`이며, 안정적인
  공개 오락실 상세 경로는 없습니다.
- **Observed:** 현재 `Arcade`는 이름 하나, 지역, 주소, 좌표, 기체 수, 가격, 코인
  수, 주간 영업시간 JSON, 전체 기체 상태 하나, 상태 설명, 일반 메모, 활성 상태
  및 범용 `updated_at`을 저장합니다.
- **Observed:** 공개 Query는 각 오락실을 `preferred_arcade_id`로 참조하는 사용자
  수를 집계합니다. 한 사용자는 선호 오락실 하나를 선택할 수 있습니다.
- **Observed:** 현재 공개 데이터에는 국가, IANA 시간대, 통화, 현지화 이름, 전화,
  웹사이트, 공개 사진, 범위가 명확한 검증 또는 기체별 레코드가 없습니다.
- **Observed issue:** 전체 `machine_status` 하나는 기체를 플레이할 수 있는지와,
  플레이 가능한 기체의 건반·판정 상태가 어떤지를 혼합합니다.
- **Observed issue:** `updated_at`은 관리자 편집 시각입니다. 기체 수·상태·
  영업시간·가격이 언제 실제로 확인됐는지를 정직하게 나타낼 수 없습니다.
- **Observed:** 기존 로그인 Feedback 흐름은 최대 `4 MB`의 비공개 선택적
  JPEG/PNG/WebP 증빙, 관리자 검수 및 처리 완료 자료 6개월 후 정리를 지원합니다.
  현재 오락실·기체 관계나 구조화된 정정 유형은 없습니다.
- **Observed:** 공개 오락실 데이터는 현재 저장된 지역과 한국어 이름으로
  정렬합니다. 검색은 client state에서 이름·지역·주소를 비교합니다.

### 현재 인터페이스와 브라우저 근거

- **Observed:** 현재 페이지에는 지역 Select, 선호 비례 bubble 지도, 검색 입력,
  지역별 결과 및 두 번째 mini-map과 전체 상세를 포함한 펼침 Card가 있습니다.
- **Observed issue:** 텍스트 검색은 목록만 필터링하고 지도는 필터링하지 않습니다.
  지도 Bubble을 선택하면 Query를 지우고 Accordion을 열며 페이지를 Scroll합니다.
  두 탐색 표현이 하나의 결과 상태를 공유하지 않습니다.
- **Observed issue:** 각 지도 범위는 해당 범위의 최고 선호 수를 가장 큰 Bubble로
  다시 환산합니다. 희소 지역에서는 선호 1명인 오락실도 큰 거점처럼 보일 수
  있습니다.
- **Observed issue:** Card를 펼치면 모바일 결과가 매우 길어지고 이미 위에 있는
  지도 맥락을 다시 중복합니다.
- **Observed:** `390×844`에서 결과는 한 열입니다. `1440×900`에서도 현재 제품은
  모바일 폭에 가까운 Shell을 유지합니다. 조사한 `320×800` 경로에서는 문서
  수준 가로 Overflow가 생기지 않았습니다.
- **Observed:** 검색 목록에 결과가 없어도 필터되지 않은 지도에는 오락실이 남을
  수 있습니다. 현재 Query/지도 불일치를 화면에서 확인했습니다.
- **Observed:** 현재 지도는 실패 시 텍스트 목록을 유지하고 Zoom control을
  제공하지만 선택, 필터, 직접 링크, 상세 복원에는 아래의 2.0 계약이 필요합니다.

### 외부 도메인 근거

- **Observed:** KONAMI와 SEGA 공식 Locator는 지역과 현재 위치 탐색을 우선합니다.
  SEGA는 Network 설치 목록, 영업시간 및 실제 가동 상태가 다를 수 있음을
  명시적으로 경고합니다.
- **Observed:** Google, Apple, Mapbox locator 지침은 내 주변 검색, 거리, 목록·지도
  연동, 선택 장소 요약, 길찾기 및 반응형 상세 표현에 수렴합니다.
- **Observed:** Musecat과 Zenius-I-vanisher는 리듬게임 사용자가 일반 사업체 정보
  이상으로 게임별 기체 수, 상태·고장 제보, 사진 및 최근 커뮤니티 갱신을 필요로
  한다는 근거를 제공합니다.
- **Observed:** 지도 수량 표현 지침은 Cluster count와 비례 수량 Symbol을 분리하고
  안정적이고 설명 가능한 시각 척도를 요구합니다.
- **Observed:** OpenStreetMap의 최신성 관례는 조사·확인 날짜와 무관한 편집 날짜를
  구분해 명시적 검증 의미를 뒷받침합니다.

## 승인 범위와 불변 조건

1. 공개 오락실 페이지군은 탐색 진입 하나와 안정적인 상세 목적지로 구성합니다.
2. 목록과 지도는 정렬이 두 표현에 의미 있는 범위에서 같은 활성 Query, 지역,
   지도 경계, Filter 및 Sort 맥락을 나타냅니다.
3. 내 주변 검색은 사용자가 시작합니다. NosLog는 로드 시 위치를 요청하지 않고
   사용자의 정확한 현재 좌표를 서버에 저장하지 않습니다.
4. 지도 이동만으로 결과를 조용히 교체하지 않습니다. 명시적인 `이 지역 검색`이
   새 경계를 적용합니다.
5. 넓은 범위·낮은 Zoom 지도는 오락실 수 Cluster를 사용합니다. 개별 오락실을
   구분할 수 있는 Zoom에서는 선택적으로 선호 사용자 수에 비례하는 개별
   오락실 Marker를 사용합니다.
6. Cluster 수량, 선호 사용자 수량 및 선택 상태는 서로 다른 시각 의미를
   사용합니다. 선택은 Outline/Ring 또는 이에 상응하는 비크기 단서를 사용합니다.
7. 선호 사용자 크기는 전국 하나의 고정 척도와 최소·최대 Cap을 사용해 지역이나
   Filter와 무관하게 같은 수가 같은 크기가 되게 합니다.
8. 승인된 최소 공개 표본 `3`명 미만의 정확한 선호 수는 숨깁니다. 이 오락실은
   기본 Marker를 사용하고 1명·2명 집계를 공개하지 않습니다.
9. 커뮤니티 수치는 선호라고 라벨링합니다. 실시간 인원, 혼잡, 대기시간, 품질 또는
   자동 부여된 `성지`라고 표현하지 않습니다.
10. 기체 이용 가능 여부와 플레이 가능한 기체 상태는 서로 다른 축이며 기체별로
    저장합니다.
11. 사용자에게 보이는 검증 시각은 관리자 편집 시각과 분리하고 실제로 확인한
    정보 범위를 명시합니다.
12. 사용자 제보는 공개 오락실·기체 상태를 직접 바꾸지 않습니다. 권한 있는
    관리자가 검증하고 정정을 적용합니다.
13. 길찾기는 오락실 상세의 주 액션입니다. 선호 오락실 지정과 문제 제보는 보조
    문맥 액션입니다.
14. 공개 사진은 선택 사항이며 검수합니다. NosLog는 공개 사진 Feed나 리뷰
    Gallery가 아닙니다.
15. UI Locale과 오락실 국가는 독립적입니다. 공식 현지 장소 정체성, 현지 시간,
    현지 통화 및 국가에 적합한 길찾기를 보존합니다.

## 승인된 정보 계층

### 탐색 진입

하나의 의미론적 `main`과 다음 모바일 우선 Source 순서를 사용합니다.

1. 페이지 정체성과 간결한 목적;
2. 오락실 검색, 지역 범위 및 사용자가 시작하는 `내 주변`;
3. 활성 결과 요약과 간결한 Filter/Sort 진입;
4. 접근 가능한 결과 목록;
5. 지도 보기 진입 및 동기화된 지도 맥락;
6. 필요한 경우 간결한 Empty, 권한, 오래된 데이터 및 실패 복구.

넓은 레이아웃에서는 목록과 지도를 나란히 구성할 수 있지만 Source 순서와
키보드 순서는 시각적 분할 없이도 이해 가능해야 합니다.

### 오락실 상세

다음 정보 우선순위를 사용합니다.

1. 공식·현지 오락실 이름과 지역;
2. NOSTALGIA 이용 가능 요약과 범위가 명확한 마지막 검증;
3. 신뢰 가능할 때 현재 영업 여부·오늘 영업시간 및 거리;
4. 주 길찾기 액션;
5. 전체·이용 가능 기체 수, 기체별 상태 및 플레이 가격;
6. 주소와 지도 맥락;
7. 선택적 전화 및 공식 웹사이트;
8. 선택적 검수된 입구 및 기체 구역 사진;
9. 전체 주간 영업시간;
10. 기체 상태 메모 및 유용한 방문 메모;
11. 공개 가능한 선호 사용자 집계와 보조 선호 오락실 액션;
12. 문맥형 정보 정정 또는 기체 문제 제보.

없는 선택 필드는 `미등록` 행을 나열하지 말고 생략합니다. 방문에 중대한 영향을
주는 알 수 없는 운영 사실은 선택 Contact처럼 생략하지 않고 `미확인` 또는
`최근 확인되지 않음`으로 명시합니다.

## 탐색, 검색, 필터 및 정렬 계약

### 공유 결과 집합

- 이름, 검수된 현지화 이름, 승인된 별칭, 지역, 도시 및 주소를 검색합니다.
- 동일한 텍스트 Query, 지역, 명시적 지도 경계, 영업 중 Filter 및 이용 가능한
  기체 Filter를 목록과 지도 모두에 적용합니다.
- 결과 수는 이 공유 집합을 설명합니다. 목록은 결과 없음인데 관련 없는 지도
  Marker가 남게 하지 않습니다.
- 사용자가 결과를 확인하거나 Filter를 바꾸는 동안 입력 Query를 보존합니다.
  Marker 선택 시 지우지 않습니다.
- 지역 선택과 현재 지도 경계는 서로 다른 개념입니다. 선택 지역은 초기 경계를
  만들 수 있지만 이후 지도 탐색은 `이 지역 검색` 후에만 결과를 바꿉니다.

### 기본 및 선택 정렬

- Query나 현재 위치 맥락이 없으면 안정적이고 설명 가능한 목록을 위해 지역 후
  Locale 인식 오락실 이름순으로 정렬합니다.
- Query가 있으면 텍스트 일치도를 우선하고, 같은 경우 지역·이름순을 사용합니다.
- `내 주변` 요청이 성공하면 현재 Session에서 사용자와의 거리순을 기본값으로
  전환합니다.
- 간결한 선택 정렬로 이름순과 선호 사용자 많은 순을 제공합니다. 사용자 위치나
  명시적 출발점이 있을 때만 거리순을 제공합니다.
- 선호 사용자순을 기본값으로 사용하지 않습니다. 초기의 불균등한 표본은 탐색을
  왜곡하고 기준을 설명하기 어렵게 만듭니다.
- 정렬은 하나의 간결한 Control 또는 하나의 `필터·정렬` Disclosure 안에 둡니다.
  영구적인 정렬 버튼 행을 만들지 않습니다.

### 필터

- 승인된 주 Filter는 `현재 영업 중`과 `이용 가능한 기체 있음`입니다.
- `현재 영업 중`은 구조화되고 충분히 검증된 영업시간이 오락실 현지 IANA
  시간대에서 영업 중으로 계산되는 오락실만 포함합니다. 영업시간 미확인은
  통과하지 않습니다.
- `이용 가능한 기체 있음`은 하나 이상의 기체가 명시적으로 `available`인
  오락실만 포함합니다. 이용 가능 여부 미확인은 통과하지 않습니다.
- 기본 목록은 미확인 또는 영업 종료 오락실을 숨기지 않습니다. Filter는 명시적인
  사용자 선택이며 쉽게 해제할 수 있어야 합니다.
- Filter를 하나의 간결한 Disclosure에 넣고 활성 Filter를 결과 수 근처에
  요약합니다. 모든 운영 속성을 영구 Chip으로 쌓지 않습니다.

### 내 주변

- `내 주변`을 명시적 액션으로 제공하고 자동 권한 요청을 하지 않습니다.
- 필요한 경우 Browser Prompt 전이나 함께 즉각적인 사용 목적을 설명합니다.
- 위치는 활성 Browser 맥락에서만 중심 이동·검색, 거리 계산 및 거리순 활성화에
  사용합니다.
- 정확한 좌표를 사용자 프로필, Analytics Payload, URL, 제보 또는 피할 수 없는
  Infrastructure 동작을 넘는 Server Log에 저장하지 않습니다.
- 거부, Timeout, 미지원 Browser 또는 비보안 Context에서는 간결한 복구 문구와
  함께 검색·수동 지역 Control을 유지합니다.
- 현재 위치와 선호 오락실은 서로 다릅니다. 하나에서 다른 하나를 추론하거나
  갱신하지 않습니다.

## 지도와 목록 연동 계약

### 지도 수량 모델

- 국가·대지역 또는 Marker가 겹치는 Scale에서는 주변 오락실 Marker를
  Cluster합니다. Cluster Label/크기는 선호 사용자가 아닌 오락실 수입니다.
- 개별 오락실을 구분 가능한 Zoom에서는 오락실마다 Marker 하나를 사용합니다.
- 개별 Marker에는 승인된 선택 사항으로 선호 사용자 수 비례 크기를 사용할 수
  있습니다. 현재 Filter마다 최대값을 다시 계산하지 않고 전국 고정 데이터 척도,
  최소 기본 Marker, 최대 Cap 및 면적 인식 비례 표현을 사용합니다.
- 3명 미만과 선호 0·미확인은 같은 기본 Marker를 사용하며 숨긴 수를 드러내지
  않습니다.
- 범례 또는 접근 가능한 설명이 Cluster, 개별 선호 Marker, 소표본 기본 Marker,
  선택을 구분합니다.
- Marker 크기를 유일한 선택 상태로 사용하지 않습니다. 이용 가능 여부, 상태,
  선호, 선택에 색상만 사용하지 않습니다.

### 선택과 내비게이션

- 목록 결과 선택은 현재 Query나 Filter를 버리지 않고 같은 Marker를 선택·노출합니다.
- Marker 선택은 같은 목록 결과나 미리보기를 선택합니다. 전체 문서를 예측
  불가능하게 Auto-scroll하지 않습니다.
- 모바일 Marker 선택은 오락실명, 간결한 이용 가능 여부, 알 수 있을 때 거리 및
  전체 상세 경로를 가진 간결한 미리보기 Sheet를 엽니다. Sheet 뒤의 지도 맥락을
  보존합니다.
- 데스크톱 Marker/목록 선택은 지도 옆 상세 미리보기 Panel을 갱신합니다.
- 전체 상세 열기는 `/[locale]/gamecenter/[arcade-slug]`로 이동하고 Browser
  History를 갱신합니다.
- Browser Back은 가능한 경우 Query, 지역, Filter, Sort, 목록/지도 모드, 선택
  오락실 및 지도 경계를 복원합니다.
- 직접 링크와 새로고침은 탐색 페이지를 먼저 방문하지 않아도 같은 공개 상세를
  재현합니다.

### 모바일과 데스크톱 탐색 구성

- 좁은 레이아웃은 목록 우선이며 명확한 `지도 보기` 액션 하나를 제공합니다. 이
  페이지를 위해 하단 내비게이션이나 영구 경쟁 List/Map Tab Bar를 추가하지 않습니다.
- 모바일 지도는 같은 결과 상태의 집중형 대체 보기이며 목록으로 돌아가는 명확한
  경로와 보존된 Control/상태를 가집니다.
- 넓은 레이아웃은 콘텐츠 공간이 허용할 때 목록과 지도를 동시에 동기화합니다.
- 펼친 결과마다 전체 지도를 중복하지 않습니다. 전체 오락실 상세는 안정적 상세
  경로에 두고 미리보기는 간결하게 유지합니다.

## 오락실 상세 경로 및 액션 계약

### 안정적 경로

- `/[locale]/gamecenter`를 페이지군 진입으로 유지합니다.
- 각 활성 공개 오락실에 안정적인 `/[locale]/gamecenter/[arcade-slug]` 경로를
  추가합니다.
- Slug는 공유 가능해야 하며 불안정한 목록 Index를 노출하지 않습니다.
- 알 수 없거나 비활성·삭제된 오락실 경로는 내부 검수 데이터를 누출하지 않는
  현지화 Not-found 상태를 반환합니다.
- 오락실 이름 변경·통합 시 공유 링크를 조용히 잃지 않도록 승인된 Redirect 또는
  Alias 전략을 보존합니다.

### 주 액션과 보조 액션

- `길찾기`가 주 액션입니다. 신뢰할 수 있는 좌표와 주소로 국가에 적합한 외부
  지도·길찾기 제공자를 엽니다.
- `선호 오락실로 지정`은 보조 액션이며 로그인이 필요합니다. 명확한 성공 또는
  복구 가능한 실패 피드백 후 사용자의 선호 오락실 하나를 갱신합니다.
- `정보 제보`는 보조 문맥 Utility이며 기존 Feedback 소유권 모델에 따라 로그인이
  필요합니다.
- 선택적 전화·공식 웹사이트는 Native Action을 사용하고 없으면 생략합니다.
- 주소 복사, 웹사이트, 선호 상태 및 제보를 여러 개의 동등한 주 버튼으로 만들지
  않습니다.

## 기체 이용 가능 여부와 상태 계약

### 서로 독립적인 두 축

모든 활성 기체 레코드는 식별자·Label과 이용 가능 여부를 가집니다.

| 이용 가능 여부 | 의미                                                              |
| -------------- | ----------------------------------------------------------------- |
| `unknown`      | 현재 플레이 가능 여부가 충분히 최근에 검증되지 않았습니다.        |
| `available`    | 기체가 켜져 있고 작동하며 플레이할 수 있습니다.                   |
| `unavailable`  | 고장, 점검, 전원 종료 또는 다른 이유로 현재 플레이할 수 없습니다. |

`available` 기체만 플레이 상태 값을 가질 수 있습니다.

| 상태      | 의미                                                                                   |
| --------- | -------------------------------------------------------------------------------------- |
| `unknown` | 플레이 가능하지만 최근의 신뢰 가능한 건반·판정 평가가 없습니다.                        |
| `good`    | 알려진 입력·판정 문제가 없습니다.                                                      |
| `normal`  | 약한 마모·감도 차이가 있지만 일반적인 플레이는 대체로 가능합니다.                      |
| `caution` | 플레이할 수 있지만 입력·판정 문제가 기록 목적 플레이에 실질적인 영향을 줄 수 있습니다. |

- `unavailable`은 상태 등급이 아닙니다.
- `normal`과 `caution`에는 간결한 상태 설명을 필수로 둡니다.
- `good`은 실험실 수준의 정밀함을 주장하지 않습니다. 검증된 커뮤니티·관리자
  맥락에서 알려진 문제가 없다는 뜻입니다.
- 활성 기체 Child에서 전체·이용 가능 기체 수를 파생합니다. 서로 모순될 수 있는
  독립 편집 총계를 유지하지 않습니다.
- 제거된 기체는 제보·검증 이력을 Hard-delete하지 말고 비활성화합니다.
- `1번 기체`, `2번 기체` 같은 결정적 기본 Label을 사용하고, 관리자는 `왼쪽
기체`, `창가 기체` 같은 유용한 장소 Label로 바꿀 수 있습니다.

### 간결한 표현과 상세 표현

- 목록·미리보기 요약 예시: `3대 중 2대 이용 가능 · 주의 기체 있음`.
- 상세는 각 활성 기체를 다음처럼 구분해 노출합니다.
    - `1번 기체 · 이용 가능 · 양호`
    - `2번 기체 · 이용 가능 · 주의`와 입력·판정 설명
    - `3번 기체 · 이용 불가 · 점검 중`
- 모든 기체가 `unknown`이면 `0대 이용 가능`이 아니라 이용 가능 여부가
  미확인이라고 표시합니다.
- 기체 상태를 색 점만으로 축약하지 않습니다. 이용 가능 여부, 상태, Label 및
  설명을 텍스트로도 제공합니다.

## 운영 정보 및 검증 계약

### 운영 사실

- 가능한 경우 구조화된 주간 영업시간과 명시적 임시 휴무·휴일 정보를 저장합니다.
  자유 텍스트 메모를 Parsing해 `영업 중`을 계산하지 않습니다.
- 자정 이후 종료를 포함해 오락실 IANA 시간대로 `영업 중`을 계산합니다.
- 플레이 가격은 통화 코드와 현지 Credit/Coin 의미를 함께 저장합니다. 글로벌
  오락실을 원화로 변환하지 않습니다.
- 국가에 맞는 표시와 검색에 충분한 주소 Component를 보존합니다.
- 선택적 전화·공식 웹사이트는 Contact 사실이며 필수 Placeholder가 아닙니다.

### 검증의 의미

- `updated_at`과 공개 검증 사실을 분리합니다.
- 검증 레코드는 무엇을 언제 어떤 신뢰 등급으로 확인했는지 기록하되 비공개 제보자
  신원을 공개하지 않습니다.
- 기체 검증은 실제 확인한 기체·이용 가능 여부·상태 범위만 갱신합니다. 가격
  편집으로 오래된 기체 상태가 새로 검증된 것처럼 보이게 하지 않습니다.
- 공개 문구는 모호한 `업데이트됨` 대신 `기체 정보 3일 전 확인`, `영업시간 최근
미확인`처럼 범위를 말합니다.
- 검증은 권한 있는 현장 확인 또는 승인된 신뢰 출처에서 올 수 있습니다. Raw
  사용자 제보는 검증이 아니라 대기 중 근거입니다.
- 정보 종류별 오래됨 Threshold는 향후 운영 정책에서 달라질 수 있지만,
  인터페이스는 최근·오래됨·미확인을 가상의 정밀함 없이 구분해야 합니다.

## 선호 오락실 및 커뮤니티 맥락

- 현재 프로필 설정과 같이 로그인 사용자 한 명은 선호 오락실 하나를 선택할 수
  있습니다.
- 선호 수는 익명 집계입니다. 공개 오락실 페이지에서 사용자 목록을 노출하지
  않습니다.
- `3`명 이상일 때만 정확한 수를 공개합니다. 그 미만은 숫자를 생략하거나 1·2를
  드러내지 않는 간결한 `선호 정보 집계 중` 문구를 사용할 수 있습니다.
- 공개 가능한 경우 목록·상세에 사실 기반 `선호 사용자 N명`을 표시할 수 있습니다.
- 선호는 선택적인 개별 지도 Bubble 크기와 사용자가 요청한 Sort에 영향을 주지만,
  기본 결과 순서나 품질 점수가 아닙니다.
- 방문 여부, 현재 위치, 대기시간, 실력 또는 품질 보증을 추론하지 않습니다.
- 초기 2.0 계약에서는 자동 `성지` Badge를 부여하지 않습니다.
- 사용자 선호 오락실의 공개 프로필 표시는 별도 Profile 개인정보 계약을 따릅니다.
  개별 Profile 공개 여부와 익명 집계 포함 여부는 서로 다릅니다.

## 검수 사진 계약

- 공개 사진은 선택 사항이며 초기에는 다음 Slot만 사용합니다.
    1. 입구·외관 대표 사진 한 장;
    2. NOSTALGIA 기체 또는 기체 구역 사진 최대 두 장.
- 모든 Slot이 비어도 오락실 상세는 완전해야 하며 Media 영역을 생략합니다.
- 사진은 관리자 검수 공개 Asset이며 제한 없는 사용자 Gallery가 아닙니다.
- 별점, 좋아요, 댓글, 소셜 정렬 또는 무한 사진 Feed를 추가하지 않습니다.
- 비공개 Feedback·정정 이미지는 검수 증거이며 자동 재게시하지 않습니다. 공개
  재사용에는 별도의 명시적 공개 사진 제출, 권리 확인 및 동의가 필요합니다.
- 식별 가능한 사람, 개인정보, 무관한 저작물 또는 현재 기체 정보로 오해할 오래된
  맥락을 포함한 이미지는 거절하거나 적절히 제거·Crop합니다.
- Slot 목적에 맞는 의미 있는 Alt Text를 제공하되 인접 오락실 이름을 기계적으로
  반복하지 않습니다. 장식 Crop은 빈 Alt를 사용합니다.
- 오래된 사진이 현재 기체 증거로 오해될 수 있을 때 촬영·검증 맥락을 표시합니다.

## 정보 정정 및 기체 문제 제보 계약

### 제보 유형과 대상

기존 로그인 Feedback 흐름에 오락실 맥락과 다음 구조화 유형을 추가합니다.

- 기체 고장 또는 이용 불가;
- 기체 상태·입력 문제;
- 기체 수 변경;
- 플레이 가격·Credit 변경;
- 영업시간 변경;
- 위치·주소 변경;
- 기타 오락실 정보.

- 기체 제보는 알 수 있으면 특정 활성 기체를, 신뢰 가능하게 구분할 수 없으면
  `기체 미지정`을 대상으로 합니다.
- 오락실 정체성과 현재 관련 사실을 미리 채워 사용자가 전체 장소를 자유 텍스트로
  다시 적게 하지 않습니다.
- 간결한 설명을 필수로 하고, 후속 보안 계약이 대체하기 전까지 기존 최대 `4 MB`
  비공개 선택적 JPEG/PNG/WebP 증빙 제한을 보존합니다.
- 제보는 이후 적용된 검증 공개 정정을 제외하고 제보자와 권한 있는 관리자에게만
  비공개로 유지합니다.

### 검수와 생명주기

- 제출은 이용 가능 여부, 상태, 수량, 가격, 영업시간, 주소 또는 검증 시각을
  자동으로 바꾸지 않습니다.
- 권한 있는 관리자는 신뢰할 수 있는 근거와 제보를 비교하고 실제 검증한 범위만
  갱신하며 간결한 처리 결과를 기록합니다.
- 여러 제보가 하나의 정정을 뒷받침할 수 있지만 중복 공개 기체나 모순된 수를
  만들면 안 됩니다.
- 처리 완료 비공개 제보 자료는 기존 6개월 정리 계약을 따릅니다. 결과 공개 사실과
  비식별 검증 이력은 유지할 수 있습니다.
- 제보 실패는 안전한 경우 입력 텍스트와 대상을 보존합니다. 인증 만료는 저장된
  것처럼 가장하지 않고 복구 가능한 로그인 경로를 제공합니다.

## 인증 및 권한 계약

### 비로그인

- 탐색, 검색, 지도/목록 전환, `내 주변`, Filter, 상세, 길찾기, Contact, 사진,
  검증 및 공개 가능한 선호 집계는 공개합니다.

- 선호·제보 액션은 로그인이 필요함을 설명하고 인증 왕복 동안 현재 오락실
  목적지를 보존할 수 있습니다.

### 로그인

- 사용자는 선호 오락실 하나를 지정·변경할 수 있습니다.

### 관리자 경계

- 공개 상세는 Draft 오락실, 비활성 기체, 비공개 제보 증빙, 관리자 메모, 제보자

- 관리자 오락실 편집과 제보 Queue는 차후 별도 디자인을 받습니다. 이 기획서는
  그 화면의 최종 UI가 아니라 반드시 지원할 공개 사실·검수 계약을 정의합니다.

## 반응형 계약

### 좁은 레이아웃

- `390px`을 대표 검토 Canvas로 사용하되 고정 앱 폭이나 범용 Breakpoint로
  취급하지 않습니다.
- 문서 수준 양방향 Scroll 없이 `320 CSS px`까지 Reflow합니다. 지도는 의미상
  필수인 2차원 상호작용이므로 자체 Pan할 수 있지만 모든 Control, 미리보기,
  상세 사실 및 대안은 정상 Reflow해야 합니다.
- 동일 결과 상태를 가진 목록 우선 탐색과 `지도 보기` 액션 하나를 사용합니다.
- Marker 선택은 간결한 하단 Sheet/미리보기를 사용하고, 전체 콘텐츠는 결과 안에
  모두 펼치지 않고 안정적인 상세 경로로 이동합니다.
- 상세 상단에서 길찾기에 빠르게 접근하게 합니다. 보조 액션은 주 사실·액션 영역을
  과밀하게 만들면 안 됩니다.
- 기체 행은 이용 가능 여부·상태를 설명 없는 Code로 축약하지 않고 Stack 또는
  Reflow합니다.
- 긴 한국어·일본어·영어 공식 오락실명, 주소 및 메모가 지도 Control이나 액션을
  덮지 않고 줄바꿈됩니다.

### 넓은 레이아웃

- Container 폭이 두 영역을 지원하면 동기화된 결과 목록과 지도 Split을 사용합니다.
- 선택 오락실은 주변 지도 맥락을 유지하는 Side Preview를 사용할 수 있습니다.
- 전체 상세는 지도·주소와 운영 사실을 보완 열로 나눌 수 있지만 Source와 읽기
  순서를 일관되게 유지합니다.
- 모바일 Card를 단순히 확대하거나 고정 휴대폰 폭 Shell을 유지하지 않습니다.
- 메모·제보 안내의 Line Length를 제한하면서 추가 폭을 비교, 기체 행, 전체 주간
  시간 및 지도 맥락에 사용합니다.

### 콘텐츠 기반 전환

- 기기 이름이 아니라 결과 정체성, 검색·Filter Control, 지도 상호작용 및 상세
  액션을 읽을 최소 공간에서 전환을 정합니다.
- 목록/지도 Split, Sheet/Panel, 기체 행, 사진 Slot 또는 액션 구성이 바뀌는 중간
  폭을 테스트합니다.
- 낮은 Viewport 높이에서 지도·Sheet Control을 가두거나 Sheet 닫기와 길찾기를
  숨기지 않습니다.

## 접근성 계약

- 목록은 지도의 완전한 의미론적 대안입니다. 어떤 오락실이나 필수 액션도
  Marker에만 존재하지 않습니다.
- 보이는 페이지 제목 하나와 Control·결과·지도·상세의 의미론적 Region을
  제공하고, 지도 이동마다 과도하게 읽지 않는 결과 수·요약을 제공합니다.
- 검색은 지속 Label 또는 접근 가능한 이름을 가지며 Placeholder만으로 대체하지
  않습니다.
- Native 또는 완전히 접근 가능한 Control로 검색, 지역, Filter/Sort, `내 주변`,
  `이 지역 검색`, 지도/목록 전환, Marker/목록 선택, Sheet 닫기, 길찾기, 선호 및
  제보를 조작합니다.
- 지도 Library가 허용하면 Marker를 논리적 순서로 키보드 접근 가능하게 합니다.
  동기화 목록은 보장된 키보드 경로로 유지합니다.
- 선택, 선호 집계, 영업 상태, 이용 가능 여부, 기체 상태, 오래됨 및 제보 결과를
  색상, Shape 또는 Marker 크기에만 의존하지 않습니다.
- 열린 Sheet/Dialog가 Modal일 때만 Focus를 이동하고 적절히 Trap하며, 닫을 때
  호출 Marker·Control로 돌려보냅니다. Nonmodal 데스크톱 Panel은 예기치 않게
  Focus를 가져가지 않습니다.
- 외부 길찾기, 전화, 웹사이트 액션은 명확한 접근 가능한 이름과 필요시 외부
  Context 표시를 가집니다.
- 지도 Zoom/Pan Control은 Target Size와 보이는 Focus 요구사항을 만족하며 Custom
  Gesture를 유일한 탐색 방법으로 사용하지 않습니다.
- 이미지는 목적에 맞는 Alt Text를 사용합니다. 반복 Thumbnail이 장황한 중복
  이름을 만들지 않습니다.
- 권한, Validation, 저장 및 제보 결과를 과도한 Assertive Live Region 없이
  간결하게 알립니다.
- 200% 텍스트 확대, Reduced Motion, 키보드 전용, High Contrast 및 Screen Reader
  읽기 순서를 지원합니다.

## 현지화 및 국제 위치 계약

### 정체성과 검색

- 공식 현지 오락실 이름을 주 정체성으로 유지합니다.
- 있으면 검수된 한국어·일본어·영어 번역, 음역 또는 인정된 별칭을 더 작은 보조
  정체성으로 표시합니다.
- 공식 이름, 모든 검수 현지화 이름, 승인 별칭 및 현지화 주소 필드를 검색합니다.
  기계 번역 장소명을 검증된 이름처럼 자동 표시하지 않습니다.
- 발음·Screen Reader 동작에 유용하면 혼합 언어 문자열에 적절한 `lang`
  Metadata를 표시합니다.

### 국가 인식 데이터

최소한 다음을 보존합니다.

- 안정적인 오락실 ID 및 Slug·Redirect Alias;
- ISO 국가·지역 코드;
- 행정구역, 도시 및 국가에 맞는 주소 Line;
- 좌표와 IANA 시간대;
- 통화 코드, 금액 및 현지 Credit/Coin 의미;
- 공식 현지 이름과 검수된 현지화 이름·별칭;
- 국가에 적합한 외부 지도·길찾기 제공자 ID;
- 선택적 전화 및 공식 웹사이트.

- UI Locale은 국가의 사실을 바꾸지 않습니다. 일본 오락실은 주변 Label이
  한국어·영어여도 일본 오락실로 유지됩니다.
- 시간·날짜는 UI Locale 형식으로 표현하되 오락실 시간대에서 계산합니다.
- 가격은 저장 통화로 형식화하고 환율 변환을 조용히 적용하지 않습니다.
- 한국에서는 Kakao Maps를 우선 사용할 수 있습니다. Provider 추상화는 제품 의미나
  안정적인 액션 Label에 `Kakao`를 박아두지 않고 일본·글로벌 목적지를 지원해야
  합니다.
- 주소 순서와 줄바꿈은 국가·Locale에 맞춥니다. 한국형 `region` 문자열 하나를
  유일한 국제 주소 구조로 저장하지 않습니다.

## 브라우저 인수 계약

- `/ko/gamecenter`, `/ja/gamecenter`, `/en/gamecenter`는 동등한 공개 탐색 동작과
  현지화 Metadata를 제공합니다.
- 모든 활성 오락실은 안정적인 현지화 상세 경로를 가지며 직접 링크, 새로고침,
  상세 왕복 및 Browser Back이 유용한 탐색 상태를 유지·복원합니다.
- 텍스트 Query, 지역, 명시적 경계, `현재 영업 중`, `이용 가능한 기체 있음`은
  같은 목록·지도 결과 집합을 만듭니다. 목록이 비면 관련 없는 Marker가 남지 않습니다.
- `내 주변`은 로드 시 Prompt하지 않고 사용자 액션 후에만 작동하며 정확한 좌표를
  서버에 보존하지 않고 거부·실패 후 수동 Control로 복구합니다.
- 지도 이동만으로 결과를 교체하지 않습니다. `이 지역 검색`이 명시적으로
  교체하고 이전·지역 맥락으로 복구할 수 있습니다.
- 낮은 Zoom Cluster는 오락실 수를, 개별 Bubble은 전국 하나의 척도에서 공개
  가능한 선호 수를 표현하며 선택은 크기에 의존하지 않습니다.
- 선호 수 `1`과 `2`는 공개되지 않고 기본 소표본 Marker와 구분할 수 없습니다.
  `3` 이상은 정확한 수를 표시할 수 있습니다.
- 모바일은 목록 우선이며 동기화된 집중 지도 보기와 간결한 Marker 미리보기를
  사용하고, 넓은 레이아웃은 의미 있는 목록·지도 비교 공간을 사용합니다.
- 상세는 승인 순서대로 공식·현지 정체성, NOSTALGIA 이용 가능 여부, 검증, 현지
  영업시간·거리, 길찾기, 기체 수·상태, 가격, 주소 및 선택 보조 사실을 전달합니다.
- 전체·이용 가능 수는 활성 기체 데이터와 일치합니다. `unavailable`을 플레이
  상태 등급으로 표시하지 않고, 보통·주의는 항상 텍스트 설명을 유지합니다.
- 모든 이용 가능 여부 미확인을 0대로 표시하지 않습니다. 오래된·미확인 사실을
  최근 검증처럼 보이게 하거나 명시적 Filter를 통과시키지 않습니다.
- 사용자 제보는 관리자 검수 전 공개 사실을 바꾸지 않고 비공개 증빙 권한을
  유지하며 승인 후 실제 검증한 사실 범위만 갱신합니다.
- 별도 권리·동의 없이 비공개 Feedback 증빙이 공개 사진 Slot에 나타나지 않습니다.
  공개 사진이 없으면 빈 Media Shell을 남기지 않습니다.
- 공식 현지 이름, 검수 별칭, 주소 순서, 현지 시간대, 통화 및 국가에 맞는 길찾기가
  한국어·일본어·영어 UI에서 정확하게 유지됩니다.
- 지도 실패 후에도 전체 목록, 주소, 운영 사실 및 외부 길찾기를 사용할 수 있습니다.
- `320 CSS px`에서 검색·Filter Control, 결과, Sheet, 긴 이름·주소, 기체 행,
  액션, 사진, 설명, 제보 필드 또는 오류가 문서 수준 가로 Overflow, 잘림 또는
  겹침을 만들지 않습니다.
- 넓은 레이아웃은 고정 휴대폰 폭 Shell을 유지하거나 모든 결과 안에 전체 지도를
  중복하지 않습니다.
- 모든 주 Control과 액션이 키보드만으로 작동하고 보이는 Focus와 일관된 읽기
  순서를 가집니다. 상태는 색상, Marker 크기 또는 지도 위치에만 의존하지 않습니다.
- 테스트한 정상·실패 흐름에서 예상하지 못한 Console 오류, Hydration 문제,
  경로 간 오래된 선택, 정확한 위치 누출, 비공개 제보자 누출, 중복 선호·제보 제출
  또는 모순된 기체 수가 발생하지 않습니다.

### 근거의 수렴

- 공식·프로덕션 Locator 출처는 지역·텍스트·현재 위치 탐색, 거리, 연동된 목록·지도
  맥락, 간결한 선택 장소 상세 및 길찾기에 수렴합니다. Query를 지우거나 목록이
  Filter될 때 관련 없는 Marker를 남기는 근거는 없습니다.
- 지도 표현 출처는 Count Cluster와 비례 Data Symbol을 분리하고 안정적이고 해석
  가능한 척도를 유지하는 데 수렴합니다. 희소 지역마다 최대값을 큰 국가적
  중요도로 다시 표시하는 근거는 없습니다.
- 리듬게임 Community 출처는 기체별 수·문제, 최근 Community 유지보수 및 장소
  사진이 방문 계획에 의미 있음을 뒷받침합니다. 실시간 혼잡 주장, 제한 없는
  소셜 Gallery 또는 Raw 제보로 관리자 검증을 대체하는 근거는 아닙니다.
- 최신성 관례와 공식 Locator 경고는 확인·조사를 범용 편집 시각과 구분하고
  불확실성을 노출하는 데 수렴합니다. NosLog의 운영상 오래됨 Threshold를 대신
  정하지는 않습니다.
- Place Card와 사진 출처는 간결한 미리보기와 대표 식별 이미지에 수렴합니다.
  개인정보와 범위를 위해 NosLog는 공개 Slot을 제한하고 별도 동의 전까지 제보
  증빙을 비공개로 유지합니다.
- 현지화 출처는 독립적인 언어, 지역, 현지 시간대 및 통화 데이터에 수렴합니다.
  한국형 이름·주소·가격 모델은 승인된 일본·글로벌 확장을 안전하게 지원할 수 없습니다.
- 접근성 출처는 완전한 목록 대안, 키보드 경로, 비색상 상태, Reflow 및 복구 가능한
  권한·지도 실패에 수렴합니다.
- 선호 공개 Threshold `3`, 사용자당 선호 하나의 의미, 전국 고정 척도, 자동 성지
  Badge 제외, 기체별 상태 어휘, 공개 사진 Slot 수 및 제보 생명주기는 외부 출처가
  결정한 것이 아니라 출처를 참고해 승인한 NosLog 제품 결정입니다.

## 거절 및 대체된 대안

- **영구 List/Map Tab을 가진 지도 우선 모바일 — Rejected:** 모바일은 목록
  우선이며 공유 상태를 보존한 지도 액션 하나를 사용하고 하단 내비게이션을
  추가하지 않습니다.
- **데스크톱의 고정 좁은 모바일 Shell — Rejected:** 넓은 레이아웃은 동기화된
  목록·지도 비교 공간을 사용합니다.
- **목록 검색과 지도의 독립 상태 — Superseded:** 둘은 하나의 활성 결과 집합을
  나타냅니다.
- **모든 지도 이동에 자동 결과 갱신 — Rejected:** 명시적인 `이 지역 검색`이
  예상치 못한 변동을 막고 통제권을 보존합니다.
- **로드 시 위치 요청 — Rejected:** 내 주변은 사용자가 시작하고 수동 Fallback과
  정확한 위치 비보존을 사용합니다.
- **선호 사용자순 기본 정렬 — Rejected:** 불균등한 초기 집계가 기준 탐색을
  지배하면 안 됩니다.
- **영구 Sort·Filter Chip 행 — Rejected:** 주 검색·지역·내 주변은 노출하고 하나의
  간결한 Disclosure로 계층을 보존합니다.
- **범위별 상대 Bubble 척도 — Superseded:** 전국 하나의 고정 척도가 희소 지역
  선호 한 명을 전국적 거점처럼 보이지 않게 합니다.
- **선택에 Bubble 크기 사용 — Rejected:** 선택과 수량은 다른 시각 의미가 필요합니다.
- **선호 수 1·2 공개 — Rejected:** `3`명 미만의 정확한 집계는 숨깁니다.
- **자동 `성지` Badge — Rejected:** 선호 수는 품질·실시간 방문 상이 아닌 맥락입니다.
- **전체 기체 상태 하나 — Superseded:** 이용 가능 여부와 플레이 가능 상태는
  기체별 독립 축입니다.
- **이용 불가를 상태 등급으로 사용 — Rejected:** 이용 불가는 이용 가능 여부이며
  이용 가능한 기체만 양호·보통·주의·미확인 상태를 가집니다.
- **제거 기체 삭제 — Rejected:** 비활성화로 제보·검증 이력을 보존합니다.
- **범용 `업데이트됨`으로 최신성 표시 — Rejected:** 범위가 명확한 검증만 확인된
  운영 사실을 전달합니다.
- **Raw 제보가 즉시 공개 상태 변경 — Rejected:** 관리자 검증이 필요합니다.
- **모든 결과 안에 전체 상세·두 번째 지도 펼침 — Superseded:** 미리보기는
  간결하고 전체 상세는 안정적 경로를 사용합니다.
- **모든 상세 액션에 같은 시각 비중 — Rejected:** 길찾기가 주 액션이며 선호·
  제보는 보조입니다.
- **제한 없는 사용자 사진 Gallery·리뷰 — Rejected:** 2.0은 입구 한 장과 기체
  구역 최대 두 장의 검수 Slot만 사용하고 별점·Social Feed를 만들지 않습니다.
- **비공개 제보 증빙 자동 공개 — Rejected:** 별도 권리와 공개 동의가 필요합니다.
- **한국 전용 지역·이름·통화 Schema — Rejected:** 출시 데이터는 한국일 수 있지만
  계약은 일본·글로벌 확장을 지원합니다.
- **사용자 시간대에서 영업 여부 계산 — Rejected:** 오락실 IANA 시간대와 현지
  구조화 시간을 사용합니다.
- **모든 가격 원화 환산 — Rejected:** 현지 통화와 Credit 의미를 보존합니다.

## 후속 전달 경계

Claude Design은 Foundation 승인 후 최종 Type Scale, 시각 계층, Surface, 지도
스타일, Cluster·Marker 그래픽, 선호 범례, Sheet·Panel Geometry, 목록 Card 해부,
액션 표현, 기체 행 구성, 사진 Crop, 간격, Grid Track, 반응형 전환값 및 Motion을
정할 수 있습니다. 공유 결과 상태, 명시적 위치·영역 액션, 고정 척도·개인정보 안전
선호 의미, 안정적 상세 내비게이션, 승인 정보 순서, 기체별 상태 의미, 검증·제보
생명주기, 제한 사진 정책, 국제 데이터 의미, 접근성 및 인수 기준은 보존해야 합니다.

향후 Codex 구현 세션은 Claude 결과를 이 기획서와 비교해야 합니다. 지도·목록의
사실을 분리하거나, 위치를 자동 요청하거나, 선호를 기본 정렬로 사용하거나, 작은
선호 수를 공개하거나, 지역별 상대 Bubble을 사용하거나, 실시간 혼잡을 암시하거나,
기체 이용 가능 여부와 상태를 합치거나, 편집 시각을 검증으로 사용하거나, 제보가
자동 공개되게 하거나, 길찾기를 숨기거나, 모든 결과 안에 전체 상세를 펼치거나,
비공개 증빙을 공개하거나, 제한 없는 리뷰·Gallery를 추가하거나, 한국 위치 형식을
전세계에 가정하거나, 필수 정보를 지도에서만 접근하게 하는 결과는 구현 전에
가이드 또는 디자인 개정을 요청해야 합니다.
