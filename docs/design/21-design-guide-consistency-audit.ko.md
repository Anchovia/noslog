## 문서 관리

- 상태: `관찰 및 승인 범위에서 해결`
- 감사일: 2026-08-03
- 정본 언어: 영어
- 영어 정본:
  [21-design-guide-consistency-audit.md](./21-design-guide-consistency-audit.md)
- 범위: 승인된 사용자 채보 에디터와 프로필 공유 카드 결정 이후의 문서 간 의미

- 제외: 프로덕션 Code 변경, 최종 시각 디자인 및 법률·운영 출시 차단 조건 해결

## 감사 방법

현재 저장소와 동기화된 영문·한글 디자인 문서에서 Route 소유권, 페이지 패밀리
의미, 모드 의미, 개인정보, 상태·복귀 동작, 현재·향후 기능 구분 및 오래된 단계
문구를 비교했습니다. 관찰된 Code는 기존 사용자 승인 없이 2.0 승인 규칙으로
승격하지 않았습니다.

## 기록만 하고 구현하지 않은 현재 Code 차이

- 현재 채보 Action은 관리자 전용이고 Schema에는 작성자 소유 Draft·제출 Entity가
  없습니다.
- 현재 프로필 카드 생성은 본인만 접근할 수 있고 마지막 플레이를 포함하며
  `비공개` Play-count Placeholder를 노출할 수 있어 승인 계약과 맞지 않습니다.
- 현재 X Label 공유 동작은 Link-only X Fallback을 정확히 구분하지 않고 Native
  Share를 호출할 수 있습니다.
- 현재 뷰어·에디터 채보 데이터는 Basic 전용이고 Recital 강약 Schema·Rendering
  계약이 없습니다.

이는 이번 디자인 가이드 세션에서 고친 결함이 아니라 이후 구현 연결입니다.

## 남은 출시 차단 조건

1. 권리, 보증, Moderation 및 공개 기여자 표기를 위한 법률 검토 완료 기여 약관
2. 개인 Draft·제출, 심사 기록, 승인 Canonical History 및 공개 기여자 표기의 승인된
   탈퇴 처리
3. 운영상 Abuse 제한, 신고·Escalation 처리 및 심사 Queue 정책
4. 운영자 신원, 법적 근거, Infrastructure 사실, 외부 Embed, 삭제 Lifecycle 및
   사람의 법률 번역에 관한 기존 개인정보 차단 조건

## 검증 계약

- 모든 영어 정본은 완전한 한글 동기화본을 가집니다.
- 교차 Link는 로컬에서 유효하고 어떤 문서도 Legacy Figma를 현재 2.0 권위로
  취급하지 않습니다.
- `승인`, `관찰` 및 `출시 차단`을 구분합니다.
- 이후 구현 감사는 Migration·출시 전 Code, Claude Design 결과 및 이 계약을
  비교해야 합니다.
