## 검증 목적

`S4`는 검증된 NOSTALGIA 뷰어와 타이밍 동작을 유지하면서 현재 셸과 컨트롤
계층을 바로잡을 수 있는지 시험한다. 다음 질문에 답해야 한다.

1. 채보 식별, 낙하형/전체 채보 모드, 손 안내, 시각화, 핵심 재생, 빠른 설정,
   상세 설정 및 제보가 문서 가로 스크롤 없이 `320 CSS px`에 들어가는가?
2. 핵심 재생 컨트롤이 초기 화면 아래로 밀리거나 무관한 페이지 푸터처럼
   동작하지 않고 낙하형 렌더러에 시각적으로 붙어 있는가?
3. 데스크톱이 늘어난 모바일 캔버스나 영구 우측 설정 레일 대신 중앙 정렬된
   형상 제한 플레이어를 사용하는가?
4. 자주 쓰는 속도와 메트로놈은 노출하면서 덜 자주 쓰는 음원, 음량, 엄밀한
   연주 및 단축키 도움말은 맥락형 공개를 사용하는가?
5. 상세 설정이 정보 순서나 핵심 재생 컨트롤을 훼손하지 않으면서 컴팩트에서는
   하단 패널, 와이드에서는 앵커형 팝오버를 사용하는가?
6. 전체 채보가 4마디 열, 컴팩트에서 완전한 한 열과 다음 열 단서, 와이드에서
   여러 열, 로컬 가로 이동을 유지하면서 문서 전체 2차원 스크롤을 만들지 않는가?
7. 상시 튜토리얼 문구를 제거하면서 렌더러, 전체 화면, 음원 및 오버플로 안내를
   해당 조건이 있을 때만 발견할 수 있는가?
8. 같은 구조가 한국어, 일본어, 영어, `200%` 텍스트, 키보드 내비게이션,
   보이는 포커스, 렌더러 실패 및 설정 포커스 복원을 견디는가?

## 제외 범위

- 최종 페이지 디자인, 최종 Figma 화면 또는 프로덕션 구현이 아니다.
- 현재 PixiJS/WebGL 낙하형 렌더러, 피아노, 노트, 손 색상, 타이밍 엔진,
  엄밀한 연주 규칙, 트릴, 테누토 또는 글리산도 동작을 다시 그리거나 교체하지
  않는다.
- 예시의 그레이스케일 표면, 설명용 채보 표시, 정확한 `276px` 전체 채보 열,
  정확한 렌더러 높이를 프로덕션 토큰으로 승인하지 않는다.
- 영구 설정 레일을 추가하거나, 가로 화면을 강제하거나, 필수 컨트롤을 자동으로
  숨기거나, 로컬 음원을 업로드하거나, 독립된 새 채보 카탈로그를 만들지 않는다.
- 브라우저 기능 감지, WebGL 복구 코드, 제보 API, 전체 화면 구현 또는 저장된
  환경설정 지속성을 확정하지 않는다.
- 레거시 NOSTORY Figma를 현재 레이아웃 기준으로 사용하지 않는다.

## 검증 대상 승인 계약

### 집중형 셸과 채보 식별

뷰어는 일반 NosLog 전역 내비게이션과 푸터를 제외한다. 출발한 악곡 상세 맥락으로
돌아가는 명확한 경로 하나, 원문 채보 제목, 아티스트, 선택 난이도, 노트 수 및
재생 시간을 유지한다. 원문 제목 식별은 간결하게 유지하고 제목 번역 공개는 악곡
상세에 남기며 집중형 뷰어에 중복하지 않는다.

낙하형과 전체 채보는 연결된 `tab` 및 `tabpanel` 의미를 갖는 수동 탭 관계로
유지한다. 방향키로 포커스를 옮기고 Enter 또는 Space로 포커스된 탭을 활성화한다.
모드 변경이 선택된 채보를 조용히 다시 쓰지 않는다.

### 낙하형 플레이어와 컨트롤 계층

- 낙하형 렌더러와 피아노는 변경되지 않는 프로덕션 책임으로 유지한다.
- 렌더러는 사용 가능한 과업 영역을 쓰면서 내부 종횡비와 레인 형상을 유지한다.
  와이드 레이아웃은 무한히 늘리는 대신 유용한 렌더러 폭을 제한한다.
- 재생/일시정지, 재시작, 탐색 위치, 경과/전체 시간, 지원될 때의 전체 화면 및
  상세 설정 진입은 렌더러에 바로 붙은 하나의 핵심 재생 컨트롤을 이룬다.
- 노트 속도와 메트로놈은 별도 보조 행의 자주 쓰는 빠른 컨트롤이다. 넓은
  레이아웃은 완전한 지역화 라벨과 타깃이 들어갈 때만 행을 정렬할 수 있으며,
  모든 컨트롤을 하나의 영구 행에 강제로 넣을 수 없다.
- 로컬 음원, 메트로놈 음량, 엄밀한 연주 및 단축키 도움말은 상세 설정이다.
  컴팩트에서는 하단 패널, 와이드에서는 앵커형 팝오버를 사용하며 두 표현에서
  같은 라벨과 순서를 유지한다.
- 데스크톱은 영구 우측 설정 레일을 예약하지 않는다. 그 공간은 주 시각화와
  균형 잡힌 중앙 정렬에 사용한다.

### 전체 채보와 로컬 2차원 이동

- 전체 채보는 승인된 4마디 묶음, 타이밍 및 박자 표시, 손 구분, 순서 있는 열을
  유지한다.
- 컴팩트 폭에서는 완전한 한 열을 읽을 수 있고 다음 열 일부가 공간 연속성 단서를
  제공한다. 간결한 가로 이동 안내는 로컬 오버플로가 실제로 있을 때만 나타난다.
- 문서가 아니라 전체 채보 영역이 가로 스크롤 컨테이너다. 선택적 `proximity`
  스냅은 열 시작을 도울 수 있지만 큰 콘텐츠를 가둘 수 없다.
- 넓은 공간은 여러 완전한 열을 드러낸다. 뷰포트를 채우기 위해 노트 바를
  단순히 키우지 않는다.

### 조건부 안내와 실패 상태

상시 튜토리얼 블록은 없다. 안내와 상태는 다음 조건에서만 나타난다.

- 전체 채보가 실제로 넘칠 때만 로컬 오버플로 안내;
- 렌더러 초기화 중 간결한 낙하형 로딩 상태;
- 공개 채보에 표시할 노트가 없을 때 간결한 노트 없음 상태;
- 사용 가능한 전체 채보로 전환하고 다시 시도를 제공하는 낙하형 실패 상태;
- 현재 뷰어를 계속 사용할 수 있게 두는 전체 화면 거부 상태;
- 채보 단독 재생을 계속하면서 상세 설정 안에 보이는 로컬 음원 오류.

상태 메시지는 프로그래밍 방식으로 노출하며 단지 변경을 알리기 위해 포커스를
이동하지 않는다. 상세 설정을 닫으면 포커스가 트리거로 돌아간다.

### Foundation 및 접근성 계약

- 컴팩트는 safe area를 고려한 `16px` 외곽 간격을 사용하고 기기 이름이 아니라
  측정된 용량에 따라 확장한다.
- 공통 사용자 대상 텍스트는 승인된 제품 최솟값 `12px`보다 작아지지 않는다.
- 일반 공개 유효 포인터 타깃은 최소 `44 × 44px`를 유지한다.
- 필수 콘텐츠는 `320 CSS px`에서 리플로우하고 전체 채보만 문서화된 로컬
  2차원 예외다.
- 페이지는 기기 방향을 강제하지 않고 세로와 가로에서 과업을 유지한다.
- 프로덕션에서 손 의미는 청록/빨강 색상에만 의존할 수 없으며 라벨과 비색상
  의미를 함께 유지한다.
- 렌더러는 매 애니메이션 프레임을 설명하는 대신 안정된 접근 가능 목적과 요약을
  제공한다.
- 보이는 포커스, 슬라이더 이름과 값, 수동 탭, 다이얼로그 라벨, Escape 닫기 및
  포커스 복원은 필수다.

### 근거의 수렴

- 접근성 및 반응형 출처는 하나의 의미 있는 과업 계층, 예측 가능한 컨트롤,
  `320 CSS px` 리플로우, 진정한 2차원 콘텐츠를 위한 문서 전체가 아닌 로컬 스크롤에
  수렴한다.
- 음악 플레이어와 악보 뷰어 레퍼런스는 악보, 재생 컨트롤, 템포, 시각 악기,
  설정 및 전체 화면을 하나의 집중 연습 맥락에 결합한다. 핵심 재생을 무관한 페이지
  영역 아래에 두는 방식은 지지하지 않는다.
- 플레이어 컨트롤 레퍼런스는 항상 사용할 수 있는 핵심 재생, 반응형 리플로우,
  라벨 있는 범위 입력, 맥락형 저빈도 설정에 수렴한다. 영구적으로 혼잡한 하나의
  행이나 과업 빈도와 무관한 데스크톱 설정 레일은 지지하지 않는다.
- 브라우저 및 렌더러 출처는 브라우저 이름 제외가 아니라 기능 감지, 점진적 향상,
  명시적 복구에 수렴한다.
- 외부 출처는 NOSTALGIA 28레인, 손 의미, 4마디 전체 채보, 엄밀한 연주,
  노트 폭 해석, 트릴, 테누토 또는 글리산도를 정의하지 않는다. 이는 검증된
  NosLog 로직과 승인된 제품 결정으로 유지한다.

## S4 구조 슬라이스

1. `S4-A` — 명시적 악곡 상세 복귀와 간결한 채보 식별을 갖는 하나의 집중형 셸;
2. `S4-B` — 연결된 패널을 갖는 수동 낙하형/전체 채보 탭;
3. `S4-C` — 지속되는 손 안내와 채보 요약;
4. `S4-D` — 형상 제한 낙하형 렌더러와 부착된 핵심 재생 컨트롤;
5. `S4-E` — 별도 고빈도 속도 및 메트로놈 컨트롤;
6. `S4-F` — 컴팩트 하단 설정과 와이드 앵커형 설정 팝오버;
7. `S4-G` — 로컬 스크롤되는 4마디 전체 채보 열;
8. `S4-H` — 조건부 오버플로 안내와 런타임 복구 상태;
9. `S4-I` — 영구 설정 레일 없이 컴팩트에서 와이드로 전환.

## 측정된 구조 후보

사용자는 인터랙티브 예시를 검토한 뒤 다음 구조 동작을 승인했다. 정확한 시각
형상은 이후 외형 및 최종 디자인 단계에 남는다.

### 집중형 플레이어 구성

- 하나의 `main`이 복귀, 채보 식별, 보기 탭, 상태, 시각화, 컨트롤 및 제보를
  포함한다. 일반 전역 내비게이션과 푸터는 없다.
- 중앙 정렬된 낙하형 단위는 영역에 반응하는 높이와 측정된 와이드 최댓값을
  갖는다. 예시의 `1024px`는 넓은 공간에서 렌더러가 끝없이 늘어나지 않는지
  검증하기 위한 값일 뿐 아직 Foundation 폭 토큰이 아니다.
- 측정된 브라우저 뷰포트에서 대표 `390px` 프레임은 `356 × 345.59px`
  렌더러와 붙어 있는 `356 × 88px` 재생 컨트롤을 만들었다. `1280px` 프레임은
  `1024 × 345.59px` 렌더러와 붙어 있는 `1024 × 62px` 재생 컨트롤을 만들었다.
- 예시에서 빠른 컨트롤은 `8px` 구조 간격 뒤에 시작하며 핵심 재생과 구별된다.
  정확한 프로덕션 간격은 이후 컴포넌트 단계가 지배한다.

### 상세 설정 공개

- 컴팩트 설정은 모달 하단 패널 안에서 사용 가능한 인라인 폭을 사용하고
  스크림 뒤에 렌더러 맥락을 유지한다.
- 와이드 설정은 영구 측면 열을 예약하는 대신 같은 내용을 앵커형 팝오버로
  제공한다.
- `320px + 200%` 텍스트에서 측정된 패널은 프레임 안에 유지됐다. 검토 스테이지
  기준 `472.5–792.5px` 안의 `485.5–779.5px`이며 프레임 가로 오버플로가 없다.
- Escape로 패널을 닫고 `aria-expanded`가 `false`로 돌아가며 포커스가 상세
  설정 트리거로 복원된다.

### 전체 채보 로컬 이동

- `390px`에서 대표 전체 채보 스크롤포트는 `356px`, 네 열 트랙은 `1140px`로
  측정됐다. 첫 `276px` 열은 완전하고 다음 열 일부가 보인다.
- `1280px`에서 영역은 `1214px`로 측정되어 대표 네 열이 로컬 오버플로 없이
  모두 들어간다.
- 이 측정은 승인된 완전한 한 열과 다음 단서, 와이드 다중 열 동작을 검증한다.
  `276px`를 최종 프로덕션 열 토큰으로 승인하지 않는다.

### 검증 중 바로잡은 사항

1. 첫 예시는 `40px` 노트 속도 Select를 사용했다. 행렬 테스트가 승인된 공개 계약보다
   작은 타깃을 발견해 측정 최솟값을 `44px`로 높였다.
2. 첫 컴팩트 상세 설정 패널은 파일/범위 입력의 고유 폭을 상속해 `320px`, 특히
   `200%` 텍스트에서 빠져나갔다. 명시적인 축소 및 포함 규칙으로 프레임
   오버플로를 제거했다.
3. 작성자 `display` 규칙이 상태 메시지의 HTML `hidden` 상태를 처음에는
   덮어썼다. 수치 행렬 통과 뒤 시각 검토가 남아 있던 전체 화면 오류를 잡았고,
   전역 명시적 hidden 계약으로 고친 뒤 상태 전환을 다시 시험했다.
4. 자동 전체 채보 단언은 의도한 로컬 오버플로와 뷰어 프레임 실패를 구별한다.
   컴팩트 채보 오버플로는 필수이고 `1280/1440px`는 대표 네 열 트랙을 맞춰야 한다.
