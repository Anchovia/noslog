# Astra 작업 지시 — NosLog 로딩 표시

아래를 그대로 붙여 넣어 시작한다. `[ ]` 안은 사용자가 고른 안으로 바꾼다(비워 두면 시안의 추천안).

---

NosLog(Next.js 16 App Router · React · TypeScript · Prisma · 순수 CSS 토큰) 의 **로딩 표시**를 정리해 줘.

## 먼저 읽을 것

1. `AGENTS.md` — 작업 규칙 원본. 특히:
    - 답은 한국어.
    - **git 은 사용자가 한다**(커밋 · 푸시 · 스테이징 금지). 끝나면 커밋 제목(영어 type + 한국어 설명)과 `git add` 명령만 준다.
    - **운영 DB 에 쓰지 않는다.** localhost:3000(사용자가 켜 둠)도 운영이 아닌 개발 DB 지만 쓰기가 필요하면 먼저 묻는다.
    - 로그인은 사용자가 한다. 인증을 우회하지 않는다.
    - 가이드에 없는 시각 · 동작 결정, 새 색 · 새 숫자 · 새 움직임은 만들지 말고 멈추고 묻는다.
    - 관리자 화면(`/admin/*`)과 채보 캔버스는 손대지 않는다.
2. `docs/design/README.md` — 디자인 가이드. 「포커스 · 상태 · 움직임」 · 「움직임」 절(토큰 표 ⑩ 스피너 · ⑪ 스켈레톤 · 동작 줄이기), 「3. 부품」.
3. `docs/design/drafts/loading/loading-states.html`(시안 — 브라우저로 열어 「재생」) · `docs/design/drafts/loading/research.md`(근거).

## 정해진 안 (시안의 결정 번호)

- 결정 1 · 사이트 안 이동: [N1 위쪽 진행 막대 + 이전 화면 유지]
    - 누른 뒤 100ms 안에 끝나면 안 보임, 넘으면 맨 위 2px 막대가 차오르고 새 화면이 준비되면 채우고 사라짐. 이전 화면을 흐리게 하지 않음.
    - 막대 색은 기존 토큰 `--nl-primary-default` 로 제안됨 — 새 부품이라 구현 전에 사용자에게 한 번 확인.
- 결정 2 · 화면 안 데이터: [S1 레이아웃 모양 스켈레톤]
    - 제목 · 탭 · 필터처럼 고정된 부분은 실제 글자, 줄 · 카드 · 막대 같은 데이터 자리만 스켈레톤. 최종 레이아웃과 같은 개수 · 크기로 자리가 튀지 않게.
    - **스켈레톤 안에 스피너를 넣지 않는다.** 로딩 표시는 한 영역에 하나.
- 결정 3 · 스켈레톤 움직임: [M1 펄스] — 기존 `nl-skeleton` · `--nl-motion-loop-pulse` · `--nl-ease-pulse` 그대로. 새 애니메이션을 만들지 않는다.
- 결정 4 · 시간: 첫 진입은 지연 없이 스켈레톤(서버 스트리밍), 화면 안 다시 불러오기는 300ms 지연 뒤 스켈레톤, 최소 표시 시간 없음, 10초 넘으면 안내 문구, 실패하면 `StatusMessage` + 「다시 시도」. 동작 줄이기 = 펄스 멈춤(토큰이 이미 0 으로 바뀜), 스피너 · 위 막대는 유지.
- 결정 5 · 버튼은 지금 규칙(스피너 16 + 진행형 라벨) 그대로. 모양을 모르는 한 덩어리(오락실 지도 등)는 그 자리 가운데 스피너 하나.

## 할 일

1. **현황 표부터** — 공개 화면(`app/(nevigation)/**`) 모두에 대해: 첫 진입 때 보이는 것 · 사이트 안 이동 때 보이는 것 · 화면 안 로딩 글자(`*.loading` 문구 · `isPending` 분기) · 이미 있는 스켈레톤. 표를 먼저 보여 주고 시작한다.
2. **사이트 안 이동 표시(결정 1)** — 셸(`components/layout/appShell.tsx` 근처)에 공용 부품 하나. Next.js 16 의 방법(`next/link` 의 `useLinkStatus` · `onNavigate`, 라우터 전환 상태 등)은 **공식 문서로 확인하고** 쓴다(추측으로 쓰지 말 것). 움직임 값은 `tokens.css` 움직임 토큰만.
3. **화면별 스켈레톤(결정 2)** — 시안의 「적용 지도」 표대로. 공용 부품으로 만든다(예: 순위 줄 · 목록 카드 · 카드 격자 스켈레톤을 `components/ui` 에 한 번). 페이지마다 따로 모양을 만들지 않는다. 서버 컴포넌트 화면은 `Suspense` 경계 · 스트리밍으로 틀을 먼저 보내는 방식을 검토하고, `loading.tsx` 를 쓰면 결정 1(이전 화면 유지)과 부딪히는지 먼저 확인해 사용자에게 알린다.
4. **글자만 뜨는 곳 교체** — 「…불러오는 중입니다」 한 줄을 스켈레톤(또는 결정 5 의 스피너)으로. 문장은 화면 읽기용으로 남긴다(`aria-busy` · `role="status"`, 안내는 한 번).
5. **문서 · 테스트** — 결정이 코드에 들어가면 같은 작업에서 `docs/design/README.md` 해당 절 → `docs/design/decisions.md` 한 줄 → 테스트 기대값을 맞춘다. 공통 규칙은 공용 소스(`app/styles/tokens.css` · `foundation.css` · `components/ui`)에서만.

## 확인

- `npm run lint` · `npm run typecheck` · `npm test` · `npx knip`(새 항목 없음) · `npm run build`(끝나면 `next-env.d.ts` 변경은 되돌림).
- localhost:3000 을 headless Playwright 로 재서 증거를 남긴다: 느린 네트워크(CDP `Network.emulateNetworkConditions`)에서 첫 진입 · 사이트 안 이동을 시간대별 스크린샷으로. 스켈레톤이 최종 레이아웃과 같은 자리인지(내용 도착 전후 요소 위치 비교), 동작 줄이기(`reducedMotion: 'reduce'`)에서 펄스가 멈추는지.
- 폭 390 · 1280 둘 다. 로그인이 필요한 화면은 사용자에게 부탁한다.
- 보고에는 실제로 한 것만. 안 한 검사는 「안 함」, 확인 못 한 것은 「미확인」.
