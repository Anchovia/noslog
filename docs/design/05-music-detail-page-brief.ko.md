## 결정 라벨

- **관찰:** 현재 저장소, 브라우저 또는 승인된 상위 산출물에서 확인했습니다.
- **승인:** 사용자가 명시적으로 동의했으며 후속 디자인의 기준입니다.
- **제안:** 근거를 갖춰 제시했으나 사용자의 명시 승인을 기다립니다.
- **미확정:** 추가 조사, 대표 데이터, 테스트 또는 사용자 결정이 필요합니다.
- **거절:** 검토했지만 명시적으로 선택하지 않았습니다.
- **대체됨:** 이후 승인된 방향으로 교체했습니다.

이 기획서는 승인 완료된 악곡 상세 Page Family 산출물입니다. `승인`, `거절`,
`대체됨`으로 표시한 결정은 명시한 범위 안에서 기준이며 정확한 Foundation Token과
고해상도 구성은 후속 작업입니다.

## 목적

악곡 상세는 하나의 악곡과 선택한 난이도 Context를 유지하면서 사용자가 다음
영역을 효율적으로 오갈 수 있게 해야 합니다.

1. 자신의 성과와 기록 이력
2. 객관적인 채보 정보와 통계
3. 선택 채보의 랭킹
4. 서열 배치, 커뮤니티 평가 및 투표
5. 공개 채보가 있을 때 집중형 채보 뷰어

이 페이지는 자주 다시 방문하는 제품 작업 공간입니다. 순서대로 읽는 편집
문서나 여러 제품 영역을 훑는 대시보드가 아닙니다.

## 주요 Context

- **상위 승인:** 이 Surface는 공개이며, 로그인 이후 개인화 정보를
  추가합니다.
- **상위 승인:** 오락실 주변에서 사용하는 모바일이 주요 Context입니다.
  데스크톱도 필수이며 추가 너비를 의도적으로 사용해야 합니다.
- **상위 승인:** 악곡 탐색에서 악곡 상세를 엽니다. 서열, 빙고, 검정, 프로필
  및 랭킹 Context도 관련 악곡과 난이도로 Deep Link할 수 있습니다.
- **상위 승인:** 집중형 채보 뷰어는 악곡 상세의 하위 목적지이며 신뢰할 수
  있는 복귀 경로를 제공해야 합니다.
- **승인:** 악곡을 안정적인 Entity Context로 사용합니다. 선택 난이도는 활성
  채보 Context입니다.
- **승인:** 현재 시각 Styling, 고정 너비 구성, 타이포, 간격, 탭 형태 및 카드
  표현은 마이그레이션 근거일 뿐입니다. NosLog 2.0 시각 기준이 아닙니다.

## 현행 제품 근거

### 관찰한 Route와 상태

- 현재 Route는
  `/[locale]/music/[index]/[difficulty]`입니다.
- `Normal`, `Hard`, `Expert` 및 선택적 `Real`은 하나의 악곡에 속한 채보 단위
  선택입니다.
- 선택 콘텐츠 영역은 `tab` Query 값으로 표현합니다. 랭킹 페이지 이동은
  `page` Query 값을 사용합니다.
- 난이도, 선택 콘텐츠 영역 및 랭킹 페이지는 브라우저 History에 참여하며
  뒤로가기와 앞으로가기로 복구할 수 있습니다.
- 현행 구현은 `tab` Query가 없으면 로그인·비로그인 사용자 모두 기록을 엽니다.
  정보를 선택하면 `?tab=detail`을 기록하며 브라우저 뒤로가기는 이전의 Query 없는
  기록 진입을 복원합니다.
- 현행 비로그인 기록 구현은 조작한 기록 분석을 Rendering한 채 어둡게 한 로그인
  Overlay를 겹칩니다. 로그인 Link는 선택 악곡, 난이도 또는 기록 목적지를
  전달하지 않습니다.
- Discord OAuth 시작 및 완료 Route는 이미 안전한 상대 `returnTo` Path를 검증,
  저장 및 복원합니다. 현행 로그인 페이지가 항상 다국어 홈을 전달하므로 정확한
  과업 복원이 전체 흐름에 연결되지 않았습니다.
- 현재 페이지는 데스크톱에서도 최대 `390px` Shell 안에서 Rendering됩니다.
  이는 관찰한 사용성 한계이며 승인된 2.0 규칙이 아닙니다.

### 관찰한 정보 목록

현재 구현은 다음 정보를 제공합니다.

- 악곡 정체성: 재킷, 원문 제목, 선택적 번역 제목 또는 일본어 읽기, 아티스트,
  Category 및 안정적인 악곡 Index
- 선택 채보 정체성: 난이도, 공식 레벨 및 선택적 레벨 상수
- 채보 정보: BPM 범위, 노트 수, 길이, 출시일, 해금 조건, 영상 또는 미리보기
  Link, 패턴 통계, 점수 분포, 플레이어 수 및 가능한 경우 현재 사용자의 상위
  비율
- 개인 기록: 점수, Rank, Full Combo 상태, 플레이 횟수, 판정 상세,
  FAST/SLOW, 노트 종류별 성공률, 점수·성과 추이, 최근 플레이 및 유사 사용자
  비교
- 랭킹: 채보 단위 행, 가능한 경우 현재 사용자 순위 및 명시적인 Pagination
- 서열 및 평가: 현재 서열 상수, 이력, 커뮤니티 분포, 개인 평가, 의견 및 반응
- 공개 채보 사용 가능 여부와 집중형 채보 뷰어 Route

이 목록은 검증된 제품 기능을 보존합니다. 현재 정보 밀도, 순서, 라벨 또는
표현을 승인하는 것은 아닙니다.

### 관찰한 데이터 Loading 경계

- 공통 악곡 및 선택 채보 데이터는 모든 콘텐츠 영역에서 불러옵니다.
- 로그인한 사용자의 개인 최고 기록을 불러옵니다.
- 상세 기록 이력과 추이는 현재 기록 영역에서만 불러옵니다.
- 채보 집계 통계는 현재 정보 영역에서만 불러옵니다.
- 랭킹 행은 현재 랭킹 영역에서만 불러옵니다.
- 서열, 평가, 의견 및 반응 데이터는 현재 서열 영역에서만 불러옵니다.
- 브라우저는 현재 페이지 Session에서 방문한 악곡, 난이도, 콘텐츠 영역 및
  랭킹 페이지 조합을 Cache합니다.

이 수요 기반 Loading 경계는 현행 구현 근거입니다. 사용자가 영역을 선택하기
전에 모든 영역 Query를 부담하지 않기 때문에 승인된 탭 구조와 운영
측면에서도 잘 맞습니다.

### 관찰한 랭킹 구현

- 현재 선택 채보 랭킹은 사용자별 베스트 스코어 행 하나를 불러오며 프로필 Link,
  Avatar, 점수 Rank, 점수 및 Full Combo 또는 Pianist 상태를 제공합니다.
- 한 페이지에 일곱 행을 사용하고 페이지 Offset에서 표시 행 번호를 계산합니다.
  같은 점수에 같은 표시 순위를 부여하지는 않습니다.
- 현재 서버 정렬은 점수 내림차순과 사용자 ID 오름차순을 사용합니다. 별도 내 순위
  역시 동점 Group 안에서 사용자 ID로 고유한 서수 위치를 강제합니다.
- 현재 사용자 전체 카드가 같은 사용자의 행이 현재 페이지에 있어도 목록 위에
  나타나며 계산한 상위 비율을 보고합니다.
- 현재 점수 분포는 양수 점수인 모든 플레이어를 전체 플레이어 수에 포함하지만
  `950k`, `960k`, `970k`, `980k`, `990k`, `Pianist` Bucket만 그립니다.
  따라서 `950,000` 미만 기록이 라벨 있는 Bucket에는 나타나지 않으면서 분모에는
  영향을 줍니다.
- 현재 점수 Rank 이미지의 대체 Text는 모든 Locale에서 한국어 `랭크` 라벨을
  고정으로 덧붙입니다.

이는 구현 관찰이며 승인된 2.0 랭킹 규칙이 아닙니다. 아래 승인 계약에서 현재
사용자 표현 중복, 순위 의미, 분포 분모, 페이지 크기 및 다국어 접근성 누락을
해결합니다.

### 관찰한 대표 데이터 및 브라우저 근거

- 원본 Catalog에는 악곡 `578`개가 있습니다. `425`개는 표준 난이도 네 개를 모두
  제공하고 `153`개는 Real이 없습니다. 따라서 Real 부재는 예외 오류가 아니라
  일반적인 데이터 차이로 처리해야 합니다.
- 현행 최장 제목은 `54`자인 **50th Memorial Songs -二人の時 ～under the cherry
  blossoms～-** (`2f733689ec21214d6180888fe0e6b42f`)입니다. 긴 일본어 읽기도
  있으며 Real 채보는 없습니다.
- 현행 최장 아티스트 값은 네 난이도를 모두 제공하는 **STULTI**
  (`bfdaadfb98501907925ecf41a076108d`)의 `67`자입니다.
- 현행 최장 일본어 읽기는 **協奏曲第1番ホ長調 RV 269「春」より第一楽章**
  (`eaa4047ce17fb873b19b42454b0f6f3b`)에 있습니다.
- 현행 악곡 10개는 아티스트가 없습니다. **Happy Birthday to You**
  (`8f655bcd097d033f7c464f96dc20223d`)는 네 난이도를 제공하는 대표 사례입니다.
- 현행 일본어 Page는 `390px`에서 긴 읽기와 제목을 심하게 잘라냅니다. `1280px`에서도
  주요 콘텐츠는 현행 좁은 Shell에 갇힙니다. 이는 승인된 말줄임이나 폭 동작이 아니라
  Migration 결함입니다.
- 현행 Client-side 영역 전환에서 랭킹을 활성화하면 DOM Focus가 `body`에 남습니다.
  현행 플레이 영상 Link도 새 Browsing Context를 안내하지 않은 채
  `target="_blank"`를 사용합니다. 아래 승인 계약은 두 동작을 모두 교체합니다.

## 승인된 Entity 및 Action 모델

### 악곡 정체성과 선택 채보

- 난이도가 바뀌어도 악곡 단위 정체성을 안정적으로 유지합니다.
- 선택 난이도를 레벨, 상수, BPM, 노트 수, 개인 기록, 랭킹, 서열·평가 및
  채보 뷰어 사용 가능 여부를 결정하는 채보 단위 Context로 취급합니다.
- 선택 난이도를 공유 가능하고 History에서 복구 가능한 URL에 유지합니다.
- 네 가지 채보 난이도가 있다는 이유로 한 악곡을 관계없는 네 개 상세
  페이지처럼 복제하지 않습니다.
- 정확한 난이도 Control Geometry, 위치 및 시각 표현은 이후 반응형 Specimen으로
  의도적으로 미루며 미확정 제품 동작 결정이 아닙니다.

### 공개 채보 뷰어 진입

- **채보 보기**를 선택 채보와 연결된 직접 Context Action으로 두고 정보
  콘텐츠 Panel 밖, 선택 난이도 Context 바로 뒤이자 의미 콘텐츠 영역 전환보다
  앞에 배치합니다.
- NosLog 공개 채보가 있으면 선택 난이도의 집중형 채보 뷰어를 엽니다.
- **채보 보기**와 **플레이 영상** 두 Action 자리를 이 순서로 안정적으로
  유지합니다. 선택 난이도에 대응하는 NosLog 공개 채보 또는 유효한 플레이 영상
  URL이 있을 때만 각각 활성화하고, 없으면 자리를 유지한 채 명확하게 비활성화하여
  조작할 수 없게 합니다.
- 별도의 **공개 채보 없음** 표시 Text를 Rendering하지 않습니다. 비활성
  **채보 보기** 상태가 경쟁하는 빈 상태 문구 없이 사용 가능 여부를 전달합니다.
- NosLog에는 외부 채보 제품 Action이 없습니다. 현행 `chart_preview_url` 필드,
  관리자 입력 또는 Fallback은 2.0 구현 Mapping에서 제거할 구현 Inventory이며 제품
  요구사항이 아닙니다.
- 다국어 Action 라벨은 `플레이 영상` / `プレー動画` / `Play video`를 사용합니다.
  유효한 플레이 영상 URL은 현재 Browsing Context에서 엽니다. NosLog가
  `target="_blank"`를 강제하거나 새 탭 안내 문구를 추가하면 안 되며 사용자는 Browser
  Control로 별도 탭 열기를 선택할 수 있습니다. 모바일 OS가 연결된 YouTube App을
  여는 것은 NosLog가 강제하는 Browsing Context 결정이 아니라 User Agent 동작입니다.
- 정확한 시각 Token과 최종 Button Geometry는 Foundation 작업으로 남깁니다.

## 승인된 콘텐츠 구조

### A형: 하나의 지속 Context와 적응형 영역 전환

- 하나의 지속적인 악곡 정체성과 선택 난이도 Context를 유지합니다.
- 그 아래에서 채보 정보, 개인 기록, 랭킹 및 서열·커뮤니티 평가의 네 가지
  의미 영역을 제공합니다. 승인된 다국어 라벨이 맞지 않으면 간결한 단일 선택
  영역 Switcher를, 맞으면 탭 목록을 사용합니다.
- 선택한 콘텐츠 Panel만 표시합니다. 네 영역의 전체 내용을 하나의 긴 읽기
  페이지로 모두 Rendering하지 않습니다.
- 사용자가 상세 영역에 들어가기 전에 네 영역의 축약 요약을 반복해서
  보여주는 영역 간 개요 Panel을 추가하지 않습니다.
- 선택 난이도와 선택 콘텐츠 영역을 복구 가능한 내비게이션 상태에
  유지합니다.
- 콘텐츠 영역을 바꾸면 최초 진입에서 모든 영역 상세를 요구하지 않고 선택한
  영역의 상세 데이터를 요청해야 합니다.
- 이미 불러왔고 유효한 영역 데이터는 재사용합니다. 정확한 Cache 수명,
  의도 기반 Prefetch 및 무효화는 구현 단계 결정으로 남깁니다.
- 네 의미 영역의 다국어 라벨은 각각을 소유하는 아래 계약에서 승인했습니다.
  반응형 선택 Pattern은 아래에서 승인합니다. 정확한 타이포·치수·전환 너비·Surface
  Styling은 현재 탭 디자인 승인이 아니라 Foundation 및 Specimen 단계 결정입니다.

### A형이 적합한 이유

승인한 선택은 다음 세 가지로 수렴한 결과를 따릅니다.

1. 하나의 Object에 서로 관련 있지만 구분되는 View가 있고 사용자가 모든
   Panel을 동시에 비교할 필요가 없으면 탭이 표준적인 Pattern입니다.
2. 리듬게임 상세 Surface는 일반적으로 악곡 또는 Map 정체성과 선택 난이도를
   유지하면서 통계, 리더보드 또는 토론 Context를 바꿉니다.
3. 현행 NosLog 데이터 계층은 이미 활성 콘텐츠 영역에 따라 비용이 큰 기록,
   랭킹 및 평가 조회를 분리합니다.

따라서 A형은 익숙한 상호작용 모델이면서 NosLog의 초기 데이터 작업량도 낮출
수 있습니다. A형 승인은 현재의 답답한 시각 구현을 보존하지 않습니다.

## 승인된 반응형 Context 및 영역 전환 계약

### 지속 Context 순서

지원하는 모든 너비에서 다음 순서를 유지합니다.

1. 지속 악곡 정체성과 선택 채보 Context
2. 네 가지 선택지 난이도 Selector
3. 콘텐츠 영역 Switcher
4. 선택한 의미 Panel

- 난이도 Selector와 콘텐츠 영역 Switcher는 서로 다른 질문에 답하므로 별도
  Control로 유지합니다. 하나의 Menu나 Control Surface로 합치지 않습니다.
- 좁은 화면에서 `Normal`, `Hard`, `Expert`, `Real`을 한 행의 네 가지 선택지로
  계속 보여줍니다. 난이도 이름은 짧고 안정적인 Domain 라벨이며, 네 개의 긴 콘텐츠
  영역 라벨을 모두 노출하는 것보다 직접 비교에 상시 너비를 사용할 가치가 큽니다.
- 선택 난이도와 선택 콘텐츠 영역은 승인된 복구 가능 URL 상태를 즉시 갱신합니다.

### 좁은 화면 영역 Switcher

- `320`, `360`, `390`, `430`px 검증 너비에서는 현재 다국어 영역 라벨과 펼침
  Chevron을 보여주는 Container 전체 너비 Selector 하나를 사용합니다.
- Selector를 열면 승인된 의미 순서의 다국어 라벨 네 개 전체를 Anchored Overlay
  목록으로 표시합니다. 선택 Panel을 아래로 밀어내면 안 됩니다.
- 현재 Option을 시각적·Programmatic하게 표시합니다. 다른 Option을 선택하면 목록을
  닫고 URL과 현재 라벨을 갱신하며 선택 Panel을 승인된 대상별 대기 상태로 교체합니다.
- 한국어·일본어·영어 라벨 전체를 보존합니다. 좁은 화면에서 축약·말줄임·아이콘 전용
  선택지·여러 행 탭·가로 Scroll 탭 Strip을 사용하지 않습니다.
- 이 Control은 지역적인 Context Switcher이며 전역 사이트 내비게이션이나 추가적인
  상시 Button 행이 아닙니다.

### 넓은 화면 탭 목록과 콘텐츠 기반 전환

- 승인된 다국어 라벨 전체, 검증된 글자 크기, Touch/Click Padding, Focus 처리 및 필수
  간격이 말줄임이나 Scroll 없이 한 행에 맞을 때만 좁은 화면 Selector를 네 개의 전체
  Auto-width 탭으로 교체합니다.
- Device 이름을 가정하지 말고 컴포넌트의 사용 가능한 Inline Size와 승인된 다국어
  라벨 중 가장 긴 조합으로 전환을 결정합니다. Switcher가 서로 다른 크기의 Parent 안에
  나타날 수 있으면 Container Query를 우선합니다.
- 정확한 수치 전환 너비는 Foundation 타이포와 Grid Specimen에서 최종 라벨을 측정할
  때까지 의도적으로 미룹니다. 측정 없이 관습적인 Breakpoint를 선택해도 된다는 뜻이
  아닙니다.
- 두 Control을 보조 기술에 동시에 노출하지 않습니다. 비활성 반응형 표현은 접근성
  Tree에 없어야 합니다.

### 넓은 화면 페이지 구성

- 현행의 상시 `390px` 시각 제한을 제거합니다. 반응형 바깥 Gutter와 검증된 최대
  콘텐츠 너비를 사용하고, 정확한 상한은 실제 악곡 상세 데이터로 Foundation Grid
  Specimen에서 정합니다.
- 악곡·선택 채보 Context를 위에 유지합니다. 데스크톱 너비를 채우거나 영역 Switcher를
  반복하기 위한 상시 왼쪽 Sidebar를 추가하지 않습니다.
- 모바일 DOM 및 읽기 순서를 보존하고 하나의 일반적인 늘어난 Column을 모든 Panel에
  적용하지 말고 선택 Panel 콘텐츠에 따라 적응합니다.
    - **채보 정보:** 간결한 사실 Group과 선택 채보 Action을 본래 읽기 좋은 너비로
      유지하고 짧은 사실을 전체 Canvas 너비로 늘리지 않습니다.
    - **내 기록:** 승인된 모바일 순서를 유지하면서 베스트·누적 비교와 더 넓은 성장
      시각화를 허용합니다.
    - **랭킹:** 리더보드를 주요 영역으로 유지하고 사용 가능한 너비가 받쳐주면 점수
      분포를 보조 넓은 화면 영역에 둡니다.
    - **서열·평가:** 승인된 의미 순서를 바꾸지 않고 여섯 위치 비교와 레이더·평가 관계에
      추가 너비를 사용합니다.
- Panel 적응은 사용 가능한 Panel 너비에 기반하며 적합할 때 Container Query를
  사용합니다. 데스크톱 적응은 비교와 분석의 명확성을 더하지만 데스크톱 전용 제품
  의미를 만들지 않습니다.

## 승인된 진입 우선순위 및 복원 계약

### 일반 진입 기본값

- 악곡 상세 URL이 콘텐츠 영역을 명시하지 않으면 로그인·비로그인 사용자 모두
  **정보** 의미 영역을 엽니다.
- 정보 의미 영역을 콘텐츠 영역 순서의 첫 번째에 둡니다. 승인된 의미 순서는
  정보, 개인 기록, 랭킹, 서열·커뮤니티 평가입니다.
- 이번 승인은 의미 순서를 정합니다. 네 영역의 다국어 라벨은 아래 채보 정보·기록
  계약과 서열·평가 계약에서 승인했습니다.
- 같은 Query 없는 URL이 사용자 인증 여부만으로 서로 다른 기본 영역을 열게
  하지 않습니다.

정보는 공개되고 안정적이며 모든 방문자에게 유용하므로 일반 진입 기본값으로
사용합니다. 개인 기록도 반복 사용자의 핵심 과업이지만, 사용자 의도를 이미
아는 진입 출처가 숨겨진 인증별 기본값에 의존하지 않고 직접 열어야 합니다.

### 출처를 아는 명시적 진입

진입 출처가 사용자 과업을 이미 식별하면 명시적이고 복원 가능한 콘텐츠 영역
상태를 사용합니다.

| 진입 출처 또는 의도                               | 필수 목적지 동작                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------- |
| 일반 탐색, 악곡 검색 또는 명시 영역 없는 공유 URL | Query 없는 표준 진입 또는 동등한 명시적 정보 상태를 통해 정보 열기        |
| 프로필, 최근 플레이 또는 개인 기록                | 선택 악곡·난이도에서 개인 기록 영역을 명시적으로 선택해 열기              |
| 랭킹 항목                                         | 선택 악곡·난이도에서 랭킹을 명시적으로 선택해 열기                        |
| 서열, 평가 또는 투표 항목                         | 선택 악곡·난이도에서 서열·커뮤니티 평가를 명시적으로 선택해 열기          |
| 집중형 채보 뷰어에서 복귀                         | 진입 출처 상태가 있으면 원래 악곡 상세 URL과 콘텐츠 영역을 정확히 복원    |
| 출처 상태 없이 뷰어에 직접 진입                   | 개인 또는 과거 사용 기본값을 추측하지 않고 선택 채보의 정보 영역으로 복귀 |

- 목적지 URL은 Locale, 악곡 Index, 선택 난이도, 선택 콘텐츠 영역 및 복귀할 때
  유효한 승인된 영역별 상태를 보존해야 합니다.
- 뒤로가기와 앞으로가기는 현재 인증 상태에서 영역을 다시 계산하지 않고 명시적
  영역을 복원해야 합니다.
- 서로 무관한 악곡이나 Session 사이에 마지막으로 사용한 악곡 상세 영역을 전역
  기억하지 않습니다. 출처가 아는 명시적 의도를 숨겨진 선호 상태보다 우선합니다.

### 비로그인 개인 기록

- 비로그인 사용자에게도 개인 기록 영역을 보이고 선택할 수 있게 합니다. 숨기거나
  비활성 탭으로 표현하지 않습니다.
- 비로그인 상태에서 기록을 선택하면 기록 콘텐츠 대신 간결한 Panel 단위 인증
  상태를 Rendering합니다. 조작한 빈 기록, 흐려진 기록 또는 어둡게 한 기록 분석을
  Overlay 뒤에 Rendering하지 않습니다.
- 인증 상태에는 간결한 설명 하나와 명시적 로그인 Action 하나를 둡니다. 기록
  탭을 선택하거나 Focus하는 것만으로 인증을 시작하면 안 됩니다.
- 로그인 Action은 Locale, 악곡 Index, 난이도 및 명시적으로 선택한 기록 영역을
  포함하는 완전하고 안전한 복귀 목적지를 전달해야 합니다.
- 인증 성공 뒤 정확한 기록 영역으로 돌아옵니다. Onboarding이 필요하면 같은
  목적지를 Onboarding 완료까지 보존하고 필수 흐름이 끝나면 복원합니다.
- 인증 오류가 나도 재시도하거나 같은 악곡 상세로 돌아갈 수 있도록 충분한
  목적지 상태를 보존합니다. 정확한 오류 문구와 표현은 이후 상태 계약에서
  정합니다.

현행 OAuth 흐름은 상대 `returnTo` Path를 저장·검증하고 인증 뒤 해당 경로로
Redirect할 수 있습니다. 현재 로그인 페이지 인계가 항상 다국어 홈을 전달하므로,
이는 새로운 인증 구조가 필요한 문제가 아니라 구현 매핑의 누락입니다.

### 접근성 및 예측 가능성 결과

- 선택 영역은 URL 및 History 상태에 표현하고 이후 구현에서는 승인된 넓은 화면의
  `tablist`·`tab`·`tabpanel` 또는 좁은 화면의 입력 없는 단일 선택
  `combobox`·`listbox` 의미 구조를 제공해야 합니다.
- 영역 활성화는 명시적 사용자 Action으로 유지합니다. Focus한 탭이나 활성 Listbox
  Option이 인증·다른 Panel 요청·예상하지 못한 Context 변경을 일으키면 안 됩니다.
- 비로그인 기록 Panel은 선택한 Panel 안에서 사용할 수 없는 개인 콘텐츠와 로그인
  Action을 설명하므로 오해를 부르는 비활성 상태 없이 기능을 발견할 수 있습니다.
- 아래 승인된 비동기 상태 계약에서 일반 Focus 유지, 실시간 안내, Loading, 실패 및
  재시도 동작을 정의합니다. 반응형 Control 구성은 위 승인 계약에서 정의했습니다.

## 승인된 비동기 상태 및 복구 계약

### 안정된 Context와 원자적 대상 선택

- 한 Dynamic 영역을 불러오는 동안 공통 Application Shell, 지속 악곡 Identity,
  선택 채보 Context, 난이도 선택지, 콘텐츠 영역 선택지 및 승인된 선택 채보 자료
  Action을 계속 사용할 수 있게 유지합니다.
- 사용자가 다른 난이도나 의미 콘텐츠 영역을 명시적으로 선택하면 선택 대상과 복원
  가능한 URL·History 상태를 즉시 갱신합니다. 이전 의미 Panel을 대상 Panel의 Loading
  상태로 교체하며, 이전 대상의 내 기록·랭킹·채보 정보·서열/평가 데이터를 새로
  선택한 대상의 데이터인 것처럼 절대로 보여주지 않습니다.
- 갱신 중인 대상 Panel만 Busy로 표시합니다. 하나의 요청이 진행 중이라는 이유만으로
  모든 난이도 및 영역 Control을 비활성화하지 않습니다.
- Navigation은 중단 가능하게 유지합니다. 나중의 유효한 선택이 앞선 대기 선택을
  대체하고, 지원되는 경우 오래된 요청을 취소하며, 마지막 선택 결과만 화면 대상에
  반영할 수 있습니다.
- 같은 악곡·난이도·콘텐츠 영역·영역별 상태에 대한 중복 요청을 합칩니다.

### 전환 종류별 Loading 표현

| 전환 종류                                  | 필수 표현                                                                                                                                                                                     |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 악곡 상세 최초 진입                        | Application Shell을 유지하고 안정된 Route 단위 악곡 상세 Placeholder를 제공합니다. 충분한 악곡 Identity가 이미 있으면 해당 Context를 계속 보여주고 미확정 선택 채보 영역만 불러옵니다.        |
| Cache 없는 난이도 또는 의미 영역 선택      | 대상과 URL을 즉시 갱신하고 대상 Panel의 핵심 Geometry를 예약하며 Panel에 `aria-busy="true"`를 설정하고 선택 Control에 간결한 대기 상태를 제공합니다. 이전 의미 Panel을 남기지 않습니다.       |
| 빠른 대상 응답                             | 시각적으로 산만한 Animated Loader를 추가하지 않고 대상 콘텐츠를 반영합니다.                                                                                                                   |
| 약 300ms 이상의 인지 가능한 요청           | Dynamic 대상 Panel에 단순화되고 구조가 일치하는 Skeleton을 보여줍니다. 고정 탭, Application Header 또는 라벨과 값을 이미 아는 Control을 Skeleton으로 만들지 않습니다.                         |
| 방문한 Fresh 대상                          | 정확한 Cache 대상을 Loading 표시 없이 즉시 보여줍니다.                                                                                                                                        |
| 랭킹 Pagination과 같은 동일 목록 Page 전환 | 이전 행을 명시적인 대기 Placeholder 데이터로 유지하고 행 Geometry를 보존하며 대상 Page가 교체될 때까지 목록만 Busy로 표시합니다. 대기 중인 Page Control이 완료를 거짓으로 안내하면 안 됩니다. |
| 과거 의견과 같은 Append 이어보기           | 불러온 모든 항목을 유지하고 이어보기 경계에 Local Loading 표시 하나만 둡니다. 전체 목록을 Skeleton으로 교체하지 않습니다.                                                                     |

- Skeleton은 예상 Panel의 안정된 상위 구조만 전달하며 모든 선택 필드나 Action을
  그대로 재현하지 않습니다.
- Loading Motion은 이후 전역 Reduced Motion 계약을 준수해야 합니다. 의미와 접근
  가능한 Loading Text가 Animation에 의존하면 안 됩니다.
- 약 300ms 기준은 불필요한 Flash를 막으면서 인지 가능한 지연에는 분명한 Feedback을
  제공합니다. 최종 Motion Curve와 Skeleton Styling은 Foundation 결정으로 남깁니다.

### Cache Freshness 및 재검증

- Cache Entry는 정확한 악곡 Index, 난이도, 콘텐츠 영역 및 영역별 상태에만
  유효합니다. 해당되는 경우 랭킹 Page나 의견 정렬·이어보기 상태도 포함합니다.
  다른 대상 Cache Entry를 현재 데이터로 사용하면 안 됩니다.
- 현재 악곡 상세 Page Session 동안 채보 정보는 Fresh로 취급합니다. 새 Route 진입은
  현재 Server 값을 다시 가져올 수 있습니다.
- 내 기록·랭킹·서열/평가 데이터는 60초 동안 Fresh로 취급합니다. 그 뒤에는 정확한
  대상의 Cache 데이터를 즉시 보여주고 Background에서 재검증합니다.
- 데이터 연동 성공, 평가 제출·수정, 의견 변경, 반응 또는 다른 승인된 데이터 변경
  Action은 60초를 기다리지 않고 영향받는 모든 대상을 즉시 무효화해야 합니다.
- Background 재검증 중에는 정확한 대상 콘텐츠를 읽을 수 있게 유지하고 관련 없는
  상호작용을 막지 않는 간결한 **업데이트 중** 상태 하나를 제공합니다.
- Background 재검증이 실패하면 정확한 Cache 콘텐츠를 유지하고 저장된 콘텐츠임을
  식별하며, 간결한 **최신 정보를 불러오지 못했습니다**와 **다시 시도** Action 하나를
  제공합니다. 오래된 데이터를 최신인 것처럼 암묵적으로 표현하지 않고, 갱신 실패만을
  이유로 유용한 Cache 콘텐츠를 제거하지 않습니다.
- 이후 데이터 계약이 해당 Domain에 정확하고 사용자에게 의미 있는 시점을 제공할 수
  있기 전에는 마지막 업데이트 시각을 영구적으로 표시하지 않습니다.

### 빈 상태, 인증, 자격 및 권한 상태

- 빈 상태는 요청은 성공했지만 적용할 데이터가 없는 상태입니다. Loading, 권한 또는
  실패 상태가 아닙니다.
- 채보 정보는 사용할 수 없는 선택 사실을 생략하고 Panel 전체를 빈 상태로 만들지
  않습니다. 악곡이나 선택 채보가 없으면 빈 상태가 아니라 Not Found입니다.
- 내 기록은 비로그인일 때 승인된 간결한 로그인 상태를, 로그인했지만 플레이 기록이
  없을 때 간결한 기록 없음 상태를 사용합니다. 0값 분석 데이터를 만들지 않습니다.
- 랭킹은 승인된 간결한 공개 기록 없음 상태를 사용합니다. 요청이 실제로 실패하지
  않았다면 다시 시도를 제공하지 않습니다.
- 서열/평가는 승인된 미등재, 미공개, 변경 이력 없음, 평가 없음, 집계 중, 의견 없음,
  Loading 및 실패 구분을 유지합니다.
- 사용자가 평가·반응·신고·수정·삭제를 할 수 없어도 공개 서열/평가 콘텐츠는 읽을 수
  있게 유지합니다. 제한된 Action 영역만 승인된 로그인·검증된 플레이·소유권·운영
  자격 설명으로 교체합니다.
- 이유를 설명하지 않는 비활성 Form을 Rendering하거나 권한 안내를 데이터 부재의
  일반 대체물로 사용하지 않습니다.

### 실패 범위, 재시도 및 Not Found

- 최초 Route 실패에서는 공통 Application Shell을 유지하고 간결한 **악곡 정보를
  불러오지 못했습니다**, **다시 시도**, **악곡 검색으로** Action을 제공하는 Route
  단위 상태를 보여줍니다. 다시 시도는 정확한 Locale, 악곡 Index, 난이도, 콘텐츠
  영역 및 유효한 영역 상태를 반복합니다.
- 확인된 악곡 또는 채보 부재는 일시 오류가 아니라 다국어 Not Found 계약을 사용하고
  오해를 부르는 다시 시도를 제공하지 않습니다.
- 사용할 수 있는 Cache가 없고 선택 Panel 요청이 실패하면 선택 대상과 URL을 유지하고
  해당 Panel만 간결한 실패와 다시 시도 Action 하나로 교체합니다. 이전 난이도나
  영역으로 조용히 되돌리지 않습니다.
- 점수 분포나 의견 이어보기처럼 독립적으로 불러올 수 있는 하위 영역 하나가 실패하면
  성공한 인접 콘텐츠를 보존하고 가장 작은 의미 영역에 실패와 다시 시도를 둡니다.
  전체 Page를 실패 처리하지 않습니다.
- 네트워크 실패나 Server `5xx` 응답의 멱등 GET만 짧은 지연 뒤 한 번 자동
  재시도합니다. 그 뒤에는 보이는 실패와 수동 다시 시도를 제공합니다. `4xx`, 인증,
  권한, 검증 또는 파괴 Action 실패는 자동 재시도하지 않습니다.
- 수동 다시 시도는 난이도·영역·Pagination·정렬·인증 복귀 상태·Scroll Context를
  초기화하지 않고 실패한 대상을 반복해야 합니다.
- Action 처리 실패는 시작 Action 가까이에 유지하고 승인된 평가·의견·반응·삭제
  결과를 따릅니다. Route Error Boundary가 예상 가능한 Action 오류 처리를 대신하지
  않습니다.

### Focus, 의미 구조 및 상태 안내

- 탭 표현을 보여주는 너비에서는 콘텐츠 영역 선택지를 `tablist`, `tab`, `tabpanel`,
  `aria-selected`, `aria-controls` 및 Labelled Panel 관계로 구현합니다. 새로 선택한
  Panel이 원격 요청을 요구할 수 있으므로 수동 활성화를 사용합니다. 좌우 방향키는
  Focus를 순환 이동하고 Home/End는 첫·마지막 탭으로 이동하며 Enter/Space가 Focus한
  탭을 활성화합니다. Focus 이동만으로 다른 영역을 요청하거나 선택하면 안 됩니다.
- 좁은 표현을 보여주는 너비에서는 `listbox` Popup, 전체 `option` 이름,
  `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-selected`를 갖춘 입력
  없는 단일 선택 `combobox`를 사용합니다. Enter·Space·방향키로 Popup을 열 수 있고,
  위아래 방향키로 Option을 살펴보며 Home/End는 첫·마지막 Option으로 이동합니다.
  Enter/Space로 확정하고 Escape로 선택 영역을 바꾸지 않은 채 닫습니다. DOM Focus는
  Combobox에 유지합니다. Option을 살펴보기만 할 때 해당 Panel을 요청하면 안 됩니다.
- 좁은 화면에서 선택한 뒤 닫힌 Combobox에 Focus를 유지하고, 연결된 탭이 없는
  `tabpanel`이 아니라 Labelled `region`으로 선택 콘텐츠를 노출합니다. 넓은 화면에서는
  완전한 탭-`tabpanel` 관계를 보존합니다. 숨겨진 탭 목록이나 Listbox를 중복 노출하지
  않습니다.
- 선택 난이도도 최종 Control Pattern에 적합한 동등하게 명시적인 현재 상태 수단을
  제공해야 합니다.
- 일반 난이도 및 콘텐츠 영역 활성화는 사용자가 활성화한 Control에 Keyboard Focus를
  유지합니다. Loading 또는 완료 Panel로 Focus를 강제로 옮기지 않습니다.
- **Real 채보 정보 불러오는 중**, **Real 채보 정보 표시 완료**, **Real 랭킹
  업데이트 중**처럼 간결하고 대상이 분명한 안내를 Page 단위 `polite` 상태 영역
  하나로 제공합니다. Skeleton이나 Card마다 경쟁하는 Live Region을 만들지 않습니다.
- 갱신 Panel이나 목록에 `aria-busy="true"`를 적용하고 일관된 갱신이 준비된 뒤에만
  해제합니다. 중간 Skeleton 변경을 모두 안내하지 않습니다.
- 보이는 요청 실패는 적합한 오류 의미로 한 번 안내하며 Focus는 예측 가능한 곳에
  유지하고 다시 시도는 일반 Focus 순서에서 접근할 수 있게 합니다.
- Hard Load, 직접 URL 진입 또는 Reload는 일반 Document Focus 동작을 따르며 Browser가
  Document를 불러온 뒤 Focus를 강제로 옮기지 않습니다.
- 탐색·랭킹·서열·프로필 또는 다른 제품 Route에서 다른 악곡 상세 목적지로 Client-side
  전환하면 안정적인 정체성 Context가 준비된 뒤 다국어 Document Title을 갱신하고 악곡명
  `h1`으로 Focus를 옮깁니다. Heading은 Programmatic Focus를 위한 `tabindex="-1"`을
  사용할 수 있지만 일반 순차 Tab 순서에는 들어가면 안 됩니다.
- 뒤로가기와 앞으로가기는 URL에 기록한 정확한 콘텐츠를 복원합니다. 원래 Collection으로
  돌아가면 해당 출발점이 아직 존재하는 한 시작한 결과 또는 Action과 인근 Scroll 위치를
  복원하며, 이 복구를 악곡명 Focus로 대체하지 않습니다.
- 악곡 상세 안의 난이도 및 콘텐츠 영역 변경은 위 규칙대로 활성화한 Control에 Focus를
  유지합니다. Loading 또는 완료 Panel로 Focus를 옮기지 않습니다.
- 확인된 Not Found 또는 전체 Route 오류로 Client-side 전환하면 준비된 상태 Heading을
  안내하고 Focus합니다. Hard Load된 오류는 일반 Document 동작을 따릅니다.

## 승인된 채보 정보 및 개인 기록 계약

### 첫 두 영역의 최종 라벨

| 의미 영역 | 한국어      | 일본어       | 영어         |
| --------- | ----------- | ------------ | ------------ |
| 채보 사실 | `채보 정보` | `譜面情報`   | `Chart Info` |
| 개인 기록 | `내 기록`   | `プレー記録` | `My Record`  |

- 활성 난이도가 이 영역의 사실을 결정하므로 **악곡 정보**가 아니라 **채보 정보**를
  사용합니다.
- **내 기록**은 명확하게 개인적이고 채보 단위인 영역으로 유지합니다. 이 영역의
  존재가 인증 상태에 따른 기본 진입 규칙을 만들지는 않습니다.
- 랭킹과 서열·평가의 최종 라벨은 아래 서열·평가 계약에서 승인했습니다.

### 채보 정보 범위

채보 정보는 선택한 채보의 간결한 객관적 요약입니다. 개인 기록, 랭킹 또는
서열·평가를 미리 보여주는 개요 Hub가 아닙니다.

- BPM, 노트 수 및 곡 길이는 항상 표시합니다.
- 수록일과 언락 조건은 의미 있는 값이 있을 때만 표시합니다. 사용할 수 없는
  선택 항목을 값이 `-`인 행으로 남기지 않습니다.
- 지속 악곡 및 선택 채보 Context에서 이미 제공하는 난이도, 공식 레벨, 레벨
  상수, Category, 제목 또는 아티스트를 반복하지 않습니다.
- 패턴 경향 데이터와 투표 수는 서열·커뮤니티 평가로 옮깁니다.
- 점수 분포, 플레이어 수 및 현재 사용자의 상대 순위나 상위 비율은 랭킹으로
  옮깁니다.
- 소유 영역으로 연결하기 위해 채보 정보에 축약 패턴 또는 점수 분포 미리보기를
  남기지 않습니다.

이 경계는 Domain마다 하나의 의미 출처를 유지하며 공개 기본 영역 안에 거절한
영역 간 개요 Pattern을 다시 만들지 않습니다.

### 선택 채보 자료 Action

- **채보 보기**와 **플레이 영상**을 채보 정보의 사실 행이 아니라 선택 채보
  Action으로 취급합니다. 외부 채보 Action은 추가하지 않습니다.
- 선택 난이도 Context 바로 뒤이자 의미 콘텐츠 영역 전환보다 앞에 안정적인 두 자리
  Context Action Group 하나를 둡니다. 순서는 **채보 보기**, **플레이 영상**입니다.
- NosLog 에디터에서 만든 공개 채보가 있을 때만 **채보 보기**를, 유효한 플레이 영상
  URL이 있을 때만 **플레이 영상**을 활성화합니다. 자료가 없으면 자리를 숨기거나
  별도의 사용 불가 문구를 추가하지 않고 해당 Action을 명확하게 비활성화합니다.
- 콘텐츠 영역과 난이도가 바뀌어도 두 자리를 유지합니다. Page 계층에서 지속되는
  것이며 Scroll 중 Viewport에 붙는 Sticky 요소는 아닙니다.
- 좁은 너비에서 검증한 한국어·일본어·영어 라벨이 맞으면 한 행을 유지하고,
  맞지 않으면 순서를 바꾸지 않고 쌓습니다. 넓은 너비에서는 좁은 정보 Column 안에
  남기지 않고 같은 두 Action을 선택 채보 Context에 맞춰 정렬합니다.
- 비활성 Action은 Hover·Pressed 반응이 없고 실행할 수 없습니다. 라벨을 알아볼 수
  있게 유지하고 비활성 상태와 간결한 사용 불가 이유를 Programmatic하게 제공하며,
  데스크톱 Tooltip을 사용한다면 Keyboard Focus에서도 설명을 제공해야 합니다.
  Tooltip을 유일한 모바일 설명으로 의존하지 않습니다.
- 최종 크기, 간격, 색상, 대비 및 Surface 처리는 Foundation Specimen이 소유합니다.
- 유효한 **플레이 영상** Link는 현재 Browsing Context에서 실행합니다. 새 탭을 강제하지
  않으므로 라벨에 새 탭 안내를 덧붙이지 않습니다. Command/Ctrl-click 같은 Browser
  기본 사용자 선택은 계속 사용할 수 있습니다.

### 개인 기록 우선순위

다음 의미 순서를 사용합니다.

1. **베스트 기록:** 베스트 스코어, Rank, Full Combo 또는 Pianist 달성 상태,
   최고 기록일 및 필요한 경우 Pianist까지의 진행도
2. **누적 요약:** 플레이 횟수, 최대 콤보, Full Combo 횟수 및 Pianist 횟수
3. **성장 추이:** 최고점 갱신 기록만 보여주는 베스트 스코어 Series
4. **최근 플레이:** 간결한 행 요약과 선택적 플레이별 상세를 제공하는 최근 채보
   플레이
5. **판정 분석:** 판정별 수와 비율, 노트 종류별 성공률 및 최근 판정·Timing
   추이. 기본 상태는 접힘

누적 요약은 빠른 확인을 지원하지만 베스트 기록과 시각적으로 경쟁하면 안 됩니다.
정확한 Geometry는 대표 모바일·데스크톱 Specimen 작업으로 미룹니다.

### 승인된 기록 용어와 데이터 의미

| 의미                         | 한국어          | 일본어         | 영어                 |
| ---------------------------- | --------------- | -------------- | -------------------- |
| 성장 Section                 | `성장 추이`     | `上達の推移`   | `Progress over time` |
| 현재 성장 Series 지표        | `베스트 스코어` | `ベストスコア` | `Best score`         |
| 사용자·채보 단위 플레이 횟수 | `플레이 횟수`   | `演奏回数`     | `Play count`         |

- **성장 추이**는 Section 라벨입니다. 현재 Series에는 최고점 갱신 기록만 있으므로
  모든 성과 지표를 그린다고 오해하지 않도록 화면의 Series 라벨과 접근 가능한 Chart
  제목에서 **베스트 스코어**를 명시해야 합니다.
- 플레이 횟수는 이 사용자가 선택 채보를 몇 번 연주했는지 보여주는 의미 있는 누적
  값입니다. 클리어 횟수와 구분해 유지합니다.
- 클리어 횟수를 악곡 상세의 성과 지표로 노출하지 않습니다. NOSTALGIA 클리어
  상태는 이 제품 목적에서 사용자의 선택 채보 결과를 의미 있게 구분하지 않습니다.
- 프로필 단위 전체 플레이 횟수, 공개 범위 및 표현은 프로필 페이지 기획서의
  결정으로 미루며 이번 채보 단위 계약에서 정하지 않습니다.

### 분석 및 시각화 규칙

- 유사 사용자 비교는 선택 사항이며 기본으로 끕니다. 켰을 때 표본 기준을
  제공하고 약하거나 사용할 수 없는 표본을 권위 있는 값처럼 표현하지 않습니다.
- 판정 분석은 보조 진단 콘텐츠이므로 기본으로 접습니다. 베스트 기록과 누적
  요약은 이를 펼쳐야 확인할 수 있는 구조가 되면 안 됩니다.
- 같은 패턴 경향 값을 레이더와 막대 Chart로 동시에 표현하지 않습니다. 승인한
  5축 커뮤니티 레이더를 주요 프로필로 사용하고 정확한 값, 축별 유효 평가 수 및
  구조화한 Text 대안을 제공합니다.
- Chart마다 질문과 지표 계약을 하나로 명확히 합니다. 정확한 값 또는 구조화한
  Text 대안을 제공하고 Series나 상태를 색상만으로 전달하지 않습니다.

## 승인된 랭킹 계약

### 목적과 정보 계층

랭킹은 선택 채보에 관한 두 질문, **현재 사용자는 어디에 있는가?**와 **공개
베스트 스코어를 어떻게 비교하는가?**에 답합니다. 두 번째 개인 기록
대시보드가 아니며 지속 Context에 보이는 악곡이나 난이도 사실을 반복하지
않습니다.

모바일에서는 다음 읽기 순서를 사용합니다.

1. 조건부 현재 사용자 위치
2. **랭킹 · 참여자 N명**에 해당하는 제목
3. 공개 리더보드
4. 필요할 때 명시적인 Pagination
5. 보조 상위 실력 점수 분포

데스크톱에서도 현재 사용자 Context를 랭킹 콘텐츠 위에 유지합니다. 그 아래에서는
리더보드를 주요 영역으로 만들고 공간과 대표 콘텐츠가 허용하면 점수 분포를 인접한
보조 영역에 둘 수 있습니다. 데스크톱에서 두 영역을 나란히 놓더라도 모바일 DOM과
읽기 순서를 보존합니다. 넓은 Viewport에서 현재 `390px` 고정 Canvas를 유지하지
않습니다.

### 조건부 현재 사용자 위치

- 로그인한 사용자 행이 현재 페이지에 있으면 별도 현재 사용자 요약을 Rendering하지
  않습니다. 색상 이외의 표현도 사용해 해당 행을 리더보드에서 강조합니다.
- 사용자 행이 현재 페이지에 없으면 목록 위에 **내 순위 37 / 120 · 976,654 ·
  S · FC**에 해당하는 간결한 요약 한 줄을 보여줍니다. 이 요약은 Context이며 두
  번째 전체 프로필 카드가 아닙니다.
- 로그인한 사용자에게 선택 채보 점수가 없으면 **순위 없음**에 해당하는 간결한
  상태를 보여줍니다.
- 비로그인 상태에서도 전체 공개 리더보드를 제공하고 **내 순위를 보려면 로그인**에
  해당하는 작은 Context Action만 제공합니다. 인증 Panel로 공개 목록을 대체하거나
  가리지 않습니다.
- 상대적인 상위 비율을 표시하지 않습니다. 정확한 순위와 전체 참여자 수가 더
  실행 가능하며 모호한 백분위 반올림을 피합니다.
- 랭킹에서 로그인을 시작하면 승인된 안전한 복귀 경로를 통해 Locale, 악곡,
  선택 난이도, 랭킹 및 유효한 페이지 Context를 보존합니다.

이 조건부 규칙은 사용자의 전체 행을 두 번 보여주지 않으면서 사용자 행이 없는
페이지에서도 위치를 확인하게 합니다.

### 리더보드 행 계약

- 플레이어별 베스트 스코어 행 하나를 보여줍니다.
- 모바일에서는 각 행을 의미상 **순위 | 플레이어 | 결과**로 묶습니다.
- 플레이어에는 Avatar와 Link가 있는 표시 이름을 둡니다. 기존 프로필 목적지를
  유지합니다.
- 결과에서는 점수를 주요 값으로, 점수 Grade와 Full Combo 또는 Pianist 상태를
  보조 값으로 둡니다.
- 데스크톱에서는 Grade, 달성 상태 및 점수를 서로 다른 시각 열에 둘 수 있지만
  정보 관계는 모바일과 같아야 합니다.
- 이 선택 채보 리더보드에 국가, 베스트 기록일, Filter, 정렬 컨트롤 또는 무관한
  프로필 필드를 추가하지 않습니다.
- 지속적인 선택 채보 Context가 이미 식별하므로 모든 행에 악곡 제목, 재킷,
  난이도 또는 레벨을 반복하지 않습니다.
- 눈에 보이거나 Program에서 의미를 인식할 수 있는 열 라벨을 제공합니다. 비교할
  숫자는 오른쪽 정렬하고 고정폭 숫자를 사용합니다.
- 현재 사용자 행은 색상에만 의존하지 않고 식별할 수 있어야 하며 이름과 프로필
  Action을 완전히 조작할 수 있어야 합니다.

### 공동 순위 및 동점 계약

- 같은 베스트 스코어에는 같은 표시 순위를 부여합니다.
- 순위를 건너뛰는 경쟁 순위 `1, 2, 2, 4`를 사용합니다.
- 같은 점수 Group 안에서는 먼저 달성한 기록을 앞에 두지만 공동 순위는 바꾸지
  않습니다.
- 달성 시점도 같으면 안정적인 내부 ID를 마지막 결정적 정렬 Key로만 사용합니다.
  해당 ID를 노출하거나 이를 고유 순위로 바꾸지 않습니다.
- 이후 구현에서는 불러온 NOSTALGIA 데이터에서 확인할 수 있는 가장 신뢰할 수 있는
  최고 기록 갱신 시점에 **달성 시점**을 매핑해야 합니다. 계정 생성 시각이나 임의의
  사용자 ID를 조용히 대신 사용하면 안 됩니다.
- 이 계약은 선택 채보 랭킹에 적용합니다. 별도 전역 랭킹 Family와의 일관성은
  여기서 조용히 바꾸지 않고 해당 페이지 기획서에서 검토해야 합니다.

### NOSTALGIA 상위 실력 점수 분포

이 시각화는 전체 모집단의 점수 Grade Histogram이 아니라 의도적인 **S 이상 상위
실력 분포**입니다. 상위 점수 차이는 일관된 `10,000`점 해상도로 살펴볼 가치가
있으므로 다음 동일 폭 Band를 유지합니다.

| Bucket    | 포함 결과                                                              |
| --------- | ---------------------------------------------------------------------- |
| `950k`    | `950,000–959,999`                                                      |
| `960k`    | `960,000–969,999`                                                      |
| `970k`    | `970,000–979,999`                                                      |
| `980k`    | `980,000–989,999`                                                      |
| `990k`    | Pianist 결과를 제외한 `990,000–999,999`                                |
| `Pianist` | 현재 NosLog Domain 조건: 점수가 `1,000,000` 이상이거나 `fc_type === 3` |

- **전체 참여자 100명**과 같이 전체 참여자 수를 독립적으로 보여줍니다.
- **S 이상 점수 분포 · 30명**과 같이 시각화와 자체 분모를 별도로 표시합니다.
- Bucket 수와 시각 비율 합계는 전체 참여자가 아니라 S 이상 분모와 일치해야
  합니다.
- 시각 비율과 함께 실제 수를 보여주고 같은 값을 접근 가능한 구조적 표현으로
  제공합니다.
- 이를 전체 모집단 Histogram으로 만들기 위해 `<950,000` 막대를 추가하지
  않습니다. 해당 플레이어도 별도의 전체 참여자 수에는 포함합니다.
- 집중한 점수 Band를 Pianist, S, A+, A, B+, B, C, D 같은 넓은 점수 Grade
  Category로 대체하지 않습니다. 그런 Group은 이 분석이 보여줘야 할
  `950k–Pianist`의 의미 있는 차이를 뭉갭니다.
- `950k`부터 `990k`까지의 구간 다섯 개와 마지막 Pianist Category를 여섯 개의
  공식 게임 Rank나 커뮤니티가 보편적으로 명명한 여섯 Milestone이 아니라 분석용
  Category로 취급합니다. 문서화된 게임 Rank는 `950,000–999,999` 전체가 S이며,
  커뮤니티 대화는 S, `990,000`, Pianist를 가장 일관되게 큰 목표로 부르고 더
  좁은 성장 Context에서는 `970,000` 또는 `980,000`도 사용합니다.
- 이 분포에서 `950,000–979,999`를 하나로 합치면서 `980k`와 `990k`는
  `10,000`점 Band로 남기지 않습니다. 해당 불균등 구간은 첫 막대가 구조적으로
  더 커질 가능성을 높여 직접 비교를 약화합니다. 차후 누적 Milestone 달성 요약은
  별도 Pattern이며 이 분포를 조용히 대체하면 안 됩니다.
- 정확한 Chart Geometry, 색상 및 간결한 데스크톱 위치는 Foundation과 대표
  Specimen 결정으로 남깁니다. Bucket 의미와 분모 계약은 미루지 않습니다.

사용자는 공식 Rank 정의, 커뮤니티 성장 언어, 공개 플레이어 게시물, 커뮤니티
Course, KAC 결과 분포 및 동일 폭 시각화 지침을 검토한 뒤 2026-08-01에 이 여섯
Category를 재확인했습니다. 현재 NosLog Rating 정책도 추가 로컬 근거를 제공합니다.
해당 정책은 `950,000`에서 시작하고 `1,000,000`까지 `10,000` 단위 Anchor를
사용하며 활성 숙련 곡선은 `990,000`과 Pianist 성과에 가장 큰 비중을 둡니다.
따라서 모든 Band를 공식 또는 보편적으로 명명한 Milestone으로 잘못 표현하지
않으면서 유용한 분석 해상도를 유지합니다.

### Pagination 및 내비게이션

- 모바일과 데스크톱 모두 고정 페이지 크기 **25명**을 사용합니다.
- 페이지당 행 수 Selector를 제공하지 않습니다.
- 전체가 `25`명 이하면 Pagination을 숨기고 스물여섯 번째 결과부터 명시적인
  Pagination을 보여줍니다.
- 현재 페이지를 다국어 URL과 브라우저 History에 보존합니다.
- Infinite Scroll이 아니라 명시적인 Pagination을 사용합니다.
- 사용자가 페이지를 바꾸면 Focus와 Scroll Context를 랭킹 제목 또는 목록
  시작점으로 이동·복원하고 갱신된 결과 범위를 보조 기술에 안내합니다.
- 숫자가 아니거나 음수, 0 또는 범위를 벗어난 페이지는 악곡, 난이도, Locale 및
  랭킹 상태를 보존한 채 첫 번째 유효 페이지로 정규화합니다.
- 페이지 변경이 현재 사용자 Context나 선택 채보 Context를 버리면 안 됩니다.

25명은 반복 비교와 모바일 Scan 길이 사이의 균형이며 운영 Table에서 흔히 쓰는
단위입니다. 현재 일곱 행 페이지는 관찰한 Legacy 동작이며 2.0 제약이 아닙니다.

### Loading, 빈 상태, 오류 및 접근성 상태

- Loading 중에는 절제한 Skeleton으로 리더보드 행 Geometry를 보존하고 갱신
  영역에 `aria-busy`를 표시합니다.
- 요청 실패 시 간결한 오류 하나와 명시적인 재시도 Action을 제공합니다. 오래된
  행을 현재 데이터인 것처럼 조용히 표시하지 않습니다.
- 공개 베스트 스코어가 없으면 **등록된 기록이 없습니다**에 해당하는 간결한 상태
  하나를 보여줍니다. 현재 사용자의 **순위 없음** 메시지를 동시에 중복 표시하지
  않습니다.
- 비로그인 사용자도 로그인 사용자와 같은 공개 빈 상태, Loading 및 오류 동작을
  사용합니다.
- 모바일 표현에서도 Table 또는 동등한 Collection 의미 구조와 Header 연결을
  보존합니다. 반응형 Styling이 행을 라벨 없는 값으로 바꾸면 안 됩니다.
- 인접한 Link 플레이어 이름이 같은 정체성을 전달하면 Avatar를 장식으로
  취급합니다. 의미 있는 점수 Grade 이미지 대체 Text는 Locale에 맞게 제공하며
  현재처럼 모든 Locale에서 한국어 대체 Text를 재사용하지 않습니다.
- 표시 숫자를 지역화하면서 안정적인 숫자 의미, 오른쪽 정렬 및 고정폭 숫자를
  유지합니다.
- 현재 사용자 행, Full Combo, Pianist, Grade, Loading 또는 오류 상태를
  색상만으로 전달하지 않습니다.

## 승인된 서열·평가 계약

### 목적, 라벨 및 읽기 순서

| 의미           | 한국어      | 일본어         | 영어                |
| -------------- | ----------- | -------------- | ------------------- |
| 공개 점수 영역 | `랭킹`      | `ランキング`   | `Ranking`           |
| 서열 및 평가   | `서열·평가` | `難易度・評価` | `Tier & Evaluation` |

서열·평가는 선택 채보에 관한 다섯 가지 질문에 답합니다.

1. 현재 어떤 공개 서열 배치가 적용되는가
2. 각 적용 가능한 서열 범위에서 목표 달성 자격이 있는 플레이어가 이 채보를 어디에
   배치하는가
3. 어떤 연주 경향이 이 패턴을 특징짓는가
4. 자격이 있는 플레이어가 어떻게 서열 투표 또는 채보 평가를 기여하거나 수정하는가
5. 검증된 플레이어가 어떤 실용적인 의견을 공유했는가

모바일에서는 다음 읽기 순서를 사용합니다.

1. 현재 서열 배치 여섯 개와 그 뒤의 통합 이력 Disclosure 하나
2. 목표별 커뮤니티 서열 투표 집계 여섯 개
3. 커뮤니티 패턴 경향 레이더
4. 현재 사용자의 자격 있는 서열 투표 및 채보 평가 Action 또는 Form
5. 커뮤니티 의견

이 영역을 또 다른 점수 랭킹으로 만들거나 채보 정보의 사실 계약을 반복하지
않습니다. 아래 커뮤니티 의견 계약은 최종 시각 디자인을 승인하지 않은 채 목록,
반응, 신고, 관리, 정렬 및 삭제 동작을 정의합니다.

### 여섯 개 서열 배치

- 먼저 Selector를 선택하도록 요구하지 않고 현재 배치 여섯 개를 모두 보여줍니다.
  **Basic S**, **Basic Full Combo**, **Basic Pianist**, **Recital S**,
  **Recital Full Combo**, **Recital Pianist**입니다.
- Basic과 Recital로 묶되 각 배치 값과 S, Full Combo 또는 Pianist 목표의 연관성을
  유지합니다.
- 현재 배치를 주요 사실로 취급합니다. 현재 배치를 이력 Disclosure 뒤에 숨기지
  않습니다.
- 넓은 레이아웃은 비교에 유리할 때 Grid 또는 Table을 사용할 수 있지만 같은 정보
  관계와 모바일 읽기 순서를 보존해야 합니다. 정확한 Geometry는 대표 Specimen에서
  정합니다.

#### 배치 상태 의미와 다국어 문구

성공한 응답에서는 여섯 위치를 항상 유지합니다. 값이 없는 모든 상황을 하나의 일반
빈 상태로 합치지 말고 다음 상태를 구분합니다.

| 상태                                    | 한국어                | 일본어                 | 영어            | 필수 의미                                                     |
| --------------------------------------- | --------------------- | ---------------------- | --------------- | ------------------------------------------------------------- |
| 공개 목록에 선택 채보가 있음            | 숫자 배치 값          | 숫자 배치 값           | 숫자 배치 값    | 현재 공개 배치                                                |
| 해당 목록은 공개됐지만 선택 채보가 없음 | `미등재`              | `未掲載`               | `Not listed`    | 해당 공개 목록에서 이 채보의 현재 배치가 없음                 |
| 해당 목록 자체가 공개되지 않음          | `미공개`              | `未公開`               | `Not published` | 해당 모드·목표의 공개 목록이 현재 없음                        |
| 요청 또는 시스템 실패                   | `불러오지 못했습니다` | `読み込めませんでした` | `Couldn’t load` | 데이터 가용성을 알 수 없음. 영역 단위 재시도 Action 하나 제공 |

- 과거에 배치됐다가 제외된 채보의 현재 위치는 **미등재**로 표시합니다. 이력을
  열었을 때 제외 사건을 설명합니다.
- Loading 중에는 절제한 Placeholder와 갱신 영역 Busy 상태로 여섯 위치의 Geometry와
  라벨을 유지합니다.
- 요청 실패를 **미등재** 또는 **미공개**로 표시하지 않습니다.
- 값이 없는 각 위치에서 교육 문구, 일러스트 또는 Action을 반복하지 않습니다. 이는
  독립적인 페이지 빈 상태 여섯 개가 아니라 비교 Group 안의 간결한 상태 값입니다.

#### 통합 서열 배치 이력 Disclosure

- Basic과 Recital 배치 Group 뒤에 **서열 변경 이력** Disclosure를 정확히 하나
  배치하고 기본 상태는 접힘으로 둡니다.
- 배치별 Disclosure 여섯 개, Mini Chart 여섯 개 또는 영구적인 다중 Series Chart를
  제공하지 않습니다. 사용자의 주요 질문은 현재 여섯 위치이고 보조 질문은 무엇이
  언제 바뀌었는지입니다.
- 이력이 있으면 접힌 행에서 Disclosure 라벨 옆에 최근 적용일을 표시할 수 있습니다.
  날짜는 보조 Text이며 라벨을 대체하지 않습니다.
- 열었을 때 최신 사건 다섯 개를 먼저 표시합니다. 적용일이 같은 사건은 날짜 제목
  하나 아래에 묶고 날짜 Group은 최신순으로 정렬합니다.
- 각 사건은 Basic 또는 Recital 모드, S, Full Combo 또는 Pianist 목표와 정확한
  전환을 표시합니다.
    - 최초 등재: **미등재 → 값**
    - 배치 변경: **이전 값 → 현재 값**
    - 배치 제외: **이전 값 → 등재 제외**
- **이전 변경 더 보기**로 과거 사건을 명시적으로 10개씩 이어 붙입니다. Infinite
  Scroll이나 페이지 크기 Selector를 사용하지 않습니다.
- 선택 채보에 배치 이력 사건이 전혀 없으면 Disclosure 대신 중립적인 **변경 이력
  없음** 한 줄을 표시합니다. 동작하지 않는 펼치기 Control을 Rendering하지 않습니다.
- 모바일과 데스크톱에서 같은 Disclosure 순서와 사건 의미를 사용합니다. 넓은
  Layout은 날짜와 전환 열을 더 효율적으로 정렬할 수 있지만 이력을 서로 무관한 여섯
  Panel로 분리할 수 없습니다.

다음 다국어 Control 및 사건 용어를 사용합니다.

| 의미               | 한국어              | 일본어                   | 영어                     |
| ------------------ | ------------------- | ------------------------ | ------------------------ |
| 이력 Disclosure    | `서열 변경 이력`    | `難易度表の変更履歴`     | `Tier placement history` |
| 최근 변경          | `최근 변경`         | `最終変更`               | `Latest change`          |
| 이력 없음          | `변경 이력 없음`    | `変更履歴なし`           | `No placement history`   |
| 과거 이력 이어보기 | `이전 변경 더 보기` | `以前の変更をさらに表示` | `Show older changes`     |
| 제외 사건          | `등재 제외`         | `掲載除外`               | `Removed from tier`      |

Disclosure Control은 접근 가능한 이름, `aria-expanded` 및 제어 영역 연결을 가진 의미
있는 Button이어야 합니다. `Enter`와 `Space`로 전환할 수 있습니다. 이력을 열거나
추가해도 Focus를 예기치 않게 옮기지 않으며, 이어 붙인 결과에는 간결한 접근성 갱신
안내가 필요합니다.

#### 배치 데이터 계약 및 구현 Mapping

- 선택 채보마다 공개 목록 상태에서 의미 있는 여섯 위치를 Materialize합니다. 제한
  없는 `findFirst` 배치 하나로 공개 결과를 만들지 않습니다.
- 제외 사건을 보존합니다. 현행 `TierPlacementHistory.bandValue = null`은 실제
  **등재 제외** 사건이며 공개 이력 Query에서 Filtering하면 안 됩니다.
- 모드·목표 Stream별로 이전 상태를 독립적으로 복원해 모든 표시 전환의 출발과 도착을
  모호하지 않게 만듭니다.
- 목록 공개 상태, 현재 배치 상태, 이력 사건 및 요청 실패를 서로 구분 가능한 데이터로
  반환합니다. UI가 같은 빈 Array에서 **미공개**, **미등재** 및 오류를 추론하면 안
  됩니다.
- 기록한 이력 없이 Migration된 현재 배치는 유효한 현재 값으로 유지하고 여섯 위치
  아래에는 **변경 이력 없음**을 사용합니다.
- 현행 제품의 최근 공개 배치 하나, 단일 Series 선 Graph, 값이 null인 제외 사건을
  누락하는 공개 Query는 관찰한 Legacy 동작이며 차후 2.0 구현에서 교체해야 합니다.

### 목표별 커뮤니티 서열 투표

#### 범위 및 공개 집계

- 모호한 단일 체감 난이도 평가를 **Basic S**, **Basic Full Combo**,
  **Basic Pianist**, **Recital S**, **Recital Full Combo**, **Recital Pianist**의
  서로 독립된 여섯 투표 범위로 교체합니다.
- 투표는 정확히 하나의 모드·목표에서 선택 채보가 승인된 NosLog 서열 값 척도의
  어디에 속하는지를 표현합니다. 기존 서열 구간 도메인과 연결되도록 `1.0`부터
  `14.5`까지 `0.1` 단위 값을 허용합니다.
- 사용자·선택 채보·모드·목표별 투표 하나를 유지합니다. 사용자는 각 범위를
  독립적으로 수정하거나 삭제할 수 있습니다.
- 읽고 있는 범위의 정확한 유효 투표 수를 항상 표시합니다.
- 유효 투표가 1~2개이면 **집계 중**과 투표 수를 표시하고 대표 결과와 분포는
  공개하지 않습니다.
- 유효 투표가 3개 이상이면 **중앙값**, 전체 값 분포 및 정확한 투표 수를
  공개합니다. 소수의 극단값이 크게 움직일 수 있으므로 산술 평균을 공개 대표값으로
  사용하지 않습니다.
- 기준 3명은 한 사람의 입력을 커뮤니티 결과처럼 제시하지 않기 위한 것이며 통계적
  신뢰도를 주장하는 수치가 아닙니다. 정확한 표본 수를 계속 표시합니다.
- 비로그인 사용자와 자격이 없는 사용자도 모든 공개 집계를 읽을 수 있습니다.
  자격은 기여 여부를 제어하며 공개 가시성을 제어하지 않습니다.
- 커뮤니티 투표는 참고 근거입니다. 중앙값이 현재 배치와 다르더라도 공식 NosLog
  서열 배치를 자동으로 바꾸지 않습니다.

#### 기여 자격

- 생성과 수정 모두 서버에서 자격을 강제합니다. 비활성화하거나 생략한 Client
  Control만으로 권한을 통제하지 않습니다.
- 사용자는 로그인했으며 정확한 선택 채보의 검증된 기록이 있어야 합니다.
- **Basic**은 해당 기록에 기존 목표 조건을 적용합니다.
    - S: 점수 `950,000` 이상
    - Full Combo: `fc_type >= 2` 또는 `1,000,000`점
    - Pianist: `fc_type === 3` 또는 `1,000,000`점
- **Recital**은 같은 목표 조건에 더해 정확한 선택 채보의 `grade_recital > 0`을
  요구합니다. 현재 데이터는 Recital 참가와 최고 목표 결과를 각각 증명하지만 둘이
  같은 플레이에서 발생했는지는 증명하지 못합니다. 이를 검증 가능한 최소 2.0
  규칙으로 사용하고, 이후 모드별 이력이 Recital 달성을 직접 증명할 수 있을 때만
  강화합니다.
- 상위 성과는 명시된 조건을 통해서만 하위 범위 자격을 얻습니다. Pianist는 Full
  Combo와 S 자격을 얻지만, 점수가 `950,000` 미만인 Full Combo는 S 자격을 얻지
  않습니다.
- 한 범위의 자격이 없어도 자격을 충족한 다른 범위에는 투표할 수 있습니다. 자격을
  채보 단위의 하나뿐인 전부 허용/전부 거절 권한으로 바꾸지 않습니다.
- 투표에 NOS, 레이팅, Badge, 진행도 또는 다른 보상을 제공하지 않습니다. 기여는
  자발적이어야 하며 값을 제출하도록 압박하면 안 됩니다.

#### 데이터 분리 및 Migration

- 목표별 투표를 일반 채보 평가와 별도로 저장합니다. 투표가 서로 덮어쓰지 않고 공식
  목록 개정 뒤에도 유지되도록 `(chart_id, user_id, mode, goal)`에 해당하는 안정적인
  Unique 범위를 사용합니다.
- 투표를 Draft 또는 Published `TierList` 행에 연결하지 않습니다. 투표는 채보·모드·
  목표에 관한 것이며 공식 목록 Version은 관리자 소유 결과입니다.
- 기존 `perceived_constant` 데이터는 명시적으로 검토한 정책을 통해서만 Migration
  합니다. 범위가 없는 값 하나를 여섯 목표별 투표로 추론하거나 모든 범위에 복사하면
  안 됩니다.
- 비공개 플레이 증빙을 공개하지 않으면서 자격 검토와 집계 재계산에 충분한 투표 생성,
  수정 및 삭제 감사 사실을 유지합니다.

#### 관리자 검토 신호

- 한 범위에 유효 투표가 최소 5개 있고 현재 숫자 공식 배치가 투표 분포의 가운데
  `50%`, 즉 사분위 범위(IQR) 밖에 있을 때만 지속적인 관리자 검토 후보를 만듭니다.
- 이 기준은 운영상 분류 규칙이지 공식 배치가 틀렸다는 증명이 아닙니다. 비교하려면
  숫자 공식 배치가 필요하며, 미등재 또는 미공개를 불일치로 조용히 분류하지 않습니다.
- 선택 채보·모드·목표를 기준으로 후보를 중복 제거합니다. 이후 투표는 반복 알림이나
  일시적 Toast를 만들지 않고 같은 후보를 갱신합니다.
- 관리자 검토 화면은 현재 공식 배치, 투표 수, 중앙값, 산술 평균, 전체 분포, 모드,
  목표 및 채보 정체성을 제공해야 합니다. 평균은 진단 Context이며 공개 대표값이
  아닙니다.
- **검토 중**, **현재 유지**, **배치 변경**, **나중에 검토**에 해당하는 지속 상태와
  명시적 Action을 지원합니다.
- **배치 변경**은 일반 관리자 서열 배치 흐름을 사용하고 `TierPlacementHistory`를
  보존해야 합니다. 어떤 검토 Action도 그 흐름 밖에서 공개 배치를 직접 변경하지
  않습니다.
- 다수에서 멀다는 이유만으로 이상치 투표를 제거하거나 가중치를 낮추지 않습니다.
  잘못된 입력이 의심되면 명시적인 관리자 감사를 거치며 통계적 불일치 자체는
  부정행위가 아닙니다.
- 정확한 관리자 Page 시각 구성은 이 공개 Page 기획서의 범위 밖이지만 Queue, 중복
  제거, 근거, 상태 및 Action 결과는 필수 하위 기능입니다.

### 커뮤니티 패턴 경향 레이더

- 5축 레이더 프로필 하나를 주요 시각화로 사용합니다. 같은 값을 두 번째 막대
  Chart로 중복하지 않습니다.
- 모든 채보와 Viewport에서 다음 축 순서와 다국어 라벨을 고정합니다.

| 축  | 한국어     | 일본어       | 영어         |
| --- | ---------- | ------------ | ------------ |
| 1   | `계단`     | `階段`       | `Stairs`     |
| 2   | `연타`     | `連打`       | `Repetition` |
| 3   | `폴리리듬` | `ポリリズム` | `Polyrhythm` |
| 4   | `즈레`     | `ズレ`       | `Offset`     |
| 5   | `동시치기` | `同時押し`   | `Chords`     |

- 한국어 설명 문구에는 통용되는 줄임말 `동치`를 함께 안내할 수 있지만 화면의 축
  라벨은 더 명확한 `동시치기`를 사용합니다.
- **동시치기**는 동시 노트 수, 건반 간격, 형태 변화, 반복 동시치기 및
  테누토-동시치기 조합을 포함한 동시 입력 부담을 평가합니다. 모든 동시 노트의 단순
  개수가 아닙니다.
- 개념을 구분합니다. **폴리리듬**은 양손의 서로 다른 리듬 구조, **즈레**는 서로
  가깝게 어긋난 Timing, **동시치기**는 같은 Timing에 요구되는 노트를 뜻합니다.
- 글리산도는 커뮤니티 레이더 축으로 사용하지 않습니다. 글리산도는 채보 노트
  유형으로 유지하고 연주 의미가 있는 개인 판정 분석에도 보존합니다.
- 고정 `0–4` 척도와 고정 축 순서를 사용해 채보와 Locale 사이에서 형태를 비교할
  수 있게 합니다.
- 커뮤니티 평균 하나만 그립니다. 같은 레이더에 현재 사용자 프로필을 겹치지
  않습니다.
- 레이더 가까이에 5축의 정확한 평균과 유효 평가 수를 간결한 구조화 Text로
  제공합니다. 이는 정확성과 접근성을 위한 동등 표현이며 두 번째 경쟁 시각화가
  아닙니다.
- 패턴 축 평가는 각각 선택 사항입니다. **평가하지 않음**은 누락 데이터로 저장하고
  유효한 `0` 값인 **없음**과 구분합니다.
- 공개하려는 각 축에 유효 평가가 최소 3개 있어야 합니다. 어느 축이든 기준 미만이면
  불완전하거나 거짓으로 완성된 Polygon을 그리지 않고 사용 가능한 축별 평가 수와
  함께 집계 중 상태를 보여줍니다.
- 5개 정의를 위해 영구적인 도움말 Button 다섯 개를 두지 않고 하나의 공용
  **패턴 경향 기준** 도움말 진입점을 제공합니다.
- 레이더에는 구조화된 Text 대안이 필요하며 색상에만 의존하면 안 됩니다. 최종
  크기, 타이포, 라벨 충돌 동작 및 대비는 Foundation과 Specimen에서 결정합니다.
  현행 컴포넌트의 작은 Geometry는 관찰 근거일 뿐 2.0 기준이 아닙니다.

### 일반 채보 평가 입력 및 자격

- 목표별 서열 투표와 일반 채보 평가는 별도 기여로 유지하며 Control과 결과도
  분리합니다.
- 로그인했으며 선택 채보의 검증된 플레이 기록이 있는 사용자만 일반 채보 평가를
  제출할 수 있습니다.
- 5개 패턴 축 각각과 작성 의견은 선택 사항입니다. 일반 평가에는 필수 체감 난이도
  필드가 없습니다.
- Form은 명시적인 **평가하지 않음** 상태를 제공해야 하며 생략한 패턴 평가를 `0`
  또는 **없음**으로 미리 채우면 안 됩니다.
- 사용자·선택 채보별 일반 평가 하나를 유지하며 사용자는 모든 목표별 투표와
  독립적으로 이를 수정하거나 삭제할 수 있습니다.
- 비로그인 사용자와 로그인했지만 제출 자격이 없는 사용자도 공개 집계를 읽을 수
  있게 유지합니다.
- 현행 입력 Schema와 Form은 모든 Legacy 패턴 필드와 의견을 필수로 요구합니다.
  2.0 구현에서는 이 계약을 명시적으로 Migration해야 합니다. 현재 폴리리듬
  의미로 사용하는 `chord` 필드와 새 동시 입력 Chords 의미를 분리하고, 글리산도
  연주 데이터를 제거하지 않은 채 커뮤니티 프로필에서 글리산도를 제외하고, 일반
  `perceived_constant` 필수 조건을 제거하며, 선택 패턴 평가를 실제 Nullable 값으로
  만들어야 합니다. 저장 값을 조용히 다른 의미로 재사용하지 않습니다.

### 커뮤니티 의견

#### 정보 계층 및 행 콘텐츠

- 의견은 평가에서 분리된 독립 게시글이 아니라 사용자 한 명이 선택 채보 평가에
  선택적으로 작성한 글로 취급합니다.
- 화면에 보이는 각 의견은 작성자 정체성, 작성 의견, 작성 또는 수정 시점, 도움 됨
  수와 선택 상태 및 Contextual Overflow Action을 제공합니다.
- 작성자의 여섯 목표별 투표 중 하나를 의견 행에 연결하지 않습니다. 목표별 투표는
  해당 범위 집계에 속하고 의견은 목표 중립적인 실용 채보 설명으로 유지합니다.
- 정확한 타이포, 굵기, 색상, Badge 처리, 간격, Surface 및 행 또는 카드 Geometry는
  승인된 Foundation과 대표 모바일·데스크톱 Specimen으로 미룹니다. 이 계약 승인에
  사용한 논의용 Mock-up은 동작 예시일 뿐 시각 Source of Truth가 아닙니다.
- 작성 의견은 행 본문의 주요 읽기 콘텐츠로 간결하고 읽기 쉽게 유지합니다. 공개
  목록에서 전체 수정 이력을 노출하지 않고 해당할 때 수정됨 표시를 제공합니다.
- 각 의견 행에서 5개 패턴 축 값을 반복하지 않습니다. 커뮤니티 레이더가 집계를
  소유하며 개인의 패턴 값은 작성 조언을 훑어보는 데 필수적이지 않습니다.
- 이 계약에 중첩 답글, 작성자 고정 또는 두 번째 토론 계층을 추가하지 않습니다.
  의견은 범용 Forum이 아니라 채보 평가와 실용적인 읽기를 지원합니다.

#### 도움 됨 반응 및 자격

- **도움 됨**에 해당하는 되돌릴 수 있는 긍정 반응 하나를 제공합니다. 수치와 현재
  사용자의 선택 상태를 함께 표시합니다.
- 공개 **도움 안 됨**, 싫어요 또는 부정 수치를 노출하지 않습니다. 반응은 유용한
  채보 조언을 찾는 데 도움을 주며 별도의 정확성 투표나 커뮤니티 제재 수단이
  아닙니다.
- 평가 자격과 동일하게 로그인하고 선택 채보의 검증된 플레이 기록이 있는
  사용자만 반응할 수 있습니다. 공개 독자는 수치를 계속 볼 수 있습니다.
- 의견 작성자는 자신의 의견에 반응할 수 없습니다. 유효하지 않은 제출 뒤에 오류만
  보여주지 말고 비활성화 또는 생략 상태와 접근 가능한 Context로 이를 설명합니다.
- 도움 됨을 전환하는 동안 도움순 목록에서 해당 행을 즉시 이동시키지 않습니다.
  Focus와 읽기 Context가 안정적으로 유지되도록 다음 명시적 새로고침, 정렬 변경
  또는 목록 요청 때 변경 순서를 적용합니다.

#### 정렬 및 명시적 이어보기

- **도움순**과 **최신순** 두 정렬만 제공하며 도움순을 기본값으로 사용합니다.
- 도움순은 도움 됨 수 내림차순으로 정렬하고 화면에서 확인 가능한 결정론적 동점
  규칙으로 작성 또는 수정 최신순을 사용합니다. 최신순은 의견의 현재 공개 시점을
  내림차순으로 정렬합니다.
- 처음 의견 10개를 Rendering합니다. 명시적인 **의견 더 보기** Action은 활성
  정렬의 다음 10개를 이미 읽은 행을 교체하지 않고 이어 붙입니다.
- 더 이상 의견이 없으면 이어보기 Action을 숨기고 도움 됨 전환이나 신고 제출 뒤에도
  이미 불러온 행을 유지합니다.
- 이 보조 목록에 Infinite Scroll, 오래된순, 페이지 크기 Selector 또는 중첩
  Pagination 컨트롤을 사용하지 않습니다.

#### 작성자 수정 및 두 가지 삭제 범위

- 의견 수정은 작성자의 Contextual Overflow Menu에 둡니다. 상위 평가를 보존하고
  수정 성공 뒤 공개 수정됨 표시를 보여줍니다.
- **의견 삭제**는 선택 작성 의견만 제거합니다. 사용자의 선택 패턴 평가와 별도
  목표별 투표는 모두 유지합니다.
- **채보 평가 삭제**는 패턴 축 평가와 작성 의견을 제거하는 별도의 파괴적
  Action이지만 목표별 서열 투표는 제거하지 않습니다.
- 각 목표별 투표는 정확한 모드·목표 범위에서 자체 수정·삭제 Action을 가집니다.
  투표 하나를 삭제해도 일반 채보 평가나 다른 투표는 삭제되지 않습니다.
- 의견이라고 이름 붙인 삭제 Action이 전체 평가를 조용히 제거하게 만들지 않습니다.
- 모든 파괴적 Action에는 결과에 맞는 Confirm이 필요합니다. 의견만, 채보 평가,
  서열 투표 확인은 각각 어떤 데이터가 남고 제거되는지 정확히 밝혀야 하며 서로
  무관한 기여가 삭제된다고 암시하면 안 됩니다.

#### 신고 및 관리

- 모든 행에 영구 Action Button을 추가하지 않고 다른 사용자 의견의 Contextual
  Overflow Menu에 **신고**를 둡니다.
- 신고 Dialog는 관련 없는 내용 또는 스팸, 욕설·괴롭힘 또는 혐오, 민감한 개인정보
  또는 위험한 내용, 기타 중 한 가지 이유를 요구합니다. 검토에 필요하면 기타는
  짧은 설명을 요청할 수 있습니다.
- 신고 성공 뒤 신고자 정체성을 공개하거나 해당 의견이 정책을 위반했다고 즉시
  단정하지 않고 접수 사실을 알립니다.
- 신고 한 건만으로 모든 사용자에게 의견을 자동으로 숨기지 않습니다. 관리자는
  신고를 검토해 **유지**, **작성 의견 숨김**, **평가 전체 제외** 중 하나의 명시적
  결과를 선택합니다.
- **작성 의견 숨김**은 공개 Text를 제거하되 유효한 비Text 평가 값을 유지합니다.
  **평가 전체 제외**는 일반 채보 평가의 모든 값을 공개 집계와 의견 표시에서
  제거하지만 별도의 목표별 투표를 조용히 제거하지 않습니다. 관리 기록과 이유는
  공개 콘텐츠와 별도로 보존합니다.
- 목표별 투표의 유효성은 별도의 관리자 감사 범위입니다. 이상치라는 이유만으로
  제외하지 않으며 제외한 투표에는 감사 이유를 보존해야 합니다.
- Rate Limit, 중복 신고 방지, 감사 보존, 알림 정책, 이의 제기 정책 및 정확한 관리자
  Queue 레이아웃은 구현·운영 결정으로 남습니다. 이 결정이 작성 Text 숨김과 평가
  제외의 승인된 구분을 약화하면 안 됩니다.

#### 접근성 결과

- 각 Overflow Trigger에 작성자별 접근 가능한 이름을 주고 열림 상태를 노출합니다.
  Menu를 열면 키보드 Focus를 Action으로 이동하고 Escape로 닫은 뒤 Trigger에
  Focus를 돌려놓습니다.
- 신고, 수정 및 파괴적 확인은 라벨이 있는 Modal Dialog 의미 구조를 사용하고 열린
  동안 Focus를 포함하며 Escape 또는 명시적인 취소 Action을 지원하고 호출한
  Control로 Focus를 돌려놓습니다.
- 390px Touch 환경에서 도움 됨과 Overflow Control을 충분히 크게 만들거나 간격을
  확보합니다. 반응, 신고, 수정됨, 숨김 또는 파괴적 상태를 색상에만 의존해 전달하지
  않습니다.
- 사용자의 현재 읽기 위치를 교체하지 않고 반응, 수정, 삭제, 신고 및 결과 이어붙임
  성공을 안내합니다.

| 다국어 제목 Variant | 승인된 긴 한국어·영어 제목 Fixture, 긴 일본어 읽기, 번역 표시 켜기·끄기 및 승인 번역 누락                        | KO/JA/EN 계층, 빈 공간 없는 생략, 줄바꿈 및 전체 Programmatic 이름                     |

상태 검증은 다음처럼 범위를 제한한 경계를 포함해야 합니다. 모든 조합을 만들지 않고 각
상태의 의미 차이를 보존하면서 위 정체성 Fixture와 Pairwise로 결합합니다.

- 로그인·비로그인 및 선택 채보 플레이·미플레이
- 랭킹 참여자 `0`, `1`, `25`, `26+`명. 동점과 현재 사용자가 보이는 Page 안팎에 있는
  경우 포함
- 각 Basic/Recital × S/Full Combo/Pianist 투표 범위의 수 `0`, `1–2`, `3–4`,
  `5+`. 자격 있음, 자격 없음, 수정, 삭제 및 서버가 거절한 투표 시도 포함
- `5+` 투표에서 공식 배치가 IQR 안과 밖에 있는 경우, 반복 갱신이 중복 제거된
  관리자 후보 하나를 만드는 경우 및 승인된 각 검토 결과
- 채보 보기와 플레이 영상의 네 자료 조합: 둘 다 없음, 어느 한쪽만 있음, 둘 다 있음
- 최초 Loading, 지연 응답, Fresh Cache, Stale 재검증, 빈 결과, 인증, 자격 또는 권한
  제한, 재시도 가능한 오류 및 확인된 Not Found
- 정확히 승인된 범위에서만 서열 투표·채보 평가·의견 파괴 Action의 확인·취소·성공·
  복구 가능한 실패

### 반응형 및 Browser 검증 대상

- 좁은 너비는 정확히 `320`, `360`, `390`, `430` CSS Pixel에서 검증합니다.
- 전환 및 넓은 레이아웃은 `768`, `1024`, `1280`, `1440` CSS Pixel에서 검증합니다.
- 측정한 콘텐츠 기반 영역 Switcher와 Panel 레이아웃 전환 주변을 연속 Resize합니다.
  탭이 좁은 Combobox를 대체하는 폭은 Device 이름 Breakpoint가 아니라 Specimen
  측정값입니다.
- 핵심 `390x844`와 `1280x900` 경로에는 Chromium 자동화를 유지합니다. 이후 2.0 구현에서
  `320`, `360`, `430`의 Parameterized Overflow·콘텐츠 검사를 추가하고 Chromium,
  WebKit/Safari 동작 및 Firefox의 Release Smoke Coverage를 추가합니다.
- 최신 iOS Safari와 Android Chrome, Desktop Chrome·Safari·Firefox에서 핵심 경로를
  수동 검증합니다. 사용 분석 또는 배포 정책이 요구하면 Edge를 Release Smoke 범위에
  추가합니다.
- Keyboard-only 조작, 보이는 Focus, iOS/Safari VoiceOver, Android/Chrome TalkBack,
  `200%` Text 확대 및 `400%` Page Zoom 또는 이에 해당하는 `320px` Reflow 상태를
  검증합니다.
- Browser Simulation은 반복 가능한 레이아웃 검사에 유용하지만 2.0 Release 전 최신
  실제 Device와 보조 기술 검증을 대신하지 않습니다.

### Page 단위 승인 기준

악곡 상세 Page Family는 다음 조건을 모두 충족할 때만 승인합니다.

1. 악곡 정체성, 선택 난이도, 자료 Action, 영역 Switcher 및 선택 Panel이 승인된 순서를
   보존하고 현행 1.x 시각 Styling에 의존하지 않아도 이해할 수 있습니다.
2. 원문 제목을 주요 계층으로 유지합니다. 필수 긴 값·누락 Fixture에서도 켜진 번역·읽기,
   아티스트 및 채보 Context를 구분할 수 있어야 합니다. 의미 있는 Text가 충돌하거나
   잘리거나 Hover에서만 제공되면 안 됩니다.
3. 난이도와 콘텐츠 영역 상태는 공유 가능하고 History로 복원됩니다. 알고 있는 출처
   의도는 승인된 영역을 열고 인증은 정확한 악곡·난이도·기록 목적지로 돌아옵니다.
4. 채보 보기와 플레이 영상은 안정적인 두 자리 Map을 유지합니다. 사용 가능 여부,
   비활성 의미, 플레이 영상의 현재 탭 이동 및 집중형 뷰어 복귀는 승인 계약을 따릅니다.
5. Loading, Cache, 빈 상태, 인증, 권한, 오류, 재시도 및 Not Found는 가장 작은 의미
   영역에만 영향을 주고 안정적인 정체성을 보존하며 서로 모순되는 과거 대상 콘텐츠를
   노출하지 않습니다.
6. Keyboard 및 보조 기술 사용자는 Page, 선택 난이도, 선택 영역, 갱신, 오류 및 현재
   랭킹 위치를 식별할 수 있습니다. Focus는 승인된 Hard Load, Soft Entry, 내부 전환,
   History 복귀 및 오류 규칙을 따르며 `body`로 유실되지 않습니다.
7. 한국어·일본어·영어 콘텐츠는 올바른 Page·구문 단위 언어 의미, 승인된 다국어 라벨,
   적합한 줄바꿈, 전체 접근 가능 이름을 사용하고 Locale별 고정 Suffix를 남기지 않습니다.
8. 모든 필수 너비에서 Page 단위 가로 Scroll 없이 Reflow합니다. 넓은 레이아웃은 현행
   `390px` Desktop Canvas를 유지하지 않고 각 Panel의 승인된 비교·분석 역할에 따라
   공간을 사용합니다.
9. 대표 상태 Suite는 처리하지 않은 Browser 오류, 깨진 History 복원, 중복 Live 안내,
   숨겨진 주요 Action 또는 접근할 수 없는 파괴 확인 없이 통과합니다.
10. 서열 투표는 정확한 채보·모드·목표 자격을 서버에서 강제하고 공개 집계는 승인된
    기준과 중앙값을 사용합니다. 어떤 투표나 관리자 검토 후보도 일반 관리자 배치
    흐름 없이 공식 배치를 변경하지 않습니다.
11. 정확한 Color, Typography, Spacing, Radius, Elevation 및 최종 Component Geometry는
    이후 승인된 Foundation과 Specimen으로 검증합니다. 이 값의 유보를 이유로 본
    기획서의 콘텐츠·동작·상태·승인 계약을 바꿀 수 없습니다.

| [Smashing Magazine: Disabled-button pitfalls](https://www.smashingmagazine.com/2021/08/frustrating-design-patterns-disabled-buttons/)              | 이유, Focus 동작 또는 복구 경로가 불명확한 비활성 Control은 자주 실패합니다.                                             | 라벨을 알아볼 수 있게 하고 거짓 상호작용 반응을 없애며 추가 상시 빈 상태 문구 없이 접근 가능한 이유를 요구합니다.                    | 규범 표준이나 NOSTALGIA 전용 연구가 아닌 실무자 가이드입니다.                                     |

사용할 수 없는 Action이 영구적으로 무관한지, 권한으로 제한되는지, 사용자가 활성화할
수 없는지에 관해서는 출처가 서로 다른 방향을 제시합니다. 반면 작은 안정적 Action Map이
선택 Context 또는 알려진 미디어 사용 가능 여부에 따라 바뀌는 경우에는 비활성 유지에
더 강하게 수렴합니다. 따라서 NosLog는 선택 채보 Action 두 자리만 유지하고 채보나 영상
자료가 없을 때만 비활성 상태를 사용하며, 이 규칙을 다른 모든 누락 선택 Action에
일반화하지 않습니다. 안정된 라벨 Control 자체가 필요한 시각 상태를 전달하므로 별도의
표시용 사용 가능 여부 문구는 거절했고, 접근 가능한 이유는 Programmatic하게 유지합니다.

레퍼런스는 범위를 제한한 Feedback, 지속되는 안정된 Context, 의미상 정확한 대상
데이터, 서로 다른 부재·실패 의미 및 중단 가능한 Navigation으로 수렴합니다. 시각적
Loader 표시 시점은 짧은 지연 표시부터 약 1초 이상 대기를 위한 Skeleton까지 서로
다릅니다. NosLog는 대상과 Busy 의미를 즉시 갱신하되 300ms 미만 응답에는 Animated
Loader Flash를 피하고, 인지 가능한 지연에만 단순화되고 구조가 일치하는 Skeleton을
보여주는 방식으로 이 차이를 해결합니다. 이전 화면 데이터는 재검증 중 정확한 대상에
속하거나 Pagination 중 같은 Schema에 속할 때만 유지하며 다른 의미 영역이나
난이도에서 가져오지 않습니다.

권위 있는 Disclosure 출처는 주요 사실을 계속 보여주고 보조 Detail을 명시적으로 되돌릴
수 있게 제공하는 방향으로 수렴합니다. 운영 이력 제품은 하나의 Chronological Activity
Surface와 요청형 과거 콘텐츠 Loading으로 수렴합니다. 빈 상태 시스템은 부재와 실패를

제공하지 않습니다. 승인 계약은 어떤 출처의 Surface Design도 복사하지 않고 이러한
전용 가능한 원칙을 결합합니다.

## 거절한 대안

- **B형 — 모든 영역을 담은 하나의 긴 페이지:** 거절했습니다. 네 영역은
  분량이 크고 인증·데이터 상태가 다르며 반드시 순서대로 읽을 내용이
  아닙니다.
- **C형 — 상세 View 전에 영역 간 요약 허브 제공:** 악곡 상세에서는
  거절했습니다. 사용자가 이미 악곡을 선택했고 보통 구체적인 후속 과업이
  있는 페이지에 개요 계층과 정보 밀도를 추가합니다. 또한 여러 초기 요청,
  여러 Domain 조회를 수행하는 하나의 집계 요청 또는 별도로 관리하는 요약
  Cache 중 하나가 필요합니다.
- **현재 UI를 시각 기준으로 사용:** 거절했습니다. 구조를 이어간다는 것이
  현재의 고정 너비 Shell, 타이포, 간격, 카드 밀도 또는 탭 Styling을
  승인한다는 뜻은 아닙니다.
- **좁은 화면에서 영역 탭 가로 Scroll 유지:** Selector와 Scroll 탭 선례를 모두 비교한
  뒤 거절했습니다. NosLog에는 동급 목적지 네 개, 별도 상시 난이도 행 및 승인된
  한국어·일본어·영어 라벨이 있습니다. 현재 영역 Selector는 숨은 목적지를 가로
  Gesture에 의존시키지 않으면서 전체 라벨과 하나의 보이는 계층을 보존합니다.
- **영역 탭 네 개를 두 행 이상으로 줄바꿈:** 거절했습니다. 줄바꿈은 하나의 탭 집합
  Geometry를 약화하고 Locale마다 상대 위치를 바꾸며 모든 선택 Panel 위의 귀한 공간을
  사용합니다.
- **영역 라벨 축약·말줄임·아이콘 대체:** 거절했습니다. 이 선택지는 익숙한 재생
  Control이 아니라 서로 다른 제품 의미이며 승인된 다국어 이름을 직접 이해할 수 있어야
  합니다.
- **상시 데스크톱 왼쪽 Sidebar 추가:** 거절했습니다. 지역 영역 내비게이션을 반복하고
  악곡 Context와 경쟁하며 간결한 채보 정보에서도 너비를 소비합니다. 추가 공간은 승인된
  Panel별 넓은 화면 구성에 사용합니다.

## Page 기획서 승인 뒤 미룬 측정값

이 악곡 상세 Page 기획서에는 제품·콘텐츠·동작·상태·다국어·접근성 또는 Page 단위 승인
결정이 미확정으로 남아 있지 않습니다. 정확한 Selector-탭 전환 너비, 바깥 최대 콘텐츠
너비, 시각 Token 및 Component Geometry는 미확정 구조가 아니라 의도적으로 미룬
측정값입니다. Downstream 고해상도 디자인 전에 Foundation 타이포·Grid Specimen에서
이를 측정·검증·기록해야 합니다.

동일 폭 상위 점수 Band 다섯 개와 마지막 Pianist Category는 폭넓은
Domain·커뮤니티·대회·시각화 근거를 검토한 뒤 명시적으로 재확인했으며, 여섯 공식
또는 보편적으로 명명된 Milestone이 아니라 분석용 Category입니다.

서열·평가에는 이제 승인된 다국어 라벨, 모바일 정보 계층, Basic/Recital 배치 여섯
개, 이에 대응하는 목표 달성 기반 커뮤니티 투표 범위 여섯 개 및 단일 Series
커뮤니티 레이더가 있습니다. 한 범위는 1~2표에서 집계 중으로 유지하고 3표부터
중앙값, 전체 분포와 정확한 수를 공개합니다. Basic 자격은 정확한 S, Full Combo,
Pianist 달성 조건을 사용하고 Recital은 선택 채보의 확인된 Recital 참가도 요구합니다.
투표는 목표 중립 일반 채보 평가 하나와 별도로 저장합니다. 레이더의 고정 축은 계단,
연타, 폴리리듬, 즈레, 동시치기입니다. 글리산도는 노트 유형과 개인 판정 지표로
유지하지만 커뮤니티 레이더 축으로 사용하지 않습니다. 일반 패턴 축과 작성 의견은
선택 사항이며 누락 값을 유효한 0점 평가와 구분해야 합니다.

커뮤니티 투표는 자동 실행되는 거버넌스가 아닌 참고 근거입니다. 유효 투표가 5개
이상일 때 공식 배치가 투표 IQR 밖이면 정확한 채보·모드·목표의 지속적이고 중복
제거된 관리자 검토 후보 하나를 만듭니다. 후보는 투표 수, 중앙값, 평균 및 전체 분포를
제공하며 명시적인 관리자 배치 Action만 공식 목록과 이력을 바꿀 수 있습니다.
이상치는 자동으로 제거하지 않습니다.

여섯 서열 위치에는 숫자 배치, 미등재, 미공개, Loading 및 실패에 관한 승인된 현재
상태 의미와 다국어 문구도 있습니다. 접힌 서열 변경 이력 Disclosure 하나가 두 배치
Group 뒤에 오며 최신 날짜 Group 전환 다섯 개로 열리고 과거 사건을 10개씩 이어
붙입니다. 제외된 현재 위치는 미등재로 유지하고 이력에서는 등재 제외로 표시합니다.
공개 데이터 계약은 값이 null인 제외 사건을 보존하고 최근 배치 하나가 아니라 명시적인
모드·목표 Slot 여섯 개를 제공해야 합니다.

커뮤니티 의견에는 이제 승인된 정보·상호작용 계약이 있습니다. 목표 중립인 각 행은
간결한 작성자·시점 Context와 도움 됨 신호 하나를 제공하고 목표별 서열 투표를 반복하지
않습니다. 정렬은 도움순과 최신순만 사용하며 처음 10개 뒤에 명시적으로 10개씩 이어
붙입니다. 의견만, 일반 평가 및 범위별 서열 투표 삭제는 서로 독립적입니다. 신고와
관리자의 유지·Text 숨김·일반 평가 제외 결과는 명시적이며 서열 투표를 조용히 제거하지
않습니다. 승인용 Mock-up은 시각 디자인 Source가 아니며 정확한 강조 방식은
Foundation과 대표 Specimen 단계로 미룹니다.

이제 Page에는 승인된 하나의 비동기 상태 및 복구 계약도 있습니다. 대상 난이도나 영역은
URL로 표현한 명시적 Context가 즉시 되며 안정된 악곡 Context는 계속 사용할 수 있고 대상
Panel만 Busy가 됩니다. Fresh한 정확한 대상은 즉시 나타나고 채보 정보는 Page Session
동안 Fresh하며 기록·랭킹·서열/평가는 60초 Freshness와 Non-blocking 재검증을
사용합니다. 데이터 변경 Action은 영향받는 대상을 즉시 무효화합니다. 빈 상태, 인증,
자격, 권한, Stale 갱신 실패, Cache 없는 실패 및 Not Found는 서로 다른 의미를
유지합니다. Network 및 `5xx` GET 실패는 정확한 수동 다시 시도 전에 한 번 자동
재시도합니다. Navigation은 중단 가능하며 Focus는 활성화 Control에 남고 Page 단위
`polite` 상태 영역 하나가 중간 Skeleton 변경을 모두 노출하지 않은 채 일관되고 대상이
분명한 진행 상황을 안내합니다.

반응형 구성도 이제 제품 Pattern 수준에서 승인했습니다. 난이도는 별도로 보이는 네 선택지
행으로 유지합니다. 좁은 너비에서는 전체 너비의 입력 없는 단일 선택 영역 Combobox와
Anchored Listbox를 사용하고, 넓은 너비에서는 가장 긴 다국어 조합이 맞을 때만 전체
Auto-width 수동 활성화 탭을 사용합니다. Page는 상시 390px 데스크톱 제한을 제거하고
악곡·채보 Context를 위에 유지하며 상시 왼쪽 Sidebar를 거절하고 모바일 읽기 순서를
보존한 채 선택 Panel별 넓은 화면 구성을 사용합니다. 측정된 전환 너비, 최대 콘텐츠
너비, 타이포, 간격 및 시각 Surface 값은 계속 Foundation Specimen이 소유합니다.

선택 채보 Action 계약도 승인했습니다. **채보 보기**와 **플레이 영상**은 선택 난이도
바로 뒤이자 콘텐츠 영역 전환보다 앞의 안정적인 두 자리를 사용하고, 콘텐츠 영역을
바꿔도 유지하며 대응 자료가 없으면 명확하게 비활성화합니다. 별도의 **공개 채보 없음**
문구와 외부 채보 Action은 사용하지 않습니다. 플레이 영상은 승인된 다국어 라벨을
사용하고 새 탭을 강제하지 않은 채 현재 Browsing Context에서 이동합니다.

이로써 진입, 인증 복원, 채보 정보, 개인 기록, 랭킹 및 커뮤니티 의견을 포함한
서열·평가 콘텐츠 계약, 공통 비동기 상태 및 반응형 영역 전환 구성이 정해졌습니다. 또한
Hard·Soft Route Focus, 출발점 복원, 실제 Catalog와 범위를 제한한 상태 Fixture Matrix,
정확한 좁은·전환·넓은 검증 너비, Release Browser·보조 기술 범위 및 Page 단위 승인
기준 열한 개를 확정했습니다.

따라서 악곡 상세 Page 기획서는 2026-08-02 기준으로 완성·승인했습니다. 이 승인은 현행
Page의 시각 디자인을 채택하거나 Foundation 값과 최종 Claude Design 구성을 미리
승인하지 않습니다. Foundation 및 대표 Specimen 단계에서는 이 승인된 제품 계약을
바꾸지 않고 의도적으로 미룬 시각 값을 측정해야 합니다.
