## 결정 라벨

- **관찰:** 현재 저장소, 브라우저 또는 승인된 상위 산출물에서 확인했습니다.
- **승인:** 사용자가 명시적으로 동의했으며 후속 디자인의 기준입니다.
- **제안:** 근거를 갖춰 제시했으나 사용자의 명시 승인을 기다립니다.
- **미확정:** 추가 조사, 대표 데이터, 테스트 또는 사용자 결정이 필요합니다.
- **거절:** 검토했지만 명시적으로 선택하지 않았습니다.
- **대체:** 이후 승인된 방향으로 교체했습니다.

이 기획서는 아직 승인 완료된 단계 산출물이 아닙니다. `승인` 또는 `거절`로
표시한 결정만 기준으로 사용합니다.

## 목적

악곡 상세는 하나의 악곡과 선택한 난이도 Context를 유지하면서 사용자가 다음
영역을 효율적으로 오갈 수 있게 해야 합니다.

1. 자신의 성과와 기록 이력
2. 객관적인 채보 정보와 통계
3. 선택 채보의 랭킹
4. 서열 배치, 커뮤니티 평가 및 투표
5. 공개 채보가 있을 때 집중형 채보 뷰어

이 페이지는 자주 다시 방문하는 제품 작업 공간입니다. 순서대로 읽는 편집
문서나 여러 제품 영역을 훑는 대시보드가 아닙니다.

## 주요 Context

- **상위 승인:** 이 Surface는 공개이며, 로그인 이후 개인화 정보를
  추가합니다.
- **상위 승인:** 오락실 주변에서 사용하는 모바일이 주요 Context입니다.
  데스크톱도 필수이며 추가 너비를 의도적으로 사용해야 합니다.
- **상위 승인:** 악곡 탐색에서 악곡 상세를 엽니다. 서열, 빙고, 검정, 프로필
  및 랭킹 Context도 관련 악곡과 난이도로 Deep Link할 수 있습니다.
- **상위 승인:** 집중형 채보 뷰어는 악곡 상세의 하위 목적지이며 신뢰할 수
  있는 복귀 경로를 제공해야 합니다.
- **승인:** 악곡을 안정적인 Entity Context로 사용합니다. 선택 난이도는 활성
  채보 Context입니다.
- **승인:** 현재 시각 Styling, 고정 너비 구성, 타이포, 간격, 탭 형태 및 카드
  표현은 마이그레이션 근거일 뿐입니다. NosLog 2.0 시각 기준이 아닙니다.

## 현행 제품 근거

### 관찰한 Route와 상태

- 현재 Route는
  `/[locale]/music/[index]/[difficulty]`입니다.
- `Normal`, `Hard`, `Expert` 및 선택적 `Real`은 하나의 악곡에 속한 채보 단위
  선택입니다.
- 선택 콘텐츠 영역은 `tab` Query 값으로 표현합니다. 랭킹 페이지 이동은
  `page` Query 값을 사용합니다.
- 난이도, 선택 콘텐츠 영역 및 랭킹 페이지는 브라우저 History에 참여하며
  뒤로가기와 앞으로가기로 복구할 수 있습니다.
- 현행 구현은 `tab` Query가 없으면 로그인·비로그인 사용자 모두 기록을 엽니다.
  정보를 선택하면 `?tab=detail`을 기록하며 브라우저 뒤로가기는 이전의 Query 없는
  기록 진입을 복원합니다.
- 현행 비로그인 기록 구현은 조작한 기록 분석을 Rendering한 채 어둡게 한 로그인
  Overlay를 겹칩니다. 로그인 Link는 선택 악곡, 난이도 또는 기록 목적지를
  전달하지 않습니다.
- Discord OAuth 시작 및 완료 Route는 이미 안전한 상대 `returnTo` Path를 검증,
  저장 및 복원합니다. 현행 로그인 페이지가 항상 다국어 홈을 전달하므로 정확한
  과업 복원이 전체 흐름에 연결되지 않았습니다.
- 현재 페이지는 데스크톱에서도 최대 `390px` Shell 안에서 Rendering됩니다.
  이는 관찰한 사용성 한계이며 승인된 2.0 규칙이 아닙니다.

### 관찰한 정보 목록

현재 구현은 다음 정보를 제공합니다.

- 악곡 정체성: 재킷, 원문 제목, 선택적 번역 제목 또는 일본어 읽기, 아티스트,
  Category 및 안정적인 악곡 Index
- 선택 채보 정체성: 난이도, 공식 레벨 및 선택적 레벨 상수
- 채보 정보: BPM 범위, 노트 수, 길이, 출시일, 해금 조건, 영상 또는 미리보기
  Link, 패턴 통계, 점수 분포, 플레이어 수 및 가능한 경우 현재 사용자의 상위
  비율
- 개인 기록: 점수, Rank, Full Combo 상태, 플레이 횟수, 판정 상세,
  FAST/SLOW, 노트 종류별 성공률, 점수·성과 추이, 최근 플레이 및 유사 사용자
  비교
- 랭킹: 채보 단위 행, 가능한 경우 현재 사용자 순위 및 명시적인 Pagination
- 서열 및 평가: 현재 서열 상수, 이력, 커뮤니티 분포, 개인 평가, 의견 및 반응
- 공개 채보 사용 가능 여부와 집중형 채보 뷰어 Route

이 목록은 검증된 제품 기능을 보존합니다. 현재 정보 밀도, 순서, 라벨 또는
표현을 승인하는 것은 아닙니다.

### 관찰한 데이터 Loading 경계

- 공통 악곡 및 선택 채보 데이터는 모든 콘텐츠 영역에서 불러옵니다.
- 로그인한 사용자의 개인 최고 기록을 불러옵니다.
- 상세 기록 이력과 추이는 현재 기록 영역에서만 불러옵니다.
- 채보 집계 통계는 현재 정보 영역에서만 불러옵니다.
- 랭킹 행은 현재 랭킹 영역에서만 불러옵니다.
- 서열, 평가, 의견 및 반응 데이터는 현재 서열 영역에서만 불러옵니다.
- 브라우저는 현재 페이지 Session에서 방문한 악곡, 난이도, 콘텐츠 영역 및
  랭킹 페이지 조합을 Cache합니다.

이 수요 기반 Loading 경계는 현행 구현 근거입니다. 사용자가 영역을 선택하기
전에 모든 영역 Query를 부담하지 않기 때문에 승인된 탭 구조와 운영
측면에서도 잘 맞습니다.

### 관찰한 랭킹 구현

- 현재 선택 채보 랭킹은 사용자별 베스트 스코어 행 하나를 불러오며 프로필 Link,
  Avatar, 점수 Rank, 점수 및 Full Combo 또는 Pianist 상태를 제공합니다.
- 한 페이지에 일곱 행을 사용하고 페이지 Offset에서 표시 행 번호를 계산합니다.
  같은 점수에 같은 표시 순위를 부여하지는 않습니다.
- 현재 서버 정렬은 점수 내림차순과 사용자 ID 오름차순을 사용합니다. 별도 내 순위
  역시 동점 Group 안에서 사용자 ID로 고유한 서수 위치를 강제합니다.
- 현재 사용자 전체 카드가 같은 사용자의 행이 현재 페이지에 있어도 목록 위에
  나타나며 계산한 상위 비율을 보고합니다.
- 현재 점수 분포는 양수 점수인 모든 플레이어를 전체 플레이어 수에 포함하지만
  `950k`, `960k`, `970k`, `980k`, `990k`, `Pianist` Bucket만 그립니다.
  따라서 `950,000` 미만 기록이 라벨 있는 Bucket에는 나타나지 않으면서 분모에는
  영향을 줍니다.
- 현재 점수 Rank 이미지의 대체 Text는 모든 Locale에서 한국어 `랭크` 라벨을
  고정으로 덧붙입니다.

이는 구현 관찰이며 승인된 2.0 랭킹 규칙이 아닙니다. 아래 승인 계약에서 현재
사용자 표현 중복, 순위 의미, 분포 분모, 페이지 크기 및 다국어 접근성 누락을
해결합니다.

## 승인된 Entity 및 Action 모델

### 악곡 정체성과 선택 채보

- 난이도가 바뀌어도 악곡 단위 정체성을 안정적으로 유지합니다.
- 선택 난이도를 레벨, 상수, BPM, 노트 수, 개인 기록, 랭킹, 서열·평가 및
  채보 뷰어 사용 가능 여부를 결정하는 채보 단위 Context로 취급합니다.
- 선택 난이도를 공유 가능하고 History에서 복구 가능한 URL에 유지합니다.
- 네 가지 채보 난이도가 있다는 이유로 한 악곡을 관계없는 네 개 상세
  페이지처럼 복제하지 않습니다.
- 정확한 난이도 컨트롤 Geometry, 위치 및 시각 표현은 이후 반응형 Specimen
  작업까지 미확정으로 둡니다.

### 공개 채보 뷰어 진입

- **채보 보기**를 선택 채보와 연결된 직접 Context Action으로 두고 정보
  콘텐츠 Panel 밖에 배치합니다.
- NosLog 공개 채보가 있으면 선택 난이도의 집중형 채보 뷰어를 엽니다.
- NosLog 채보는 없지만 승인된 외부 채보 자료가 있으면 NosLog 뷰어인 것처럼
  표현하지 않고 보조 외부 Action으로 제공합니다.
- 둘 다 없으면 **공개 채보 없음**에 해당하는 간결한 사용 가능 여부 Text를
  보여줍니다. 사용할 수 없는 주요 Button 자리를 상시 확보하지 않습니다.
- 정확한 위치, 아이콘, 한국어·일본어·영어 문구 및 반응형 처리는
  미확정입니다.

## 승인된 콘텐츠 구조

### A형: 하나의 지속 Context와 탭 콘텐츠

- 하나의 지속적인 악곡 정체성과 선택 난이도 Context를 유지합니다.
- 그 아래에서 개인 기록, 채보 정보, 랭킹 및 서열·커뮤니티 평가의 네 가지
  의미 영역을 탭 구조로 제공합니다.
- 선택한 콘텐츠 Panel만 표시합니다. 네 영역의 전체 내용을 하나의 긴 읽기
  페이지로 모두 Rendering하지 않습니다.
- 사용자가 상세 영역에 들어가기 전에 네 영역의 축약 요약을 반복해서
  보여주는 영역 간 개요 Panel을 추가하지 않습니다.
- 선택 난이도와 선택 콘텐츠 영역을 복구 가능한 내비게이션 상태에
  유지합니다.
- 콘텐츠 영역을 바꾸면 최초 진입에서 모든 영역 상세를 요구하지 않고 선택한
  영역의 상세 데이터를 요청해야 합니다.
- 이미 불러왔고 유효한 영역 데이터는 재사용합니다. 정확한 Cache 수명,
  의도 기반 Prefetch 및 무효화는 구현 단계 결정으로 남깁니다.
- 채보 정보와 내 기록의 다국어 라벨은 아래에서 승인했습니다. 랭킹과 서열·평가
  문구, 탭 Geometry 및 반응형 Overflow 동작은 미확정입니다. 이번 승인은 현재
  탭 디자인이 아니라 구조에 해당합니다.

### A형이 적합한 이유

승인한 선택은 다음 세 가지로 수렴한 결과를 따릅니다.

1. 하나의 Object에 서로 관련 있지만 구분되는 View가 있고 사용자가 모든
   Panel을 동시에 비교할 필요가 없으면 탭이 표준적인 Pattern입니다.
2. 리듬게임 상세 Surface는 일반적으로 악곡 또는 Map 정체성과 선택 난이도를
   유지하면서 통계, 리더보드 또는 토론 Context를 바꿉니다.
3. 현행 NosLog 데이터 계층은 이미 활성 콘텐츠 영역에 따라 비용이 큰 기록,
   랭킹 및 평가 조회를 분리합니다.

따라서 A형은 익숙한 상호작용 모델이면서 NosLog의 초기 데이터 작업량도 낮출
수 있습니다. A형 승인은 현재의 답답한 시각 구현을 보존하지 않습니다.

## 승인된 진입 우선순위 및 복원 계약

### 일반 진입 기본값

- 악곡 상세 URL이 콘텐츠 영역을 명시하지 않으면 로그인·비로그인 사용자 모두
  **정보** 의미 영역을 엽니다.
- 정보 의미 영역을 콘텐츠 영역 순서의 첫 번째에 둡니다. 승인된 의미 순서는
  정보, 개인 기록, 랭킹, 서열·커뮤니티 평가입니다.
- 이번 승인은 의미 순서를 정합니다. 채보 정보와 내 기록의 다국어 라벨은
  아래에서 승인했으며 랭킹과 서열·평가 문구는 미확정입니다.
- 같은 Query 없는 URL이 사용자 인증 여부만으로 서로 다른 기본 영역을 열게
  하지 않습니다.

정보는 공개되고 안정적이며 모든 방문자에게 유용하므로 일반 진입 기본값으로
사용합니다. 개인 기록도 반복 사용자의 핵심 과업이지만, 사용자 의도를 이미
아는 진입 출처가 숨겨진 인증별 기본값에 의존하지 않고 직접 열어야 합니다.

### 출처를 아는 명시적 진입

진입 출처가 사용자 과업을 이미 식별하면 명시적이고 복원 가능한 콘텐츠 영역
상태를 사용합니다.

| 진입 출처 또는 의도                               | 필수 목적지 동작                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------- |
| 일반 탐색, 악곡 검색 또는 명시 영역 없는 공유 URL | Query 없는 표준 진입 또는 동등한 명시적 정보 상태를 통해 정보 열기        |
| 프로필, 최근 플레이 또는 개인 기록                | 선택 악곡·난이도에서 개인 기록 영역을 명시적으로 선택해 열기              |
| 랭킹 항목                                         | 선택 악곡·난이도에서 랭킹을 명시적으로 선택해 열기                        |
| 서열, 평가 또는 투표 항목                         | 선택 악곡·난이도에서 서열·커뮤니티 평가를 명시적으로 선택해 열기          |
| 집중형 채보 뷰어에서 복귀                         | 진입 출처 상태가 있으면 원래 악곡 상세 URL과 콘텐츠 영역을 정확히 복원    |
| 출처 상태 없이 뷰어에 직접 진입                   | 개인 또는 과거 사용 기본값을 추측하지 않고 선택 채보의 정보 영역으로 복귀 |

- 목적지 URL은 Locale, 악곡 Index, 선택 난이도, 선택 콘텐츠 영역 및 복귀할 때
  유효한 승인된 영역별 상태를 보존해야 합니다.
- 뒤로가기와 앞으로가기는 현재 인증 상태에서 영역을 다시 계산하지 않고 명시적
  영역을 복원해야 합니다.
- 서로 무관한 악곡이나 Session 사이에 마지막으로 사용한 악곡 상세 영역을 전역
  기억하지 않습니다. 출처가 아는 명시적 의도를 숨겨진 선호 상태보다 우선합니다.

### 비로그인 개인 기록

- 비로그인 사용자에게도 개인 기록 영역을 보이고 선택할 수 있게 합니다. 숨기거나
  비활성 탭으로 표현하지 않습니다.
- 비로그인 상태에서 기록을 선택하면 기록 콘텐츠 대신 간결한 Panel 단위 인증
  상태를 Rendering합니다. 조작한 빈 기록, 흐려진 기록 또는 어둡게 한 기록 분석을
  Overlay 뒤에 Rendering하지 않습니다.
- 인증 상태에는 간결한 설명 하나와 명시적 로그인 Action 하나를 둡니다. 기록
  탭을 선택하거나 Focus하는 것만으로 인증을 시작하면 안 됩니다.
- 로그인 Action은 Locale, 악곡 Index, 난이도 및 명시적으로 선택한 기록 영역을
  포함하는 완전하고 안전한 복귀 목적지를 전달해야 합니다.
- 인증 성공 뒤 정확한 기록 영역으로 돌아옵니다. Onboarding이 필요하면 같은
  목적지를 Onboarding 완료까지 보존하고 필수 흐름이 끝나면 복원합니다.
- 인증 오류가 나도 재시도하거나 같은 악곡 상세로 돌아갈 수 있도록 충분한
  목적지 상태를 보존합니다. 정확한 오류 문구와 표현은 이후 상태 계약에서
  정합니다.

현행 OAuth 흐름은 상대 `returnTo` Path를 저장·검증하고 인증 뒤 해당 경로로
Redirect할 수 있습니다. 현재 로그인 페이지 인계가 항상 다국어 홈을 전달하므로,
이는 새로운 인증 구조가 필요한 문제가 아니라 구현 매핑의 누락입니다.

### 접근성 및 예측 가능성 결과

- 선택 영역은 URL 및 History 상태에 표현하고 이후 구현에서는 올바른 `tablist`,
  `tab`, `tabpanel` 의미 구조를 제공해야 합니다.
- 영역 활성화는 명시적 사용자 Action으로 유지합니다. 탭 Focus가 인증이나 다른
  예상하지 못한 Context 변경을 일으키면 안 됩니다.
- 비로그인 기록 Panel은 선택한 Panel 안에서 사용할 수 없는 개인 콘텐츠와 로그인
  Action을 설명하므로 오해를 부르는 비활성 상태 없이 기능을 발견할 수 있습니다.
- 정확한 Focus 배치, 실시간 안내, Loading 동작 및 모바일 Overflow는 미확정이며
  이후 승인된 상호작용 계약이 필요합니다.

## 승인된 채보 정보 및 개인 기록 계약

### 첫 두 영역의 최종 라벨

| 의미 영역 | 한국어      | 일본어       | 영어         |
| --------- | ----------- | ------------ | ------------ |
| 채보 사실 | `채보 정보` | `譜面情報`   | `Chart Info` |
| 개인 기록 | `내 기록`   | `プレー記録` | `My Record`  |

- 활성 난이도가 이 영역의 사실을 결정하므로 **악곡 정보**가 아니라 **채보 정보**를
  사용합니다.
- **내 기록**은 명확하게 개인적이고 채보 단위인 영역으로 유지합니다. 이 영역의
  존재가 인증 상태에 따른 기본 진입 규칙을 만들지는 않습니다.
- 랭킹과 서열·평가의 최종 라벨은 해당 영역 계약을 승인할 때까지 미확정입니다.

### 채보 정보 범위

채보 정보는 선택한 채보의 간결한 객관적 요약입니다. 개인 기록, 랭킹 또는
서열·평가를 미리 보여주는 개요 Hub가 아닙니다.

- BPM, 노트 수 및 곡 길이는 항상 표시합니다.
- 수록일과 언락 조건은 의미 있는 값이 있을 때만 표시합니다. 사용할 수 없는
  선택 항목을 값이 `-`인 행으로 남기지 않습니다.
- 지속 악곡 및 선택 채보 Context에서 이미 제공하는 난이도, 공식 레벨, 레벨
  상수, Category, 제목 또는 아티스트를 반복하지 않습니다.
- 패턴 경향 데이터와 투표 수는 서열·커뮤니티 평가로 옮깁니다.
- 점수 분포, 플레이어 수 및 현재 사용자의 상대 순위나 상위 비율은 랭킹으로
  옮깁니다.
- 소유 영역으로 연결하기 위해 채보 정보에 축약 패턴 또는 점수 분포 미리보기를
  남기지 않습니다.

이 경계는 Domain마다 하나의 의미 출처를 유지하며 공개 기본 영역 안에 거절한
영역 간 개요 Pattern을 다시 만들지 않습니다.

### 선택 채보 자료 Action

- **채보 보기**, **플레이 영상** 및 승인된 외부 채보 자료는 채보 정보의 사실
  행이 아니라 선택 채보 Action으로 취급합니다.
- 선택 난이도와 연결된 Context Action Group으로 채보 정보 Panel 밖에 둡니다.
- 유효한 자료가 있는 Action만 보여줍니다. 내부 및 승인된 외부 채보가 모두 없을
  때는 이미 승인한 간결한 **공개 채보 없음** 상태를 사용합니다.
- 정확한 Action 순서, 위치, 다국어 문구 및 반응형 처리는 대표 레이아웃
  Specimen 작업까지 미확정입니다.

### 개인 기록 우선순위

다음 의미 순서를 사용합니다.

1. **베스트 기록:** 베스트 스코어, Rank, Full Combo 또는 Pianist 달성 상태,
   최고 기록일 및 필요한 경우 Pianist까지의 진행도
2. **누적 요약:** 플레이 횟수, 최대 콤보, Full Combo 횟수 및 Pianist 횟수
3. **성장 추이:** 최고점 갱신 기록만 보여주는 베스트 스코어 Series
4. **최근 플레이:** 간결한 행 요약과 선택적 플레이별 상세를 제공하는 최근 채보
   플레이
5. **판정 분석:** 판정별 수와 비율, 노트 종류별 성공률 및 최근 판정·Timing
   추이. 기본 상태는 접힘

누적 요약은 빠른 확인을 지원하지만 베스트 기록과 시각적으로 경쟁하면 안 됩니다.
정확한 Geometry는 대표 모바일·데스크톱 Specimen 작업으로 미룹니다.

### 승인된 기록 용어와 데이터 의미

| 의미                         | 한국어          | 일본어         | 영어                 |
| ---------------------------- | --------------- | -------------- | -------------------- |
| 성장 Section                 | `성장 추이`     | `上達の推移`   | `Progress over time` |
| 현재 성장 Series 지표        | `베스트 스코어` | `ベストスコア` | `Best score`         |
| 사용자·채보 단위 플레이 횟수 | `플레이 횟수`   | `演奏回数`     | `Play count`         |

- **성장 추이**는 Section 라벨입니다. 현재 Series에는 최고점 갱신 기록만 있으므로
  모든 성과 지표를 그린다고 오해하지 않도록 화면의 Series 라벨과 접근 가능한 Chart
  제목에서 **베스트 스코어**를 명시해야 합니다.
- 플레이 횟수는 이 사용자가 선택 채보를 몇 번 연주했는지 보여주는 의미 있는 누적
  값입니다. 클리어 횟수와 구분해 유지합니다.
- 클리어 횟수를 악곡 상세의 성과 지표로 노출하지 않습니다. NOSTALGIA 클리어
  상태는 이 제품 목적에서 사용자의 선택 채보 결과를 의미 있게 구분하지 않습니다.
- 프로필 단위 전체 플레이 횟수, 공개 범위 및 표현은 프로필 페이지 기획서의
  결정으로 미루며 이번 채보 단위 계약에서 정하지 않습니다.

### 분석 및 시각화 규칙

- 유사 사용자 비교는 선택 사항이며 기본으로 끕니다. 켰을 때 표본 기준을
  제공하고 약하거나 사용할 수 없는 표본을 권위 있는 값처럼 표현하지 않습니다.
- 판정 분석은 보조 진단 콘텐츠이므로 기본으로 접습니다. 베스트 기록과 누적
  요약은 이를 펼쳐야 확인할 수 있는 구조가 되면 안 됩니다.
- 같은 패턴 경향 값을 레이더와 막대 Chart로 동시에 표현하지 않습니다. 이후
  서열·평가 기획서는 주요 표현 하나를 선택하고 정확한 값, 투표 수 및 접근성
  대안을 제공해야 합니다.
- Chart마다 질문과 지표 계약을 하나로 명확히 합니다. 정확한 값 또는 구조화한
  Text 대안을 제공하고 Series나 상태를 색상만으로 전달하지 않습니다.

## 승인된 랭킹 계약

### 목적과 정보 계층

랭킹은 선택 채보에 관한 두 질문, **현재 사용자는 어디에 있는가?**와 **공개
베스트 스코어를 어떻게 비교하는가?**에 답합니다. 두 번째 개인 기록
대시보드가 아니며 지속 Context에 보이는 악곡이나 난이도 사실을 반복하지
않습니다.

모바일에서는 다음 읽기 순서를 사용합니다.

1. 조건부 현재 사용자 위치
2. **랭킹 · 참여자 N명**에 해당하는 제목
3. 공개 리더보드
4. 필요할 때 명시적인 Pagination
5. 보조 상위 실력 점수 분포

데스크톱에서도 현재 사용자 Context를 랭킹 콘텐츠 위에 유지합니다. 그 아래에서는
리더보드를 주요 영역으로 만들고 공간과 대표 콘텐츠가 허용하면 점수 분포를 인접한
보조 영역에 둘 수 있습니다. 데스크톱에서 두 영역을 나란히 놓더라도 모바일 DOM과
읽기 순서를 보존합니다. 넓은 Viewport에서 현재 `390px` 고정 Canvas를 유지하지
않습니다.

### 조건부 현재 사용자 위치

- 로그인한 사용자 행이 현재 페이지에 있으면 별도 현재 사용자 요약을 Rendering하지
  않습니다. 색상 이외의 표현도 사용해 해당 행을 리더보드에서 강조합니다.
- 사용자 행이 현재 페이지에 없으면 목록 위에 **내 순위 37 / 120 · 976,654 ·
  S · FC**에 해당하는 간결한 요약 한 줄을 보여줍니다. 이 요약은 Context이며 두
  번째 전체 프로필 카드가 아닙니다.
- 로그인한 사용자에게 선택 채보 점수가 없으면 **순위 없음**에 해당하는 간결한
  상태를 보여줍니다.
- 비로그인 상태에서도 전체 공개 리더보드를 제공하고 **내 순위를 보려면 로그인**에
  해당하는 작은 Context Action만 제공합니다. 인증 Panel로 공개 목록을 대체하거나
  가리지 않습니다.
- 상대적인 상위 비율을 표시하지 않습니다. 정확한 순위와 전체 참여자 수가 더
  실행 가능하며 모호한 백분위 반올림을 피합니다.
- 랭킹에서 로그인을 시작하면 승인된 안전한 복귀 경로를 통해 Locale, 악곡,
  선택 난이도, 랭킹 및 유효한 페이지 Context를 보존합니다.

이 조건부 규칙은 사용자의 전체 행을 두 번 보여주지 않으면서 사용자 행이 없는
페이지에서도 위치를 확인하게 합니다.

### 리더보드 행 계약

- 플레이어별 베스트 스코어 행 하나를 보여줍니다.
- 모바일에서는 각 행을 의미상 **순위 | 플레이어 | 결과**로 묶습니다.
- 플레이어에는 Avatar와 Link가 있는 표시 이름을 둡니다. 기존 프로필 목적지를
  유지합니다.
- 결과에서는 점수를 주요 값으로, 점수 Grade와 Full Combo 또는 Pianist 상태를
  보조 값으로 둡니다.
- 데스크톱에서는 Grade, 달성 상태 및 점수를 서로 다른 시각 열에 둘 수 있지만
  정보 관계는 모바일과 같아야 합니다.
- 이 선택 채보 리더보드에 국가, 베스트 기록일, Filter, 정렬 컨트롤 또는 무관한
  프로필 필드를 추가하지 않습니다.
- 지속적인 선택 채보 Context가 이미 식별하므로 모든 행에 악곡 제목, 재킷,
  난이도 또는 레벨을 반복하지 않습니다.
- 눈에 보이거나 Program에서 의미를 인식할 수 있는 열 라벨을 제공합니다. 비교할
  숫자는 오른쪽 정렬하고 고정폭 숫자를 사용합니다.
- 현재 사용자 행은 색상에만 의존하지 않고 식별할 수 있어야 하며 이름과 프로필
  Action을 완전히 조작할 수 있어야 합니다.

### 공동 순위 및 동점 계약

- 같은 베스트 스코어에는 같은 표시 순위를 부여합니다.
- 순위를 건너뛰는 경쟁 순위 `1, 2, 2, 4`를 사용합니다.
- 같은 점수 Group 안에서는 먼저 달성한 기록을 앞에 두지만 공동 순위는 바꾸지
  않습니다.
- 달성 시점도 같으면 안정적인 내부 ID를 마지막 결정적 정렬 Key로만 사용합니다.
  해당 ID를 노출하거나 이를 고유 순위로 바꾸지 않습니다.
- 이후 구현에서는 불러온 NOSTALGIA 데이터에서 확인할 수 있는 가장 신뢰할 수 있는
  최고 기록 갱신 시점에 **달성 시점**을 매핑해야 합니다. 계정 생성 시각이나 임의의
  사용자 ID를 조용히 대신 사용하면 안 됩니다.
- 이 계약은 선택 채보 랭킹에 적용합니다. 별도 전역 랭킹 Family와의 일관성은
  여기서 조용히 바꾸지 않고 해당 페이지 기획서에서 검토해야 합니다.

### NOSTALGIA 상위 실력 점수 분포

이 시각화는 전체 모집단의 점수 Grade Histogram이 아니라 의도적인 **S 이상 상위
실력 분포**입니다. NOSTALGIA 성과 차이는 상위 점수 Milestone에서 훨씬 의미 있게
벌어지므로 다음 Bucket을 유지합니다.

| Bucket    | 포함 결과                                                              |
| --------- | ---------------------------------------------------------------------- |
| `950k`    | `950,000–959,999`                                                      |
| `960k`    | `960,000–969,999`                                                      |
| `970k`    | `970,000–979,999`                                                      |
| `980k`    | `980,000–989,999`                                                      |
| `990k`    | Pianist 결과를 제외한 `990,000–999,999`                                |
| `Pianist` | 현재 NosLog Domain 조건: 점수가 `1,000,000` 이상이거나 `fc_type === 3` |

- **전체 참여자 100명**과 같이 전체 참여자 수를 독립적으로 보여줍니다.
- **S 이상 점수 분포 · 30명**과 같이 시각화와 자체 분모를 별도로 표시합니다.
- Bucket 수와 시각 비율 합계는 전체 참여자가 아니라 S 이상 분모와 일치해야
  합니다.
- 시각 비율과 함께 실제 수를 보여주고 같은 값을 접근 가능한 구조적 표현으로
  제공합니다.
- 이를 전체 모집단 Histogram으로 만들기 위해 `<950,000` 막대를 추가하지
  않습니다. 해당 플레이어도 별도의 전체 참여자 수에는 포함합니다.
- 집중한 점수 Band를 Pianist, S, A+, A, B+, B, C, D 같은 넓은 점수 Grade
  Category로 대체하지 않습니다. 그런 Group은 이 분석이 보여줘야 할
  `950k–Pianist`의 의미 있는 차이를 뭉갭니다.
- 정확한 Chart Geometry, 색상 및 간결한 데스크톱 위치는 Foundation과 대표
  Specimen 결정으로 남깁니다. Bucket 의미와 분모 계약은 미루지 않습니다.

승인한 Band는 NOSTALGIA Milestone 동작과 현재 NosLog Rating 정책 모두의 근거를
가집니다. 현재 정책은 `950,000`에서 시작하고 `1,000,000`까지 `10,000` 단위
Anchor를 사용하며 활성 숙련 곡선은 `990,000`과 Pianist 성과에 가장 큰 비중을
둡니다. 이 로컬 제품 근거는 이전에 제안한 넓은 Grade 분포를 바로잡습니다.

### Pagination 및 내비게이션

- 모바일과 데스크톱 모두 고정 페이지 크기 **25명**을 사용합니다.
- 페이지당 행 수 Selector를 제공하지 않습니다.
- 전체가 `25`명 이하면 Pagination을 숨기고 스물여섯 번째 결과부터 명시적인
  Pagination을 보여줍니다.
- 현재 페이지를 다국어 URL과 브라우저 History에 보존합니다.
- Infinite Scroll이 아니라 명시적인 Pagination을 사용합니다.
- 사용자가 페이지를 바꾸면 Focus와 Scroll Context를 랭킹 제목 또는 목록
  시작점으로 이동·복원하고 갱신된 결과 범위를 보조 기술에 안내합니다.
- 숫자가 아니거나 음수, 0 또는 범위를 벗어난 페이지는 악곡, 난이도, Locale 및
  랭킹 상태를 보존한 채 첫 번째 유효 페이지로 정규화합니다.
- 페이지 변경이 현재 사용자 Context나 선택 채보 Context를 버리면 안 됩니다.

25명은 반복 비교와 모바일 Scan 길이 사이의 균형이며 운영 Table에서 흔히 쓰는
단위입니다. 현재 일곱 행 페이지는 관찰한 Legacy 동작이며 2.0 제약이 아닙니다.

### Loading, 빈 상태, 오류 및 접근성 상태

- Loading 중에는 절제한 Skeleton으로 리더보드 행 Geometry를 보존하고 갱신
  영역에 `aria-busy`를 표시합니다.
- 요청 실패 시 간결한 오류 하나와 명시적인 재시도 Action을 제공합니다. 오래된
  행을 현재 데이터인 것처럼 조용히 표시하지 않습니다.
- 공개 베스트 스코어가 없으면 **등록된 기록이 없습니다**에 해당하는 간결한 상태
  하나를 보여줍니다. 현재 사용자의 **순위 없음** 메시지를 동시에 중복 표시하지
  않습니다.
- 비로그인 사용자도 로그인 사용자와 같은 공개 빈 상태, Loading 및 오류 동작을
  사용합니다.
- 모바일 표현에서도 Table 또는 동등한 Collection 의미 구조와 Header 연결을
  보존합니다. 반응형 Styling이 행을 라벨 없는 값으로 바꾸면 안 됩니다.
- 인접한 Link 플레이어 이름이 같은 정체성을 전달하면 Avatar를 장식으로
  취급합니다. 의미 있는 점수 Grade 이미지 대체 Text는 Locale에 맞게 제공하며
  현재처럼 모든 Locale에서 한국어 대체 Text를 재사용하지 않습니다.
- 표시 숫자를 지역화하면서 안정적인 숫자 의미, 오른쪽 정렬 및 고정폭 숫자를
  유지합니다.
- 현재 사용자 행, Full Combo, Pianist, Grade, Loading 또는 오류 상태를
  색상만으로 전달하지 않습니다.

덮어쓰지 않습니다.

## 거절한 대안

- **B형 — 모든 영역을 담은 하나의 긴 페이지:** 거절했습니다. 네 영역은
  분량이 크고 인증·데이터 상태가 다르며 반드시 순서대로 읽을 내용이
  아닙니다.
- **C형 — 상세 View 전에 영역 간 요약 허브 제공:** 악곡 상세에서는
  거절했습니다. 사용자가 이미 악곡을 선택했고 보통 구체적인 후속 과업이
  있는 페이지에 개요 계층과 정보 밀도를 추가합니다. 또한 여러 초기 요청,
  여러 Domain 조회를 수행하는 하나의 집계 요청 또는 별도로 관리하는 요약
  Cache 중 하나가 필요합니다.
- **현재 UI를 시각 기준으로 사용:** 거절했습니다. 구조를 이어간다는 것이
  현재의 고정 너비 Shell, 타이포, 간격, 카드 밀도 또는 탭 Styling을
  승인한다는 뜻은 아닙니다.
- **채보 보기를 채보 정보 안에 배치:** 거절했습니다. 뷰어는 직접 채보 단위
  Action이며 정보 Panel을 먼저 열도록 요구하면 안 됩니다.
- **사용할 수 없을 때 비활성 채보 보기 Button 자리 유지:** 거절했습니다.
  사용할 수 없는 주요 컨트롤을 보존하지 않고 간결한 사용 가능 여부 Text를
  사용합니다.
- **로그인·비로그인 사용자에게 서로 다른 Query 없는 기본값 사용:** 거절했습니다.
  같은 URL이 숨겨진 인증 상태에 따라 다른 콘텐츠를 열어 예측 가능성과 공유 Link의
  의미를 약화합니다.
- **마지막 사용 영역을 전역 기억:** 거절했습니다. 다른 악곡의 이전 방문이 공개
  기본값이나 출처가 아는 의도를 조용히 덮어쓰면 안 됩니다.
- **비로그인 상태에서 개인 기록 숨김 또는 비활성화:** 거절했습니다. 명확한 복구
  Action이 있는 핵심 제품 기능이므로 발견 가능해야 합니다.
- **빈 기록 분석 위에 로그인 Overlay:** 거절했습니다. Gate 뒤에 접근할 수 없는
  데이터가 있는 것처럼 보이며 과업 복구에 도움 없이 시각 노이즈만 추가합니다.
- **기록 로그인 뒤 홈으로 복귀:** 거절했습니다. 검증된 복귀 경로로 선택 악곡,
  난이도 및 기록 영역을 복원해야 합니다.
- **패턴 경향과 점수 분포를 채보 정보에 유지:** 거절했습니다. 각각 서열·평가와
  랭킹에 속하며 공개 기본 영역을 영역 간 미리보기 Hub로 되돌립니다.
- **사용할 수 없는 선택 사실을 `-` 행으로 유지:** 거절했습니다. 수록일과 언락
  조건은 의미 있는 값이 있을 때만 표시합니다.
- **같은 패턴 값을 레이더와 막대 Chart로 동시 표시:** 거절했습니다. 소유 영역인
  서열·평가에서 주요 표현 하나를 선택하고 정확한 값과 접근성 대안을 유지합니다.
- **클리어 횟수를 악곡 상세 성과 요약으로 사용:** 거절했습니다. 사용자·채보별
  플레이 횟수는 유지하지만 NOSTALGIA 클리어 횟수가 이 목적에서 의미 있는 결과
  차이를 만든다고 표현하지 않습니다.
- **랭킹 위에 전체 현재 사용자 카드를 항상 표시:** 거절했습니다. 현재 사용자
  행이 페이지에 있으면 별도 요약을 숨기고 행을 강조합니다. 없을 때만 간결한
  요약 한 줄을 사용합니다.
- **현재 사용자 주요 위치로 상대 상위 비율 사용:** 거절했습니다. 모호한 백분위
  반올림 없이 정확한 공동 순위와 전체 참여자 수를 보여줍니다.
- **사용자 ID로 같은 점수에 고유 순위 강제:** 거절했습니다. 같은 점수는 공동
  경쟁 순위를 사용합니다. 달성 시점은 동점 Group 내부 순서만 정하고 안정적인
  ID는 보이지 않는 최종 정렬 Key로만 사용합니다.
- **집중 점수 Band를 넓은 Pianist/S/A+/A/B+/B/C/D Grade로 대체:** 대체 후
  거절했습니다. 이 제안은 NOSTALGIA 상위 점수의 실력 분리를 잘못 이해했으며
  의미 있는 `950k–Pianist` 성장을 숨깁니다.
- **950k 미만 분포 Bucket 추가:** 거절했습니다. 시각화는 자체 분모가 있는
  명시적인 S 이상 분석이며 별도 참여자 수에는 양수 점수 플레이어 전체를
  포함합니다.
- **페이지당 일곱 명 유지 또는 열 명으로 축소:** 거절했습니다. 고정 25명
  페이지를 사용하고 전체 목록이 한 페이지에 맞으면 Pagination을 숨깁니다.
- **페이지당 행 수 Selector 또는 Infinite Scroll 추가:** 거절했습니다. 승인한
  페이지 길이가 안정적인 집중 리더보드에 불필요한 컨트롤 또는 내비게이션
  복잡성을 만듭니다.
