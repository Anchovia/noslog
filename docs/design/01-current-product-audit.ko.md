# NosLog 2.0 현재 제품 감사

## 문서 관리

- 상태: `정보 구조 계획 기준선으로 승인`
- 근거 상태: `저장소 및 대표 브라우저 확인에서 관찰`
- 브라우저 검증: `1차 확인 완료, 드물거나 비공개 상태는 보류`
- 작성 시작일: 2026-07-29
- 범위 결정 확정일: 2026-07-29
- 문서 언어: 한국어 동기화본
- 영어 원본: [01-current-product-audit.md](./01-current-product-audit.md)
- 범위: NosLog v1.6.0 사용자 애플리케이션, 공통 시스템 상태 및 관리자
  애플리케이션
- 결정 권한: 이 문서는 현재 제품을 기록합니다. NosLog 2.0의 정보 구조, 시각적
  방향, 페이지 콘텐츠 또는 기능 제거를 승인하는 문서가 아닙니다.

## 목적

이 감사 문서는 NosLog 2.0 페이지 기획서 또는 디자인 결정을 만들기 전에
파악해야 할 제품 기능과 상태를 수집합니다. 저장소에서 확인한 내용은 사실로
기록합니다. 아직 확보하지 못한 브라우저 근거, 모호한 동작, 변경 제안 및 향후
결정은 명시적으로 미해결 상태로 유지합니다.

## 검토한 근거

- Next.js App Router 페이지, 레이아웃, Route Handler 및 Proxy 구조
- 공통 레이아웃, 내비게이션, 다국어, 테마 및 UI 컴포넌트
- 페이지 단위 서버 데이터 로딩과 클라이언트 상호작용 컴포넌트
- Prisma 데이터 모델
- 기존 Vitest 및 Playwright 검증 범위
- v1.6.0 기능과 운영 기준을 설명하는 프로젝트 README
- `390 × 844` 및 `1440 × 900`에서 대표 개발 데이터로 진행한 로그인 상태
  브라우저 확인

1차 브라우저 확인에는 대표 로그인 사용자 페이지, 관리자 페이지, 세 언어 및
채보 미리보기 예외가 포함됩니다. 드문 상태, 파괴적 상태, 권한 거부 상태,
로딩 상태 및 비공개 상태는 안전하게 재현할 수 있는 경우에 한해 별도 근거가
더 필요합니다.

## 현재 제품 구조

### 애플리케이션 셸

| 셸          | 소스                                                                                     | 확인된 동작                                                                                                               |
| ----------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 사용자 셸   | `app/(nevigation)/layout.tsx`                                                            | 공통 건너뛰기 링크, 헤더, 메인 영역 및 푸터를 제공합니다. 현재 셸은 넓은 뷰포트에서도 `390px`(`max-w-97.5`)로 제한됩니다. |
| 인증 셸     | `app/(auth)/layout.tsx`                                                                  | 건너뛰기 링크가 있고 일반 헤더와 푸터가 없는 독립적인 로그인 및 온보딩 페이지입니다. 검색엔진 색인을 허용하지 않습니다.   |
| 관리자 셸   | `app/admin/layout.tsx`                                                                   | 관리자 역할을 요구한 뒤 공통 헤더와 푸터, 관리자 내비게이션 컨트롤을 렌더링합니다. 현재 관리자 셸도 `390px`로 제한됩니다. |
| 시스템 상태 | `app/error.tsx`, `app/global-error.tsx`, `app/not-found.tsx`, `app/maintenance/page.tsx` | 다국어 라우트 오류, 전역 오류, 찾을 수 없음, 재시도 및 점검 중 화면을 제공합니다.                                         |

`nevigation`은 현재 소스 코드의 Route Group 이름입니다. 공개 URL에는 노출되지
않습니다.

### 다국어 및 URL 규칙

- 지원하는 사용자 언어는 한국어(`ko`), 일본어(`ja`), 영어(`en`)입니다.
- 사용자 페이지는 `/ko/music`, `/ja/music`, `/en/music`처럼 언어 접두사가
  포함된 경로를 사용합니다.
- 언어가 없는 사용자 요청은 경로 언어, 로그인 사용자의 설정, 언어 쿠키,
  브라우저 `Accept-Language` 순서로 언어를 결정하여 리디렉션합니다.
- 관리자, API, Discord OAuth 및 프레임워크 경로에는 언어 접두사를 붙이지
  않습니다.
- 로그인 사용자의 언어 설정은 계정에 저장됩니다. 비로그인 사용자는 헤더
  메뉴에서 언어를 변경할 수 있습니다.
- 악곡 제목 표시 설정은 원문 제목을 유지하면서 승인된 한국어·영어 번역 또는
  저장된 일본어 읽기 제목을 표시할 수 있습니다.
- 사용자 페이지와 전역 시스템 상태는 다국어를 지원합니다. 관리자 페이지는
  한국어로 유지됩니다.

### 인증 및 권한 규칙

- Discord OAuth를 로그인 방식으로 사용합니다.
- 로그인했지만 프로필을 완료하지 않은 계정은 온보딩으로 리디렉션됩니다.
- `/profile/settings`와 `/onboarding`은 로그인이 필요합니다.
- 프로필을 완료한 계정은 온보딩으로 다시 이동할 수 없습니다.
- 공개 콘텐츠는 로그인하지 않아도 볼 수 있지만, 개인 기록, 빙고 진행 상태
  편집, 검정 제출, 선호 오락실 선택 및 비공개 분석은 로그인 여부에 따라
  달라집니다.
- 관리자 페이지는 `admin` 역할을 가진 로그인 사용자만 접근할 수 있으며,
  나머지 사용자는 찾을 수 없음 응답을 받습니다.
- 사용자 세션은 최대 14일 동안 유지되며 HTTP-only `SameSite=Lax` 쿠키를
  사용합니다.

## 공통 사용자 내비게이션 및 전역 기능

### 헤더

- 56px 높이의 Sticky 헤더입니다.
- NosLog 홈 링크를 제공합니다.
- 주요 내비게이션은 악곡, 랭킹, 서열입니다.
- 비로그인 상태에서는 로그인 액션을, 로그인 상태에서는 프로필 아바타를
  표시합니다.
- 보조 메뉴는 빙고, 검정, 오락실, 데이터 연동으로 구성됩니다.
- 관리자에게는 관리자 진입 항목을 표시합니다.
- 비로그인 사용자의 보조 메뉴에는 언어 전환기를 표시합니다.
- `1024px` 미만 뷰포트에서는 아래로 스크롤할 때 헤더가 숨겨지고, 화면 상단
  부근이나 위로 스크롤할 때 또는 키보드 포커스가 헤더 안에 있을 때 다시
  표시됩니다.
- 메뉴가 열리면 본문 스크롤을 잠그고 `Escape`로 닫을 수 있습니다.

## 현재 시각적·컴포넌트 기준선

이 절은 구현 사실만 기록합니다. NosLog 2.0은 이 값을 유지하도록 제한되지
않습니다.

### 현재 Foundations

- 로컬 Variable Pretendard를 전역 폰트로 사용합니다.
- 다크·라이트 테마용 Semantic Color Token을 지원합니다.
- 현재 Semantic Token 그룹은 배경, 표면, 텍스트, 상호작용, 상태, 차트·점수,
  랭크, 난이도, 검정 모드, 장르, Discord 및 카드 Radius를 포함합니다.
- 현재 이름이 정의된 Type Utility는 Display, Score Display, Title, Wordmark,
  Section, Body, Muted Body, Label, Caption, Micro, Badge 및 Input입니다.
- 공통 사용자·관리자 셸은 현재 최대 너비 390px를 사용합니다.

### 현재 공통 UI 컴포넌트

- Button: Primary, Secondary, Ghost, Danger Variant와 Small, Medium, Large,
  Icon 크기
- Badge: Neutral, Outline, 상태, 난이도, 모드, 점수 및 랭크 Variant
- Card: Card, Header, Title, Content Primitive
- Switch
- 전역 Toaster
- 기능 컴포넌트에서 Radix Dialog, Popover, Select, Slider, Switch 및 Tabs도
  직접 사용합니다.

여러 기능 페이지에는 작은 공통 컴포넌트 집합을 사용하지 않고 페이지 내부에서
스타일을 정의한 컨트롤과 카드가 남아 있습니다. 이는 구현 상태에 대한
관찰이며, 아직 승인된 통합 계획이 아닙니다.

#### 390px 헤더 상호작용

- 헤더는 측정 높이 `56px`, `y = 0`에서 시작합니다.
- `700px`까지 아래로 스크롤하면 헤더가 `y = -56px`로 이동합니다.
- `350px`까지 다시 위로 스크롤하면 `y = 0`으로 돌아옵니다.
- 따라서 구현된 아래 방향 스크롤 숨김 및 위 방향 스크롤 표시 동작이 실제
  렌더링 UI에서도 동작함을 확인했습니다.

#### 1440px 데스크톱 셸

- 홈, 악곡 탐색, 악곡 상세, 랭킹, 관리자 대시보드 및 확인한 관리자 목록·관리
  페이지는 중앙의 `390px` 메인 열을 유지했습니다. 측정된 가로 위치는
  `x = 525px`이었습니다.
- 따라서 악곡, 사용자, 검정, 빙고, 오락실 및 연동 관리처럼 밀도 높은 관리자
  작업도 사용 가능한 데스크톱 너비를 활용하지 않고 세로로 쌓입니다.
- 대표 문서 높이는 관리자 악곡 약 `7,335px`, 관리자 빙고 `3,246px`, 관리자
  검정 `2,990px`, 관리자 오락실 `2,365px`, 관리자 사용자 `2,289px`이었습니다.
- 이는 기존 셸 제약을 확인한 결과이며, `390px`를 NosLog 2.0 데스크톱
  기준으로 정한 것이 아닙니다.

- 관리자 채보 미리보기는 일반 셸 너비를 의도적으로 벗어납니다.

  너비가 `364px`, 가로 콘텐츠가 `1,164px`였고, 확인한 각 채보 Canvas는
  `274 × 718px`였습니다.

- 넓은 데스크톱 뷰포트에서 일반 사용자·관리자 페이지 양옆에 큰 미사용 공간이
  남습니다.
- 밀도 높은 목록과 관리 도구가 매우 긴 단일 열 페이지가 됩니다.
- 빙고, 서열표, 프로필 및 설정처럼 정보량이 많은 사용자 페이지도 세로 순서에
  크게 의존합니다.
- 채보 뷰어는 시각화에 필요한 최소 유효 너비가 있어 일반 콘텐츠 페이지와
  다른 반응형 모델이 이미 필요합니다.
- 일본어와 영어는 한국어와 동일하게 동작한다고 가정하지 않고 실제 긴
  콘텐츠로 검증해야 합니다.

이 증상들은 조사 대상을 정할 뿐입니다. 특정 Grid, Breakpoint, 최대 너비,
내비게이션 모델 또는 콘텐츠 제거를 아직 승인하지 않습니다.

### 아직 필요한 브라우저 근거

- 깨끗한 세션에서 비로그인 로그인·둘러보기 및 언어별 첫 진입 동작
- 확인한 채보가 미리보기 전용이었으므로 공개된 공개 채보 리비전
- 안전하게 재현할 수 있는 대표 빈 상태, 로딩, 요청 오류, 비활성, 권한 및
  파괴적 상태
- 세 언어의 긴 번역 악곡명과 극단적인 실제 기록 값
- 키보드 이동, 보이는 포커스, 메뉴 포커스 관리 및 모션 감소 동작
- 감사 결정으로 공식 비교 근거에 보존할 상태가 정해진 뒤의 대표 스크린샷

## 확정된 감사 결정

### 핵심 사용자 페이지 패밀리

1. **홈은 가장 중요한 첫 진입 경험입니다.** 새로 방문한 사용자가 어디로
   이동해야 하는지 직관적으로 파악하고, 필요한 정보를 즉시 얻을 수 있어야
   합니다.
2. **악곡 탐색과 악곡 상세는 핵심 제품 과업입니다.** 리듬게임 서비스에서 악곡
   검색은 가장 자주 발생할 것으로 예상되는 행동 중 하나이므로, 탐색과 상세를
   연결된 최우선 사용자 흐름으로 다룹니다.
3. **서열표는 핵심 플레이 계획 과업입니다.** 많은 사용자가 서열표의 진행
   순서에 따라 플레이할 악곡을 선택하므로 서열 경험도 우선순위가 높은 페이지
   패밀리로 다룹니다.

이 우선순위는 조사 및 대표 화면 설계 순서를 정합니다. 다른 검증된 기능을
별도 합의 없이 제거할 수 있다는 뜻은 아닙니다.

### 기능 처리 원칙

- 현재 제거하거나 보류하기로 예정된 기존 기능은 없습니다.
- 이후 근거가 변경 필요성을 뒷받침하고 사용자가 명시적으로 승인하기 전까지
  검증된 모든 사용자 기능을 유지 대상으로 둡니다.
- 정보 구조에서 기능을 통합하거나 다시 묶고 점진적으로 공개할 수는 있지만,
  별도로 승인된 결정 없이 기능 자체나 발견 가능성을 제거해서는 안 됩니다.
- 페이지 기획서 또는 레퍼런스 조사 중 제거·보류 후보가 발견되면 근거와
  Trade-off를 제시하고 사용자와 논의해야 합니다.

### 관리자 범위

- 관리자 기능은 현재 제품의 일부로 계속 문서화합니다.
- 관리자 인터페이스는 NosLog 2.0 사용자 UI 재설계 범위에서 제외합니다.
- 별도 승인이 없다면 NosLog 2.0 사용자 화면 작업 중 관리자 페이지에는 기능
  유지보수만 진행합니다.
- 프로덕션 수준의 관리자 재설계는 2.0 완료 후 별도 단계로 시작할 수 있습니다.
