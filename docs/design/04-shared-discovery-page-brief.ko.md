## 결정 라벨

- **관찰:** 현재 저장소, 브라우저 또는 승인된 상위 문서에서 검증했습니다.
- **승인:** 사용자가 명시적으로 동의했으며 후속 디자인의 기준으로 사용할 수
  있습니다.
- **제안:** 근거를 바탕으로 제시했으나 사용자의 명시적 승인을 기다립니다.
- **미확정:** 추가 조사, 대표 데이터, 테스트 또는 사용자 결정이 필요합니다.
- **거절:** 검토한 뒤 명시적으로 선택하지 않았습니다.
- **대체:** 이후 승인된 방향으로 교체했습니다.

중요한 동작 중 `미확정` 또는 `제안`으로 남은 것은 없습니다. 동기화된 공용
탐색 기획서 전체는 하나의 단계 산출물로 승인됐습니다. 예정된 Specimen과
구현 Gate가 이 승인을 다시 열지는 않습니다.

## 목적

공용 탐색 Surface는 사용자가 서로 다른 두 Catalog를 배울 필요 없이 다음 두
질문 중 하나에 답할 수 있게 해야 합니다.

1. **악곡 범위:** “내가 찾는 악곡은 무엇이며 상세와 기록에 어떻게
   도달하는가?”
2. **채보 범위:** “집중형 뷰어에서 확인하거나 재생할 공개 채보는 무엇인가?”

하나의 검색 위치, Query 모델 및 반응형 상호작용 체계를 재사용하면서도 악곡
항목과 난이도 채보의 의미 차이는 보존해야 합니다.

## 주요 사용 Context

- **승인:** 오락실 플레이 전후의 짧은 검색처럼 불필요한 확인과 숨은 상태가
  큰 비용이 되는 모바일을 주요 Context로 둡니다.
- **승인:** 데스크톱도 필수 대상이며 중앙의 `390px` 휴대폰 Canvas를 유지하지
  않고 추가 너비를 보이는 필터와 결과 비교에 사용해야 합니다.
- **승인:** 이 Surface는 공개입니다. 로그인하면 개인 기록 필터와 기록
  Context를 추가하지만 일반 악곡·공개 채보 탐색에 로그인을 요구하면 안
  됩니다.
- **승인:** 홈은 빈 탐색 요청, 제출한 Query 또는 선택한 홈 미리보기 결과를
  이 Surface로 넘길 수 있습니다.
- **승인:** 홈의 악곡 목적지는 악곡 범위를 엽니다. 홈과 더보기의 채보 뷰어
  목적지는 같은 Surface를 채보 범위가 선택된 상태로 엽니다.

## 현재 제품 근거

### 관찰된 저장소 동작

- `/[locale]/music`이 현재 공개 악곡 탐색 Route입니다.
- 현재 Query는 제목, 아티스트 및 악곡 Index Text 검색을 지원합니다.
- Category, Normal·Hard·Expert·Real 난이도 선택, 난이도별 레벨 범위,
  이름·레벨·최근 플레이·취약점 정렬, 오름차순·내림차순, 목록·Grid 보기 및
  로그인 사용자의 개인 기록 필터 14개를 지원합니다.
- 명시적인 난이도 Query Parameter가 없으면 현재 Normalizer가 Expert와 레벨
  `8–12`만 조용히 활성화합니다.
- Category, 난이도 및 기록 Toggle은 현재 Route를 즉시 교체합니다. 범위 변경은
  `200ms` Debounce 후 반영하고 조작 종료 시 다시 Commit합니다.
- 현재 결과 Query는 Cursor 기반으로 `20`개씩 반환합니다.
- 현재 목록은 `IntersectionObserver` Sentinel이 Viewport에 들어오면 다음
  묶음을 자동으로 가져옵니다.
- 현재 공개 탐색 결과는 악곡 중심입니다. 전용 채보 범위와 공개 난이도
  Grouping은 아직 없습니다.
- 공개 결과 데이터에는 이미 악곡 원문 제목, 선택적인 승인 번역 제목 또는
  일본어 읽기, 아티스트, Category, 배경 및 Normal·Hard·Expert·Real 레벨이
  포함됩니다.
- 비로그인 요청에서는 데이터 계층이 개인 기록 필터와 개인 정렬을
  무시합니다.
- 점검한 Local Dataset에는 악곡 `583`개와 MusicChart `2,180`개가 있습니다.
  `title_kana`는 악곡 `583`개 모두에 있지만 현재 `released_at`이 있는
  MusicChart는 `3`개뿐입니다.
- `prisma/data/nosdata-musics.json`의 원본 Import Catalog에는 `578`개 항목이
  있습니다. 원문 제목 길이 중앙값은 `11`자, 90백분위는 `25`자, 최댓값은
  `54`자이며 `15`자 이상 제목이 `178`개, `20`자 이상이 `92`개입니다.
  아티스트 길이 중앙값은 `10`자, 90백분위는 `34`자, 최댓값은 `67`자이며
  `15`자 이상 아티스트가 `218`개, `20`자 이상이 `172`개입니다. 이 원본 파일
  감사는 위의 Local Database `583`행 감사와 구분되며, 긴 제목과 아티스트가
  예외가 아니라 일반적인 처리 대상임을 보여줍니다.
- 같은 Dataset에는 공개 ChartPattern과 MusicTranslation 항목이 없습니다.
  이는 대표 채보·다국어 테스트를 위한 준비 제약이지 승인된 제품 모델을
  약화할 이유가 아닙니다.
- 악곡 `created_at`과 `updated_at`은 Import 또는 유지보수 시각이며 공식
  “신곡” 날짜로 표시하면 안 됩니다.

### 관찰된 브라우저 기준선

승인된 현재 제품 감사는 좁은 `390px` Viewport와 넓은 데스크톱 Viewport에서
`/ko/music`, `/ja/music`, `/en/music`을 검증했습니다.

- 검색, 필터, 정렬, 보기 컨트롤 및 결과는 문서 단위 가로 Overflow 없이
  사용할 수 있었습니다.
- 현재 넓은 레이아웃은 여전히 일반 `390px` Shell에 시각적으로 제한됩니다.
- 일본어 콘텐츠는 한국어·영어보다 페이지가 길었으며 실제 다국어 라벨과 제목
  길이를 테스트해야 함을 확인했습니다.
- `2026-07-31`에 진행한 점진적 불러오기 집중 감사에서 현재 첫 `20`개 결과는
  `390px` 목록 약 두 Viewport, Grid 약 3.5 Viewport를 차지했습니다. 현재 목록
  Markup의 페이지 DOM 요소는 결과 20개에서 `464`, 40개에서 `764`, 60개에서
  `1,073`개였습니다.
- 이 관찰은 현재 기능을 확인한 것입니다. 현재 기본 Expert 필터, 자동 불러오기,
  시각 밀도, 카드 구성 또는 데스크톱 너비를 승인하지 않습니다. DOM 수치는
  후속 Component의 성능 테스트 기준선이며 2.0의 고정 Markup 예산이 아닙니다.
- `2026-07-31` 로그인 집중 감사에서 현재 NosLog는 넓은 화면과 `390px` 모두
  **미플레이**와 **최근 플레이순**을 동시에 활성화할 수 있었습니다. Query는
  모든 미플레이 악곡에 최근 기록값 `0`을 부여한 뒤 제목으로 동률을 해소하므로,
  보이는 최근순 Label이 실제 순서를 더 이상 설명하지 못합니다. 이는 승인된
  대체 동작이 아니라 마이그레이션 근거입니다.
- `2026-07-31` 일시적 응답 집중 감사에서 현재 검색 교체 중 결과 영역에는
  `[role="status"]` 또는 `aria-busy` 상태가 없었습니다. 현재 Route는 첫 Data
  요청이 끝날 때까지 기다린 뒤 페이지를 Render하고, Route 단위 Loading
  Boundary가 없으며, 처리하지 않은 조회 실패는 더 넓은 Route 또는 Global
  Error Boundary에 맡깁니다. 이는 승인된 2.0 동작이 아니라 마이그레이션
  공백입니다.

## 승인된 탐색 모델

### 하나의 공용 Surface와 두 범위

- 악곡과 공개 채보 검색에 하나의 공용 탐색 Surface를 사용합니다.
- 검색창 선행 영역에 간결한 범위 선택기를 둡니다.
- 접힌 선택기는 활성 범위 아이콘과 펼침 단서를 사용합니다. 열린 컨트롤에는
  **악곡 검색**과 **채보 검색**의 보이는 다국어 Text를 제공합니다.
- 검색창 위에 악곡·채보 모드 Button 행을 상시 배치하지 않습니다.
- 이후 사용성 근거에서 유지한 Text가 실제 오해를 만든다고 확인되지 않는 한
  범위를 바꿔도 현재 Query를 유지합니다.
- 활성 범위를 공유하고 History에서 복구 가능한 URL 상태로 표현합니다. 정확한
  Path와 Query 문법은 구현 단계 결정으로 남깁니다.
- 검색 단서, 결과 요약, 빈 상태 및 결과 Action이 활성 범위를 보강해야 하며
  아이콘에만 의존하면 안 됩니다.

### 악곡 범위 기본 탐색

- 빈 악곡 범위 Query는 명시적인 묶음 단위로 전체 악곡 Catalog를 노출합니다.
- 초기 Catalog를 Expert 또는 레벨 `8–12`로 조용히 제한하지 않습니다.
- “전체 Catalog”는 승인된 `20`개 결과 점진적 불러오기 규칙으로 모든 이용
  가능한 악곡 항목에 도달할 수 있다는 뜻입니다. 시각적 카드 밀도를 정하는
  것은 아닙니다.
- 사용자가 선택한 난이도나 레벨 범위는 필터이며 보이지 않는 기본값이 아니라
  적용 상태로 표시해야 합니다.

### 채보 범위 결과 Grouping

- 활성 Query와 필터에 일치하는 공개 채보가 있는 악곡 및 난이도 Target만
  반환합니다.
- 하나의 악곡마다 하나의 결과 카드 또는 결과 단위로 묶습니다.
- 해당 악곡 결과 안에는 일치하는 공개 난이도만 노출합니다.
- 공개 난이도를 선택하면 정확한 집중형 채보 뷰어로 바로 이동합니다.
- 같은 악곡에 속한 난이도마다 시각적으로 독립된 최상위 결과 카드를 만들지
  않습니다.
- 공개하지 않은 난이도를 선택 가능한 것처럼 표시한 뒤 선택 이후 실패를
  설명하지 않습니다.

### 승인된 기본 탐색 정렬과 정렬 의미

- Query가 비어 있으면 악곡 범위는 이용 가능한 전체 Catalog를 `title_kana`
  오름차순으로 정렬합니다. 이 일본어 읽기 순서는 선택적 번역·읽기 제목
  Caption 표시 여부와 관계없이 안정적으로 유지합니다.
- Query가 비어 있으면 채보 범위는 각 악곡 Group의 가장 최근 공개 채보 시각을
  기준으로 내림차순 정렬합니다. Group 안의 선택 가능한 Target은
  `Normal → Hard → Expert → Real`의 안정적인 순서를 유지합니다.
- 검증된 공식 악곡 단위 출시일 Field를 채운 뒤 악곡 범위에 **신곡순**을
  제공합니다. 악곡 `created_at`, `updated_at` 또는 채보 Import 시각으로
  대체하지 않습니다. 이후 추가된 난이도를 어떻게 Mapping할지는 구현 전에
  검토해야 합니다.
- Text Query가 있고 현재 탐색 상태에서 사용자가 다른 정렬을 선택하지 않았다면
  **관련도순**을 기본으로 사용합니다. 관련도는 안정적인 악곡 식별자, 원문 제목,
  승인된 번역·읽기 제목 및 아티스트에서 정확하고 가까운 일치를 약한 부분
  일치보다 앞에 둡니다. 정확한 가중치와 동률 조정은 구현 단계에서 다룹니다.
- 사용자가 선택한 정렬은 Text와 필터를 변경해도 유지합니다. 관련도순 상태에서
  Query를 지우면 활성 범위의 승인된 빈 Query 정렬로 돌아갑니다. 관련도순은
  빈 Query 탐색 선택지가 아닙니다.
- 악곡 범위는 능동 Text 검색의 관련도순, 일본어 읽기순, 검증된 데이터 Gate를
  충족한 신곡순, 명시적인 대상 난이도를 가진 레벨순 및 로그인 사용자의 최근
  플레이순을 제공합니다.
- 채보 범위는 능동 Text 검색의 관련도순, 최신 공개 채보순, 일본어 읽기순,
  명시적인 대상 난이도를 가진 레벨순 및 로그인 사용자의 최근 플레이순을
  제공합니다.
- 현재 **취약순** 정렬은 제거합니다. 불투명한 복합 점수는 승인된 이해 가능한
  탐색 목표와 연결되지 않습니다.
- 레벨순은 사용자가 대상 난이도를 명시적으로 선택한 뒤에만 유효합니다.
  Expert를 조용히 사용하거나 여러 난이도에서 하나의 대표 레벨을 만들면
  안 됩니다.
- 정렬 컨트롤 밖에는 현재 정렬 요약만 보여줍니다. 대상 난이도는 상시
  `Normal / Hard / Expert / Real` Button 행이 아니라 점진적 공개 안에서
  선택합니다.
- 정렬 방향 컨트롤은 상시 Button을 추가하지 않고 정렬 Surface 안에 둡니다.
  레벨순 대상처럼 Context에 따른 필수 항목은 해당 정렬을 선택한 뒤에만
  노출합니다.

### 승인된 필터 분류

- 공개 악곡·채보 탐색은 도메인에 의미 있는 공식 악곡 Category,
  Normal/Hard/Expert/Real 난이도 및 선택한 난이도 Target의 레벨 범위만
  공유합니다.
- 채보 범위는 악곡 정체성과 Category를 상속하면서 일치하는 공개 채보
  Target으로 결과를 제한합니다. 공개 여부는 범위 자체의 조건이며 중복된
  보이는 필터가 아닙니다.
- NosLog에 승인된 공개 데이터나 사용자 요구가 없는 채보 제작자, Community
  평점, Marketplace 상태 또는 일반 Tag 필터를 만들지 않습니다.
- 로그인 개인 기록 세부 필터는 아래 정의처럼 부차적으로 공개되는 Group이며
  공개 필터 분류를 바꾸지 않습니다.

## 검색 상호작용

### 능동형 Text 검색

- **승인:** 전체 탐색 Surface에서는 IME 입력을 안전하게 처리하며 추가 Text
  입력이 없는 `300ms` 후 결과를 갱신합니다.
- 일반 Text 결과 좁히기에 별도 검색 Button 클릭을 요구하지 않습니다.
- 결과가 없어도 사용자의 Query를 유지합니다. 오류 복구를 위해 검색창을
  지우지 않습니다.
- Enter는 현재 Query를 즉시 Commit할 수 있지만 의미가 다른 두 번째 검색
  동작을 만들면 안 됩니다.
- 새로운 Query나 범위 변경은 이전 결과를 무효화합니다. 순서가 뒤바뀐 응답이
  현재 상태의 결과를 교체하면 안 됩니다.
- 안정된 Query를 Commit한 뒤 URL을 갱신할 수 있지만 글자 입력마다 History
  항목을 만들어 뒤로가기를 사용할 수 없게 하면 안 됩니다.

### 홈 인계

- Target이 모호하지 않으면 홈 미리보기 선택이 관련 악곡 상세 또는 집중형 채보
  Target을 바로 열 수 있습니다.
- 홈의 `전체 결과 보기` Action은 정확한 Query와 범위를 유지해 이 Surface를
  엽니다.
- 홈에서 빈 값을 제출하면 빈 `q` Parameter 없이 선택한 범위의 탐색 상태를
  엽니다.
- 전체 필터, 정렬, 묶음 불러오기 및 결과 복구는 이 Surface가 담당하며 홈에서
  복제하지 않습니다.
- 홈 미리보기는 별도로 승인된 계약을 따릅니다. 이전 제안을 즉시
  무효화하고 요청 시작 후 `400ms`가 지나야 시각 Loading 행을 표시합니다.
  탐색은 `300ms` 요청 표시 Threshold 전까지 주 콘텐츠인 결과 Collection을
  정상적으로 조작 가능하게 유지하고, 교체가 계속 대기 중이면 그 뒤 오래된
  Collection을 약화하고 실행을 막습니다. 두 계약은 서로 다르며 새로운 근거와
  사용자 승인 없이 하나로 통일하면 안 됩니다.

## 필터·정렬 적용 모델

승인된 모델은 모든 상황에 하나의 `즉시 반영` 또는 `적용` 규칙을 사용하는
것이 아니라 반응형이며 과업 특성에 따라 달라집니다.

### 모바일 및 결과가 가려지는 레이아웃

- 필터와 정렬 Button을 각각 상시 두지 않고 명확한 **필터·정렬** Trigger 하나를
  제공합니다. Badge는 적용된 필터만 세며 항상 존재하는 정렬 선택을 적용
  필터로 세지 않습니다.
- Layer 밖에 Commit된 결과 수와 현재 정렬을 계속 표시합니다. 예를 들면
  “악곡 583개 · 관련도순”과 같은 의미 구조이며, Trigger만 보고 현재 순서를
  추론하게 하면 안 됩니다.
- 결과 요약을 안정적인 독립 Semantic Focus Target으로 취급합니다. 이 요구는
  결과 요약과 필터·정렬 Trigger를 반드시 서로 다른 시각 행에 두라는 뜻이
  아닙니다. 같은 행 또는 분리 행 구성은 사용 가능한 너비와 한국어·일본어·영어
  콘텐츠를 사용하는 `390px` Specimen에서 결정합니다.
- 결과 Collection을 컨트롤 옆에서 의미 있게 유지할 수 없다면 전체 화면 또는
  화면 대부분을 차지하는 Layer 하나로 엽니다.
- Layer 안에서 정렬, 공개 필터 및 로그인 개인 기록 Group을 시각적으로 명확히
  분리합니다. 진입점을 합쳐도 정렬을 찾기 어렵거나 다중 선택 필터처럼 보이지
  않도록 정렬을 먼저 둡니다.
- 가려진 결과 Collection을 선택마다 교체하지 않고 정렬과 여러 Category,
  난이도, 범위 및 개인 기록 변경을 임시로 선택할 수 있게 합니다.
- 행정적인 확인이 아니라 결과 과업으로 복귀하는 하나의 고정 주요 Action을
  사용합니다. 라벨은 **결과 보기**, 유효한 결과 수가 준비되면
  **N개 결과 보기**를 사용합니다.
- 주요 Action은 임시 정렬과 조건을 Commit하는 동시에 Layer를 닫습니다. 적용
  뒤에 두 번째 닫기 Action을 요구하지 않습니다.
- 성공적으로 Commit한 뒤에는 결과 요약 위치를 보이게 하고 복귀한 Trigger나
  첫 결과가 아니라 결과 요약으로 Programmatic Focus를 옮깁니다. 결과를
  자동으로 열거나 선택하면 안 됩니다.
- 결과 수 계산 중에도 일반 **결과 보기** 라벨을 사용할 수 있어야 하며 결과
  수 계산이 완료를 막으면 안 됩니다.
- 뒤로가기 또는 닫기는 임시 변경을 Commit하지 않고 종료하며 이전에 적용한
  정렬·필터 상태, 이전 Scroll Context 및 필터·정렬을 연 Trigger Focus를
  복구합니다.
- Layer를 닫은 뒤 적용 필터를 결과 요약 근처에서 계속 확인할 수 있어야
  합니다.
- 악곡 목록·Grid 보기는 결과 포함 여부나 순서가 아니라 표현을 바꾸므로 별도의
  간결한 보기 컨트롤로 유지합니다. 채보 범위에는 해당 컨트롤을 표시하지
  않습니다.

이는 과업 단계를 추가한 것으로 취급하지 않습니다. 결과가 가려지는 Layer의
사용자는 어느 모델에서든 결과로 돌아가야 하며 주요 Action이 필요한 복귀와
정렬·필터 Commit을 하나로 합치기 때문입니다.

### 데스크톱 및 결과가 보이는 레이아웃

- 필터와 정렬을 서로 다른 간결한 컨트롤로 유지합니다. 필터는 이용 가능한
  콘텐츠 너비에 따라 고정된 영역 또는 Rail을 노출할 수 있고, 정렬은 현재 값이
  직접 Label된 단일 선택 컨트롤을 사용합니다.
- 노출된 필터 컨트롤 옆이나 가까이에 주요 결과 Collection을 계속 보이게 합니다.
- 사용자가 결과 변화를 볼 수 있으므로 개별 필터 선택을 즉시 반영합니다.
- 선택한 정렬은 즉시 반영합니다. 모든 정렬 대안을 상시 Button 행으로 만들지
  않고 현재 값을 계속 표시합니다.
- Text와 유사하거나 연속적인 컨트롤은 Debounce합니다. 범위 컨트롤이 Pointer
  1 Pixel마다 결과 요청을 보내면 안 되며 짧은 안정 구간 이후 또는 조작
  Commit 시 갱신합니다.
- 필터 컨트롤은 안정적으로 유지하고 결과 영역만 Loading을 전달합니다.
- 전체 페이지를 Remount하지 않고 Focus와 가까운 Scroll Context를 보존합니다.

### 적용 상태 Action

- 결과 요약에서 적용 필터 하나를 제거하면 모든 Viewport에서 즉시 반영합니다.
- 모든 적용 필터 초기화도 즉시 반영하며 활성 범위의 승인된 기본 탐색 상태로
  복구합니다.
- 적용 조건, 결과 수 및 결과는 같은 Commit 상태를 설명해야 합니다. 모바일의
  임시 선택을 이미 적용된 것처럼 표시하면 안 됩니다.
- 결과 집합을 바꾸는 필터와 정렬은 묶음 불러오기를 첫 묶음으로 초기화합니다.
- 모든 Viewport에 확인 단계를 추가하는 대신 요청 취소, 오래된 응답 거부 및
  Cache·Query 최적화로 성능을 보호합니다.

### 승인된 로그인 사용자 개인 기록 세부 필터

개인 기록 세부 필터는 로그인 사용자를 위한 고급 기능입니다. 일반 악곡·채보
탐색보다 항상 펼쳐진 주요 필터 Group으로 승격하지 않고 부차적으로 유지해야
합니다.

- 도메인에 의미 있는 상태와 목표 조건인 **미플레이**, **S**, **FC** 및
  **Pianist**를 유지합니다.
- **최근 30일 내 플레이**는 제거합니다. 다른 필터와 기간을 교차하는 근거가
  약한 사용 사례만 별도로 지원하면서 지속적인 조건을 하나 더 만들기 때문입니다.
  로그인 사용자의 **최근 플레이순**이 최근에 플레이한 악곡으로 돌아가는
  목적을 이미 지원합니다.
- **클리어** 필터는 제공하지 않습니다. NOSTALGIA에서 클리어 상태는 이 탐색
  과업을 유의미하게 구분하지 않으므로 현재 컨트롤은 실제 사용자 목표를
  나누지 못합니다.
- 판정 수준 수치 세부 필터는 선택적인 최솟값과 최댓값을 갖는 포괄 범위
  **MISS 수** 하나만 제공합니다. 비어 있는 한쪽 값은 제한 없음입니다.
- MISS 수는 최근 플레이나 MISS+NEAR 비율이 아니라 대상 난이도마다 저장된
  사용자의 최고 기록을 기준으로 계산합니다.
- 서로 다른 Group의 조건은 `AND`, 같은 Group 안의 여러 값은 `OR`로
  결합합니다.
- **미플레이**는 모든 달성 기록 조건과 상호 배타적이며 최근 플레이순도 의미가
  없습니다. 불가능하거나 오해를 만드는 Query를 만들면 안 됩니다.
- 최근 플레이순이 활성 상태일 때 사용자가 **미플레이**를 선택하면 필터를
  받아들이고 임시 또는 Commit된 정렬을 현재 Context 기본값으로 초기화합니다.
  활성 Text Query에서는 관련도순, 빈 악곡 범위에서는 일본어 읽기순, 빈 채보
  범위에서는 최신 공개 채보순을 사용합니다.
- **미플레이**가 활성 상태인 동안 최근 플레이순은 숨기지 않고 발견 가능한
  비활성 상태로 유지합니다. **미플레이 악곡에는 사용할 수 없음**에 해당하는
  간결한 다국어 사유 하나를 제공합니다.
- 정렬 선택이 결과 구성을 조용히 바꾸면 안 됩니다. 따라서 **미플레이**가
  활성 상태이면 최근 플레이순을 선택할 수 없고, 최근 플레이순이 미플레이
  필터를 자동으로 지워서도 안 됩니다. 최근 플레이순으로 돌아가려는 사용자가
  미플레이를 먼저 제거합니다.
- **미플레이**를 제거해도 이전 최근 플레이순을 자동 복구하지 않습니다. 사용자가
  다른 정렬을 명시적으로 고를 때까지 현재 보이는 대체 정렬을 유지하며 숨은
  정렬 History Stack을 만들지 않습니다.
- 결과가 보이는 데스크톱에서는 이 전환을 즉시 반영합니다. 결과를 가리는 모바일
  Layer에서는 임시 필터와 정렬만 함께 갱신하고 **결과 보기**가 둘을 Commit합니다.
  닫기, 뒤로가기 또는 Escape는 이전에 Commit된 두 값을 모두 복구합니다.
- ◆JUST 비율, MISS+NEAR 비율, FAST/SLOW 경향 및 스탠다드·테누토·글리산도·
  트릴 성공률 탐색 필터를 제거합니다. 이러한 값은 해석할 수 있는 기록 상세
  Context의 분석 데이터로 유지합니다.
- MISS 수는 기본 공개 필터 집합으로 승격하지 않습니다. 일반 Catalog 탐색이
  아니라 집중 연습 계획을 지원하므로 점진적으로 공개되는 로그인 개인 기록
  Group에 둡니다.

이 Group은 공개 필터 다음에 접힌 상태로 두며 로그인 사용자가 명시적으로 열기
전까지 펼치지 않습니다. 비로그인 사용자에게는 비활성화된 조건이나 내부 로그인
안내를 보여주지 않고 개인 기록 Group 전체를 생략합니다. 일반 탐색은 공개
상태를 유지하며 인증 홍보가 세부 필터 과업에 불필요한 정보를 추가하면 안
됩니다.

## 명시적인 점진적 불러오기

- Scroll 위치를 기준으로 결과를 자동으로 더 불러오지 않습니다.
- 처음 `20`개 결과 단위를 반환하고 실행할 때마다 `20`개를 추가합니다. 악곡
  결과 단위는 악곡 하나이고, 채보 결과 단위는 대상이 되는 공개 난이도를
  포함한 악곡 Group 하나입니다.
- 악곡·채보 범위, 목록·Grid 보기, 좁고 넓은 레이아웃에서 같은 논리적 묶음
  크기를 유지합니다. 반응형 보기 변경이 결과 단위를 조용히 추가하거나
  제거하면 안 됩니다.
- 다음 묶음이 있으면 현재 Collection 뒤에 명확한 **더 보기** 컨트롤을
  제공합니다. 보이는 다국어 Label은 실제 다음 수량을 사용합니다. 다음
  묶음은 **결과 20개 더 보기**, 마지막 세 개만 남으면 **결과 3개 더 보기**로
  표시합니다.
- 전체 수를 확인한 Commit Query에서는 **583개 중 20개 표시**처럼 정확한
  진행을 보여줍니다. 정확한 전체 수가 아직 준비 중이면 전체 값을 추측하지
  않고 현재 표시 수만 보여줍니다.
- 활성화하면 이미 보이는 Collection을 제거하거나 재정렬하지 않고 다음 묶음을
  추가합니다.
- Loading 중에도 컨트롤 위치를 안정적으로 유지하고 다국어 **불러오는 중…**
  상태로 Label을 바꾸며 결과 영역을 Busy로 표시하고 중복 실행을 막습니다.
- 추가가 성공하면 새로 추가된 첫 실행 가능 결과로 Focus를 옮기고, 추가된
  수량과 새 표시 진행을 절제된 Polite 상태 메시지로 알립니다. 이는 사용자가
  직접 실행한 이어보기이며 일반 검색 갱신에 의한 자동 Focus 변경이 아닙니다.
- 증분 불러오기 실패 시 기존 결과를 유지하고 같은 위치에서 재시도를
  제공하며 실패한 Action에 Focus를 유지합니다.
- 더 이상 결과가 없으면 Action을 제거하고 다국어 **모든 결과를
  확인했습니다.** 완료 상태를 전달합니다. 설명 없이 비활성화된 컨트롤을
  남기지 않습니다.
- 범위, Query, 적용 필터, 정렬 및 보기는 공유 가능한 URL에 지속 탐색 조건으로
  보존합니다. 불러온 결과 수, 선택 결과 Anchor 및 의미 있는 Scroll 위치는
  일시적인 묶음 상태를 공개 URL에 추가하지 않고 해당 Browser History 항목에
  보존합니다.
- 악곡 상세나 집중형 채보 뷰어에서 돌아올 때 이전에 불러온 `20`개 단위 묶음을
  먼저 다시 구성한 뒤 선택 결과 Anchor와 가까운 읽기 위치를 복구합니다.
  복사한 URL을 새로운 History Context에서 열면 첫 `20`개부터 시작합니다.
- 후속 2.0 결과 Component는 대표 모바일·데스크톱 브라우저에서 결과
  `20`·`60`·`100`개 누적 상태로 검증합니다. Virtualization을 미리 의무화하기
  전에 카드 Markup, 재킷 Lazy Loading 및 Rendering을 최적화합니다. 측정한
  상호작용, Memory 또는 DOM 비용이 여전히 요구할 때만 접근 가능한 Windowing을
  도입하며 승인된 사용자 대면 `20`개 묶음 규칙을 조용히 바꾸지 않습니다.

## 콘텐츠 및 기능 요구사항

### 항상 제공하는 구조

1. 일반 반응형 헤더와 건너뛰기 Link
2. 페이지 정체성과 간결한 활성 범위 Context
3. 범위를 인식하는 검색창
4. 필터 및 정렬 진입
5. Commit된 필터 상태가 있는 결과 요약
6. 악곡 또는 채보 범위 결과 Collection
7. 필요할 때 명시적인 점진적 불러오기 컨트롤
8. 일반 푸터

최종 시각 순서와 Grouping은 너비에 따라 적응할 수 있지만 검색, Commit된
상태, 결과 및 복구 컨트롤은 명확한 의미 관계를 유지해야 합니다.

### 필수 결과 데이터

#### 악곡 범위

- 안정적인 악곡 식별자
- 재킷 이미지
- 원문 제목
- 활성화되어 있고 사용할 수 있을 때 선택한 승인 한국어·영어 제목 또는
  일본어 읽기
- 사용할 수 있을 때 아티스트
- Category Context
- 이용 가능한 모든 공식 난이도와 레벨 정보
- 선택하면 악곡 상세가 열린다고 예측할 수 있는 충분한 목적지 Context
- 사용자가 전환할 수 있는 목록 보기와 재킷 중심 Grid 보기

#### 채보 범위

- 안정적인 악곡 식별자와 정체성
- 원문 및 선택한 번역·읽기 제목 처리
- 악곡을 구분하는 데 유용할 때 아티스트
- 일치하는 공개 난이도 Target만 표시
- 선택 가능한 모든 Target의 난이도와 레벨
- 선택 가능한 난이도마다 직접 연결되는 명확한 집중형 뷰어 목적지

### 승인된 결과 보기 구조

- 악곡 범위는 목록 보기를 기본으로 엽니다. 시각적 식별이 더 유용할 때
  사용자가 재킷 중심 Grid 보기로 전환할 수 있습니다.
- 채보 범위는 하나의 Grouping 목록 표현만 사용합니다. 채보 Grid 전환은
  추가하지 않습니다. 주요 Action은 재킷 비교가 아니라 올바른 악곡 정체성
  아래에서 공개 난이도 Target을 고르는 것입니다.
- 채보 결과는 악곡 정체성을 먼저 보여주고 그 아래에 일치하는 공개 난이도
  Target을 안정적인 난이도 순서로 제공합니다.
- 어느 결과 Collection 위에도 난이도 컨트롤 행을 상시 추가하지 않습니다.
  필터, 레벨순 Target 및 채보 목적지 Target은 의미가 다르며 하나의 반복적인
  컨트롤 Strip으로 합치면 안 됩니다.
- 현재 NosLog 악곡 목록과 Grid의 유용한 구조 모델을 2.0 기준선으로 보존하되,
  아래 규칙으로 명시합니다. Screenshot이나 “현재 UI 재사용”이라는 지시만으로는
  후속 디자인 명세가 충분하지 않습니다.
- 정확한 Typography, 간격, 색상 및 Motion Token은 Foundation과 Component
  Specimen 단계에 남깁니다. 이 Token은 시각 표현을 다듬을 수 있지만 승인된
  콘텐츠 순서, 밀도 경계 또는 상호작용 모델을 조용히 바꾸면 안 됩니다.
  정확한 채보 행 시각 구조는 후속 채보 결과 명세에서 다룹니다.

### 승인된 악곡 결과 구조와 밀도

#### 공통 정체성과 실행

- 각 악곡 결과 전체를 악곡 상세로 가는 하나의 Link로 사용합니다. 공식 난이도
  값은 간결한 정보이며 별도 이동 Button이 아닙니다.
- 제목 Group은 다음 순서를 유지합니다.
    1. 선택적 승인 번역 제목 또는 일본어 읽기: 가장 작고 강조가 낮은 Caption
    2. 원문 제목: 가장 크고 강한 주요 정체성
    3. 아티스트: 제목 Group 아래의 보조 정체성
- 번역·읽기 Caption과 원문 제목은 하나의 제목 Group으로 읽히도록 가깝게 두고,
  아티스트 앞에는 더 명확한 간격을 둡니다. 선택 Caption을 끄거나 사용할 수
  없으면 그 공간을 완전히 접습니다.
- Category는 재킷 위의 작은 Text Badge로 계속 보입니다. Badge 색상에만
  의존하지 않으며 아티스트와 같은 행에 두지 않습니다.
- 탐색 카드에서 시각적으로 말줄임하더라도 접근 가능한 이름과 악곡 상세에는
  원문 제목과 아티스트 전체 값을 보존합니다.

#### 목록 보기

- 재킷은 `56px`로 유지하고 공식 난이도는 현재 약 `92px` 전체 너비의 간결한
  후행 Group에 두며 `20px` Badge를 구조 기준선으로 사용합니다. 난이도를 별도
  행으로 옮기지 않습니다.
- 하나의 커진 고정 행 대신 콘텐츠 기반 카드 높이를 사용합니다. 번역·읽기
  Caption이 없는 짧은 결과는 약 `64px`, 일반적인 번역 결과는 약 `80px`,
  원문 제목이 두 줄이면 약 `96–100px`까지 늘어날 수 있습니다.
- 번역·읽기 Caption은 한 줄, 원문 제목은 두 줄, 아티스트는 말줄임과 함께 한
  줄로 제한합니다. 아티스트나 번역이 없을 때 빈 구조 행을 남기지 않습니다.
- 감사한 `390px` 기준선에서 결과 카드 너비는 약 `343px`이며, 간결한 후행
  난이도 Group이 세로 난이도 행보다 적합합니다.
- 결과 영역이 카드마다 약 `440–460px`의 사용 가능 너비를 주지 못하면 목록을
  한 열로 유지합니다. 두 카드가 모두 그 최솟값을 보존할 때만 두 열을
  사용합니다. 목록은 최대 두 열이며 더 조밀한 Artwork 탐색은 Grid가
  담당합니다. 이 전환은 기기 이름 Breakpoint가 아니라 결과 Container 공간을
  따릅니다.

#### Grid 보기

- 모든 재킷은 `aspect-ratio: 1 / 1`로 정확한 정사각형을 유지합니다. 카드 전체가
  정사각형일 필요는 없습니다.
- 재킷 아래 정보 영역은 독립적으로 늘어날 수 있습니다. 모든 카드에 일관된
  아티스트 두 줄 영역을 확보하고 두 번째 줄 뒤에서 말줄임하여 난이도 위치와
  행 정렬을 안정적으로 유지합니다.
- Category Text Badge를 재킷 위에 두고 공식 난이도 정보는 정체성 아래에 두며,
  목록과 같은 번역·읽기 Caption → 원문 제목 → 아티스트 계층을 사용합니다.
- `390px` 모바일 기준선에서는 두 열을 사용합니다. 더 넓은 결과 영역은 검증된
  최소 가독 카드 너비에 따라 열을 추가할 수 있습니다. 정확한 Foundation
  Breakpoint는 미확정이지만 두 카드를 늘리는 대신 대략 세 열에서 다섯 열
  범위를 의도합니다.
- 감사한 모바일 카드는 약 `168 × 261px`입니다. 아티스트 한 줄을 더 확보하면
  약 `168 × 279px`, 약 7% 높아질 수 있으며 정사각형 재킷을 왜곡하지 않습니다.

### 승인된 개인 기록 미리보기

- 평상시 악곡 결과는 악곡 정체성에 집중합니다. 개인 필터나 정렬이 활성화됐다는
  이유만으로 카드에 기록 설명 한 줄을 상시 추가하지 않으며, Commit된 조건은
  결과 요약에서 계속 확인합니다.
- Hover 기능과 정밀 Pointer를 모두 보고하는 기기에서는 결과에 Hover하면
  간결한 개인 기록 미리보기를 보여줍니다. Viewport 너비로 이 기능을 추정하지
  않습니다. Keyboard Focus에서도 동등한 정보와 동작을 제공합니다.
- 미리보기는 별도 Popup, 확장 Panel, Action 또는 후행 난이도 Group만 바꾸는
  요소가 아니라 같은 결과 카드의 대체 상태입니다. 나타날 때 카드 크기를
  바꾸거나 결과 레이아웃을 이동하면 안 됩니다.
- 목록 보기에서는 재킷 이미지를 선명하게 유지하고 제목 Text, 아티스트,
  Category Badge 및 공식 난이도를 포함한 나머지 평상시 정보를 어둡게 하거나
  가립니다. 그 재킷 외 영역에 기록 미리보기를 표시합니다.
- Grid 보기에서는 재킷을 포함한 평상시 카드 전체를 어둡게 하거나 부드럽게
  처리하고 카드 위에 기록 미리보기를 표시합니다.
- 난이도 필터가 하나이면 일치한 난이도 기록을 미리 봅니다. 여러 난이도 필터가
  있으면 실제로 일치하는 모든 난이도의 기록을 보여줍니다. 난이도 필터가 없으면
  해당 악곡에서 사용자가 가장 최근에 플레이한 난이도를 미리 봅니다.
- 간결한 기록 행에는 사용할 수 있을 때 난이도, ◆JUST 비율, 절대 MISS 수 및
  달성 상태를 넣습니다. 예:
  `Expert · ◆JUST 92.4% · MISS 3 · FC`.
- ◆JUST와 JUST는 서로 다른 NOSTALGIA 판정입니다. 사용자 대상 Copy에서
  ◆JUST를 `S-Just`로 바꾸지 않습니다.
- Touch 레이아웃은 Hover를 흉내 내거나 첫 Tap에 공개하거나 Long Press를
  사용하거나 기록 미리보기 Button을 추가하지 않습니다. 한 번 Tap하면 카드
  전체 Link를 통해 악곡 상세로 바로 이동하고 그곳에서 전체 기록 Context를
  제공합니다.
- Pointer나 Focus가 벗어나거나 사용자가 Escape로 닫을 때까지 미리보기를
  유지합니다. Enter는 계속 악곡 상세 Link를 실행합니다. 모션 감소 설정에서는
  전환을 최소화합니다.
- Near, FAST/SLOW 및 노트 종류별 성공률은 상세 기록 분석에서 유지하지만
  간결한 탐색 미리보기에는 넣지 않습니다.

악곡의 필수 Field, 목록 기본·Grid 선택 모델, 악곡 카드 구조와 밀도 경계,
기능 기반 미리보기 및 채보 Grouping 목록 모델은 승인됐습니다. Foundation
Token과 정확한 채보 행 시각 구조는 악곡 카드 구조의 미확정 사항이 아니라
후속 명세 작업으로 남습니다.

### 승인된 결과 없음 분류와 복구

결과 서비스는 확정된 결과 0개 응답에 표시 Copy를 고르기 전에 원인을 내부적으로
분류해야 합니다. 이 분류는 정확한 Copy, 분석 및 Browser 승인 테스트를 지원하기
위한 것이며 화면에 진단 문단으로 노출하면 안 됩니다.

1. 조회, 권한 또는 전송 실패는 재시도가 있는 오류 상태로 처리하며 결과 없음으로
   표현하지 않습니다.
2. Commit된 필터가 있으면 같은 Commit Query와 범위에서 해당 필터만 제거해
   확인합니다. 이때 공개 결과가 존재하면 필터 조건으로 인한 결과 없음으로
   분류합니다.
3. 채보 범위에서 Commit Query와 호환 필터에 맞는 악곡·난이도 후보는 있지만
   사용할 수 있는 공개 `ChartPattern`이 하나도 없으면 공개 채보 없음으로
   분류합니다. 필터를 제거했을 때 공개 채보가 나타난다면 필터 조건 분류를
   우선합니다.
4. 비어 있지 않은 Query가 필터를 제거한 뒤에도 악곡을 식별하지 못하면 Text
   불일치로 분류합니다.
5. Query와 필터가 모두 비어 있으면 실제로 빈 악곡 Catalog를 검색 불일치와
   구분합니다. 해당 서비스 단위 부재는 검색 안내를 새로 만들지 않고 별도의
   No-data 상태로 보냅니다. 이번 승인은 그 별도 상태의 새로운 표시 Copy나
   Action을 정의하지 않습니다. 빈 채보 Catalog에는 승인된 공개 채보 없음
   상태를 사용합니다.

승인된 표시 동작:

- Commit된 Query, 범위, 정렬, 보기 방식 및 적용 필터를 그대로 유지합니다.
- 검색창, 범위 선택기, 적용 필터 Chip, 개별 제거 및 하나의 전체 필터 초기화
  컨트롤을 원래 위치에서 계속 사용할 수 있게 합니다.
- 전체 필터 초기화는 필터만 제거합니다. Query, 범위, 정렬 및 목록·Grid 선택은
  유지합니다.
- 범위에 맞는 짧은 결과 문장 하나만 표시합니다. 빈 결과 영역 안에 설명 문단,
  복구 안내, Illustration, 추천 콘텐츠 또는 Action을 추가하지 않습니다.
- 빈 상태에서 **검색어 지우기**, **필터 초기화**, **악곡 검색**, **악곡 정보
  보기** 또는 비슷한 Action을 중복하지 않습니다. 보이는 검색·범위·필터
  컨트롤이 이미 해당 복구 경로를 제공합니다.
- Query를 자동으로 지우거나 넓히고, 필터를 제거하거나 범위를 바꾸고, 인기
  악곡 또는 관련 없는 악곡으로 빈 결과를 채우지 않습니다.
- 미리 존재하는 Polite 상태 영역을 통해 확정된 한 줄 결과만 알립니다.
  결과가 0개가 됐다는 이유만으로 Alert를 쓰거나 Focus를 이동하지 않습니다.

### 승인된 일시적 응답과 조회 복구

승인된 입력 안정화 `300ms`와 요청 표시 Threshold `300ms`는 서로 다른
시계입니다. 첫 번째는 Text 입력이 이어지는 동안 요청하지 않게 합니다. 두
번째는 요청이 시작된 뒤에만 흐르며 짧은 요청에서 Loading 처리가 깜빡이지 않게
합니다.

1. **빠른 초기 또는 교체 요청:** 최신 요청이 시작 후 `300ms` 안에 끝나면 결과
   Collection을 원자적으로 교체합니다. Spinner, Skeleton, Loading Label,
   Dimming 처리 또는 중간 Live Region 메시지를 보이지 않습니다. 컨트롤 Focus와
   Scroll 위치를 유지하고 확정된 결과 수 또는 결과 없음 상태만 한 번 알립니다.
2. **느린 초기 요청:** Commit된 결과 Collection이 없고 최신 요청이 `300ms`
   뒤에도 대기 중이면 실제 검색·범위·정렬·필터 컨트롤을 계속 사용할 수 있게
   유지하고 결과 영역만 간결한 결과 형태의 Skeleton으로 교체합니다. 재킷,
   제목, Metadata Block은 Collection 구조를 근사하되 최종 세부를 전부
   흉내내지 않습니다. 대표 초기 Viewport 안에 들어가야 하며 전체 화면 Overlay
   또는 중앙 Spinner가 되면 안 됩니다. 정확한 Skeleton 수량과 Foundation
   Style은 후속 Specimen 작업으로 남깁니다.
3. **느린 교체 요청:** Commit된 결과 Collection이 이미 있으면 요청이 `300ms`
   를 넘을 때 Skeleton으로 바꾸지 않고 유지합니다. Collection을 시각적으로
   약화하고 안정적인 결과 요약 안이나 인접 위치에 간결한 진행 표시 하나를
   보이며 결과 영역을 Busy로 노출합니다. 검색·범위·정렬·필터 컨트롤은 계속
   사용할 수 있어 사용자가 요청을 수정할 수 있습니다. 느린 상태가 보인 뒤에는
   오래된 결과 카드가 Commit된 요청과 맞지 않으므로 실행되면 안 됩니다.
   Threshold 전에는 오래된 시각 상태를 표시하지 않으므로 바뀌지 않은
   Collection이 정상적으로 실행 가능해도 됩니다.
4. **요청 대체:** 오래된 요청은 취소하거나 논리적으로 무효화합니다. 최신
   요청만 Collection을 확정하고 URL 기반 결과 상태를 갱신하며 Busy 상태를
   지우거나 결과를 알릴 수 있습니다. 취소되거나 오래된 요청은 보이는 오류가
   되지 않습니다.
5. **초기 또는 교체 실패:** Commit된 Query, 범위, 정렬, 보기 및 필터를
   유지합니다. 결과 영역만 승인된 범위별 한 줄 조회 오류와 **다시 시도**
   Action 하나로 교체합니다. 맞지 않는 오래된 Collection을 무기한 남기거나,
   Route 전체 오류 화면으로 Redirect하거나, Toast만 유일한 복구 수단으로
   쓰거나, 문단·Illustration을 추가하거나, 실패를 결과 0개로 잘못 분류하지
   않습니다.
6. **재시도:** 초기 오류에는 Autofocus하지 않습니다. 사용자가 **다시 시도**를
   실행하면 해당 컨트롤에 Focus를 유지하고 중복 실행을 막으며 Focus Node를
   제거하지 않은 채 요청을 Busy로 노출합니다. 다시 실패하면 **다시 시도**에
   Focus를 유지하고 간결한 오류를 한 번 Polite하게 알립니다. 성공하면 재시도
   컨트롤을 제거하고 Collection을 복구하며 안정적인 결과 요약으로 Focus를
   옮긴 뒤 확정된 결과를 한 번 알립니다.
7. **유한 Timeout Gate:** 운영 지연을 측정하기 전에 가이드에서 고정 Timeout을
   임의로 만들지 않습니다. 구현 승인 전 대표 운영 `p95`/`p99` 지연, Platform
   제한 및 Backend 취소 동작을 근거로 유한한 요청 Timeout을 선택·기록해야
   합니다. 측정값은 같은 조회 실패·재시도 모델로 연결되어야 하며 무한 대기는
   허용하지 않습니다.

## 반응형 요구사항

### 좁은 레이아웃

- 범위 인식 검색, 간결한 Commit 상태, 결과, 명시적인 더 보기 순서로 하나의
  강한 세로 과업 흐름을 유지합니다.
- 밀도 높은 컨트롤을 영구 콘텐츠 열에 두지 않습니다. 하나의 Label된 Trigger로
  정렬·필터를 승인된 결과 가림 Layer 안에 열되, 결과 요약에는 현재 정렬과 적용
  필터 수를 계속 표시합니다.
- 모바일 전용 하단 내비게이션이나 범위·필터 Button 행을 상시 추가하지
  않습니다.
- Software Keyboard, 한국어·일본어 IME 조합, 브라우저 Chrome 및 낮은
  Viewport 높이가 필터 완료 Action을 가리지 않아야 합니다.
- 결과 카드는 긴 일본어 제목과 여러 줄 번역 Caption을 가로 Overflow 없이
  처리해야 합니다.
- `390px` 기준선에서 Grid는 두 열, 목록은 한 열을 사용합니다. Grid 재킷은
  정사각형을 보존하고 긴 콘텐츠에는 아래 정보 영역만 늘립니다.

### 넓은 레이아웃

- `390px` 모바일 Canvas를 데스크톱 전체로 늘리지 않습니다.
- 추가 너비를 사용해 노출된 필터 Rail 또는 영역과 결과를 함께 보이게 하고
  악곡·난이도 비교를 개선합니다.
- 필터와 정렬을 직접 Label된 별도 컨트롤로 유지하고 결과를 보면서 즉시
  반영합니다.
- 데스크톱 전용 분류 체계를 만들지 않고 하나의 검색·범위 모델을 보존합니다.
- 검색, 필터 또는 결과 비교를 지원할 공간에 무관한 공지나 내비게이션을
  배치하지 않습니다.
- 대표 결과 카드 테스트 이후 읽기 좋은 외부 콘텐츠 경계를 정합니다. 정확한
  Container와 열 Token은 미확정입니다.
- 목록 카드는 카드당 사용 가능 너비가 약 `440–460px`보다 작으면 한 열로
  유지하고 두 카드 모두 그 너비를 확보할 때만 두 열을 사용하며 두 열을 넘지
  않습니다. Grid는 검증된 최소 카드 너비에 따라 대략 세 열에서 다섯 열까지
  추가할 수 있습니다.

## 접근성 요구사항

- 활성 범위를 포함하거나 Programmatically 연결한 명시적인 검색창 접근 가능
  이름을 제공합니다.
- 간결한 범위 선택기는 선택 값, 펼침 상태, 제어 Popup, Keyboard 동작, 보이는
  Text 선택지 및 예측 가능한 Focus 복귀를 노출해야 합니다.
- 검색 갱신마다 Focus를 이동하면 안 됩니다.
- 결과 수 갱신은 절제된 Live Region 의미를 사용하며 중간의 오래된 응답을
  읽으면 안 됩니다.
- 요청이 `300ms` 표시 Threshold 전에 끝나면 결과 영역의 `aria-busy`를
  `false`로 유지합니다. 요청이 Threshold를 넘으면 최신 요청이 성공, 결과 없음
  또는 실패로 끝날 때까지 `true`로 설정합니다.
- 느린 교체 중 오래된 콘텐츠는 이전 콘텐츠로 인지할 수 있게 유지하지만 보이는
  Busy 상태가 지속되는 동안 결과 Link의 실행과 Keyboard 상호작용을 막습니다.
  검색·범위·정렬·필터 및 취소·수정 컨트롤은 계속 사용할 수 있습니다.
- 결과 형태의 Skeleton은 표현용이며 접근성 Tree에서 숨깁니다. 안정적인 결과
  영역과 상태 Semantic이 Loading을 전달하고 Placeholder Block을 실제 악곡이나
  채보 결과처럼 읽지 않게 합니다.
- 확정된 결과 없음 문장은 미리 존재하는 같은 Polite 상태 영역을 사용해 간결한
  다국어 문장만 알립니다. Focus를 받거나 Alert Semantic을 쓰거나 보이는 복구
  컨트롤을 문장으로 반복하지 않습니다.
- 모바일 필터·정렬 Layer에는 접근 가능한 이름과 Modal 상태의 Focus 제한이
  필요합니다. Escape, 뒤로가기 또는 명시적인 닫기는 임시 변경을 버리고 이전
  결과 읽기 위치를 보존하며 Layer를 연 Trigger로 Focus를 돌려보냅니다.
- 통합 Trigger의 접근 가능한 이름은 정렬을 또 하나의 필터로 취급하지 않으면서
  기능, Commit된 적용 필터 수 및 현재 정렬을 전달해야 합니다.
- 모바일 완료 Action은 브라우저 Zoom과 낮은 Viewport 높이에서도 도달할 수
  있어야 합니다.
- **결과 보기**는 임시 값을 Commit하고 Layer를 닫으며 안정적인 결과 요약을
  보인 뒤 해당 요약으로 Programmatic Focus를 옮깁니다. 결과 요약은 Action이
  되거나 첫 결과를 자동 선택하지 않으면서 Commit된 범위, 결과 수 또는 확정
  결과 상태 및 현재 정렬을 전달합니다.
- Touch, Keyboard 및 Screen Reader 입력에 같은 DOM Focus 목적지를 사용합니다.
  Keyboard 이동에는 보이는 Focus 표현이 필요하며 Pointer 실행에 장식적인
  Focus Ring이 계속 남지 않도록 `:focus-visible`을 사용할 수 있습니다.
- Layer가 닫힐 때 확정 결과가 이미 준비됐다면 Focus된 요약이 방향을 전달하며
  같은 결과 수를 두 번 읽으면 안 됩니다. 결과 요청이 계속 진행 중이면 결과
  영역에 Busy 상태를 노출하고 완료 시 확정된 결과 수, 간결한 결과 없음 문장
  또는 실패 하나만 Polite하게 알립니다. 임시 값이 바뀌지 않은 상태에서
  제출해도 결과 요약으로 돌아가지만 결과가 변경됐다고 알리지는 않습니다.
- 이 모바일 Commit 후 Focus 규칙은 보이는 결과 요약과 필터·정렬 Trigger가
  같은 행을 공유하는지 규정하지 않습니다. 정확한 Grouping은 좁은 화면과
  다국어 Specimen에서 나중에 검증하며 어느 경우든 요약은 독립 Semantic
  요소로 유지합니다.
- 적용 필터 제거 컨트롤의 접근 가능한 이름에는 Category와 값을 포함합니다.
- 미플레이가 최근 플레이순을 초기화하면 같은 상호작용에서 보이는 선택 정렬을
  함께 갱신하고 새로 선택된 정렬을 말하는 간결한 Polite 알림 하나를 제공합니다.
  종속 값이 바뀌었다는 이유만으로 오류를 알리거나 Focus를 이동하지 않습니다.
- 사용할 수 없는 최근 플레이순을 정렬 Surface에서 인지할 수 있게 유지합니다.
  간결한 미플레이 사유를 Programmatic하게 연결하고 비활성 상태를 Semantic으로
  노출하며 색상이나 낮은 불투명도에만 의존하지 않고 실행을 막습니다.
- 모바일 Layer의 임시 상태 알림은 Commit된 결과가 바뀌었다고 말하면 안 됩니다.
  사용자가 취소하면 두 번째 결과 갱신 알림 없이 이전 Commit 필터와 정렬을
  복구합니다.
- Pointer Hover로 개인 기록 미리보기에 드러나는 정보는 Keyboard Focus에도
  제공해야 합니다. 미리보기가 접근 가능한 이름이나 Commit된 필터 상태를
  나타내는 유일한 수단이면 안 됩니다.
- 평상시 콘텐츠를 가리는 미리보기는 Escape로 닫을 수 있고 Hover나 Focus가
  유지되는 동안 계속 표시되며, Enter로 카드 전체 Link를 실행하고 레이아웃을
  움직이지 않아야 합니다.
- Touch 사용자가 결과를 실행하기 전에 가상의 Hover 단계를 거치게 하면 안 됩니다.
- **더 보기**는 Keyboard로 작동하는 명시적 컨트롤이어야 합니다. 추가된 실행
  가능 결과는 이동한 컨트롤보다 문서 순서상 앞에 오므로, 사용자가 직접 실행한
  추가가 성공하면 첫 새 결과로 Focus를 옮기고 추가 수와 표시 진행을 알립니다.
  실패하면 Action에 Focus를 유지합니다.
- 결과 영역은 현재 갱신이 끝나지 않은 동안만 `aria-busy`를 노출하고, Polite
  상태 영역은 중간 상태를 반복하지 않고 확정된 Loading·성공·실패·완료 메시지
  하나를 알립니다.
- 초기 조회 실패는 Focus를 빼앗지 않습니다. 재시도 대기 중에는 Focus된 재시도
  컨트롤을 보존하고 해당 Node를 제거하지 않은 채 중복 실행을 막습니다. 반복
  실패는 Focus를 그곳에 유지하며 성공하면 재시도 컨트롤이 사라지므로 안정적인
  결과 요약으로 Focus를 옮깁니다.
- 취소되거나 대체됐거나 순서가 뒤바뀐 요청은 실패나 결과를 알리지 않습니다.
- 의미 있는 결과 Heading·목록과 하나의 페이지 단위 `main` Landmark를
  사용합니다.
- 범위, 필터, 초기화, 결과 및 점진적 불러오기 컨트롤은 WCAG 2.2 Target 크기
  또는 Target 간격 요구사항을 충족합니다.

## 다국어 요구사항

- 모든 보이는 라벨과 접근 가능한 라벨을 한국어, 일본어 및 영어에서
  검증합니다.
- 악곡 원문 제목을 주요 정체성으로 보존합니다.
- 제목 표시 설정을 켰으면 승인된 한국어·영어 제목 또는 일본어 읽기를 원문을
  대체하지 않는 작은 보조 Caption으로 원문 제목 위에 표시합니다.
- 목록에서는 Caption 한 줄, 원문 제목 두 줄, 아티스트 한 줄로 제한합니다.
  Grid에서는 아티스트 두 줄을 확보합니다. 접근 가능한 이름과 상세 목적지에는
  전체 값을 보존하여 시각적 말줄임이 유일한 완전한 식별 Text를 없애지 않게
  합니다.
- Text 검색과 `300ms` 유휴 Trigger는 한국어·일본어 IME 조합을 안전하게
  처리해야 합니다.
- 동적 결과 수, 표시 범위 및 더 보기 수량은 Locale에 맞는 숫자와 문법 처리가
  필요하며 안전하지 않은 문자열 연결로 만들면 안 됩니다.
- 승인된 점진적 불러오기 표시 Copy Pattern을 사용합니다.
    - 한국어: `결과 20개 더 보기`, `583개 중 20개 표시`,
      `모든 결과를 확인했습니다.`
    - 일본어: `結果をあと20件表示`, `583件中20件を表示`,
      `すべての結果を確認しました。`
    - 영어: `Load 20 more results`, `Showing 20 of 583`,
      `You have viewed all results.`
      마지막 일부 묶음에서는 `20`을 실제 다음 수량으로 바꿉니다. 접근 가능한
      Action 이름에는 보이는 Label을 길게 만들지 않으면서 활성 악곡·채보 검색
      Context를 추가합니다.
- 페이지 패밀리 승인 전에 세 언어의 범위, 필터, 난이도, 결과 상태, 재시도 및
  끝 상태 Copy를 모두 준비해야 합니다.
- Subtitle 없이 승인된 조회 실패·재시도 Copy를 사용합니다.
    - 악곡 범위 — 한국어: `악곡을 불러오지 못했습니다.`; 일본어:
      `楽曲を読み込めませんでした。`; 영어: `Couldn’t load songs.`
    - 채보 범위 — 한국어: `채보를 불러오지 못했습니다.`; 일본어:
      `譜面を読み込めませんでした。`; 영어: `Couldn’t load charts.`
    - 재시도 — 한국어: `다시 시도`; 일본어: `再試行`; 영어: `Try again`.
      구현 승인 전 Native Language QA에서 문장부호, 어조 및 접근 가능한 Busy
      확장 문구를 검증해야 하지만, 결정을 다시 열지 않고 보이는 상태를 설명
      본문으로 늘리면 안 됩니다.
- 설명 Subtitle 없이 승인된 다음 결과 없음 표시 Copy를 사용합니다.
    - Text 불일치 — 한국어: `일치하는 악곡이 없습니다.`; 일본어:
      `一致する楽曲がありません。`; 영어: `No matching songs.`
    - 필터 조건 악곡 없음 — 한국어: `조건에 맞는 악곡이 없습니다.`; 일본어:
      `条件に一致する楽曲がありません。`; 영어:
      `No songs match these conditions.`
    - 공개 결과 0개인 채보 범위 — 한국어: `공개된 채보가 없습니다.`; 일본어:
      `公開された譜面がありません。`; 영어: `No published charts.`
      이 문장들은 본문 Copy가 필요한 제목이 아니라 그 자체로 완전한 표시
      상태입니다.
- 번역하면 공유나 구현 Mapping이 깨지는 Query·필터 URL 값에는 안정적인 기술
  식별자를 유지합니다.
- 빈 악곡 탐색은 모든 Locale에서 `title_kana`를 기술 정렬 Key로 사용합니다.
  번역 표시 설정은 보이는 보조 Text만 바꾸며 Catalog 순서를 바꾸지 않습니다.
- 정렬 Label, 방향 및 명시적인 레벨순 난이도 Target에는 완전한 한국어·일본어·
  영어 이름이 필요합니다. 색상이나 약어만으로 난이도 Target을 표현하지
  않습니다.

### 모바일 Commit 후 Focus 비교

집중 비교에서는 일반 Dialog 닫기와 결과 중심 필터 Workflow 완료를 분리합니다.
일반 Dialog System은 Layer를 연 Trigger로 Focus를 돌려보내는 방향에 수렴하지만,
WAI-ARIA APG는 Dialog 과업이 다음 단계로 직접 이어지면 더 논리적인 Workflow
목적지를 허용합니다. 필터 전용 System은 명시적인 모바일 Commit, 보이는 결과 요약
및 갱신 결과로의 방향 제시에 수렴합니다. Primer가 개별 필터 선택마다 Focus를
옮기지 말라고 한 내용은 NosLog와 충돌하지 않습니다. 선택 중에는 임시 상태를
유지하고 사용자가 **결과 보기**를 실행한 뒤에만 Focus를 옮기기 때문입니다.

따라서 NosLog는 입력 방식과 무관한 DOM 규칙 하나를 사용합니다. 모바일
**결과 보기** 성공은 안정적인 요약을 보이고 Focus하며, 취소·뒤로가기·Escape는
Layer를 연 Trigger와 이전 읽기 Context를 복구합니다. 확정 데이터가 준비됐다면
Focus된 요약을 한 번만 읽고, 대기 중이면 Busy 상태 뒤 확정 결과 하나만
Polite하게 알립니다. 데스크톱과 일반 검색 갱신은 컨트롤 Focus를 유지합니다.
요약의 같은 행·분리 행 시각 선택은 Focus 규칙이 아니라 다국어 `390px`
Specimen 결정으로 남깁니다.

### 결과 없음 복구 비교

승인된 처리는 현재 제품, 필터 중심 시스템, 빈 상태 시스템, 접근성 표준, 검색
Platform 및 리듬게임 Catalog 구조를 포함한 19개 항목 비교를 따릅니다. 레퍼런스는
정확한 상태, 사용자 작업 보존 및 사용할 수 있는 복구 경로의 필요성을 뒷받침합니다.
관련 컨트롤이 이미 보일 때 NosLog가 설명 Copy나 새 Button을 추가해야 한다는
뜻은 아닙니다.

근거의 수렴:

- Commit된 Query와 컨트롤을 보존하고 사용자가 탐색을 다시 시작하게 하지
  않습니다.
- 일부 표시 문장을 의도적으로 간결하게 유지해도 Text 불일치, 필터 조건, 공개
  부재, Catalog 부재 및 조회 실패는 구분합니다.
- 적용 조건을 제거할 수 있게 유지하고 필터만 지우는 전체 초기화 하나를
  제공합니다.
- Focus를 이동하거나 결과 0개를 오류로 취급하지 않고 확정된 Polite 상태를
  알립니다.
- 다음 단계는 주변 컨트롤이 제공할 수 있습니다. 설명 본문과 빈 상태 Button은
  본질적인 필수 요소가 아니라 선택 사항입니다.

근거의 불일치와 NosLog 결정:

- Commerce 검색은 Query 확장, 관련 재고 또는 인기 콘텐츠를 자주 권장합니다.
  NosLog는 정확한 악곡과 공개 의미를 흐릴 수 있으므로 해당 대체를 거절합니다.
- 여러 Component System은 제목, 본문, Image 및 CTA를 예시로 듭니다. NosLog는
  검색·범위·적용 필터 복구가 계속 보이고 과업이 빠르고 반복적인 Catalog
  검색이므로 Text만 사용합니다.
- 일부 시스템은 상세 원인 설명을 표시합니다. NosLog는 결과 서비스, 분석 및
  테스트에는 자세한 원인 논리를 유지하되 Interface에는 승인된 한 줄 다국어
  문장만 사용합니다.

### 점진적 불러오기 비교

승인된 `20`개 결과 규칙은 측정한 NosLog 근거를 포함한 24개 항목 비교를
따릅니다. 출처는 명시적인 사용자 제어, 예측 가능한 수량, 보이는 진행, 확정된 상태
전달, 제한된 초기 작업 및 복구 가능한 History에 수렴합니다. 하나의 보편 수량과
Focus를 Trigger에 유지할지 새 콘텐츠로 옮길지는 의견이 다릅니다. NosLog는 자체
결과 밀도로 수량을 정하고, 모든 추가 카드가 실행 가능하며 Keyboard 순서에서
이동한 컨트롤보다 앞에 오므로 첫 새 결과 Focus를 선택합니다.

### 미플레이와 최근순 충돌 비교

승인한 전환은 저장소, 도메인, 접근성, Design System, 검색 Platform 및 Collection
제품의 독립 출처 18개와 비교했습니다. 출처는 진실한 정렬 Label, 발견 가능한 임시
비활성 상태, 보존된 적용 상태 Context 및 한 선택이 다른 선택을 바꿀 때의 명시적인
Feedback에 수렴합니다. 일반 System은 서로 충돌하는 두 NosLog 컨트롤 중 무엇이
의미상 우선인지 정하지 않습니다. 필터는 결과 구성을 정하고 정렬은 그 구성의
순서만 바꾼다는 승인 제품 규칙으로 그 우선순위를 해결합니다.

최근순을 Context 기본값으로 교체하고, 정렬 선택은 미플레이를 제거하지 않습니다.
이 방식은 결과를 좁힐 때 단계 수를 줄이면서 정렬 컨트롤이 결과를 조용히 넓히지
못하게 합니다.

### 일시적 응답과 조회 실패 비교

승인된 응답 모델은 현재 NosLog 근거와 최소 16개의 독립적인 외부 출처군을
비교한 결과입니다. 검색 전용 시스템은 짧은 지연 Threshold를, Component
System은 첫 Loading Placeholder와 국소적인 제자리 진행의 구분을, 접근성
지침은 안정적인 Busy 영역과 확정 알림을 뒷받침합니다. 어떤 외부 출처도 보편적
`300ms` 값이나 NosLog의 정확한 오래된 카드 규칙을 정하지 않습니다. 이는
빠르고 반복적인 Catalog 과업에 대해 승인한 제품 차원의 해결입니다.

승인된 종합:

- 두 `300ms` 시계를 분리합니다. 입력 안정화가 요청보다 먼저이고 Loading 표시는
  요청이 시작된 뒤에만 셉니다.
- 빠른 응답에는 일시 UI를 쓰지 않고, 느린 첫 Collection에는 결과 형태 Skeleton,
  느린 교체에는 약화한 기존 결과를 사용합니다.
- Feedback과 실패를 결과 영역으로 제한하고 탐색 컨트롤과 Commit 상태를
  보존합니다.
- 교체 결과가 시각적으로 오래된 상태가 된 뒤에는 실행을 막되 요청 수정은 계속
  허용합니다. 최신 요청만 결과를 확정하거나 알릴 수 있습니다.
- 조회 실패는 결과 0개가 아니라 범위별 한 줄과 재시도가 있는 오류입니다.
  재시도 중 Focus를 보존하고 성공 후 Focus된 컨트롤이 사라질 때만 이동합니다.
- 구현 승인 전 운영 지연과 Platform 제약을 측정해 유한한 요청 Timeout을
  고릅니다. 임의의 외부 지속 시간을 복사하거나 무한 대기를 허용하지 않습니다.

### 근거의 수렴

- 결과가 계속 보이고 동작이 단순하며 응답 성능이 안정적이면 능동 갱신이 가장
  유용합니다.
- 사용자가 여러 관련 조건을 고르거나 결과가 가려지면 묶음 Commit이 가장
  유용합니다.
- 모바일 적용은 필요한 결과 복귀를 함께 수행할 때만 저마찰 방식입니다. 적용
  뒤에 별도 닫기를 요구하면 피할 수 있는 작업을 추가합니다.
- 갱신 방식과 관계없이 Query, Commit 필터, 결과 수 및 보이는 결과가 서로
  모순되면 안 됩니다.
- 모든 Viewport에 확인 단계를 추가하기 전에 안정된 입력, 요청 취소, Cache 및
  국소적인 결과 Loading으로 성능을 보호해야 합니다.
- NOSTALGIA는 많은 기록 차원을 제공하지만 도메인 데이터가 존재한다는 사실만으로
  모든 수치가 효과적인 Catalog 필터가 되지는 않습니다.
- 절대 MISS 수는 NOSTALGIA Mission 데이터와 비교 가능한 리듬게임 Catalog
  도구에서 직접적인 연습 목표 근거가 있습니다. 승인된 사용자 요구에는
  MISS+NEAR 합산 비율보다 해석하기 쉽습니다.
- 비교 서비스는 Miss를 필터, 정렬 또는 상세 중 어디에 둘지 서로 다릅니다.
  수렴하는 점은 Miss가 유용한 기록 Context라는 것이지 일반 공개 탐색을
  지배해야 한다는 뜻이 아닙니다.
- 클리어·Lamp 의미는 리듬게임마다 크게 다릅니다. IIDX 분류를 가져오지 않고
  NOSTALGIA 자체의 과업 의미를 따라야 합니다.
- 풍부한 판정과 노트 종류 Breakdown은 분석 데이터로 유용하지만 간결한 탐색
  Surface에는 실행 가능한 조건만 점진적으로 공개하는 편이 적합합니다.
- 공식 Catalog와 Community 채보 Browser는 관련 난이도를 한 악곡 정체성
  아래 유지하는 데 수렴하지만 목록과 Artwork 탐색 중 무엇을 강조하는지는
  다릅니다. NosLog는 악곡 범위에 목록 기본·Grid 선택, 채보 범위에
  Grouping 목록 전용을 적용해 해결합니다.
- 완전한 `title_kana` Field는 중립적이고 결정적인 빈 악곡 탐색을 지원합니다.
  출시 최신순에는 신뢰할 수 있는 출시 Metadata가 필요하며 Database 유지보수
  시각으로 흉내 내면 안 됩니다.
- 레벨순은 난이도 기준을 명시해야만 이해할 수 있습니다. Expert 대체값을
  숨기거나 여러 난이도를 섞으면 겉보기에 같은 “레벨” 값의 의미가 달라집니다.
- 모바일 필터·정렬의 통합 및 분리 진입은 모두 확립된 Pattern입니다. 통합
  Trigger는 Label이 두 기능을 모두 말하고 내부 Section을 구분하며 Commit된
  현재 정렬을 계속 보일 때 적합합니다.
- 최근 플레이순이 존재한다는 이유만으로 기간 필터도 정당화되지는 않습니다.
  검증된 교차 조건 과업이 없으면 둘을 모두 두는 것은 별도 고가치 결과 없이
  분류만 늘립니다.
- 긴 아티스트 문자열이 충분히 흔하므로 Category와 아티스트가 같은 행을 두고
  경쟁하면 안 됩니다. 일관된 줄 수 제한과 정렬로 탐색성을 높이되 상세와 접근
  가능한 이름에는 전체 값을 보존합니다.
- 목록 탐색과 재킷 탐색은 필요한 밀도가 다릅니다. NosLog는 간결하고 최대 두
  열인 목록과, 아래 정보 영역이 독립적으로 늘어날 수 있는 정사각형 재킷 Grid를
  유지합니다.
- Hover는 모바일 상호작용 모델이 아니라 선택적인 기능 강화입니다. 같은 카드
  미리보기는 지원 기기에서 Hover와 Keyboard Focus를 사용하고 Touch는 주요
  상세 Link를 즉시 따릅니다.
- 일시적인 컨트롤 종속성은 간결한 이유와 함께 발견 가능하게 유지하고, 영구히
  관련 없는 컨트롤만 생략할 수 있습니다. 미플레이는 결과 구성원을 정하고 최근
  플레이는 그 구성원의 순서만 정하므로 미플레이가 의미상 우선하며 규칙은
  의도적으로 비대칭입니다.
- 점진적 불러오기 레퍼런스는 제한된 초기 요청, 명시적인 사용자 제어, 예측
  가능한 다음 수량, 보이는 진행, 명확한 Busy·오류·끝 상태 및 복구 가능한
  복귀 Context에 수렴합니다. 하나의 보편 묶음 수는 제공하지 않습니다.
- 현재 `390px` 밀도, 기존 Cursor 단위, Catalog 규모 및 보기 간 일관성을
  종합하면 `20`개가 승인된 NosLog 결과 단위 규칙입니다. 한 묶음을 `20`에서
  `16`으로 바꿔도 무제한 누적은 해결되지 않으므로 누적 DOM 비용은 별도로
  검증합니다.
- 검색·Component 레퍼런스는 짧은 요청의 진행 표시 깜빡임 억제, 첫 Loading
  구조와 교체 Feedback의 구분 및 영향 영역으로의 방해 제한에 수렴합니다.
- 접근성 레퍼런스는 안정적인 Busy 영역 하나, 최신 요청만의 확정, 간결한 복구
  및 일반적인 Autofocus 없이 상태를 전달하는 방향에 수렴합니다.
- 근거는 유한한 실패 경계를 지지하지만 하나의 보편 Timeout은 제공하지
  않습니다. 따라서 운영 측정이 숫자 구현 결정에 선행합니다.

### 근거의 차이와 NosLog의 해결

- Visa와 DWP는 묶음 필터를 선호하고 SAP는 가능하면 능동 갱신을 선호합니다.
  Carbon, Dell, NSW, Siemens, Maersk 및 Baymard는 필터 복잡도, 결과 가시성,
  응답 시간 또는 Viewport에 따라 선택합니다.
- NosLog는 한 출처를 보편 규칙으로 택하지 않고 승인된 반응형 혼합형으로 이
  차이를 해결합니다.
- Algolia와 Elastic은 기술적 가능성을 보여주지만 상호작용 자체의 근거가
  되지는 않습니다. 후속 구현은 측정한 지연, 요청 취소 및 접근성 요구사항을
  충족해야 합니다.
- IIDX와 TrackBrowser는 명시적인 MISS 필터를 제공하지만 osu!, ScoreSaber 및
  Tachi 근거에서는 비슷한 통계를 Score, 정렬, 목표 또는 분석 Context에 더 자주
  둡니다. NosLog는 고급 로그인 MISS 범위를 유지하되 공개 주요 Facet으로
  승격하지 않는 방식으로 이 차이를 해결합니다.
- 공식 악곡 Catalog는 안정적인 악곡 Grouping을 선호하고 Community 채보
  서비스는 공개 최신성을 더 강하게 강조합니다. NosLog는 하나의 보편적인 빈
  탐색 정렬을 강요하지 않고 각 범위에 맞는 Pattern을 적용합니다.
- 검색 System은 활성 Query 관련도순을 지원하지만 언제 명시적인 사용자 정렬을
  덮어야 하는지는 레퍼런스마다 다릅니다. NosLog는 명시적 정렬이 없는 능동
  Query에만 관련도순을 사용하고 사용자의 선택을 유지하는 방식으로 해결합니다.
- 일부 지침은 즉각적인 구분을 위해 별도 모바일 필터·정렬 컨트롤을 선호하고
  SAP와 비교 가능한 Catalog Pattern은 통합 진입을 지원합니다. NosLog는 좁은
  화면의 상시 밀도를 줄이기 위해 통합 Trigger를 사용하고 내부 Section은
  분리하며 결과가 보이는 너비에서는 별도 컨트롤을 유지합니다.
- 점진적 불러오기 사례는 작은 검색 Group부터 `20`개·`25`개 Catalog/API
  기본값까지 다양하며 수량을 Context에 맞춰야 함을 확인합니다. NosLog는 외부
  기본값 하나를 보편 규칙으로 보지 않고 측정한 카드 밀도를 사용합니다.
- Primer는 새로 추가한 실행 가능 콘텐츠에 Focus하는 방식을, University of
  Arizona는 더 보기 컨트롤의 Focus를 유지하는 방식을 기록합니다. NosLog는
  새 카드가 이동한 컨트롤보다 문서 순서상 앞에 오므로 첫 새 카드로 Focus를
  옮기고 확정된 Polite 알림 하나로 보완합니다.
- 검색 전용 지침은 수백 Millisecond 정도 뒤 진행을 보일 수 있지만 일반
  Application System은 더 긴 지연을 허용하기도 합니다. NosLog는 반복 검색
  과업이므로 요청 시작 후 `300ms`를 사용하고, 이를 보편값으로 여기지 않고 운영
  환경에서 다시 검증합니다.
- React는 시각적으로 오래된 콘텐츠 유지를 지원하고 SAP식 Busy 처리는 영향
  영역을 막을 수 있습니다. NosLog는 두 방식을 결합해 레이아웃 Context를 위해
  기존 결과를 유지하되 오래된 상태가 보인 뒤에만 실행을 막습니다.
- 일부 Framework는 Route Loading·Error Boundary를 주 단위로 삼습니다.
  NosLog에서는 조회 실패가 결과에만 해당하므로 공용 Shell과 탐색 컨트롤을
  안정적으로 유지합니다.

## 거절되거나 대체된 대안

- **별도 중복 채보 검색 페이지 — 대체:** 명시적인 악곡·채보 범위를 가진 하나의
  탐색 Surface를 유지합니다.
- **악곡·채보 상시 Button 행 — 거절:** 간결한 선행 선택기를 사용하고 Text
  단서와 결과로 범위를 보강합니다.
- **숨은 Expert `8–12` 초기 필터 — 거절:** 초기 악곡 탐색은 이용 가능한 전체
  Catalog를 포함합니다.
- **채보 난이도마다 최상위 카드 하나 — 거절:** 같은 악곡의 일치하는 공개
  난이도를 악곡 정체성 아래에 묶습니다.
- **결과 없음에서 Query 지우기 — 거절:** 사용자의 입력을 유지하고 수정할 수
  있게 합니다.
- **결과 없음 안내 Subtitle — 거절:** 검색·범위·필터 컨트롤이 계속 보입니다.
  명확한 복구 단계를 문장으로 다시 설명하지 않습니다.
- **중복 결과 없음 Action Group — 거절:** 빈 영역에 **검색어 지우기**,
  **필터 초기화**, **악곡 검색** 또는 악곡 상세 Action을 추가하지 않고 Query
  지우기, 필터 제거·초기화 및 범위 전환을 원래 컨트롤에 유지합니다.
- **결과 없음 뒤 인기 악곡, 관련 없는 추천 또는 자동 Query 확장 — 거절:**
  정확한 공식 Catalog와 공개 의미를 보존합니다.
- **조회 실패를 결과 없음으로 표시 — 거절:** 사용할 수 없는 데이터와 유효한
  결과 0개 응답을 서로 다른 상태로 유지합니다.
- **모든 요청에 Loading 처리 표시 — 거절:** 요청 후 `300ms` Threshold 안에
  끝나는 요청은 진행 표시를 깜빡이지 않고 결과를 교체합니다.
- **전체 화면 Spinner·Skeleton·차단 Overlay 하나 사용 — 거절:** 결과 영역만
  진행을 전달하고 검색·범위·정렬·필터 컨트롤은 계속 사용할 수 있습니다.
- **모든 갱신을 Skeleton으로 교체 — 거절:** Skeleton은 느린 초기 Collection만
  나타냅니다. 이후 변경은 공간 Context를 보존하도록 이전 Collection을
  유지합니다.
- **시각적으로 오래된 결과 카드 실행 유지 — 거절:** 느린 교체 Feedback이
  나타난 뒤에는 해당 카드가 Commit 요청과 맞지 않아 진실하게 이동할 수
  없습니다.
- **교체 실패 뒤 맞지 않는 오래된 결과 유지 — 거절:** 탐색 조건은 유지하되
  결과 영역을 간결하고 재시도 가능한 오류로 바꿉니다.
- **Route 전체 오류 화면 또는 Toast만으로 조회 실패 표시 — 거절:** 실패는 결과
  영역에 속하며 인접한 영구 **다시 시도** Action이 필요합니다.
- **조회 오류 설명 문단 또는 Illustration 추가 — 거절:** 범위별 한 문장과
  **다시 시도**만 사용하고 진단 세부는 Logging에 남깁니다.
- **초기 조회 오류 Autofocus — 거절:** 사용자의 현재 컨트롤이나 읽기 위치를
  빼앗지 않고 Polite하게 알립니다.
- **대기 중 Focus된 재시도 컨트롤 제거·재생성 — 거절:** Focus Node를 유지하고
  중복 실행을 막으며 성공으로 사라질 때만 Focus를 옮깁니다.
- **지금 임의의 고정 Timeout 도입 — 측정 구현 Gate로 이관:** 운영 지연과
  Platform 제한을 근거로 유한한 값을 선택합니다.
- **요청의 무한 대기 허용 — 거절:** 승인되는 모든 구현에는 측정한 유한
  Timeout과 재시도 가능한 실패 경로가 필요합니다.
- **모든 상황의 즉시 필터 — 거절:** 결과를 가리는 모바일 Layer가 선택마다
  보이지 않는 콘텐츠를 바꾸고 반복 요청을 만듭니다.
- **모든 상황의 적용 필터 — 거절:** 결과가 보이는 데스크톱에서 유용한 Feedback
  없이 확인 단계를 추가합니다.
- **모바일에서 적용 후 닫기 두 Action — 거절:** 하나의 **결과 보기** Action이
  Commit과 복귀를 함께 수행합니다.
- **모바일 성공 Commit 후 필터·정렬 Trigger로 복귀 — 거절:** Trigger 복귀는
  취소에 유지합니다. 성공한 **결과 보기**는 Layer 과업을 완료하고 직접 연결된
  결과 요약 단계로 진행합니다.
- **모바일 Commit 후 첫 결과 Focus 또는 자동 열기 — 거절:** Commit 결과 수,
  정렬 및 적용 상태 Context를 건너뛰고 결과 집합이 비었을 때 안정적인 Target도
  없습니다.
- **Touch와 Keyboard 입력에 따라 모바일 Commit Focus 선택 — 거절:** 한 기기가
  입력 방식을 바꿀 수 있고 Screen Reader도 Touch로 동작할 수 있습니다. 논리적
  DOM 목적지 하나를 쓰고 필요한 경우 보이는 Focus 표현만 다르게 합니다.
- **지금 결과 요약을 별도 시각 행으로 의무화 — 이관:** 요약은 독립적으로
  보이는 Semantic 요소여야 하지만 같은 행·분리 행 구성은 다국어 `390px`
  Specimen 검증이 필요합니다.
- **자동 무한 Scroll — 거절:** 복구 가능한 증분 상태와 Context 복구를 갖춘
  명시적인 더 보기를 사용합니다.
- **묶음당 결과 `16`개 — 거절:** 첫 모바일 탐색은 짧아지지만 넓고 조밀한
  결과 레이아웃에서 불필요한 이어보기 실행이 늘어납니다.
- **결과 `24`개 또는 Viewport별 묶음 수 — 거절:** 모바일 Grid가 길어지고
  반응형 보기 변경이 논리 결과 집합을 바꿉니다. 예측 가능한 `20`개 단위
  규칙 하나를 유지합니다.
- **보이는 “악곡 20개” 또는 “채보 20개” 이어보기 Copy — 거절:** 채보 결과는
  여러 난이도 Target을 포함할 수 있는 악곡 Group입니다. 보이는 Label은
  다국어 **결과 20개 더 보기**를 쓰고 접근 가능한 이름에 활성 범위를 넣습니다.
- **성공 후 이동한 더 보기 Action에 Focus 유지 — 거절:** 새 실행 카드가 문서
  순서상 앞에 있어 Keyboard 역방향 이동을 강요합니다. 첫 새 결과로 이동하고
  확정된 진행을 알립니다.
- **공개 `loaded=60` 또는 묶음 Query Parameter — 거절:** 불러온 수량과 읽기
  위치는 일시적인 History 항목 상태이며 공유 URL에는 지속 탐색 조건만 둡니다.
- **Virtualization 사전 의무화 — 현재 거절:** 새 Component를 `20/60/100`으로
  먼저 검증하고 Markup과 Loading을 단순화하며 측정 비용이 여전히 허용할 수
  없을 때만 접근 가능한 Windowing을 요구합니다.
- **내부 Scroll이 있는 홈 5개 결과 미리보기 — 상위 문서에서 거절:** 홈 안에
  두 번째 Scroll 영역을 넣지 않고 이 페이지에 전체 탐색을 넘깁니다.
- **NOSTALGIA 클리어 필터 — 거절:** 이 게임의 탐색에서 의미 있는 결과를
  구분하지 못하고 일반 플레이 결과 범위와 중복됩니다.
- **◆JUST, MISS+NEAR, Timing 및 노트 종류 약점을 검색 필터로 사용 — 거절:**
  풍부한 수치는 기록 분석에 두고 고급 탐색에는 실행 가능한 절대 MISS 범위만
  유지합니다.
- **MISS 세부 필터 완전 제거 — 거절:** 절대 MISS Threshold는 NOSTALGIA의
  직접적인 연습 목표 근거와 비교 가능한 Catalog 선례가 있으며 부차적으로
  유지할 가치가 있습니다.
- **평상시 모든 카드에 일치 기록 행 상시 표시 — 거절:** 승인된 정체성 중심
  카드를 보존하고 적용 상태 요약과 기능 기반 Hover·Focus 미리보기 또는 목적지
  상세를 사용합니다.
- **Pointer 전용 기록 미리보기 — 거절:** Hover로 공개되는 정보에는 동등한
  Keyboard Focus 경로가 있어야 하며 Touch에서 요구하면 안 됩니다.
- **복합 취약순 — 거절:** 구현에 종속된 가중치는 이해 가능한 승인 사용자
  목표가 아닙니다.
- **숨은 Expert 대체값 또는 혼합 대표 레벨 — 거절:** 레벨순에는 명시적으로
  선택한 난이도가 필요합니다.
- **레벨순을 위한 상시 난이도 Button 행 — 거절:** Collection Toolbar가
  반복적인 컨트롤 Strip이 되지 않도록 Target을 점진적 정렬 공개 안에 둡니다.
- **좁은 레이아웃의 상시 별도 필터·정렬 Button — 거절:** Layer 밖에 현재
  정렬과 적용 필터 수를 계속 보이면서 하나의 명시적인 필터·정렬 진입을
  사용합니다. 내부 의미까지 하나로 합치는 것은 아닙니다.
- **최근 30일 내 플레이 필터 — 대체됨:** 현재 구현 컨트롤을 유지한 이전 결정은
  가치가 검증된 교차 조건 과업 없이 가져온 것이었습니다. 최근 플레이는 로그인
  정렬로만 유지합니다.
- **채보 Grid 보기 — 거절:** 공개 난이도 선택에는 추가 Artwork 모드보다 악곡
  정체성 아래의 Grouping된 탐색 목록이 필요합니다.
- **Database 생성·갱신 시각을 악곡 출시일로 사용 — 거절:** Import와 유지보수
  Timestamp는 진실한 신곡순을 지원할 수 없습니다.
- **악곡 목록의 별도 난이도 행 — 거절:** 안정적인 후행 Group에 들어가는
  간결한 정보 값에 부족한 세로 공간을 사용합니다.
- **모든 악곡 목록을 `96–112px` 행으로 확대 — 거절:** 짧은 정체성은
  간결하게 유지하고 긴 다국어 콘텐츠에만 필요한 공간을 주도록 콘텐츠 기반
  `64–100px` 높이를 사용합니다.
- **데스크톱 목록을 한 열의 전체 너비 Table처럼 사용 — 거절:** 카드마다 약
  `440–460px`을 유지할 수 있으면 간결한 목록 두 열을 추가하고, 더 조밀한
  다열 Artwork 탐색은 Grid에 맡깁니다.
- **후행 난이도만 기록 미리보기로 교체 — 거절:** 공식 난이도 Context를
  가리면서도 일치하는 여러 기록을 표시할 공간이 부족합니다.
- **별도 Popup, 확장 Panel 또는 레이아웃을 움직이는 기록 미리보기 — 거절:**
  같은 카드 크기 안의 대체 상태를 사용합니다.
- **첫 Tap 또는 Long Press Touch 미리보기 — 거절:** 한 번 Tap하면 악곡 상세를
  열어 주요 Action을 보존하고 숨은 모바일 단계를 만들지 않습니다.
- **카드 전체 높이를 맞추기 위한 Grid 재킷 왜곡·Crop — 거절:**
  `1 / 1` Artwork를 보존하고 아래 정보 영역이 긴 콘텐츠를 흡수하게 합니다.
- **미플레이와 최근 플레이순을 함께 유지하고 제목 동률 해소 사용 — 거절:**
  보이는 정렬 Label이 실제 결과 순서를 더 이상 설명하지 못합니다.
- **미플레이 활성 중 최근 플레이순 숨김 — 거절:** 종속성은 일시적이고 사용자가
  제거할 수 있으므로 사용할 수 없는 선택과 간결한 이유를 발견 가능하게
  유지해야 합니다.
- **최근 플레이순을 고르면 미플레이 자동 제거 — 거절:** 정렬 컨트롤이 결과
  구성원을 조용히 넓히면 안 됩니다.
- **미플레이를 제거하면 이전 최근 플레이순 자동 복구 — 거절:** 숨은 정렬
  이력은 예상하지 못한 두 번째 전환을 만듭니다. 사용자는 미플레이 제거 후
  최근순을 명시적으로 다시 고를 수 있습니다.
- **사용자가 최근순을 먼저 바꿀 때까지 미플레이 차단 — 거절:** 피할 수 있는
  단계를 추가하고 부차적인 정렬 선택이 주요 구성원 필터를 막게 됩니다.

## 미확정 디자인 질문

공용 탐색의 중요한 제품 동작 중 미확정인 것은 없습니다. Foundation Token,
정확한 Skeleton 수량과 Style, 결과 요약 행 구성 및 정확한 채보 행 시각은
승인된 동작을 다시 여는 것이 아니라 예정된 Specimen 결정으로 남습니다. 숫자로
된 유한 요청 Timeout은 운영 측정으로 해결해야 하는 구현 준비 Gate이며 임의의
제품 동작을 고르는 미확정 질문이 아닙니다.

## 브라우저 검증 대상

후속 구현은 최소한 다음을 검증해야 합니다.

- 악곡·채보 범위의 `/ko/music`, `/ja/music`, `/en/music`
- 홈·더보기 직접 진입, 빈 탐색, Query 인계, URL 공유, 새로고침, 뒤로가기 및
  앞으로가기 복구
- `300ms` 안정 검색을 사용하는 한국어·일본어 IME 조합
- `300ms` 입력 안정화 시계와 추가 `300ms` 요청 표시 시계를 별도로 검증하고,
  표시 Threshold 바로 전·후의 대표 응답에서 빠른 경우 Loading이 깜빡이지
  않는지 확인
- 활성 요청 중 Query, 범위 및 필터 변경과 의도적으로 순서를 바꾼 응답
- 숨은 난이도 제한 없는 전체 악곡 초기 탐색
- 세 Locale 모두에서 `title_kana` 오름차순인 빈 악곡 탐색
- 악곡 Group의 가장 최근 공개 채보 시각 내림차순인 빈 채보 탐색과
  `Normal → Hard → Expert → Real` Target 순서
- 검증된 공식 출시일을 사용하는 신곡순, 데이터가 없을 때의 Gate 상태 및
  Database Timestamp로 대체하지 않음
- 취약순이 없고 레벨순 전에 난이도를 명시적으로 선택함
- 능동 Query 관련도순 대체값, 명시적 정렬 유지 및 관련도 Query를 지웠을 때
  범위 기본 정렬로 복귀
- 일치하는 공개 난이도 0개, 1개 및 여러 개인 채보 Grouping
- 공개 난이도에서 집중형 뷰어로 직접 진입하고 정확한 복귀 상태 복구

## 이 기획서의 승인 기준

- 하나의 공용 Surface 안에서 악곡·채보 범위의 의미 차이를 유지합니다.
- 초기 악곡 탐색에 숨은 Expert `8–12` 제한이 없습니다.
- 빈 악곡·채보 탐색에 범위에 맞는 명시적인 정렬이 있고 신곡순은 검증된 공식
  출시일 데이터가 있을 때만 제공합니다.
- 공개 채보 결과를 악곡별로 묶고 사용할 수 없는 Target을 노출하지 않습니다.
- 취약순이 없고 레벨순에 암묵적인 난이도 기준이 없습니다.
- 능동 Query 관련도순, 명시적 정렬 유지, 모바일 통합 필터·정렬 Commit,
  데스크톱 별도 능동 컨트롤 및 적용 상태 제거에 충돌하지 않는 명시적인 규칙이
  있습니다.
- 모바일 **결과 보기**는 Commit·닫기 후 보이는 결과 요약으로 Focus하고,
  취소 경로는 Trigger와 이전 읽기 Context를 복구하며, 대기 중인 갱신은 결과
  수를 중복해 읽지 않고 확정된 Polite 알림 하나만 제공합니다. 요약의 정확한
  같은 행·분리 행 시각 배치는 미확정 동작이 아니라 Specimen 결정으로 남깁니다.
- 로그인 기록 세부 필터에 간결한 승인 분류, 최고 기록 MISS 의미, 결합 규칙,
  미플레이·최근순 정규화, 발견 가능한 사용 불가 이유, 원자적인 모바일 복구,
  숨은 정렬 복원 금지 및 불가능한 상태 처리가 있습니다.
- 악곡 결과 정체성, 콘텐츠 순서, 줄 수 제한, 목록·Grid 밀도 경계, 정사각형
  재킷 동작, 기능 기반 Hover·Focus 기록 Context 및 직접 Touch 상세 동작을
  명시합니다. Foundation 스타일 Token은 승인된 구조를 다시 여는 것이 아니라
  후속 작업으로 남습니다.
- 자동 무한 Scroll이 없습니다. 명시적인 점진적 불러오기에 안정적인 `20`개
  결과 규칙, 다국어 다음 수량·진행 Copy, Loading, Focus, 알림, 재시도, 끝,
  History 복구 및 `20/60/100` 성능 요구사항이 있습니다.
- 결과 없음 처리는 탐색 작업을 보존하고 원인을 내부적으로 구분하며 승인된
  한 줄 다국어 Copy를 사용합니다. 복구는 기존 컨트롤에 유지하고 설명 문단,
  중복 Action, 관련 없는 대체 콘텐츠 또는 오류 상태로 바꾸지 않습니다.
- 일시적 응답 처리는 승인된 입력·요청 시계를 분리하고 빠른 응답의 깜빡임을
  피하며 초기 Skeleton과 기존 결과 유지 교체를 구분하고, Busy·실패를 결과로
  제한하며, 보이는 오래된 결과 실행을 막고 최신 요청만 확정하게 합니다.
- 조회 실패는 세 Locale에서 승인된 악곡·채보 한 줄 Copy와 **다시 시도**를
  사용하고 Commit 탐색 상태를 보존하며 명시적인 Focus 복구를 제공하고 결과
  0개와 구분하며 구현 승인 전에 측정한 유한 Timeout을 요구합니다.
- 현재 구현 사실을 승인된 2.0 동작으로 잘못 표시하지 않습니다.
- 모바일과 데스크톱이 하나의 제품 모델을 공유하면서 결과 가시성과 공간에
  맞게 적응합니다.
- 한국어·일본어·영어, 접근성, 성능 및 브라우저 검증 요구사항을 기록합니다.
- 중요한 페이지 동작 중 `미확정` 또는 `제안`으로 남은 것은 없습니다. 예정된
  Specimen 세부와 측정할 구현 Timeout Gate는 미확정 제품 동작으로 오해하지
  않게 구분합니다.
- 사용자는 2026-07-31에 동기화된 전체 기획서와 해결된 결정 기록을
  승인했습니다.
