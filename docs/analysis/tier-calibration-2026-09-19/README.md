## 추정 규칙

아래 수치들은 이번 임시 초안을 완성하기 위해 정한 보수적 정책값이다. 데이터에서 검증된 최적값이나 외부 가이드라인이 아니다. 추정치는 1.0–14.5 범위에서 0.1 단위로 반올림한다. 네 목표의 상대 서열을 각각 추정하며 S ≤ 990k ≤ Pianist 같은 목표 간 수치 순서를 보장하지 않는다. 특히 S에는 수동 기준점이 많고 다른 목표에는 두 개뿐이라 절대 눈금이 완전히 일치하지 않는다.

### 1. 목표별 성적 변환

`log1p(x) = ln(1+x)`, `deficit = 1,000,000-score`로 두고, 값이 클수록 어렵게 나타난 성적으로 변환한다.

- S: `log1p(max(0,950000-score)/50000) + 0.35*log1p(deficit/50000)`.
- 990k: `log1p(max(0,990000-score)/10000) + 0.35*log1p(deficit/10000)`.
- Pianist: `log1p(deficit/1000)`.
- Recital: 양수인 `chart_recital_grd_raw`의 `-ln(Grd)`. 0은 결측으로 제외한다. Basic 점수를 대체 사용하지 않는다.

Basic은 양수 점수만 쓴다. Pianist 달성 인원은 사이트와 같은 `fc_type=3 또는 score=1000000`이다. 이번 자료에서 `fc_type=3`인데 만점이 아닌 사례는 없다. Basic 변환식은 목표 달성 여부만 아니라 목표까지 남은 점수도 반영한다.

Recital 변환은 **같은 조건에서 얻은 Grd가 상대적으로 낮은 정도를 난도의 대용 지표로 삼는다**. 최대 Recital Grd 공식이 확인되지 않아 달성률/최대값 비율을 주장하지 않는다. 이 모형은 곡 고유 Grd 산식·플레이 선택·성적 차이를 완전히 구분하지 못한다. 전체를 채우기 위한 가장 약한 근거의 초안이다.

### 2. 같은 유저 및 비슷한 Grd와 비교

해당 채보를 모든 유저의 비교 집합에서 제외한다. 같은 난이도 종류(Hard/Expert/Real)이고 공식 상수 차이가 1.5 이하인 채보를 사용한다. 상수 차이의 정규 커널 폭은 0.75다. 로컬 선형 회귀로 목표 공식 상수 위치의 기대 성적과 잔차 표준편차를 구한다. 기울기에는 총 가중치의 0.1만큼 규제를 가한다.

Recital은 노트 수의 로그 비율에 폭 0.5인 커널도 적용한다. 노트 수가 없으면 그 기록의 직접 보정을 생략한다. 이는 경험적 비교 조건이며 Basic 최대 Grd 공식을 Recital에 적용한 것이 아니다.

같은 유저 비교에 더해 다른 유저의 공식 Grd 근접도를 사용한다. 표시 Grd 기준 커널 폭은 Basic 400, Recital 1,000이다. 다른 유저별 총 가중치는 최대 1로 제한하여 기록이 많은 유저가 압도하지 않게 한다. 같은 유저 기준과 다른 유저 기준을 `같은 유저 유효 표본 수/(그 수+12)`로 혼합한다. 비교 자료가 3개 미만이거나 가중 유효 표본이 3 미만이면 해당 기준은 사용하지 않는다.

정규화한 잔차 표준편차의 하한은 0.15다. 해당 기록의 보정값은 `0.5 * (관측 손실-기대 손실)/표준편차`, 범위는 ±1.0이다. 이 0.5는 임시 상수 눈금을 정하는 정책값이다.

### 3. 공식 상수·기존 수동 배치로 눈금 유지

기본값은 현재 공식 상수다. 같은 난이도 종류에서 공식 상수가 ±1 이내인 변경 이력 배치가 5개 이상이면, `기존값-공식값` 중앙값을 기준점 수 `k/(k+8)`만큼 반영한다. 기준점 보정은 ±1.2로 제한한다. 이 조건은 주로 S에 적용된다. 두 기준점만 있는 다른 목표로 S 보정량을 복사하지 않는다.

직접 비교 가능한 인원 `n`명의 보정 중앙값은 `n/(n+3)`만큼 반영한다. 나머지는 같은 난이도·공식 상수 ±0.5인 채보 중 비교 인원이 3명 이상인 채보들의 보정 중앙값을 사용한다. 유사 채보 보정에는 채보 수 `k/(k+10)` 축소를 적용한다. 비교 자료가 전혀 없으면 공식 상수와 해당 목표의 기준점 보정만 남는다.

98개 기존 변경 이력 배치는 모델 제안과 무관하게 유지한다. 모델 참고값은 해당 배치 자체도 기준점 집합에 들어간 결과이므로 독립 검증 성적으로 해석하면 안 된다.

### 4. 표의 근거와 민감도

- `관측 보정`: 직접 비교 가능한 유저 3명 이상. 확정/고신뢰라는 뜻이 아니다.
- `소표본 보정`: 직접 비교 가능한 유저 1–2명.
- `유사 채보·공식 상수 보정`: 직접 비교 가능한 기록 없음.
- `수동 배치 유지`: 변경 이력이 있는 현재값 유지.

민감도는 이미 계산한 개인 보정값에서 한 사람씩 제외한 범위다. 비교 집합 전체를 다시 학습하는 교차검증이나 통계적 신뢰구간이 아니다. 227개 제안에서 이 범위가 0.3 이상이다. 최대값 14.5에서 잘린 모델값도 그 이상 난도 차이를 표현하지 못한다.

## Rating 영향

현행 `lib/tiers/basicRating.ts`의 Pianist 상수 제곱·상위 70개·mastery 보간 공식을 그대로 오프라인 계산했다. Recital Rating 역시 현재 제품 코드대로 점수 기반 기여도이며 `grade_recital>0`만 필터링한다. 이를 Recital 상수 추정 방식과 혼동하지 않는다.

- 표본 7명의 Basic Rating: 약 444.16–846.15점 하락.
- 표본 7명의 Recital Rating: 약 67.85–315.01점 하락.
- 전체 회원/비공개 회원 영향은 계산하지 않았다.
- 상위 70개 이론상 분모와 개인 반영 채보 모두 달라져 생기는 변화다. 기존 점수·공식 Grd·Rating 계산식은 수정하지 않는다.
- 저장된 과거 Rating 이력은 수정하지 않으므로 적용 전후 눈금 차이는 남는다.

## SQL 사용

1. `review.html`에서 제안을 검토한다.
2. `01-preview.sql` 전체를 Neon SQL Editor에 복사해 실행한다. 위 표와 건수를 비교한다.
3. 반영하기로 결정하면 `02-apply.sql` 전체를 한 번에 실행한다. 부분 실행하지 않는다.
4. `03-verify.sql`을 실행한다. `differences_from_applied_snapshot`이 0인지 확인한다.
5. 원복이 필요하고 그 사이 후속 편집이 없으면 `04-rollback.sql` 전체를 실행한다.

반영 SQL은 네 서열표와 관련 테이블의 쓰기를 트랜잭션 동안 잠근다. 잠금 대기는 5초, 쿼리 제한은 60초다. 입력 이후 배치/이력/Hard 이상 전체 채보 목록/상수/노트 수가 변했거나 필요한 상수 구간이 없으면 전체 중단한다. 원본·반영 후 배치와 이력은 별도 보조 테이블 `public."_TierCalibration_20260919_v1"`에 보관한다. 애플리케이션 스키마/Prisma 모델 변경은 없지만 이 백업 테이블은 DB에 추가된다. 재실행은 차단하며, 원복 후에도 백업은 남긴다.

Normal의 상수와 포함 여부는 유지한다. 같은 구간의 위치 고유 제약을 지키기 위해 정렬 번호는 다시 매긴다. 같은 구간에 남은 채보의 상대 순서는 유지하고 이동/신규 채보를 뒤에 채보 ID순으로 붙인다. 변경/신규 상수에만 이력을 추가한다. 원복은 원래 정렬 번호·타임스탬프까지 복원한다.

Neon 직접 수정은 Next.js 캐시 태그를 무효화하지 않는다. 서열/Rating 기준에 3,600초 재검증 캐시가 있어 화면 반영은 즉시가 아닐 수 있다. 브라우저 새로고침만으로 서버 캐시가 없어지지는 않는다. 실제 운영 반영/캐시 갱신/화면 검수는 아직 하지 않았다.

## 검증

`check-tier-draft-sql.py`로 실제 PostgreSQL의 임시 Unix socket 전용 클러스터에서 테스트했다. 운영 환경변수·운영 DB를 사용하지 않았다. 테스트 종료 후 클러스터를 중지하고 삭제했다. 관련 컬럼과 FK/고유 제약을 재현한 fixture 8,636배치·2,171채보로 실행했다. 전체 애플리케이션 DB 스키마/e2e 테스트는 아니다.

통과 항목:

- 미리보기 건수와 제안 건수 일치.
- 6,364개 제안값 모두 일치; 4,680개 수정·40개 신규; 위치는 모두 양수.
- Normal 상수 유지, 변경/신규 4,720개 이력 추가.
- 자료 이후 배치 수정·새 채보 추가 시 실행 거절.
- 반영 SQL 재실행 거절, 거절 후 데이터 유지.
- 반영 후 이력 편집이 있으면 원복 거절.
- 원복 후 원본 배치·정렬·타임스탬프·서열표·이력이 JSON 지문까지 일치.
- 원복 재실행 거절.

모형의 난도 예측 정확도는 검증하지 못했다. UI 제품 코드 변경이 없으므로 앱 lint/typecheck/e2e는 실행하지 않았다.

## 재현

출력 경로 `--output`은 `.local/analysis/tier-calibration-2026-09-19`로 지정한다. 생성 스크립트와 SQL 검사 스크립트에 모두 같은 출력 경로를 사용한다.

Python 3 + NumPy로 `scripts/analysis/calibrate-tier-draft.py`에 `--placements`, `--records`, `--catalogue`, `--output`을 지정한다. 앞의 세 파일은 각각 사용자가 제공한 JSON 내보내기다. 원본 유저별 기록은 저장소에 복사하지 않았다. 이어 `scripts/analysis/build-tier-draft-sql.py`에 `--placements`, `--catalogue`, `--output`을 지정한다. 로컬 PostgreSQL 설치가 있으면 `check-tier-draft-sql.py`에 같은 세 인자를 주어 SQL을 재검증한다. 현재 검사 스크립트는 Homebrew PostgreSQL 경로를 사용한다.
