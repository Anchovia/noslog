# 서열 변경 공지 이미지

관리자 공지 작성·수정 화면의 **서열 변경 이미지** 펼침 칸에서 생성한다.
양식은 사용자가 지정한 [2026-09 서열 변경 공지](https://noslog.app/ko/announcements/tier-update-2026-09)와 첨부한 1200×706 PNG를 기준으로 한다.

1. Basic/Recital, 목표, 변경 날짜를 고른다. Recital은 기존 모델대로 Pianist 목표만 사용한다.
2. 곡 제목·아티스트를 검색해 추가한다. 제목과 채보 레벨은 기존 음악 검색에서 채우며 난이도는 등록된 채보 중에서 고른다.
3. 변경 전·후 서열 값을 입력한다. 기존 서열 규칙인 1–14.5, 소수 한 자리를 따른다. 같은 값·중복 곡/난이도는 생성하지 않는다.
4. **이미지 미리보기**를 누른다. 자체 호스팅 Pretendard JP 폰트와 브라우저 캔버스로 PNG를 만들며 이 단계는 업로드하지 않는다.
5. **현재 언어 본문에 이미지 첨부**를 누르면 기존 공지 이미지 업로드 권한과 공개 Blob 경로로 올리고 본문 끝에 마크다운을 넣는다. 실제 공지 저장·게시와 서열표 수정은 기존 기능에서 별도로 수행한다.

생성 중·첨부 중에는 관련 입력과 공지 저장을 막는다. 첨부를 시작할 때 선택한 언어의 최신 본문에 추가하므로,
업로드 중 다른 언어 탭으로 옮기거나 글을 더 써도 기존 내용을 덮어쓰지 않는다. 업로드 실패는 본문을 변경하지 않고 재시도할 수 있다.
미리보기 후 입력이 바뀌면 오래된 이미지가 붙지 않도록 미리보기를 지운다. 폰트 실패는 대체 폰트로 숨기지 않고 오류를 보여준다.

고정 이미지 양식은 앱 UI 토큰과 분리한다. 폭 1200, 상향/하향 묶음·화살표·전후 한 자리 숫자·날짜·곡 수·NosLog 표기를 유지한다.
원본 예제 두 곡은 1200×706이며 긴 곡명은 자르지 않고 줄바꿈해 높이를 늘린다.
비어 있는 방향은 생략하고 묶음 안에서는 입력 순서를 유지한다. 캔버스 크기 한도나 기존 업로드 4MB를 넘으면 곡을 나누어 생성하도록 안내한다.
이미지 자체는 동일하게 공유할 수 있고, 첨부된 대체 설명에는 해당 언어의 안내와 모든 곡·난이도·레벨·전후 값이 들어간다.

구현 원본:

- 입력: `features/announcements/schemas/tier-change-image-schema.ts`
- 고정 양식·캔버스: `features/announcements/lib/tier-change-image.ts`
- 비동기 첨부: `features/announcements/lib/attach-tier-change-image.ts`
- 생성 칸: `features/announcements/components/tier-change-image-builder.tsx`

Storybook `Features/Announcements/TierChangeImageBuilder`는 실제 검색 결과 형태와 생성 코드를 사용하고 검색·업로드만 mock으로 격리한다.
기준 예제·곡 검색/자동 레벨·빈 입력·첨부/미리보기 무효화·업로드 실패/재시도를 검증한다.
단위 테스트 `tests/tier-change-image.test.ts`는 입력 계약·방향 분류·원본 크기·긴 제목·세 언어 대체 설명·업로드 중 본문 보존과 실패를 검사한다.
DB·Blob·로그인·실제 공지 저장/게시는 자동 부품 검사에서 실행하지 않는다.

## 대규모 재배치의 전체 변경 파일

2026-10-08 전체 재배치의 공지용 CSV는 `public/downloads/noslog-tier-changes-2026-10-08.csv`에 둔다.
공지 본문에는 `/downloads/noslog-tier-changes-2026-10-08.csv` 링크를 넣는다. 공개 데이터 파일이므로 배포 후 다운로드할 수 있다.
원본 8,688개 배치 중 상향 3,760건·하향 3,782건·신규 12건, 총 7,554건을 담고 값 유지 1,134건은 제외한다.
서열표·채보 ID·곡명·난이도·전후 값·차이·구분·비고만 공개한다. 신규의 변경 전 값과 차이는 빈칸으로 두고, `月の光 Real`의 분석용 임시 기준 11.0은 비고에 명시한다.
이 파일은 적용 당시의 고정 변경 내역이다. 이후 서열표 변경을 자동으로 반영하거나 곡별 이미지 생성 칸에서 CSV를 읽는 기능은 제공하지 않는다.
